# 모바일 텍스트 표시 조절

2026-09-29, 사용자가 Android 삼성 인터넷에서 키보드 수정 후 정상 동작을 확인했으며, 작은 화면에 더 많은 코드를 볼 수 있도록 개선을 요청했다.

## 변경

- 기존 40px 터미널 전환 줄에 `A− / 현재 크기 / A+`를 배치했다. 별도 세로 줄을 추가하지 않는다. 10~24px 범위에서 1px씩 조절하며 현재 크기를 누르면 14px로 복원한다.
- 크기는 현재 브라우저의 `mongle.fontSize`에 저장하며 기존 설정 화면과 공유한다. 잘못된 저장값은 14px로 복구한다. 다른 기기의 글자 크기 설정을 변경하지 않는다.
- `화면 넓게`는 모바일에서 컴퓨터·그룹 제목 영역만 접는다. 터미널 메뉴, 패널 전환, 제어 상태와 복귀 버튼은 유지한다. 로그아웃 후 페어링 화면에서는 제목 영역을 복원한다.
- 글자 조절과 화면 넓게 버튼을 누를 때 입력 포커스를 유지한다. 기존 크기 변경·화면 ACK 동기화 경로를 사용하며, 보기 전용 연결은 셸 크기를 바꾸지 않는다. 브라우저 자체 확대 제스처를 차단하지 않는다.

## 검증 기록

아래 자동 검사는 실제 휴대폰 소프트 키보드의 검증과 구분한다. 기존 키보드 수정의 실물 사용자 확인은 [모바일 키보드](mobile-keyboard.md)에 기록했다. 새 크기 조절 및 화면 넓게의 실물 입력 결과는 별도 확인 대상이다.

모바일 표시 회귀 **4/4 통과, 실패·생략 0, 13.59초**(상위 검사 1개·하위 시나리오 3개). 폰트 변경 후 실제 렌더링 크기와 해당 크기 변경의 화면 ACK를 확인했다. 크기 경계·잘못된 저장값·설정 화면 연동·새로고침 유지, 포커스와 입력 상태 유지, 화면 넓게와 복귀 시 실제 행 수와 이후 입력, 로그아웃 시 제목 영역 복원, 데스크톱 헤더 유지까지 확인했다. 보기 전용 연결의 크기 변경 차단은 코드 검토에서 확인했다.

추가로 기존 모바일 키보드 및 설정 검사 **2개**, 실제 HostCore + Chrome UI 검사 **1개**, TypeScript 검사와 웹 빌드가 통과했다. 320px·390px 화면 캡처에서 표시 버튼과 복귀 버튼이 한 줄 안에 있으며 잘리지 않음을 확인했다.

| 시험 너비 | 14px 기본 화면 | 10px + 화면 넓게 | 추가 터미널 높이 |
|---|---|---|---|
| 390px | 43열 × 33행 | 60열 × 55행 | 60px |
| 320px | 34열 × 33행 | 48열 × 55행 | 60px |

이는 높이 844px의 데스크톱 Chrome 모바일 화면 시험 결과이며, 실제 휴대폰의 브라우저 도구 모음·소프트 키보드 높이에 따라 표시량은 달라진다. 증거: `test-results/mobile-display/summary.md`, `mobile-display-320.png`, `mobile-display-390.png`.

09:15 KST에 실행 중인 웹 자산만 교체했다. 실제 Tailscale HTTPS 주소의 HTML·JavaScript·CSS가 개발 빌드와 일치하며, 기존 호스트 PID 6400·bootId와 PowerShell PID 14060이 유지됨을 확인했다. 증거는 `test-results/mobile-display-hot-update.json` 및 `test-results/mobile-display-live-check.json`이다. 호스트를 재시작하거나 다시 페어링하지 않았다.
