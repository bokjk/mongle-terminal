# 기존 원격 연결 복구

2026-09-29, Windows x64. 사용자가 현재 컴퓨터에서 원격 접속을 켰을 때 `SERVE_SHARED_HOST` 오류를 보고했다.

**검증 정정:** 이 문서의 최초 HTTPS 성공은 Codex의 MSIX 설정 폴더를 사용한 실행 맥락의 결과였다. 탐색기로 실행한 실제 사용자 앱에는 다른 설정·인증 키가 적용돼 오류가 계속됐다. 이후 원인을 확인하고 실제 프로필의 원격 접속까지 복구했다. [설정 폴더 분리 원인과 최종 검증](msix-profile-recovery.md)을 현재 상태로 삼는다.

## 진단과 수정

실제 Tailscale의 HTTPS 경로는 사용자 데이터 폴더에 저장된 몽글 관리 기록과 일치했다. 진단 당시 몽글터미널 GUI와 사용자 호스트는 종료되어 있었고 기존 Serve 경로와 게이트웨이 포트 기록은 남아 있었다. 사용자가 오류를 보았던 순간의 실행 상태까지 재현한 것은 아니다.

기존 코드는 관리 파일이 없거나 내부 포트가 바뀌면 이전 자기 경로도 다른 서비스로 분류했다. 현재 게이트웨이의 정확한 루프백 주소를 가리키는 단일 HTTPS 경로는 관리 파일을 복원해 재사용한다. 이전 포트를 바꾸는 경우는 유효한 저장 기록과 현재 경로가 일치하는 자기 연결로 한정한다.

재사용 분기에도 같은 DNS의 다른 HTTPS 포트·경로·Funnel·TLS 프록시 검사를 적용했다. Foreground와 Services 내 같은 DNS 설정도 확인하며 호스트 이름의 대소문자를 구분하지 않는다. 다른 서비스나 알 수 없는 이전 포트를 추정해 인계하지 않고, 전체 Serve 초기화는 사용하지 않는다. 켜기·끄기는 순서대로 처리하고 변경 직전 설정을 다시 읽는다. 해제 시 포트를 공유하는 다른 경로는 보존한다.

이는 원격 켜기·끄기와 진단 시점의 검사다. 다른 프로그램이 나중에 Serve를 바꾸는 상황을 상시 감시해 기존 승인을 자동 폐기하는 기능은 추가하지 않았다. 경로 재사용 성공 시 기존 인증 데이터를 초기화하지 않는다.

설정 구조는 설치된 Tailscale 1.102.2의 [공식 ServeConfig 정의](https://github.com/tailscale/tailscale/blob/v1.102.2/ipn/serve.go)를 확인했다.

## 검증

- 격리 폴더의 실제 관리 파일과 시험 CLI 응답으로 45/45 통과: 누락·손상 복구, 이전 포트 갱신, 알 수 없는 경로 거부, 중첩 서비스·Funnel·TLS 프록시·대소문자 충돌, 변경 직전 경합, 접근 오류, 동시 켜기·끄기, 공유 포트 해제 방지.
- 타입 검사와 코드 검토 통과. `scripts/package.ts --dir --output release-remote-recovery`로 최신 소스를 패키징하고 네이티브 의존성과 아이콘을 검사했다. 최종 패키지의 격리 Electron 실행 검사 1/1 통과.
- 앱 교체 전 사용자 GUI·호스트가 실행 중이지 않은지 확인하고 기존 실행 파일을 백업했다. 실제 `release/win-unpacked`에 0.2.0 수정본을 적용한 뒤 새 앱과 호스트를 실행했다. 세션·인증 데이터는 삭제하거나 초기화하지 않았다.
- 실행 중인 실제 호스트의 인증된 소유자 IPC에서 `remote.enable`을 두 번 호출해 같은 주소 재사용을 확인했다. 전후 Tailscale Serve JSON은 동일했다.
- 인증서 검증을 유지한 실제 HTTPS `/health` 응답의 hostId·bootId가 로컬 호스트와 일치했다. 원격 켜기 전후 4개 터미널의 식별자·PID·상태와 호스트 bootId도 같았다. 실제 휴대폰의 후속 접속은 별도 사용자 확인 대상이다.

로컬 증거는 `test-results/remote-recovery/deployment.json`, `live-result.json`, `desktop-stderr.log`와 `test-results/remote-recovery-package.log`다. 기기 주소와 사용자 식별 정보가 있는 실행 로그는 커밋하지 않는다. 이전 파일 백업은 `.test-data/remote-recovery/previous-app`에 보존했다.

이번 산출물은 실행 폴더다. `release-autoupdate/`의 앞서 만든 NSIS·ZIP에는 이 후속 원격 수정이 포함되지 않으며, 공개 배포 전에 미배포 변경 정리와 전체 패키징을 다시 해야 한다.
