# README 화면 캡처

`desktop.png`와 `mobile.png`는 몽글터미널 v0.3.6의 실제 웹 UI와 실제 Windows PowerShell을 사용해 촬영한 화면입니다. 픽셀 편집, 앱 화면의 DOM 교체, 상태 응답 조작은 하지 않았습니다.

| 이미지 | 캡처 조건 |
| --- | --- |
| `desktop.png` | Chrome 1440 × 900, 어두운 테마, 3개 분할 영역·4개 셸. 첫 영역에 독립된 탭 두 개와 마지막 탭 뒤 + |
| `mobile.png` | Chrome 모바일 에뮬레이션 390 × 844, 12px 글꼴, 같은 호스트의 첫 번째 터미널 |
| `git-switch.png` / `git-files.png` / `git-changes.png` | 실제 0.3.6 패키지 Electron·OwnerPipe·cmd·Git, 격리된 샘플 저장소. 실제 탐색기 제목줄과 트리 영역을 각각 캡처 |

터미널 내용은 README를 위한 **예시 프로젝트**입니다. 화면의 테스트 2개는 예시 프로젝트의 패널 추가·그룹 이름 변경 함수를 실제 Node 테스트 러너로 실행한 결과이며, 몽글터미널 전체 회귀 검사 결과를 나타내지 않습니다. 모바일 이미지는 반응형 화면 설명용입니다. 실제 휴대폰, 소프트 키보드, Tailscale 통신을 검증했다는 의미는 아닙니다.

Git 캡처는 실제 변경 결과이며 상태 응답을 조작하지 않았습니다. 예시 README는 삭제를 스테이징한 뒤 다시 만들어 삭제·새 파일 두 그룹에 나타납니다. 전체 개수에는 한 번만 포함하고 파일 트리에서는 현재 새 파일 상태를 표시합니다. 개인 폴더 경로를 포함하지 않는 실제 UI 영역만 촬영했습니다.

## 다시 촬영하기

Windows, Node.js 24, Chrome, 설치된 PowerShell이 필요합니다.

```powershell
npm ci
npm run build
npx tsx scripts/capture-readme.ts
```

스크립트는 `.test-data/readme-demo/` 아래에 새 호스트 데이터와 예시 프로젝트를 만듭니다. 개인 경로 노출을 피하기 위해 비어 있는 드라이브 문자를 잠시 매핑하며, 화면에는 `X:\workspace` 같은 예시 경로가 표시됩니다. 그룹 생성·이름 변경·분할·화면 설정은 실제 UI로 수행하고, 호스트의 실제 터미널 처리·입력·출력·제어권 흐름을 사용합니다. 브라우저와 호스트 사이 연결만 로컬 테스트 브리지로 연결합니다.

PowerShell은 `-NoProfile`로 실행하고 명령 기록 저장을 끕니다. 기존 사용자 호스트·셸·인증 데이터·Tailscale 설정을 사용하지 않습니다. 종료 시 자신이 만든 브라우저와 호스트를 닫고, 소유한 드라이브 매핑과 이번 실행의 격리 폴더만 확인 후 제거합니다.

2026-10-01에 0.3.6으로 재생성했습니다. 영역별 탭·**새 터미널**과 모바일 설정 조작을 사용하며, Git 기능은 [별도 실제 패키지 검증](../validation/git-file-explorer.md)으로 확인합니다. 검증 결과는 [0.3.6 배포 기록](../validation/public-release-0.3.6.md)에 정리합니다.

## 0.3.7 재촬영 · 2026-10-02

`capture-readme.ts`로 1440×900 데스크톱과 390×844 모바일 화면을 다시 촬영했다. 격리한 예제 Git 저장소, `기본` 작업과 `로그인 개선` 워크트리, 일반 터미널을 실제 HostCore·Windows 셸에 연결했다. 네 개 터미널과 세 개 분할 영역을 사용한다. 화면은 실제 렌더링 그대로이며 픽셀·앱 DOM을 수정하지 않았다. 공용 임시 폴더와 임시 드라이브 경로만 표시하고 실사용 경로·인증 정보·Tailscale을 포함하지 않는다. 모바일은 Chrome의 터치 화면 에뮬레이션이다. 기존 Git 보기 이미지는 0.3.6 촬영본을 유지한다.

이번 촬영은 `MONGLE_README_DATA_ROOT=C:\Users\Public\Documents\ESTsoft\CreatorTemp\MongleDemo`로 실행했다. Git이 임시 드라이브를 실제 경로로 정규화하므로 사용자별 개발 경로 대신 공용 폴더에 격리 예제를 생성하고 종료 후 삭제했다.
