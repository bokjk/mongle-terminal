# 작업 상태 표시 재설계와 Claude 상태 오류 수정

2026-10-08~09. **구현·자동 검사·실제 CLI 재현·실제 앱 검증 완료, 0.3.18 배포 준비.** 실제 앱에서 확인한 범위와 확인하지 못한 범위는 [실제 앱 검증](#실제-앱-검증)에 따로 기록한다. 배포 검사는 [0.3.18 배포 검증](public-release-0.3.18.md)에 기록한다.

## 제보

작업 중·완료 표시(맥동하는 원과 종)가 보기 좋지 않고, 진행 중이 아닌데도 진행 표시가 뜨는 등 상태가 맞지 않는다는 제보다. Claude만의 문제인지 Codex도 그런지 확인이 필요했다.

## 수정 전 실제 CLI 재현

몽글의 실제 TerminalEngine과 PowerShell 7 셸 통합(safeShellEnvironment, 셸별 토큰, 프롬프트 표식)을 쓰는 시험 스크립트로 ConPTY에서 CLI를 실행했다. 훅 이벤트·BEL/OSC 신호·상태 변화를 시간순으로 기록했다. 사용자의 몽글 앱·실행부·설정·인증은 바꾸지 않았다. Claude는 사용자 PC에 이미 설치된 몽글 훅을 그대로 썼다. 시험 스크립트와 기록은 커밋하지 않는 .test-data/status-probe/에 있다.

- Claude Code 2.1.294(Windows 네이티브), Codex CLI 0.161.0. 두 CLI가 이미 신뢰한 저장소 폴더에서 짧은 응답만 요청했다.

| 상황 | 받은 훅 | 수정 전 상태 |
| --- | --- | --- |
| 일반 응답 | UserPromptSubmit → 약 2초 뒤 Stop | 작업 중 → 응답 완료, 알림 1 (정상) |
| /context, /cost | 없음 | 변화 없음 (정상) |
| Esc로 응답 중단 | 없음 | 작업 중 → 대기 (정상) |
| 작업 중 / 메뉴를 Esc로 닫음 | 3.8초 뒤 Stop | 대기로 바뀐 뒤 Stop을 버림. **완료 알림 유실** |
| 작업 중 추가 메시지 | UserPromptSubmit 2회, Stop 2회 | 첫 Stop에서 완료. **두 번째 완료는 알림 없음** |
| !echo(셸 명령) 뒤 Claude 응답 | Stop만 | 새 알림 없음 |
| /compact | SessionStart(compact) | **대기로 초기화** |
| 쓰기 권한을 "3. No"로 거절 | 거절 뒤 80초 이상 없음 | **다음 질문까지 확인 요청 유지** |
| 질문(AskUserQuestion)에 Enter로 답함 | PostToolUse(입력에 답 추가) → Stop | **응답이 끝날 때까지 확인 요청 유지** |
| 정상 Stop 뒤 | 약 60초 뒤 Notification(idle_prompt) | 무시 (정상) |

이 실행에만 --settings로 20종 이벤트 기록 훅을 붙여 확인했다. 수동 거절과 Esc 취소 뒤에는 PostToolBatch·PermissionDenied·Stop을 포함해 어떤 훅도 오지 않았다. PermissionRequest에는 tool_use_id가 없고 PreToolUse·PostToolUse에는 있다. 사용자 설정의 다른 훅과 함께 실행할 때는 SessionStart(startup)·SessionEnd가 몽글로 전달되지 않았고, CLI 종료는 셸 프롬프트 표식으로 반영됐다.

**Codex:** 사용자 기본 설정에서 정상 응답·/status·Esc 중단·종료 동안 몽글 상태 변화와 BEL/OSC9 알림이 모두 0회였다. Codex 연동은 대화 재개용 SessionStart/End만 전달하므로 **작업 중 표시는 Claude 경로에서만 생긴다.** 다만 기존 화면은 모바일·접힌 사이드바의 터미널 전환 버튼에 그룹 전체 상태를 붙였다. 그래서 같은 그룹의 Claude가 일하면 Codex 터미널을 보고 있어도 작업 중 표시가 보였다.

## 수정

- **훅:** tool_use_id의 SHA-256과 SessionStart의 source(startup·resume·clear·compact·fork만)를 추가로 보낸다. 원문 ID·프롬프트·도구 입력은 보내지 않는다.
- **도구 추적:** PreToolUse·PostToolUse를 호출 ID로 짝짓는다. 예전 훅은 입력 해시로 대신한다. ID가 없는 PermissionRequest는 같은 입력 중 아직 요청이 붙지 않은 가장 오래된 호출에 연결한다.
- **중단·응답 입력:** 작업 중 Esc·Ctrl+C는 표시를 대기로 내리되 대화 추적은 유지한다. 그 뒤 새 도구 사용·권한 요청·Stop이 오면 다시 표시하고, 이미 실행 중이던 도구가 끝난 것만으로는 다시 올리지 않는다. 확인 요청 중 해당 터미널에 전달된 Enter(괄호 붙여넣기 안의 줄바꿈 제외)는 가장 오래된 요청에 대한 응답으로 본다. 다른 대기 요청 없이 뜬 권한 요청에 다른 키 없이 Enter만 왔다면 Claude가 미리 선택해 둔 "1. Yes"로 승인한 것이므로 바로 작업 중으로 올린다. 방향키·숫자·마우스 등으로 선택이 옮겨졌을 수 있거나, 질문이거나, 여러 요청 중 두 번째 이후라면 거절일 수 있어 표시만 내리고, 승인한 호출이 끝나면 작업 중으로 돌아간다. 숫자 키는 선택만 옮길 수 있어 응답으로 보지 않는다. 이 터미널에서 답한 요청에 대해 늦게 온 permission_prompt 알림은 새 요청으로 보지 않는다.
- **입력 전달:** 호스트는 입력 원문 대신 그 의미만 출력과 같은 엔진 큐에 넣어 순서를 지킨다. 취소 키는 그대로, Enter와 괄호 붙여넣기 경계는 제자리에 두고 나머지는 한 글자로 줄인다. 확인 요청이 보이지 않을 때 글자·공백·한글만 있는 입력은 큐에 넣지 않는다. 확인 요청이 보이는 동안에는 Claude가 J/K 같은 글자로도 선택을 옮기므로 글자도 선택 이동으로 본다. 포커스·장치 응답은 제외하고 마우스 보고는 사용자 입력으로 본다. 상태가 바뀐 경우에만 화면을 다시 보낸다.
- **완료·정리:** Stop·StopFailure는 상태가 같아도 응답마다 알림을 만든다. 같은 대화의 compact는 상태를 유지한다. idle_prompt는 최근 30초 안에 다른 훅이 없을 때만 남은 작업 중을 응답 완료로, 남은 확인 요청을 대기로 정리한다.
- **알림 종류:** 호스트가 Claude 알림이 만든 알림 번호(agentNotificationCount)를 기록한다. 화면은 읽은 번호와 비교해 Claude 완료를 확인한 뒤 온 일반 알림을 "알림"으로 표시한다. 새 터미널 세대·종료·저장 로드에서 함께 지운다. 이 값이 없는 예전 실행부의 상태는 기존 방식으로 표시한다.
- **화면:** 작업 중은 옅은 원 위에서 도는 135° 호 스피너(0.9초 회전, 모션 줄이기에서는 정지), 미확인 완료·알림은 작은 점, 확인 요청·오류는 서로 다른 아이콘으로 표시한다. 미확인 테두리를 없앴다. 작업 중 터미널에 이전 미확인 알림이 있거나, 그룹에서 더 급한 상태 뒤에 미확인 알림이 있으면 아이콘 옆에 작은 점을 붙이고 툴팁에 개수를 보여 준다. 접힌 사이드바의 전환 버튼과 모바일 메뉴 버튼은 보고 있는 터미널을 뺀 요약이다. 모바일 전환 버튼은 제목 옆에 이 터미널의 상태를, 개수 옆에 다른 터미널 요약을 나눠 보여 준다. 연결이 끊기면 마지막 상태를 흐리게 멈추고 설명에 밝힌다.

## 자동 검사

- 타입 검사 통과.
- 상태 판정 16/16: 수정 전 실제 CLI에서 재현한 메뉴 Esc·거절·질문 답변·대기 메시지·compact·idle_prompt, 동일 입력 병렬 요청·나뉜 괄호 붙여넣기·늦게 온 idle_prompt, 기본 선택 승인과 선택 이동·질문·여러 요청의 보수적 처리, 원문 없이 입력 의미만 전달하는 규칙을 포함한다.
- 상태 집계 단위 2/2, 화면 회귀 10/10(헤드리스 Chrome, 가짜 호스트), 대화 재개 입력 11/11(마우스 보고를 사용자 입력으로 보는 경우 포함).
- 실제 PTY 호스트 1/1: 제어권을 가진 기기의 ↓+Enter로 확인 요청 해제, 포커스 보고 뒤 Enter만으로 승인하면 작업 중, 확인 요청 중 글자를 입력한 뒤의 Enter는 대기, 알림 번호 기록.

## 수정 후 실제 CLI 재현

같은 시험 스크립트에 수정한 엔진과 호스트의 입력 관찰 규칙을 적용했다. 이번 빌드의 훅만 쓰는 실행(--setting-sources project,local --settings)과, 사용자에게 설치된 예전 훅을 쓰는 실행을 함께 돌렸다.

| 상황 | 새 훅 | 예전 훅 |
| --- | --- | --- |
| 작업 중 메뉴 Esc | 대기 → Stop에서 완료·알림 | 같음 |
| 작업 중 추가 메시지 | Stop 두 번 모두 알림 | 같음 |
| 쓰기 권한 "No" | Enter에서 대기, 남는 표시 없음 | 같음 |
| 질문에 Enter로 답함 | 대기 → PostToolUse(호출 ID)에서 작업 중 → 완료 | 대기 → 완료 |
| /compact | 상태 유지 | 대기로 초기화(예전 훅에는 source 없음) |

아스트라 검토를 반영한 최종 판정 규칙으로 다시 실행해 같은 결과를 확인했다. 반영으로 추가한 동일 입력 병렬 요청·괄호 붙여넣기·호스트 입력 순서는 자동 검사로 확인했다.

실제 앱 1차 검증에서 찾은 공백(아래)을 고치려고 기본 선택 승인을 추가한 뒤, 이번 빌드의 훅으로 권한 승인·거절을 다시 실행했다(Claude 2.1.294, manual 모드). 권한 대화상자는 "❯ 1. Yes / 2. Yes, and don't ask again for: ping * / 3. Yes, and switch to auto mode / 4. No"였고, Claude는 포커스 보고 모드를 켰다.

| 상황 | 결과 |
| --- | --- |
| 포커스 보고 뒤 다른 키 없이 Enter로 21초 ping 승인 | Enter 즉시 작업 중, 실행 내내 유지, Stop에서 완료·알림 |
| ↓·↑로 선택을 옮겼다 되돌린 뒤 Enter로 승인 | 대기 → 도구가 끝난 PostToolUse에서 작업 중 → 완료 |
| ↓↓↓로 "4. No"를 골라 Enter | 대기, 15초 동안 다시 올라가지 않음 |
| 질문에 Enter로 답함 | 대기 → 0.08초 뒤 작업 중 → 완료 |

| 디자인 | 다크·라이트 모두 정렬·잘림 문제는 없었다. 작은 크기에서 스피너가 완료 점보다 약해 보인다는 의견이 나와 호의 선 굵기를 2에서 2.5로, 길이를 약 100°에서 135°로, 트랙 불투명도를 .22에서 .28로 바꿨다 |
| 정리 | 시험 앱·호스트·셸·CLI를 정상 종료했고 실제 몽글 창과 기존 프로세스 4개는 그대로였다. 시험 중 Codex가 시작한 공유 app-server 데몬 2개는 다른 Codex 작업이 쓸 수 있어 종료하지 않았다 |

1차에서 권한을 기본 선택으로 승인한 뒤 긴 명령이 도는 47.4초 동안 표시가 사라지는 공백을 확인했다. 기본 선택 승인 판단은 이 결과로 추가했다.

Codex를 사용자 기본 설정으로 실행하는 동안 사용자 Codex 설정 파일의 수정 시각이 바뀌었다. 확인한 설정 구획과 줄 위치는 그대로였고, 무엇이 기록했는지는 확인하지 못했다.

**2차 (2026-10-09, 기본 선택 승인·스피너 대비 반영 빌드)** — 호스트 EB1CFAA4…FFE, 웹 05C4A8F1…643, 데스크톱 0EF58F7D…7F7. Claude 2.1.294를 manual 모드로, 시험 폴더에 둔 이번 빌드의 훅만 지정해 실행했다. Codex는 실행하지 않았다.

2차 검토에서 아스트라가 짚은 대로 Claude는 방향키 외에 J/K로도 선택을 옮기고 단축키도 바꿀 수 있다. 그래서 확인 요청이 보이는 동안의 글자 입력도 선택 이동으로 보도록 호스트를 보완했다. 최종 호스트 빌드(BA96C999…827)의 이 부분은 실제 PTY 호스트 테스트로 확인했고, 실제 앱에서는 다시 확인하지 않았다.

실제 앱에서 확인하지 못한 범위: 700px 이하 모바일 배치(데스크톱 창 최소 폭이 760px이라 화면 회귀 검사로만 확인), 좁은 탭, 모션 줄이기, 연결 끊김 흐림.

## 남은 제약

- 거절·질문 답변은 해당 터미널에 전달된 Enter로 판단한다. 숫자 키나 마우스로만 답하면 다음 Claude 신호까지 확인 요청이 남을 수 있다.
- 선택을 옮긴 뒤 승인하거나 여러 권한 요청 중 두 번째 이후를 승인하면, 그 도구가 끝날 때까지 작업 중 표시가 없을 수 있다.
- 기본 선택 승인 판단은 Claude 2.1.294가 권한 대화상자의 첫 항목(승인)을 미리 선택한다는 동작에 기댄다. 첫 항목이 거절인 대화상자가 생기면, 다른 키 없이 Enter로 거절했을 때 다음 Claude 신호까지 작업 중으로 남을 수 있다.
- 작업 중 보낸 메시지의 두 번째 응답에는 시작 신호가 없어, 진행되는 동안 응답 완료로 보인다. 끝나면 다시 알림을 보낸다.
- 새 대화의 첫 입력이 ! 명령이면 대화를 확인할 신호가 없어 그 응답의 완료를 표시하지 못할 수 있다.
- 실행부가 갱신되기 전의 예전 훅에서는 compact 때 상태가 초기화되고, 질문에 답한 뒤 남은 응답 동안 작업 중 표시가 없다. 새 실행부는 시작할 때 훅 스크립트를 갱신한다.
- Codex의 작업 중 상태 연동은 제공하지 않는다. Codex 알림은 Codex 알림 설정을 따른다.
- 훅 2초 제한 초과로 Stop이 유실되는 경우는 재현하지 못했다. 유실되면 idle_prompt(약 60초 뒤)로 정리한다.
