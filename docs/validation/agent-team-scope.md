# AI 팀의 작업 범위와 브랜치 맞추기

2026-10-15, Windows x64. **0.3.25에 공개**했다. 배포 검사와 공개 파일 검증은 [0.3.25 배포 검증](public-release-0.3.25.md#final)에 기록한다. [AI 팀 실행부](agent-teams-host.md)와 [AI 팀 화면](agent-teams-ui.md)에 더한 기능이다.

## 왜 만들었나

사용자는 보통 아무 폴더에서 Claude Code나 Codex를 켜고, 프론트·백엔드·AI 저장소 위치를 알려 준 뒤, 모든 저장소의 브랜치 이름을 같게 맞추고 나서 일을 시킨다. 그러면 한 요청으로 여러 저장소를 함께 고친다. 0.3.24의 AI 팀은 그룹 폴더 하나에서만 일했고, 그룹에 저장소가 여럿이면 새 워크트리 점검에서 막혔다([작업 폴더로 저장소 찾기](agent-teams-host.md#작업-폴더로-저장소-찾기)). 이번 변경은 그 준비 과정(폴더 알려 주기, 브랜치 맞추기, CLI 켜기)을 팀 시작 창이 대신하게 한다. 팀이든 구성원 한 명이든 같은 흐름을 쓴다.

## 동작

- **후보(`teams.scope`):** 그룹 폴더, 그룹에 연결된 저장소, 그룹 터미널의 현재 폴더를 모아 Git 작업 트리의 맨 위 폴더로 바꾸고 중복을 뺀다(최대 12개). 줄마다 이름, 경로, 지금 브랜치(분리된 HEAD면 표시), 저장하지 않은 변경 수, 공통 Git 폴더를 준다. 사용자가 추가한 경로는 같은 방법으로 확인하고, 열 수 없으면 이유를 돌려준다. 앱 데이터 폴더와 원격 경로는 제안하지 않는다.
- **기본 선택:** 그룹 폴더(첫 후보)를 시작 폴더로 하고, 저장소마다 작업 트리 하나를 체크한다. 같은 저장소의 다른 워크트리는 체크하지 않는다. 한 브랜치는 두 작업 트리에서 동시에 쓸 수 없기 때문이다. 시작 폴더의 체크를 끄면 첫 번째로 체크된 폴더가 시작 폴더가 된다.
- **브랜치:** 기본은 "지금 브랜치 그대로"다. "모두 같은 브랜치로 맞추기"를 고르면 이름 칸에 바로 커서가 가고, 체크한 Git 저장소마다 바뀔 내용이 미리 보인다. 이름이 비었거나 공백·`~ ^ : ? * [ \`이 들어가거나 `-`로 시작하면, 또는 같은 저장소의 작업 트리를 둘 체크하면 화면에서 바로 알린다.
- **점검(`teams.check`):** 시작 폴더 줄과 함께 작업 범위의 폴더마다 한 줄씩 보인다. 브랜치를 맞출 때는 Git의 이름 검사(`check-ref-format --branch`)를 거친 뒤 저장소마다 할 일을 정한다. 이미 그 브랜치면 그대로, 로컬에 있으면 바꾸기, 원격 하나에만 있으면 그 원격을 따라가는 새 브랜치, 없으면 지금 커밋에서 새로 만들기다. 저장하지 않은 변경이 옮겨지면 주의로 표시한다. 다음 경우는 오류로 막는다.
  - 커밋이 없는 저장소
  - 병합·리베이스·체리픽·되돌리기가 진행 중인 저장소
  - 그 브랜치를 다른 작업 트리에서 쓰는 중인 경우
  - 저장하지 않은 변경이 있는 파일이 지금 커밋과 대상 브랜치 사이에서도 달라, Git이 바꾸기를 거절할 경우

  점검은 아무것도 바꾸지 않는다.
- **시작(`teams.start`):** 점검을 다시 한 뒤 모든 브랜치를 먼저 바꾼다(`git switch`, 훅은 끈 채로). 하나라도 실패하면 구성원을 띄우지 않고, 실패한 저장소와 이미 바꾼 저장소를 알린다. 이미 바뀐 브랜치는 되돌리지 않는다. 팀 기록에 실제 경로(시작 폴더·폴더 목록·브랜치)를 남긴다.
- **CLI에 넘기기:** 구성원은 모두 시작 폴더에서 켠다. 시작 폴더 안에 있지 않은 폴더는 Claude Code에 `--add-dir '폴더1' '폴더2'`, Codex에 `--add-dir '폴더'`를 폴더마다 붙인다. 읽기 전용 Codex는 이미 모든 곳을 읽을 수 있어 쓰기 가능한 폴더를 주지 않는다. 경로에 따옴표·`$`·백틱·제어 문자가 있으면 점검에서 막는다. 실행부를 다시 켜서 대화를 이어 갈 때도 같은 인자를 붙인다(`codex resume`도 `--add-dir`을 받는다).
- **역할 지시문:** 폴더가 둘 이상이거나 브랜치를 맞출 때 "작업 범위(함께 보고 고칠 폴더)" 목록, 시작 폴더, "모두 `feature/login` 브랜치에서 일하고 다른 브랜치로 바꾸지 말 것"을 적는다.
- **구성원 작업 폴더:** 기본 템플릿의 구성원은 모두 기본 폴더로 시작한다. 사용자가 워크트리를 거의 쓰지 않고, 쓰는 사람만 구성원별로 고르면 된다는 의견을 반영했다(0.3.24 기본 템플릿은 팀장 말고 모두 새 워크트리였다). "구성원 추가"도 기본 폴더로 더한다. 폴더를 둘 이상 고르면 모든 구성원이 기본 폴더로 정해지고 선택 칸이 잠긴다. 템플릿에 저장된 새 워크트리 설정은 그대로 둔다. 실행부도 여러 폴더 팀에서는 새 워크트리를 만들지 않고 주의로 알린다.
- **팀 화면 아래 줄:** 폴더가 둘 이상이거나 브랜치를 맞춘 팀은 폴더 이름들과 브랜치 칩을 보여 준다.
- **함께 고친 것:** 팀 시작 창의 내용이 창보다 길면 가로 스크롤을 가진 구성원 표가 세로로 줄어 보이지 않았다. 본문 항목이 줄어들지 않게 했다.

## 검증

- `npx.cmd tsc --noEmit -p .`, `npm.cmd run build`, `node scripts/release-check.ts` 통과.
- `tests/host/teams.test.ts` 6/6. 실행 인자의 `--add-dir`(Claude는 한 번에, Codex는 폴더마다, 읽기 전용 Codex에는 없음, 위험한 경로 거절)와 역할 지시문의 작업 범위·시작 폴더·브랜치 문구를 확인했다.
- `tests/host/teams-host.test.ts` 3/3(샌드박스 밖, 격리된 `MONGLE_DATA_DIR`). 새 시험은 실제 임시 Git 저장소 front·back과 일반 폴더 notes로 다음을 확인한다.
  - 그룹 터미널이 있는 저장소가 후보로 나온다. 추가한 경로는 실제 경로·브랜치·변경 수와 함께 돌아온다.
  - back에서 대상 브랜치와 겹치는 파일을 고친 상태, 병합 진행 중(`MERGE_HEAD`), 잘못된 이름(`bad name`, `-x`, `a..b`)은 점검에서 막힌다.
  - 정상 상태에서는 front는 "새로 만듦"이면서 변경 1개가 옮겨진다는 주의, back은 "있는 브랜치로 바꿈", notes는 Git이 아닌 폴더로 나온다. 여러 폴더 팀의 새 워크트리 구성원은 주의로 알린다. 점검 뒤에도 브랜치는 그대로다.
  - 시작하면 두 저장소가 모두 `feature/login`이 되고, 추적하지 않은 파일이 남는다. 세 구성원 모두 같은 폴더 터미널에서 시작한다. Claude 실행 줄에는 `--add-dir 'back' 'notes'`, Codex 개발 구성원에는 `--add-dir` 두 개가 붙고, 읽기 전용 Codex에는 없다. 역할 지시문에 폴더와 브랜치가 적힌다.
- `tests/ui/teams.test.ts` 5/5. 기본 선택(저장소마다 하나), 시작 폴더 이동, 브랜치 미리보기, 입력 문제 안내, 작업 범위 목록이 그리는 내용을 확인했다.
- 화면 확인(Aside): 실제 `TeamSetup` 컴포넌트와 `styles.css`를 시험용 응답(쇼핑몰 그룹, frontend·backend·ai 저장소)으로 묶은 미리보기를 Aside에서 열어 조작했다. 작업 범위 표, 브랜치 맞추기와 이름 칸 자동 커서, 저장소별 미리보기, 잠긴 작업 폴더 칸, 2단계 점검 줄을 확인했다. 이 과정에서 구성원 표가 보이지 않던 문제를 찾아 고쳤다. 미리보기의 점검 응답은 실행부 문구 형식을 옮긴 것이고 실제 실행부가 아니다. 캡처는 커밋하지 않는 `test-results/team-scope-preview/shots/`에 있다.
- 호스트 시험 전체와 팀 화면 시험의 결과는 PR의 검증 결과에 적는다.

## 확인하지 못한 범위

- 실제 Electron 앱에서 팀 시작 창을 조작하고 팀을 띄우는 확인(아스트라 실기 확인)은 아직 하지 않았다.
- 실제 Claude Code·Codex가 `--add-dir`로 받은 폴더를 읽고 고치는지는 확인하지 않았다. 두 CLI의 도움말에서 옵션이 있음(Claude Code 2.1.300의 `--add-dir <directories...>`, Codex 0.162.1과 `codex resume`의 `--add-dir <DIR>`)만 확인했다. 모델 요청을 보내는 확인은 하지 않았다.
- 원격 브랜치를 따라가는 경우(`track`)는 단위 수준에서만 다뤘고, 실제 원격이 있는 저장소에서 시험하지 않았다.
- 브랜치 바꾸기가 중간에 실패했을 때 이미 바뀐 저장소를 되돌리지 않는다. 알림으로만 알린다.
