# AI 팀 실행 (호스트)

2026-10-15, Windows x64. **0.3.24에 공개**했다. 배포 검사와 공개 파일 검증은 [0.3.24 배포 검증](public-release-0.3.24.md#final)에 기록한다. AI 팀 기능의 2단계 중 호스트 부분이다([설계안](../08-agent-team-design.md)). 팀 화면과 새 작업 흐름은 [AI 팀 화면](agent-teams-ui.md)에 있다.

## 동작

- **템플릿:** 기본 제공 3개(설계·개발·검토 3명, 4명 개발팀, 구현·검토 2명)는 바꾸거나 지울 수 없다. 사용자가 고친 구성은 `user:` 아이디로 따로 저장한다(최대 50개).
- **구성원:** 이름, 역할(설계(팀장)·개발·검토·테스트·조사·직접 만들기), CLI(Claude Code·Codex), 모델, 끝나면 보고할 대상, 역할 지시문, 덧붙일 말, 작업 폴더(기본 폴더·새 워크트리), 읽기 전용. 첫 구성원이 팀장이다. 최대 6명.
- **시작 전 점검(`teams.check`):** PowerShell, CLI별 설치·버전·로그인·몽글 연동, 작업 폴더, 워크트리가 필요할 때 작업 폴더의 Git 저장소와 저장하지 않은 변경 수, 터미널 한도, 읽기 전용 구성원, 팀 구성 오류를 줄마다 알린다. 오류가 하나라도 있으면 팀을 시작하지 않는다. 워크트리를 만들 저장소가 없으면 오류가 아니라 주의로 알린다([작업 폴더로 저장소 찾기](#작업-폴더로-저장소-찾기)). 여러 폴더와 공통 브랜치는 [작업 범위와 브랜치 맞추기](agent-team-scope.md)에서 점검한다. 모델 요청은 보내지 않는다.
- **팀 시작(`teams.start`):** 구성원마다 기본 폴더 터미널 또는 기존 워크트리 작업(`worktrees.create`)으로 만든 워크트리의 터미널을 PowerShell 탭으로 연다. 탭 이름은 구성원 이름이다. 셸이 첫 프롬프트를 낸 뒤 CLI 실행 줄을 한 번 입력한다. 그 전에 사람이 입력하거나 15초 안에 프롬프트가 오지 않으면 입력하지 않고 알린다. 시작하지 못한 구성원은 이유를 남기고, 나머지는 계속 시작한다.
- **역할 지시문:** 실행부 데이터 폴더의 `agent-teams/<팀>/<구성원>` 파일에 둔다. 팀 이름, 구성원 목록(팀장, CLI·모델, 읽기 전용, 보고 대상), 메시지가 들어오는 형식, 역할 지시문, 덧붙일 말이 들어간다. Claude는 `--append-system-prompt-file`로, Codex는 파일 내용을 `-c developer_instructions=`로 넘긴다. 명령줄에는 파일 경로만 들어가므로 지시문의 따옴표·줄바꿈이 셸 명령이 되지 않는다.
- **읽기 전용:** Claude는 `--tools 'Read,Grep,Glob'`, Codex는 `-s read-only -a never`로 실행한다. 0단계에서 Codex는 `-s read-only`만 주면 사용자의 자동 검토 설정이 쓰기를 승인했다.
- **이어 켜기:** 실행부를 다시 시작해 구성원의 대화를 이어 열 때도 모델, 역할 지시문 파일, 읽기 전용 옵션을 다시 붙인다. 0단계에서 Claude는 지시문 없이 이어 켠 실행에서 압축하면 역할을 잊었다.
- **저장:** 팀과 내 템플릿은 별도 `agents.sqlite`(user_version 1)에 둔다. `sessions.sqlite`는 더 새 user_version을 열지 않으므로 그 파일은 바꾸지 않았다.
- **팀 지우기(`teams.remove`):** 팀 기록과 역할 지시문 파일만 지운다. 터미널과 워크트리는 일반 터미널·워크트리로 남는다.

## 구현 전 확인 (2026-10-15)

- Claude Code 2.1.299: `claude -p --model haiku --append-system-prompt-file <파일>`로 넘긴 한국어 지시문 속 암호명과 `C:\work\a.ts` 경로를 그대로 답했다(격리 시험 폴더, 모델 요청 1회).
- Codex 0.162.1: 같은 내용을 JSON 문자열로 쓴 파일을 PowerShell의 `-c ('developer_instructions=' + [IO.File]::ReadAllText(...))`로 넘기고 `codex debug prompt-input`으로 로컬에서 확인했다. developer 메시지에 따옴표·백슬래시까지 그대로 들어갔다. 지시문 끝 바로 뒤에 다른 안내문이 붙어서, 몽글이 만드는 지시문은 빈 줄로 끝낸다. 실제 모델 요청으로 확인하려던 시험은 지시문을 외부 서비스로 보내는 범위라는 이유로 자동 승인 검토가 거절해, 로컬 확인으로 대신했다.

## 작업 폴더로 저장소 찾기

2026-10-15, **0.3.25에 공개**. 0.3.24 설치본을 쓰던 사용자가 Git 프로젝트가 있는 그룹에서도, 새 프로젝트를 만들고 `git init`을 한 뒤에도 시작 전 점검의 Git 줄이 "구성원별 워크트리를 만들려면 이 그룹에서 프로젝트(Git 저장소) 하나를 먼저 열어 주세요"로 막혀 팀을 시작하지 못했다.

**원인:** 점검이 팀의 작업 폴더를 보지 않고, 그룹에 **프로젝트 열기**로 연결된 저장소가 정확히 하나인지만 셌다. 일반 그룹으로 만든 뒤 `git init`한 폴더, 커밋이 없어 프로젝트로 연결되지 않은 새 저장소, 저장소를 두 개 이상 연결한 그룹은 모두 막혔다. 기본 템플릿 3개에는 모두 새 워크트리 구성원이 있어 어떤 템플릿도 시작할 수 없었다. 이후 기본 템플릿은 모두 기본 폴더로 바꿨다([작업 범위](agent-team-scope.md)).

**바꾼 동작:** 워크트리 구성원이 있으면 다음 순서로 저장소를 정한다.

1. 그룹에 연결된 프로젝트 중 작업 폴더를 담은 것(저장소 폴더나 그 워크트리 안)이 하나면 그것을 쓴다.
2. 아니면 작업 폴더를 **프로젝트 열기**와 같은 방법(`inspectProject`)으로 확인한다. 저장소가 그룹에 연결되어 있지 않으면 점검은 "이 그룹의 프로젝트로 연결합니다"라고 알리기만 하고, 팀을 시작할 때 `projects.attach`로 연결한다.
3. 작업 폴더가 저장소가 아니어도 그룹에 연결된 프로젝트가 하나뿐이면 그것을 쓴다(이전 동작).
4. 그래도 없으면 Git 줄을 주의로 표시하고 이유(Git 저장소가 아님, 아직 커밋이 없음, Git을 찾지 못함, 지원하지 않는 폴더)를 알린다. 팀은 시작하며, 새 워크트리로 고른 구성원도 기본 폴더에서 일한다. 팀 기록의 작업 폴더도 기본 폴더(`base`)로 남긴다.

조회가 바쁘거나 연결이 끊긴 경우처럼 폴더와 상관없는 실패는 그대로 요청을 멈춘다. 점검 결과에는 화면에 필요한 줄만 보내고, 시작은 점검에서 정한 저장소를 그대로 쓴다.

**검증:** `npx.cmd tsc --noEmit -p .` 통과. `tests/host/teams-host.test.ts` 2/2와 `tests/host/teams.test.ts` 5/5(Git 사용으로 샌드박스 밖, 격리된 `MONGLE_DATA_DIR`). 바꾼 시험은 프로젝트를 연결하지 않은 그룹에서 다음을 확인한다.

- 일반 폴더: 점검 통과(Git 줄은 주의), 두 구성원 모두 기본 폴더 터미널로 시작, 그룹에 저장소를 연결하지 않음.
- 커밋 없는 새 저장소: "아직 커밋이 없어…첫 커밋을 만들면" 주의.
- 커밋이 있는 저장소: 점검은 연결 예정만 알리고 상태를 바꾸지 않음. 시작하면 그룹에 그 저장소가 연결되고, 개발 구성원이 새 워크트리·브랜치·탭을 받음. 다음 점검부터는 연결 안내가 나오지 않음.

이전 코드에서는 첫 일반 폴더 점검이 "준비되지 않음"으로 실패한다. 실제 Electron 앱에서의 조작 확인은 아직 하지 않았다.
