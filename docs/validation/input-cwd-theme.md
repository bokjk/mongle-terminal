# 한글 입력·현재 폴더·밝은 테마 검증

검사일: 2026-09-30. 소스 버전 0.3.0의 미배포 수정입니다. 실사용 호스트·셸·인증·Tailscale Serve와 기존 설치본은 변경하지 않았습니다.

## 원인과 수정

- 한글: `BrowserPresentationAdapter`가 `compositionstart`부터 `compositionend` 뒤까지 전체 화면과 ACK를 보류했습니다. 다음 음절의 조합이 유지되는 동안 앞서 확정된 글자의 출력도 멈춥니다. xterm 6.0.0의 `reset()`은 VT 상태를 초기화하며 textarea와 CompositionHelper는 유지하므로, 이벤트 한 턴만 기다린 뒤 출력 갱신을 허용했습니다. 입력 제어권이 닫힌 동안의 조합 입력을 버리는 처리는 유지했습니다.
- 경로: `TerminalInfo.cwd`에는 생성 시 지정한 폴더만 있었고 셸 이동을 수집하지 않았습니다. 새 셸에 프로세스 내부 프롬프트 보고를 추가하고, 호스트 VT 파서가 OSC 7·OSC 9;9를 처리해 `currentCwd` 상태를 배포합니다. 경로는 표시용이며 실행 명령·분할·재시작·복원 경로에 사용하지 않습니다. 상태 알림은 출력 프레임 주기에 묶어 중복 보고를 줄입니다. 사용자 프로필 파일을 수정하지 않습니다.
- 색상: 밝은 테마의 ANSI white/brightWhite가 흰색이었고 brightRed 등 6색은 어두운 배경용 기본값으로 남아 있었습니다. 16색을 모두 지정하고 xterm의 최소 대비 4.5를 설정해 256색·RGB 출력도 보정했습니다.

## 재현 및 관련 검사

- Chrome DevTools의 실제 IME 조합 API로 `한글입력`을 입력하며 각 조합 도중 호스트 프레임 완료와 조합 표시를 검사했습니다. 기존 소스로 동일 검사를 실행하면 첫 조합 중 프레임 완료를 기다리다 2초 제한으로 실패했고, 수정 소스에서는 모든 글자를 정확히 한 번 전달하며 통과했습니다. Windows Microsoft IME의 물리 키 입력 검증과는 구분합니다.
- 실제 PowerShell 7·Windows PowerShell·cmd·Git Bash를 격리된 임시 폴더에서 실행해 한글·공백을 포함한 하위 폴더로 이동했습니다. 현재 경로 상태 알림, 초기 폴더 유지, PID 유지를 확인했습니다.
- OSC를 문자 단위로 나누어 전달하는 검사와 잘못된 경로·제어문자·과도한 길이·잘못된 URI 거부 검사를 통과했습니다.
- 실제 Chrome DOM에서 밝은 테마의 ANSI 16색·256색 흰색·RGB 밝은 회색 18글자의 렌더링 색을 읽어 대비 4.45 이상을 확인했습니다(8비트 색상 반올림 허용).
- 타입 검사와 웹·호스트·데스크톱 빌드를 통과했습니다. 웹 번들 크기 안내 외 오류는 없었습니다.

## 범위와 남은 확인

실제 앱 설치·업데이트·패키지 E2E·Android 삼성 인터넷은 이번 작업에서 확인하지 않았습니다. 별도 Electron 개발 앱의 한글 입력·폴더 이동·밝은 테마는 사용자가 직접 시험한 뒤 정상 동작을 확인했습니다. 새 보고 훅은 새로 실행한 셸부터 적용됩니다. WSL의 기본 셸이나 사용자 설정이 보고 훅을 덮어쓴 셸은 자체 OSC 7/9;9 보고가 있어야 현재 경로가 표시되며, 보고가 없으면 시작 폴더와 설명 툴팁을 표시합니다. 프롬프트를 보고하지 않는 프로그램 실행 중에는 마지막으로 보고한 경로를 유지합니다.

`MONGLE_DATA_DIR`를 작업 폴더의 `.test-data/input-cwd-theme`로 지정했고, HostCore 회귀는 각 검사의 별도 임시 데이터 폴더를 사용했습니다.

## 사용자 수동 테스트 결과

PR 준비 중 Windows 8.3 짧은 TEMP 경로로 UI 검사를 추가 실행해, PowerShell이 보고한 긴 경로와 같은 폴더임에도 문자열 비교가 실패하는 경우를 재현했습니다. UI 검사를 `realpath` 기준으로 보완했고 같은 짧은 TEMP 환경에서 재검사했습니다. 앱 동작 변경은 없습니다.

### GitHub Windows CI에서 확인한 이식성 보완

PR #3의 첫 완료 CI 실행에서 PowerShell 두 버전과 UI 경로 검사가 실패했습니다. 영어 Windows의 출력 코드 페이지에서 `[Console]::Write`가 한글 폴더명을 `?`로 바꾸는 원인이었으며, 로컬에서도 `[Console]::OutputEncoding`을 ASCII로 지정해 두 버전 모두 재현했습니다. 경로 보고는 콘솔 인코딩 설정을 바꾸지 않고 PowerShell 호스트의 Unicode 출력(`Write-Host -NoNewline`)을 쓰도록 수정했습니다. 같은 ASCII 조건의 4종 셸/파서 회귀 6건, 모바일 표시 회귀 4건, 실제 UI 회귀 1건과 타입·빌드가 통과했습니다. 함께 실패한 모바일 페이지 초기 로딩은 5초 제한을 넘겨, 화면 조작 제한은 유지하고 최초 탐색 제한만 15초로 조정했습니다. GitHub 전체 CI 결과는 PR의 최신 검사 결과를 기준으로 확인합니다.

2026-09-30 사용자 요청으로 최신 소스를 다시 빌드하고, `%TEMP%`의 새 `mongle-manual-fixes-*` 폴더를 `MONGLE_DATA_DIR`로 지정해 별도 Electron 개발 앱을 열었습니다. 호스트 이름은 `수정본 테스트 PC`, 그룹 이름은 `수정본 테스트 (별도 환경)`이며, 새 PowerShell 하나와 `이동 확인` 하위 폴더를 준비했습니다. 정상 소유자 인증 후 readiness와 hostId·bootId·PID 일치, 데스크톱 제어권 획득, 현재 경로 보고, 실제 창 핸들과 응답 상태를 확인했습니다. 시작 직후 닫힌 최초 IPC 연결은 호스트 준비 완료 후 재접속했습니다. 기존 앱·세션·설치본·Tailscale 설정은 변경하지 않았으며, 사용자는 세 가지 항목을 직접 시험한 뒤 정상 동작을 확인하고 커밋·푸시·main 병합을 요청했습니다.
