# PC 앱 컴퓨터 추가 목록

2026-10-11, Windows x64, 미배포. PC 앱의 **컴퓨터 추가** 창에서 같은 Tailscale에서 찾은 다른 몽글 PC를 골라 등록하고 바로 연결하게 했다. 다음 기능과 함께 배포할 예정이며 공개 배포 검증은 아직 하지 않았다.

## 배경

0.3.20부터 휴대폰 브라우저는 같은 Tailscale의 다른 몽글 PC를 찾아 전환할 수 있다([휴대폰 컴퓨터 전환](mobile-computer-switcher.md)). PC 앱의 **컴퓨터 추가** 창은 여전히 이름과 `https://….ts.net` 주소를 직접 입력해야 했다. 두 PC를 0.3.20으로 올린 사용자가 PC 앱에서 다른 PC를 추가하려 했지만 자동으로 나오는 목록이 없었다.

## 설계 판단

- 찾기는 0.3.20의 호스트 찾기(`packages/host/computers.ts`)를 그대로 쓴다. PC 앱은 지금 연결한 호스트에 `computers.list`를 묻는다. 이 PC에 연결해 있으면 소유자 채널로, 원격 컴퓨터에 연결해 있으면 그 컴퓨터에서 승인받은 세션으로 묻는다. 원격 컴퓨터가 0.3.20보다 이전 버전이면 찾지 못했다고 알리고 주소 입력을 권한다.
- 찾은 PC를 고르면 주소를 입력했을 때와 같은 등록·전환을 거친다. 찾기만으로는 어떤 PC에도 접속 권한이 생기지 않으며, 그 PC의 연결 화면에서 기존처럼 연결 코드로 승인받는다.
- 이미 등록한 PC와 이 PC는 목록에서 뺀다. 응답의 주소는 저장할 때와 같은 규칙으로 다시 검사해 몽글 `https://*.ts.net` 주소만 남긴다. 이름은 제어 문자를 지우고 60자로 자르며, 비어 있으면 주소의 첫 부분을 쓴다. 이 PC는 Tailscale 상태의 `Peer` 목록에 없어 찾기 대상이 아니다. 원격 컴퓨터가 돌려준 목록에서는 이 PC의 원격 주소(`remote-serve.json`)와 같은 항목을 뺀다.

## 변경

- 호스트: 소유자 채널이 받는 요청에 `computers.list`를 추가했다(`packages/host/gateway.ts`, `packages/host/main.ts`). 게이트웨이가 처리하고 core로 보내지 않으며 매개변수는 `refresh`만 받는다. 기기 WebSocket 경로는 0.3.20과 같다.
- PC 앱: `mongle:find-computers` 요청(`apps/desktop/main.ts`)과 결과 정리(`apps/desktop/computer-search.ts`), preload·계약·클라이언트 형식을 추가했다.
- 화면: 컴퓨터 추가 창 위쪽에 **같은 Tailscale에서 찾은 PC**(`apps/web/src/FoundComputers.tsx`)를 두고 아래 **주소로 직접 추가**는 유지했다. 창을 열 때 한 번 찾고 제목 오른쪽 버튼으로 다시 찾는다. 찾는 중이거나 추가하는 중에는 버튼을 `aria-disabled`로 두어 초점을 지킨다. 다시 찾은 결과에서 초점이 있던 PC가 빠지면 결과를 반영하기 전에 다시 찾기 버튼으로 초점을 옮긴다.
- 공용 창(`apps/web/src/Modal.tsx`): 창을 연 버튼을 화면을 그릴 때 기억하고, 창 안에 이미 초점이 있으면 옮기지 않는다. 그래서 자동 초점 입력칸이 초점을 유지하고, 창을 닫으면 연 버튼으로 돌아간다. 연 항목이 닫힌 **···** 메뉴 안에 있어 초점을 받을 수 없으면 그 메뉴의 **···** 버튼으로 돌아간다. 전에는 창을 열면 닫기 버튼으로 초점이 갔고, 닫은 뒤에는 초점이 문서 본문으로 빠졌다.

## 디자인 참고 (Mobbin)

2026-10-11에 Aside 브라우저로 Mobbin에서 로그인 없이 볼 수 있는 모바일 흐름 두 개를 확인했다.

- SmartThings [Adding a device](https://mobbin.com/explore/flows/2dc9a169-0590-444c-b9b5-3cbdb75b06ae): "Add devices to use at this location." 화면의 **AVAILABLE DEVICES** 제목 오른쪽에 찾는 중 표시가 돌고, 찾은 기기 줄 오른쪽에 작은 **Add** 버튼이 있다. 목록 아래에는 "Searching for devices"가 보인다. **Add**를 누르면 "Processing..."이 뜨고, 제목 오른쪽 표시는 새로고침 아이콘으로 바뀐다. 그 뒤 "Connecting to device", 기기 화면의 OK를 고르거나 기기 화면의 PIN을 입력하는 "Verify your device", "Registering your device"로 이어진다. 적용: 제목 오른쪽에 찾는 중 표시와 다시 찾기 버튼, 줄 오른쪽에 **추가**, 추가하는 동안 그 줄에 진행 표시. 추가한 뒤에는 그 PC의 연결 화면에서 연결 코드로 승인한다.
- Roku [Connecting to a device](https://mobbin.com/explore/flows/1d3f175c-1289-4aa7-85c7-60869e6b7c52): **Available on this network** 제목 옆에 찾는 중 표시가 있고, 못 찾으면 "No devices found"와 함께 휴대폰과 같은 네트워크에 있어야 한다고 알려 준다. 찾으면 기기 이름과 "Connect device"가 있는 줄을 보여 준다. 적용: 못 찾으면 그 PC의 몽글터미널과 원격 접속이 켜져 있는지 확인하라고 알리고 아래 주소 입력으로 이어지게 했다.
- 줄 모양은 몽글의 기존 **컴퓨터 전환**·**터미널 전환** 창의 목록 줄(아이콘, 이름 아래 주소)과 같게 맞췄다.

## 독립 코드 검토와 실제 앱 확인 (2026-10-11)

아스트라(`gpt-6-astra`)에게 커밋 `e8e5dca`·`0a48383`의 읽기 전용 검토와 격리한 실제 Electron 확인을 맡겼다. P0·P1은 없었고, 소유자 채널의 권한·매개변수 검사, 주소 정규화와 등록한 PC·이 PC 제외, 바쁜 버튼의 클릭 방어에서 문제를 찾지 못했다. P2 2건은 고쳤다.

- [P2] **···** 메뉴에서 연 창의 초점 복귀: 터미널 **··· → 이름 변경 → Esc** 뒤 초점 표시가 사라지고, 다음 Tab이 화면 맨 앞의 컴퓨터 선택으로 갔다(실제 앱에서 재현). 메뉴 항목을 누르면 메뉴가 닫혀 그 항목이 숨겨지는데, 창이 닫힐 때 숨겨진 항목으로 초점을 돌리려다 실패했다. 이제 돌려보낼 항목이 초점을 받지 못하면 그 항목이 든 메뉴의 **···** 버튼으로 돌린다. 터미널 탭을 두 번 눌러 연 이름 변경 창은 원래도 정상으로 돌아왔다.
- [P2] 다시 찾은 결과에서 초점이 있던 PC가 빠질 때: 찾는 동안에는 이전 결과의 줄이 남아 Tab으로 갈 수 있는데, 새 결과에 그 PC가 없으면 초점이 있던 버튼이 사라져 Esc·Tab이 창 밖으로 빠질 수 있었다(코드 검토로 찾았고 실제 앱에서는 재현하지 않음). 이제 결과를 반영하기 전에 사라질 줄에 초점이 있으면 다시 찾기 버튼으로 옮긴다.

두 수정은 위의 화면 시험으로 확인했다. 실제 Electron에서 다시 확인하는 일은 다음 기능의 실제 앱 확인과 함께 한다.

실제 확인은 %TEMP% 아래 새 데이터 폴더(`MONGLE_DATA_DIR`, `MONGLE_E2E_DATA_ROOT`)로 띄운 개발 실행부와 Electron으로 했다(커밋 `0a48383`, 위 수정 전). 확인한 것:

- 맨 위 **+**로 창을 열면 이름 입력칸에 초점이 가고, 찾는 중 표시 뒤 실제 Tailscale에서 다른 몽글 PC 1대가 나왔다. 이 PC는 나오지 않았다.
- 다시 찾는 동안 초점 유지, 창 안의 Tab 순환(다시 찾기 → 찾은 PC → 이름 → 주소 → 취소 → 추가하고 연결 → 닫기), Esc 뒤 **+**로 초점 복귀.
- 찾은 PC의 **추가**를 누르면 컴퓨터 목록에 들어가 선택되고 그 PC의 "이 기기를 연결하세요" 화면이 나왔다. 연결 코드 입력·연결 요청·승인은 하지 않았다. 시험 등록을 해제한 뒤 창을 다시 열면 그 PC가 다시 나왔다.
- 새 작업 그룹 창과 터미널 탭을 두 번 눌러 연 이름 변경 창의 자동 초점, Esc 뒤 초점 복귀.
- 호스트는 설정 → 컴퓨터의 백그라운드 실행 종료로 정상 종료했다.

정리: 앱 메뉴(Alt·F10)가 나타나지 않고 Ctrl+Q로도 끝나지 않아 시험 Electron은 해당 PID만 강제로 정리했다. 시험 잔존 프로세스 0개, 기존 몽글 프로세스 보존, Tailscale Serve 설정의 해시 동일, 소스·Git 변경 없음을 확인했다. 호스트를 끈 뒤 오프라인 안내가 보이는 동안 아래쪽에 "1개 실행 중"이 남아 있었다(실제 셸은 종료됨). 원인과 이번 변경과의 관계는 조사하지 않았다. 기록은 커밋하지 않는 `test-results/desktop-computer-picker-live/`에 있다.

## 확인하지 않은 범위

- 위 두 초점 수정의 실제 Electron 확인.
- 원격 컴퓨터에 연결한 상태에서 그 컴퓨터가 돌려준 목록의 실제 제외 동작(이 PC의 원격 주소 빼기). 자동 시험으로만 확인했다.
- 찾은 PC의 연결 승인까지 마친 흐름(이번에는 연결 화면에서 멈춤).
- 앱 전체의 정식 메뉴 종료(시험 Electron은 PID로 정리)와 호스트 종료 뒤 남은 "1개 실행 중" 표시.
- Tailscale 접근 규칙으로 PC끼리 막힌 환경.
