# 작업 상태 표시 재설계와 Claude 상태 오류 수정

2026-10-08. **구현·자동 검사·실제 CLI 재현 완료, 미배포.** 실제 앱 화면 검증 결과는 [실제 앱 검증](#실제-앱-검증)에 따로 기록한다.

## 제보

작업 중·완료 표시(맥동하는 원과 종)가 보기 좋지 않고, 진행 중이 아닌데도 진행 표시가 뜨는 등 상태가 맞지 않는다는 제보다. Claude만의 문제인지 Codex도 그런지 확인이 필요했다.

## 수정 전 실제 CLI 재현

몽글의 실제 TerminalEngine과 PowerShell 7 셸 통합(safeShellEnvironment, 셸별 토큰, 프롬프트 표식)을 쓰는 시험 스크립트로 ConPTY에서 CLI를 실행했다. 훅 이벤트·BEL/OSC 신호·상태 변화를 시간순으로 기록했다. 사용자의 몽글 앱·실행부·설정·인증은 바꾸지 않았다. Claude는 사용자 PC에 이미 설치된 몽글 훅을 그대로 썼다. 시험 스크립트와 기록은 커밋하지 않는 .test-data/status-probe/에 있다.

- Claude Code 2.1.294(Windows 네이티브), Codex CLI 0.161.0. 두 CLI가 이미 신뢰한 저장소 폴더에서 짧은 응답만 요청했다.

| 상황 | 받은 훅 | 수정 전 상태 |
| --- | --- | --- |
| 일반 응답 | UserPromptSubmit → 약 2초 뒤 Stop | 작업 중 → 응답 완료, 알림 1 (정상) |
| /context, /cost | 없음 | 변화 없음 (정상) |
| Esc로 응답 중단 | 없음 | 작업 중 → 대기 (정상) |
| 작업 중 / 메뉴를 Esc로 닫음 | 3.8초 뒤 Stop | 대기로 바뀐 뒤 Stop을 버림. **완료 알림 유실** |
| 작업 중 추가 메시지 | UserPromptSubmit 2회, Stop 2회 | 첫 Stop에서 완료. **두 번째 완료는 알림 없음** |
| !echo(셸 명령) 뒤 Claude 응답 | Stop만 | 새 알림 없음 |
| /compact | SessionStart(compact) | **대기로 초기화** |
| 쓰기 권한을 "3. No"로 거절 | 거절 뒤 80초 이상 없음 | **다음 질문까지 확인 요청 유지** |
| 질문(AskUserQuestion)에 Enter로 답함 | PostToolUse(입력에 답 추가) → Stop | **응답이 끝날 때까지 확인 요청 유지** |
| 정상 Stop 뒤 | 약 60초 뒤 Notification(idle_prompt) | 무시 (정상) |

이 실행에만 --settings로 20종 이벤트 기록 훅을 붙여 확인했다. 수동 거절과 Esc 취소 뒤에는 PostToolBatch·PermissionDenied·Stop을 포함해 어떤 훅도 오지 않았다. PermissionRequest에는 tool_use_id가 없고 PreToolUse·PostToolUse에는 있다. 사용자 설정의 다른 훅과 함께 실행할 때는 SessionStart(startup)·SessionEnd가 몽글로 전달되지 않았고, CLI 종료는 셸 프롬프트 표식으로 반영됐다.

**Codex:** 사용자 기본 설정에서 정상 응답·/status·Esc 중단·종료 동안 몽글 상태 변화와 BEL/OSC9 알림이 모두 0회였다. Codex 연동은 대화 재개용 SessionStart/End만 전달하므로 **작업 중 표시는 Claude 경로에서만 생긴다.** 다만 기존 화면은 모바일·접힌 사이드바의 터미널 전환 버튼에 그룹 전체 상태를 붙였다. 그래서 같은 그룹의 Claude가 일하면 Codex 터미널을 보고 있어도 작업 중 표시가 보였다.

## 수정

- **훅:** tool_use_id의 SHA-256과 SessionStart의 source(startup·resume·clear·compact·fork만)를 추가로 보낸다. 원문 ID·프롬프트·도구 입력은 보내지 않는다.
- **도구 추적:** PreToolUse·PostToolUse를 호출 ID로 짝짓는다. 예전 훅은 입력 해시로 대신한다. ID가 없는 PermissionRequest는 같은 입력 중 아직 요청이 붙지 않은 가장 오래된 호출에 연결한다.
- **중단·응답 입력:** 작업 중 Esc·Ctrl+C는 표시를 대기로 내리되 대화 추적은 유지한다. 그 뒤 새 도구 사용·권한 요청·Stop이 오면 다시 표시하고, 이미 실행 중이던 도구가 끝난 것만으로는 다시 올리지 않는다. 확인 요청 중 해당 터미널에 전달된 Enter(괄호 붙여넣기 안의 줄바꿈 제외)는 가장 오래된 요청에 대한 응답으로 보고, 남은 요청이 없으면 표시를 내린다. 승인한 호출이 끝나면 작업 중으로 돌아간다. 숫자 키는 선택만 옮길 수 있어 응답으로 보지 않는다. 호스트는 입력 종류만 보고 출력과 같은 엔진 큐에 넣어 순서를 지킨다.
- **완료·정리:** Stop·StopFailure는 상태가 같아도 응답마다 알림을 만든다. 같은 대화의 compact는 상태를 유지한다. idle_prompt는 최근 30초 안에 다른 훅이 없을 때만 남은 작업 중을 응답 완료로, 남은 확인 요청을 대기로 정리한다.
- **알림 종류:** 호스트가 Claude 알림이 만든 알림 번호(agentNotificationCount)를 기록한다. 화면은 읽은 번호와 비교해 Claude 완료를 확인한 뒤 온 일반 알림을 "알림"으로 표시한다. 새 터미널 세대·종료·저장 로드에서 함께 지운다. 이 값이 없는 예전 실행부의 상태는 기존 방식으로 표시한다.
- **화면:** 작업 중은 옅은 원 위의 얇은 호 스피너(0.9초 회전, 모션 줄이기에서는 정지), 미확인 완료·알림은 작은 점, 확인 요청·오류는 서로 다른 아이콘으로 표시한다. 미확인 테두리를 없앴다. 작업 중 터미널에 이전 미확인 알림이 있거나, 그룹에서 더 급한 상태 뒤에 미확인 알림이 있으면 아이콘 옆에 작은 점을 붙이고 툴팁에 개수를 보여 준다. 접힌 사이드바의 전환 버튼과 모바일 메뉴 버튼은 보고 있는 터미널을 뺀 요약이다. 모바일 전환 버튼은 제목 옆에 이 터미널의 상태를, 개수 옆에 다른 터미널 요약을 나눠 보여 준다. 연결이 끊기면 마지막 상태를 흐리게 멈추고 설명에 밝힌다.

## 수정 후 실제 CLI 재현

같은 시험 스크립트에 수정한 엔진과 호스트의 입력 관찰 규칙을 적용했다. 이번 빌드의 훅만 쓰는 실행(--setting-sources project,local --settings)과, 사용자에게 설치된 예전 훅을 쓰는 실행을 함께 돌렸다.

| 상황 | 새 훅 | 예전 훅 |
| --- | --- | --- |
| 작업 중 메뉴 Esc | 대기 → Stop에서 완료·알림 | 같음 |
| 작업 중 추가 메시지 | Stop 두 번 모두 알림 | 같음 |
| 쓰기 권한 "No" | Enter에서 대기, 남는 표시 없음 | 같음 |
| 질문에 Enter로 답함 | 대기 → PostToolUse(호출 ID)에서 작업 중 → 완료 | 대기 → 완료 |
| /compact | 상태 유지 | 대기로 초기화(예전 훅에는 source 없음) |

아스트라 검토를 반영한 최종 판정 규칙으로 다시 실행해 같은 결과를 확인했다. 반영으로 추가한 동일 입력 병렬 요청·괄호 붙여넣기·호스트 입력 순서는 자동 검사로 확인했다.

## 남은 제약

- 거절·질문 답변은 해당 터미널에 전달된 Enter로 판단한다. 숫자 키나 마우스로만 답하면 다음 Claude 신호까지 확인 요청이 남을 수 있다.
- 오래 걸리는 도구를 승인하면 그 도구가 끝날 때까지 작업 중 표시가 없을 수 있다.
- 작업 중 보낸 메시지의 두 번째 응답에는 시작 신호가 없어, 진행되는 동안 응답 완료로 보인다. 끝나면 다시 알림을 보낸다.
- 새 대화의 첫 입력이 ! 명령이면 대화를 확인할 신호가 없어 그 응답의 완료를 표시하지 못할 수 있다.
- 실행부가 갱신되기 전의 예전 훅에서는 compact 때 상태가 초기화되고, 질문에 답한 뒤 남은 응답 동안 작업 중 표시가 없다. 새 실행부는 시작할 때 훅 스크립트를 갱신한다.
- Codex의 작업 중 상태 연동은 제공하지 않는다. Codex 알림은 Codex 알림 설정을 따른다.
- 훅 2초 제한 초과로 Stop이 유실되는 경우는 재현하지 못했다. 유실되면 idle_prompt(약 60초 뒤)로 정리한다.
