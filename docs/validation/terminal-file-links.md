# 터미널 파일 경로 열기

터미널 출력에 나온 파일 경로를 `Ctrl+클릭`하면 오른쪽 파일 탭으로 여는 기능의 구현과 검증 범위다. 미배포 상태다.

## 동작

- 경로 인식과 해석은 `apps/web/src/terminal-file-links.ts` 한 곳에 있다. xterm 화면 버퍼만 읽고 터미널 입력으로 아무것도 보내지 않는다. Claude·Codex의 훅·설정·실행 인자는 바꾸지 않는다.
- 줄바꿈된 논리 줄을 이어 읽고, 넓은 글자(한글)가 들어가지 않아 비워 둔 줄 끝 칸을 건너뛴다. Windows 전체 경로(`C:\...`), `\`·`/` 상대 경로, `.\` 시작, `:줄:칸`·`(줄,칸)` 접미사를 알아본다. 폴더 없는 이름은 흔한 확장자 목록에 있을 때만 링크다. 웹 주소 안, `..`, `~/`, POSIX 절대 경로, UNC 경로는 링크로 만들지 않는다. 공백이 있는 경로는 정규식이 마지막 단어들만 잡으므로, 앞 단어에 경로 구분자가 있으면 그 경로를 시작한 드라이브·`.\`·여는 따옴표까지 이어 붙인다. 시작을 찾지 못하면 일부만 링크로 만들지 않는다(따옴표 없는 상대 경로의 공백은 지원하지 않음).
- 열기는 기존 파일 탭(`files.open`·`files.preview`)을 그대로 쓴다. 해석 결과는 터미널 현재 폴더 기준 상대 경로이며, 호스트의 폴더 경계 검사(`resolvePreviewTarget`)도 그대로 적용된다. 폴더 밖 경로는 요청을 보내지 않고 안내한다.
- 클릭 처리: 터미널 마운트의 캡처 단계에서 가장 먼저 등록한다. 왼쪽 버튼 + Ctrl(또는 Cmd)이고 그 칸이 경로일 때만 mousedown·mouseup·click을 막는다. 그래서 마우스를 보고하는 CLI, 드래그 선택·자동 복사, 탭으로 제어권 가져오기가 이 클릭을 받지 않는다. 경로가 아닌 곳의 Ctrl+클릭과 모든 일반 클릭은 이전과 같다. xterm 링크의 `activate`는 비워 두어 일반 클릭으로 열리지 않는다.

## 검증(2026-10-12)

- 단위 검사 `tests/ui/terminal-file-links.test.ts` 3/3 통과: 경로 형식별 인식과 제외, 폴더 경계 판정(대소문자·구분자·다른 드라이브·형제 폴더·`..`), headless xterm에서 한글 뒤에 나오고 줄바꿈된 경로의 칸 위치.
- 실제 Chrome 검사(`tests/terminal/browser.test.ts`의 경로 링크 2개) 2/2 통과: CLI가 마우스 보고(1003·SGR)를 켠 상태에서 Ctrl+클릭은 파일을 열고 누름·뗌 보고를 CLI로 보내지 않음, 같은 위치의 일반 클릭과 경로 밖 Ctrl+클릭은 CLI 보고로 전달됨, 일반 셸 출력에서 경로를 연 클릭이 뒤에 등록된 처리기(선택 복사·탭 제어)에 도달하지 않음. 처리를 끈 상태로 같은 검사를 돌려 두 검사가 모두 실패하는 것을 확인했다.
- 타입 검사 통과.

## 아스트라 검토와 수정(2026-10-12)

아스트라(`gpt-6-astra`)가 커밋 `ca6a83f`를 검토해 두 결함을 재현했다. (1) `C:\work\my project\src\a.ts`를 `project\src\a.ts`로 인식해 다른 파일을 열 수 있었다. (2) 경로를 Ctrl+누른 채 터미널 밖에서 떼면 다음 일반 클릭의 뗌·클릭이 막혔다. 문서의 "`..` 경로는 이유를 알려 준다"도 실제 동작(링크로 만들지 않음)과 달랐다.

수정: 공백 경로 이어 붙이기·거부, 새 누름마다 막기 상태 초기화와 터미널 밖 뗌에서 초기화, 문서 정정. 단위 검사 1개와 실제 Chrome 검사 단계 1개를 추가했고, 수정 전 모듈로 돌리면 둘 다 실패하고 수정 후 통과함을 확인했다(단위 4/4, Chrome 2/2).

아스트라가 실제 격리 앱에서 확인한 범위: 일반 PowerShell 출력 경로의 일반 클릭은 파일 탭을 열지 않고, 드래그 자동 복사와 Ctrl+V는 그대로였다. Ctrl+클릭은 컴퓨터 유즈 도구가 Ctrl과 클릭을 함께 보내지 못해 실제 앱에서 확인하지 못했다.

## 확인하지 않은 범위

- 실제 몽글터미널 창에서 Claude·Codex 출력의 경로를 Ctrl+클릭하는 확인은 하지 않았다. 저장소 규칙상 컴퓨터 유즈 검증은 아스트라가 맡는다.
- 마우스 보고 중인 CLI 화면에서 hover 밑줄이 표시되는지는 브라우저 검사에서 보지 않았다(열기 동작만 확인).
- 휴대폰 등 Ctrl 키가 없는 기기의 열기 방법, 줄 번호로 이동은 제공하지 않는다.
