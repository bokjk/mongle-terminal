# 터미널 탭과 상단 공간 검증

검증일: 2026-10-01 · 소스 버전: 0.3.3 · 작업 브랜치: `codex/terminal-tabs` · **미배포 소스 변경**

이 문서는 개발 단계의 검증 기록이다. 이후 0.3.4의 전체 회귀·실제 패키지·공개 배포 결과는 [0.3.4 배포 기록](public-release-0.3.4.md)에 구분한다.

## 변경 범위

기존 중첩 드래그 분할을 유지하고 **각 분할 영역 안에 독립된 터미널 탭**을 표시한다. 영역의 +는 그 영역에 새 탭을 추가한다. 탭 전환은 옆 영역의 선택·분할 비율·배치를 바꾸지 않는다. 좌우·상하 분할 버튼과 왼쪽 아래 새 분할은 새 영역을 만든다. 탭 제목 드래그는 탭 하나를 이동하고, 점 손잡이 드래그는 해당 영역의 모든 탭을 함께 이동하거나 교환한다. 그룹 전체의 탭/분할 보기 전환은 제공하지 않는다.

PC에서 터미널이 열려 있으면 별도 상단 도구줄을 제거하고 새 분할·파일 탐색기·설정을 왼쪽 아래에 표시한다. 탭과 기존 패널 조작은 32px 제목줄에 모았다. PC 좌우 바깥 여백은 6px다. 모바일의 60px 상단과 기존 패널 전환·화면 넓게·44px 터치 대상은 유지한다.

PC에서 탭 전환·재배치·최대화는 같은 `SplitTree`의 터미널 인스턴스를 유지한다. 숨긴 탭은 표시 크기를 호스트에 전송하지 않으며, 처음부터 숨겨진 탭은 자동으로 제어권을 얻지 않는다. 탭 전환은 선택만 바꾸고 다른 기기의 제어권을 가져오지 않는다. 탭 X·Delete는 기존 종료 확인 절차를 사용한다. 첫 탭을 닫으면 같은 영역의 다른 탭을 대표로 올리고, 마지막 탭을 닫을 때만 영역과 분할을 합친다.

## 저장과 API

`LayoutNode`의 기존 leaf는 유지하며 `tabs?: string[]`에 추가 세션 ID를 표시 순서대로 저장한다. `terminalId`와 `tabs`를 합쳐 그룹 내 모든 터미널이 정확히 한 번 포함되는지 검증한다. 기존 단일 탭 leaf는 변환 없이 읽는다. `terminals.create`에 `tabTarget`을 추가했으며 다른 그룹·삭제된 대상·splitTarget/axis 동시 지정은 거부한다. 기존 그룹당 16개·호스트 전체 한도와 배치 CAS를 유지한다.

호스트가 `layout.tabs` 기능을 알릴 때만 새 탭을 추가한다. 탭 지원 이전 버전은 여러 탭을 담은 배치를 모두 표시할 수 없다. 탭 구성·분할은 호스트 DB에 저장하고, 선택한 탭은 `mongle.tabs.<hostId>.<groupId>`에 각 구성원 ID 기준으로 기억하여 대표 탭이 닫혀도 나머지 영역의 선택을 찾는다. 다른 기기의 선택은 변경하지 않는다.

설정 이동 후 버튼 이름에 버전까지 포함되어 정확한 접근성 이름으로 찾지 못한 문제는 `aria-label="설정"`으로 수정했다. 호스트 전환 후 화면 동기화가 끝나기 전에 원격 제어권 검사가 시작되던 경합은 보이는 두 영역의 제어 준비를 확인한 뒤 원격 기기가 획득하도록 시험 순서를 수정했다. 기존 PC 제목 누르기 검증은 새 탭의 선택만으로 다른 기기의 제어권을 가져오지 않는지 확인하도록 갱신했다. 실제 PowerShell·모바일 왕복에서는 탭 선택 후 휴대폰 제어권을 유지하고 명시적인 가져오기로 전환해 ACK·명령 입력·동일 PID와 generation을 검증한다. 모바일 제목과 내용 누르기 검증도 유지했다. 인증 검사나 제품 제어권 정책은 완화하지 않았다.

## 마지막 탭 뒤 + 배치 재검증

2026-10-01 후속 수정에서는 탭 목록이 남는 폭 전체로 늘어나 +가 오른쪽 끝으로 밀리던 동작을 수정했다. 일반 폭에서는 마지막 탭과 + 사이가 4px이며, 좁은 영역에서는 탭 목록만 줄어 가로로 스크롤하고 +는 목록 옆에서 계속 사용할 수 있다. 검색·분할·메뉴·최대화는 오른쪽 도구 모음에 유지한다.

참고 자료로 [Mobbin 공개 웹 Tab 사례](https://mobbin.com/explore/web/ui-elements/tab)와 [Notion 화면](https://mobbin.com/explore/screens/4efec287-162f-4d70-ac18-7e5c7a5a05b6)을 실제 브라우저에서 열고 이미지를 확인했다. 공개 예시는 화면 전환용 탭의 참고 자료이며, 이번 새 터미널 추가 버튼 위치의 직접 기준은 사용자가 첨부한 Orca 분할 화면이다. Mobbin의 로그인 전용 전체 라이브러리는 조사하지 않았다.

개발 Electron 실행본에서 별도 `%TEMP%\mongle-tab-placement-*` 프로필과 실제 cmd.exe 셸을 사용했다. 제품의 OwnerPipe와 preload IPC를 통해 연결한 창에서 버튼 클릭·키 입력·실제 창 크기 변경을 조작했으며, 사용자 테스트 창의 세션은 이 검증에 사용하지 않았다.

## 같은 영역의 탭 드래그 분할 재검증

2026-10-01 후속 수정에서는 탭 제목을 끌어도 영역 전체를 이동하고 자기 영역 대상은 무시하던 처리를 분리했다. **탭 제목은 탭 하나**, **점 손잡이는 영역 전체**를 옮긴다. 탭 하나를 자기 영역의 네 가장자리로 놓으면 나머지 탭을 유지한 채 새 분할을 만든다. 다른 영역 가장자리는 탭 하나를 분할하고, 가운데는 해당 영역의 마지막 탭으로 합친 뒤 이동한 탭을 선택한다. 원래 영역의 마지막 탭이 떠나면 빈 영역만 합친다. 자기 영역 가운데·혼자 있는 탭의 자기 가장자리는 배치를 변경하지 않는다. 기존 셸을 생성·종료·재실행하지 않으며 기존 배치 CAS·호스트 선택·부팅 식별·외부 드래그 거부와 취소 검사는 유지했다. `layout.tabs`를 알리지 않는 호스트에는 가운데 병합을 보내지 않는다.

실제 브라우저에서 [Mobbin의 Databricks Visualization Tooltip 화면](https://mobbin.com/explore/screens/dfea709f-3245-4e15-983f-f76b96001f2c)을 열어 SQL 편집기와 아래 결과 영역의 독립된 탭 구조를 확인했다. 영역별 탭 구성을 참고했고 사용자 Orca 이미지의 기존 분할 구조를 유지했다. Mobbin 공개 화면은 정적 이미지이므로 이번 탭 드래그 제스처를 직접 검증한 참고 사례라고 표현하지 않는다.

최종 타입·웹/호스트/Electron 빌드·배포 문서 검사와 `git diff --check`를 수행했다. 관련 검사 `layout`, `terminal-tabs`, `pane-drag`, `workspace`는 **16/16 통과**했다. 이 중 배치 단위 검사는 13개이며, 탭 회귀는 실제 Chrome HTML5 마우스 드래그로 네 방향 자기 분리·대표/비활성 탭·다른 영역 분리/병합·Esc 취소·한 탭 영역을 검사한다. 기존 영역 교환 회귀의 드래그 시작점은 새 동작 구분에 맞게 제목에서 점 손잡이로 변경했다. 탭 회귀는 `layout.tabs` 기능 알림이 없는 상태도 주입해 병합 RPC를 보내지 않는지 확인했으며 실제 구버전 설치본을 실행한 검증은 아니다. 전체 회귀를 이번 후속 변경에서 재실행하지는 않았다.

개발 Electron의 별도 `%TEMP%\mongle-tab-drag-*` 프로필에서 실제 OwnerPipe·preload와 cmd.exe 셸을 사용해 **9개 조작 시나리오가 통과**했다. 제품 화면의 +·분할 버튼으로 시험 터미널 세 개를 연 뒤 탭은 실제 마우스로 끌었다. 배치 초기화와 시험 제목 설정만 IPC로 수행했다.

드래그 전후 같은 xterm DOM과 셸 PID·generation·상태·제어 기기를 확인했다. 캡처 6개를 직접 열어 미리보기와 분리/병합 결과를 확인했다. 증거는 `test-results/ui/tab-drag/result.json`, 같은 폴더의 캡처와 `related-regression.log`에 있다. 시험 창·호스트는 정상 종료했으며 사용자가 시험 중인 개발 창의 터미널을 이 조작 검증에 사용하지 않았다.

최종 빌드는 열려 있던 개발 창의 렌더러만 새로고침하여 반영했다. 반영 전후 같은 hostId·bootId·셸 PID·generation·상태와 그룹 배치를 확인했고 기존 터미널 **4개를 유지**했다. 개별 탭의 실제 `draggable` 속성과 조작 안내도 확인했다. 증거는 `test-results/interactive-tabs/tab-drag-applied.json`에 기록했다.

## 적용·미검증 범위

이 기록은 빌드한 공통 웹 UI를 Chrome에서 실제 셸과 연결한 결과와 후속 개발 Electron 조작 검증을 구분한다. 기존 PowerShell/ConPTY 입력·드래그·불확실 입력 검사도 함께 통과했으며 실사용 설치본의 호스트·세션·인증 데이터와 Tailscale Serve는 변경하지 않았다. 후속 수정은 사용자가 열어 시험 중인 별도 개발 창의 화면을 새로고침하여 반영했고 같은 hostId·bootId·셸 PID·generation·상태와 분할 배치가 유지되는지 확인했다. 증거는 `test-results/interactive-tabs/placement-applied.json`에 기록했다.

위 기능 개발 검증 시점에는 기존 설치 앱에 파일을 적용하지 않았고 버전·설치본·공개 Release를 변경하지 않았다. 이어 수행한 **0.3.4 배포**에서는 실제 패키지의 탭 드래그 9개 시나리오와 정상 종료·복원 1/1, 전체 회귀·GitHub PR 검사, 공개 게시와 인증 없는 실제 업데이트 다운로드를 통과했다. 자세한 결과와 범위는 [0.3.4 배포 검증](public-release-0.3.4.md)에 기록했다.

실사용 NSIS 설치·제거, 이번 변경의 사용자 화면 확인·실물 휴대폰·실제 Tailscale 연결은 별도다. 기본 회귀의 선택 실행 E2E 생략을 해당 영역의 통과로 표현하지 않는다.
