# 파일 첨부

휴대폰이나 다른 기기의 사진·파일을 터미널이 실행 중인 PC로 보내고 저장 경로를 입력 줄에 넣는 기능의 구현과 검증 범위다. 미배포 상태다.

## 동작

- **호스트**(`packages/host/uploads.ts`): 원격 연결의 메시지 한도(128 KiB) 때문에 `files.upload.begin` → `files.upload.chunk`(48 KiB) → `files.upload.finish`로 나눠 받는다. 시작 요청은 살아 있는 터미널(호스트·부팅·세대 일치)과 그 터미널의 현재 폴더가 요청한 폴더와 같을 때만 받는다. 조각은 시작한 연결만 보낼 수 있고, 순서(오프셋)와 선언한 크기를 넘지 않아야 한다. 받는 중에는 `.<id>.part` 파일(소유자 전용 권한)에 쓰고, 완료하면 겹치지 않는 이름으로 바꾼다. 같은 이름이 있으면 덮어쓰지 않는다.
- **제한과 정리**: 파일당 10 MiB, 연결당 동시 2개, 전체 8개. 시작 요청은 비동기 작업 전에 자리를 먼저 잡으므로 동시에 들어와도 이 제한을 넘지 않는다. 시작 중에 연결 종료·호스트 종료가 오면 그 시작은 임시 파일을 지우고 실패한다. 취소, 연결 종료, 2분 무응답, 호스트 종료 때 받다 만 파일을 지운다. 이전에 비정상 종료로 남은 10분 넘은 `.part` 파일도 다음 시작 때 지운다. 저장된 파일은 자동으로 지우지 않는다.
- **저장 위치**: 터미널 현재 폴더 안 `.mongle-attachments`. 이 이름이 파일이거나 링크·정션이면, 또는 실제 위치가 터미널 폴더 밖이나 앱 데이터 폴더 안이면 거부한다. 이름은 `날짜-시각-임의8자-원래이름.확장자`이며 원래 이름의 셸·Windows 특수 문자와 예약 장치 이름을 바꾼다.
- **Git 제외**: 현재 폴더가 Git 저장소 안이면 먼저 Git에 이번 업로드의 실제 이름 두 개(임시 `.<id>.part`와 최종 이름)가 무시되는지 묻는다(`git check-ignore`, Git 보기와 같은 안전 옵션·환경, 이 명령이 지원하지 않는 `GIT_LITERAL_PATHSPECS`만 뺌). 이미 무시되면 아무것도 쓰지 않는다. 아니면 `.git`을 읽어 공용 Git 폴더의 `info/exclude`에 `.mongle-attachments/` 한 줄을 한 번 추가하고 다시 묻는다. `info` 폴더와 `exclude` 파일은 링크·정션·하드 링크가 아니고 실제 위치가 공용 Git 폴더 안이며 앱 데이터 폴더 밖이어야 한다. 우리 줄이 이미 있는데도 무시되지 않거나 추가 뒤에도 무시되지 않으면(`!` 규칙), 저장소를 읽지 못하거나 Git을 실행하지 못하면, 첨부 폴더를 만들기 전에 `UPLOAD_GIT_EXCLUDE`로 중단한다. 커밋되지 않는 로컬 파일이며 `.gitignore`는 바꾸지 않는다. 워크트리는 원래 저장소의 파일을 쓴다.
- **웹**(`apps/web/src/terminal-upload.ts`, `TerminalPane.tsx`): 터미널 `···` → **파일 첨부…** 또는 클립보드에 글자 없이 파일만 있을 때의 붙여넣기. 차례로 올린 뒤 셸 종류에 맞춘 경로(PowerShell·cmd는 그대로·공백 시 따옴표, Git Bash는 작은따옴표, WSL은 `/mnt/<드라이브>/`)와 공백 하나를 기존 붙여넣기 경로로 입력한다. Enter는 보내지 않는다. 진행률·취소 줄과 완료 알림을 보여 준다.
- **원격 권한**: 업로드 요청도 다른 파일 요청처럼 원격 게이트웨이의 첫 프레임 인증 뒤에만 코어로 전달되며, 원격 기기는 소유자가 아닌 권한으로 처리된다. 파일 저장은 터미널 입력·제어권이 필요하지 않지만, 경로 입력은 붙여넣기와 같이 제어권을 가져온다.
- **저장 위치 결정**: 작업 폴더(+Git 로컬 제외)와 앱 데이터 폴더 중 사용자에게 물었으나 답을 받기 전에 추천안인 작업 폴더로 구현했다. 앱 데이터 폴더는 Claude가 프로젝트 밖 파일이라 읽기 권한을 물을 수 있고, 작업 폴더에 두고 제외하지 않으면 에이전트의 `git add -A`로 커밋될 수 있다. 위치는 `attachmentDirectory`·`excludeFromGit` 두 함수로만 정해져 바꾸기 쉽다.

## 디자인 참고

2026-10-12 Aside로 Mobbin 공개 화면 이미지를 열어 확인했다.

- Slack(iOS, 사진·영상 첨부 플로우): 입력 영역 왼쪽 **+** → 메뉴에 `Upload a file` 등. 업로드 진행 표시는 보지 못함. 결과는 채널 메시지로 게시.
- ChatGPT(Android): 입력창 왼쪽 카메라·사진·파일 아이콘, 첨부 후 입력 영역 위 썸네일과 X. 진행 표시는 보지 못함.
- Google Drive(iOS): 업로드 확인 화면의 `Upload` 버튼, 아래쪽 `1 upload complete` 완료 문구와 X.

적용한 판단: 몽글 터미널에는 별도 입력창이 없어 Slack처럼 메뉴 항목(**파일 첨부…**)으로 넣었다. 완료는 Google Drive처럼 짧은 완료 문구로 알린다. 업로드 중 진행률·취소 줄은 확인한 사례에서 보지 못한 부분으로, 몽글의 기존 안내 줄(`connection-banner`) 형식을 따랐다. 휴대폰 보조 키 줄 옆 첨부 버튼(ChatGPT 방식)은 보조 키 편집 변경과 함께 정리할 후속 후보로 남겼다.

## 아스트라 검토와 수정(2026-10-12)

아스트라(`gpt-6-astra`)가 커밋 `1b83d5e`를 검토해 격리 시험으로 다음을 재현했다. (P1) `.git/info`를 보호 폴더로 향하는 정션으로 바꾸면 업로드가 보호 폴더의 `exclude`를 고쳤다. (P2) 서로 다른 연결의 동시 시작 12개가 전체 제한 8개를 넘어 모두 허용됐고, 시작 직후 연결 종료·호스트 종료에도 `.part`가 남았다. (P2) 기존 `/.mongle-attachments/`를 하위 폴더까지 덮는 규칙으로 오판해 하위 폴더 첨부가 `git status`에 나타났고, 제외 쓰기 실패도 조용히 넘겼다. (P2) 완료 응답 대기 중 취소해도 성공으로 반환되어 경로가 입력될 수 있었다. 문서의 동시 제한·정리·Git 제외 설명도 실제와 맞지 않았다.

수정: 시작 자리 선점과 시작 중 취소 표시, 제외 경로의 링크·위치 검사와 모든 깊이 규칙만 인정·추가 후 재확인·실패 시 저장 중단, 완료 응답 뒤와 입력 직전의 취소 확인, 뒤 파일 실패·취소 때 앞서 저장된 파일 안내, 빈 파일 사전 검사. 재현 조건을 호스트 검사 2개(동시 시작·시작 중 종료, 정션·하드 링크·루트 전용 규칙)와 웹 단위·Chrome 검사 단계(완료 응답 중 취소)로 추가했고, 수정 전 코드로 돌리면 모두 실패하고 수정 후 통과함을 확인했다.

아스트라가 실제 격리 앱에서 확인한 범위: 클립보드 이미지 `Ctrl+V`로 격리 작업 폴더에 114바이트 PNG가 저장되고 경로와 공백만 입력 줄에 들어갔으며 Enter는 실행되지 않았다. 메뉴의 Windows 파일 선택창은 열렸으나 컴퓨터 유즈 도구가 자식 대화상자에 입력하지 못해 선택 완료는 확인하지 못했다. 실제 원격 연결·휴대폰·대용량 전송도 확인하지 못했다. 저장 위치는 아스트라도 작업 폴더를 권했다(안전한 경로 검사와 Git 제외 성공 확인 전제).

재검토(커밋 `62caf67`)에서 아스트라가 두 문제를 더 재현했다. (P2) 제외 파일의 `!.mongle-attachments/`나 `.gitignore`의 같은 규칙이 첨부 폴더를 다시 포함해도 규칙 문자열만 보고 성공 처리했다. (P2) 업로드 완료 뒤 제어권을 받아오는 동안 취소하면 취소 뒤에도 경로가 입력됐다. 이제 Git에 직접 무시 여부를 묻고, 경로 입력은 제어권을 받은 뒤 실제 입력 직전에 취소를 다시 확인한다. 호스트 검사 1개(기존 `.gitignore` 무시, 제외 파일·`.gitignore`의 되돌림 규칙, 거부 뒤 줄이 늘지 않음)와 Chrome 검사 단계(다른 기기가 제어 중일 때 제어권 대기 중 취소)를 추가했고, 직전 커밋 코드로는 실패하고 수정 후 통과함을 확인했다(호스트 9/9, 웹 단위 2/2, Chrome 3/3).

3차 검토(커밋 `a62aa8e`)에서 아스트라가 고정된 시험 경로(`.mongle-attachments/probe`)만 묻기 때문에 `.gitignore`의 `.mongle-attachments/*` + `!.mongle-attachments/*.png`에서 PNG가 저장되고 `git status`에 보이는 것을 재현했다. 이제 시작 전에 최종 이름과 임시 이름을 정하고 그 두 경로를 Git에 묻는다. 위 규칙에서는 PNG가 무시되지 않으므로 폴더 규칙을 추가하고, Git은 제외된 폴더 안의 파일을 다시 포함하지 않으므로 다시 물으면 무시된다. 이 사례를 호스트 검사에 추가해 직전 코드로는 제외 줄이 추가되지 않아 실패하고 수정 후 PNG·TXT 모두 `git status`에 보이지 않음을 확인했다(호스트 9/9).

## 확인하지 않은 범위

- 실제 휴대폰에서 카메라·사진 선택, 실제 원격(Tailscale) 연결로 큰 파일을 보내는 속도, 실제 몽글터미널 앱과 Claude·Codex가 그 경로의 이미지를 읽는 동작은 확인하지 않았다. 컴퓨터 유즈 검증은 저장소 규칙상 아스트라가 맡는다.
- PC에서 파일을 터미널로 끌어다 놓기는 제공하지 않는다(패널 끌어 놓기와 겹침).
