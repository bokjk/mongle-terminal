# 고정 입력창과 기록 복사 보기

2026-10-06, `fix/claude-selection-live`, 미배포 구현·검사 기록이다. 공개 0.3.12와 사용자 설치본에는 이 기능이 없다.

## 해결 범위

Claude 2.1.291 전체화면의 `Jump to bottom` 안내와 겹친 글자가 자체 복사에서 빠진다. 몽글의 마우스 전달 수정 뒤에도 남는 [별도 결함](claude-native-selection.md#전체화면-안내-겹침-대조-검사)이다. 전체화면과 고정 입력창을 포기하는 일반 렌더링 기본값은 제거했다. 명시된 환경 변수 값만 유지한다.

새 **기록 복사 보기**는 일반 터미널 버퍼의 완성된 프레임을 읽어 별도 읽기 전용 문자열로 보관한다. 사용자가 Claude에서 `Ctrl+O` → `[`를 누르고 **현재 기록 가져오기**를 선택한 뒤, 터미널에서 `Esc`로 돌아가면 고정 입력창과 복사창을 함께 사용할 수 있다. 새 출력은 복사창의 텍스트·선택을 갱신하지 않는다. 버튼을 통한 새 가져오기만 내용을 바꾼다.

이는 기존 전체화면의 평소 드래그를 완전히 고친 것이 아니다. 원문을 가져오는 추가 조작이 필요하다. 숨겨진 CLI 키 입력, 개인 대화 파일 읽기, 누락 글자 추측·재구성, OSC52 허용 범위 변경을 사용하지 않는다.

## 구현과 보관 범위

- 공개 xterm 버퍼 API로 자동 줄바꿈을 합친다. 한글 너비·실제 끝 공백·중간 빈 줄을 보존하고 장식용 ANSI는 복사하지 않는다.
- 대체 화면에서는 부분 기록을 전체처럼 가져오지 않고 안내한다. 프레임 적용 중이면 완료를 기다리며, 3초 초과·연결 교체·읽기 실패 시 기존 복사창 내용을 유지한다.
- 상한은 2,097,152 UTF-16 코드 단위다. 최신 온전한 논리 줄부터 보관하고 오래된 부분을 생략하면 안내한다. 한 줄 자체가 상한을 넘으면 중간을 자르지 않고 오류를 표시한다. 호스트 기록 생략·현재 버퍼 상한도 보수적으로 알린다.
- 닫기·패널 재생성·호스트/셸 교체 시 메모리 복사본이 사라진다. 현재 화면의 **저장된 출력 지우기** 진입 시에도 닫는다. 다른 창의 복사본이나 OS 클립보드를 지우지는 않는다.
- 복사창 자체는 디스크에 저장하지 않는다. Claude가 일반 터미널에 출력한 기록은 기존 출력 기록 저장 설정의 대상이다.

## 실제 Windows 앱 검사

공개 ZIP에서 추출한 실행 파일의 웹 자산만 최종 개발 빌드로 교체하고, TEMP 아래 별도 프로필·합성 대화로 검사했다. 실제 사용자 설치본·호스트·인증 데이터를 교체하지 않았다. Claude 2.1.291은 `--safe-mode --tools "" --no-chrome`으로 실행했다. 이 시험 프로필의 `CLAUDE_CODE_NO_FLICKER=1`로 고정 입력창을 사용했다.

| 검사 | 실제 결과 |
|---|---|
| 전체화면에서 바로 가져오기 | 일반 기록을 먼저 열라는 안내 표시 |
| 대화 기록 가져오기 | 786 논리 줄, 44,112자 읽기 전용 원문 확보 |
| 터미널에서 Esc로 고정 입력창 복귀 | 복사창 문자열이 전후 동일 |
| 복사창 아래→위 12초 경계 드래그 후 Ctrl+C | LIVE-001~300, FIX-001~300 두 한글 묶음의 번호·본문·끝 글자 모두 Windows 클립보드와 일치 |
| 선택 복사 버튼 | 직전 Ctrl+C 결과와 CRLF/LF 차이를 제외한 전체 문자열 일치 |
| 전체 복사 버튼 | 가져온 44,112자 문자열과 정확히 일치 |
| 복사창 선택 후 Claude에 새 STABLE-001~080 응답 생성 | 응답 완료 후에도 이전 복사창 원문과 선택 표시 유지 |
| 최종 빌드, 680×900 좁은 창 | 터미널 아래 복사창 배치·직접 기록 가져오기 확인. 데스크톱/모바일 레이아웃 전환으로 패널이 재생성되면 이전 복사본은 닫힘 |

새 응답의 모든 토큰 시점에 복사 버튼을 누른 시험은 아니다. 네이티브 Ctrl+C는 CRLF, 앱 복사 버튼은 LF를 클립보드에 썼으며 글자·줄 내용은 같았다. 합성 프롬프트와 원시 프레임·스크린샷·로컬 경로는 무시된 시험 폴더에만 보관한다.

## 자동 검사와 협업

Opus가 정상 버퍼 수집기와 실제 headless xterm 회귀 7개를 구현했고 수명·오류 처리·설치 검사를 교차 리뷰했다. 부모 작업에서 UI를 통합하고 네이티브 조작·실제 클립보드를 대조했다.

타입 검사·전체 빌드와 관련 회귀 58개(수집기, 셸 환경, 마우스 모드, 엔진, 기록 복원, 입력 큐)가 통과했다. 실제 React TerminalPane의 복사창 문자열·선택 유지, 대체 화면 재가져오기 거부, 기록 지우기 진입·재열기 회귀를 추가했다. 이 브라우저 fixture는 실제 CLI 검사와 구분하고 전체 Windows CI에서 실행한다. 최종 CI 상태는 PR #44의 해당 커밋 Checks를 기준으로 확인한다.

앞선 문서 커밋의 설치 CI는 종료된 PID를 Windows가 재사용해 실패했다. 이전 프로세스의 실제 종료 검사는 유지하면서 새 단계 PID 집합을 분리하고, 새 셸 `generation`·실행 여부로 복원을 판단하도록 고쳤다. 설치 해시·정상 종료·호스트 `bootId` 검사는 완화하지 않았다.

모든 Claude/Codex 버전·사용자 플러그인·WSL/SSH·원격 웹·실물 모바일·모든 긴 줄 조합은 미검증이다. 이 기능은 현재 버퍼 범위의 복사이며 무제한 전체 대화 보관이 아니다. 새 공개 버전 배포·사용자 확인과 구현 검사를 구분한다.
