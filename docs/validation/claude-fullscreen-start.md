# Claude 전체 화면 모드의 시작 신호

2026-10-15, Windows x64, Claude Code 2.1.300. **0.3.24 배포 준비** 상태다. 배포 검사는 [0.3.24 배포 검증](public-release-0.3.24.md)에 기록한다.

## 문제

PowerShell에서 Claude Code를 켜거나 AI 팀을 시작한 뒤, 첫 요청을 보내기 전까지는 에이전트에게 메시지와 팀 대화를 보낼 수 없었다. 화면에는 "준비되기를 기다리는 중"이 남았다. 이전 기록([작업 상태 표시 재설계](agent-status-indicator.md), [에이전트에게 메시지 보내기](agent-messages.md))은 사용자 설정의 다른 `SessionStart` 훅과 함께 실행하면 생긴다고 적었는데, 확인해 보니 원인이 달랐다.

## 원인 확인

1단계에서 이미 신뢰한 시험 저장소(`.test-data\agent-team-probe\work`)에서 `claude.exe`를 PTY로 띄우고 `--debug-file`로 훅 처리를 기록했다. 시작 화면만 띄우고 `/exit`로 끝냈으며 모델 요청은 보내지 않았다. 사용자 설정을 뺀 실행은 `--setting-sources project,local`과 `--settings`를 썼다. 사용자 설정 파일은 고치지 않았다.

| 조건 | 몽글 시작 신호 | 종료 신호 |
| --- | --- | --- |
| 사용자 설정 그대로 | 오지 않음 | 오지 않음 |
| 몽글 훅만 | 0.8초에 도착 | 도착 |
| 몽글 훅 + 실패하는 훅(앞이나 뒤) | 도착 | 도착 |
| 몽글 훅 + Orca 훅(`{}` 출력) | 도착 | 도착 |
| 몽글 훅 + ouroboros 플러그인(Python을 찾지 못해 실패) | 도착 | 도착 |
| 몽글 훅 + `tui: fullscreen` | **오지 않음** | **오지 않음** |
| 몽글 훅 + `tui: fullscreen`, 화면이 뜬 뒤 `/clear` | `SessionStart(clear)` 도착 | 도착 |

사용자 설정 그대로일 때의 디버그 기록에서도 몽글 훅은 `SessionStart`에서 149ms 만에 정상 종료했고, Claude Code는 그 `terminalSequence`를 읽었다. 같은 때 ouroboros 플러그인의 Python 훅이 상태 49로 실패했지만, 위 표처럼 이 실패는 원인이 아니었다. 정리하면 **Claude Code 전체 화면 모드는 화면을 그리기 전(시작 직후)과 화면을 닫은 뒤(종료 직후)에 나온 `terminalSequence`를 터미널에 쓰지 않는다.** 작업 중 이벤트는 화면이 뜬 뒤라 영향이 없다. 이 PC의 사용자 설정은 `"tui": "fullscreen"`이다.

## 고친 내용

- **훅:** 관리 Claude 훅이 `SessionStart`를 터미널 신호와 함께 실행부의 로컬 파이프(`MONGLE_AGENT_PIPE`, PowerShell 터미널에만 있음)로도 보낸다. 보내는 값은 터미널 신호와 같다(셸 토큰, 대화 UUID, 폴더, 시작 종류). 메시지 버전 2로 보내서, 버전 1만 아는 이전 몽글은 이 줄을 무시한다. 파이프가 없거나 실행부가 응답하지 않아도 훅은 0.8초 안에 끝나 Claude를 붙잡지 않는다.
- **실행부:** 이 신호로는 대화 기록(앱 업데이트 뒤 이어 하기용)과 "준비됨"만 켠다. 작업 상태는 계속 터미널 신호로만 판단한다. 파이프 신호는 터미널 출력과 순서가 보장되지 않는다. 그래서 마지막 입력 뒤 셸 프롬프트가 다시 나온 터미널에서는 받지 않는다. Claude가 끝난 뒤 늦게 온 신호 때문에 메시지가 셸 명령으로 들어가는 일을 막는다. 실행부가 재개 줄을 입력한 것도 입력으로 친다. PowerShell이 아닌 셸에서는 받지 않는다.
- **파이프:** Codex 연동이 설치됐을 때뿐 아니라 Claude 연동만 준비됐을 때도 만든다. Codex PowerShell 래퍼는 지금처럼 Codex 연동이 설치됐을 때만 붙인다.
- **화면:** "Claude Code는 첫 요청을 보낸 뒤 준비될 수 있습니다" 안내를 뺐다.

## 검증

- `npm.cmd run typecheck`, `npm.cmd run build` 통과.
- `tests/host/claude-start.test.ts` 1/1(신규): 실제 훅 스크립트, 파이프, HostCore와 가짜 PowerShell을 이었다.
  - 셸 프롬프트가 나온 뒤 온 신호는 무시한다.
  - 입력 뒤 온 신호로 준비됨이 켜진다. 도구는 Claude로, 작업 상태는 비어 있는 채로 남고, 대화가 기록된다.
  - 첫 요청 없이 메시지가 붙여넣기로 전달된다.
  - 셸 프롬프트로 돌아오면 준비됨이 꺼지고, 다시 온 신호는 무시한다. 명령 프롬프트에서는 받지 않는다.
  - 프롬프트 조건을 빼면 이 시험이 실패하는 것을 확인했다.
- `tests/host/claude-integration.test.ts`(1개 추가): 훅이 기본 대화의 `SessionStart`만 몽글 파이프로 보내고, 다른 이벤트·하위 에이전트·몽글 이외의 파이프에는 보내지 않는다. 응답 없는 실행부와 없는 파이프에서도 2초 안에 끝나고 터미널 신호는 그대로 쓴다.
- `tests/host/codex-integration.test.ts`(1개 추가, 1개 보강): 버전 2 Claude 시작만 받고 Codex 실행 추적에는 넣지 않는다. Claude 연동만 있을 때 셸에 파이프는 넘기고 Codex 래퍼는 붙이지 않는다.
- **실제 조건 확인:** 실제 PowerShell, 이 브랜치의 실행부 코드와 파이프, 사용자 설정 그대로인 Claude Code 2.1.300(전체 화면)으로 확인했다. 격리 데이터 폴더를 썼고 모델 요청은 없었다.
  - 설치된 훅만으로는 20초 동안 준비됨이 켜지지 않았고, 메시지는 `AGENT_NOT_RUNNING`으로 거절됐다.
  - 새 훅을 `--settings`로 더하면 Claude를 실행하고 0.7초 뒤 준비됨이 켜졌다. 메시지는 방해 금지를 켠 상태라 접수만 되고 보류됐고, 이를 취소했다.
  - `/exit`로 셸에 돌아오자 준비됨이 꺼지고 대화 기록이 지워졌다. 남은 Claude 프로세스는 없었다.
- 전체 회귀(샌드박스 밖, `MONGLE_DATA_DIR`은 %TEMP% 아래 격리 폴더): 724개 중 703 통과, 1 실패, 20 생략. 실패한 1개는 이 PC의 PowerShell 실행 정책이 막는 기존 배포 스크립트 시험(`release publisher checks all deliverables and rejects tampering before contacting GitHub`)이다. 회귀가 덮어쓴 `artifacts/ui` 스크린샷은 되돌렸다.

## 확인하지 않은 범위

- 실제 Electron 앱에서는 확인하지 않았다. 개발 빌드가 Claude 연동을 설치하면 사용자 Claude 설정(`settings.json`)의 훅 실행 파일 경로를 바꾸기 때문이다. 개발 빌드의 Node가 설치본과 다르다. 앱을 업데이트하면 실행부가 시작할 때 훅 스크립트를 새로 쓴다.
- 전체 화면이 아닌 모드에서는 터미널 신호와 파이프 신호가 모두 온다. 같은 대화는 한 번만 기록되고 준비됨도 한 번만 켜지는데, 이것은 코드로만 확인했다.
- 구성원 CLI를 여러 개 동시에 띄우는 팀 시작에서 준비 시간은 재지 않았다.
