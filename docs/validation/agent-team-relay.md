# AI 팀 구성원끼리 메시지와 팀 화면 크기 조절

2026-10-15, Windows x64. **미배포.** [설계안](../08-agent-team-design.md) 3단계의 몽글 MCP와, [AI 팀 화면](agent-teams-ui.md)의 크기 조절이다.

## 왜 만들었나

사용자가 팀장에게 일을 보내면, 팀장은 화면에 "개발에게 맡긴다"고 쓰고 멈췄다. 구성원도 일을 마치면 답변 첫 줄에 "보고 대상: 검토"라고 적을 뿐이었다. 0.3.24의 역할 지시문은 "아직 구성원에게 직접 보내는 도구는 없습니다. 사용자가 몽글 화면에서 전달합니다"라고 안내했다. 그래서 사용자는 보고 대상이 화면에 나와도 실제로 보내지지 않는다고 느꼈다. 이번 변경으로 구성원이 스스로 맡기고 보고하며, 몽글이 그 메시지를 받는 사람의 터미널에 넣는다. 사용자는 팀 화면의 칸 크기도 바꾸고 싶어 했다. 팀장 칸과 구성원 칸이 고정 비율이었다.

## 동작

- **중계 붙이기:** 팀을 시작하거나 구성원 대화를 이어 갈 때 실행부가 팀 폴더에 세 파일을 쓴다. 공용 중계 스크립트(`agent-teams/mongle-team-relay.cjs`), 구성원 키 파일(`<구성원>.relay.json`: 실행부 파이프 이름과 64자리 키), CLI용 MCP 설정이다.
  - Claude Code: `<구성원>.mcp.json`을 `--mcp-config`로 넘기고, `--allowedTools 'mcp__mongle_team'`으로 이 서버의 도구만 묻지 않고 쓰게 한다.
  - Codex: `<구성원>.mcp.toml`을 `-c ('mcp_servers.mongle_team=' + [IO.File]::ReadAllText(...))`로 넘긴다. 이 값은 TOML 리터럴 문자열만 써서 큰따옴표와 백슬래시 이스케이프가 없다. `default_tools_approval_mode = 'approve'`로 승인 없이 부르게 해, `-a never`인 읽기 전용 구성원도 보고할 수 있다.
  - 사용자의 `~/.claude`·`~/.codex` 설정 파일은 고치지 않는다. 중계 스크립트는 실행부의 node 런타임(`process.execPath`)으로 실행된다.
- **중계 스크립트:** stdio MCP 서버다. 도구는 `list_agents`(읽기 전용 표시)와 `send_message(to, text)` 두 개다. 부를 때마다 키 파일을 읽고 실행부 파이프에 `{v:3, key, op, ...}` 한 줄을 보낸 뒤 한 줄 답을 받는다. 그 밖의 파일·네트워크·모델 요청은 하지 않는다. 키 파일이 깨졌거나 실행부가 응답하지 않으면 이유를 도구 오류로 돌려준다.
- **파이프:** 메시지 v3만 답을 받는다. 키·요청 형식(`list`, 또는 `send`와 이름 200자·본문 8000자 이하)이 맞을 때만 실행부에 넘기고, 아니면 답 없이 끊는다. 훅 메시지(v1·v2)는 이전처럼 한 방향이고 4096자 제한을 그대로 둔다.
- **실행부:** 키로 보낸 구성원을 정한다. 키는 구성원마다 실행부를 켤 때 새로 만들고, 팀을 해제하면 지운다. 따라서 이전 실행의 키와 다른 구성원의 이름으로는 보낼 수 없다.
  - `list_agents`: 팀 이름과 구성원마다 역할, 팀장 여부, 도구·모델, 읽기 전용, 지금 상태(일하는 중·쉬는 중·사용자 확인 대기·시작하는 중·CLI 꺼짐·터미널 닫힘), 받을 메시지 수, 보고 대상을 돌려준다.
  - `send_message`: 받는 사람은 구성원 이름(대소문자 무시) 또는 "사용자"다. 자기 자신, 없는 이름, 빈 내용(제어 문자를 지운 뒤), 4000자 초과, 닫힌 터미널, 꺼진 CLI, 가득 찬 보류함(10개)은 이유와 함께 거절한다. 아직 시작 중인 CLI에는 보낼 수 있어서, 팀을 막 시작했을 때 팀장이 일을 맡겨도 받는 쪽이 준비되면 들어간다.
  - 받는 사람의 보류함에 `[몽글 팀 메시지] 보낸 구성원 → 받는 구성원` 머리글로 넣는다. 전달 조건(하던 일 끝남, 사람 입력 없음, 방해 금지 아님)과 기록은 사용자 메시지와 같다. 사용자에게 보낸 보고는 보류함을 거치지 않고 팀 대화에 **보고**로 남는다.
- **역할 지시문:** 중계가 있는 구성원에게 도구 쓰는 법을 알린다. 팀장에게는 일을 나눠 `send_message`로 맡기고 차례를 끝내고 기다리라고 한다. 모든 구성원에게는 끝나면 반드시 `send_message`로 보고 대상에게 보고하라고 한다. 중계를 붙일 수 없으면(실행부 파이프가 없거나 경로에 작은따옴표가 있음) 이전 안내를 쓴다. 이전에 시작한 팀은 구성원 대화를 이어 갈 때 역할 지시문 파일을 새로 써서 도구를 안내한다.
- **팀 대화:** 구성원끼리 주고받은 메시지가 `설계 → 개발`처럼 보이고, 사용자에게 보낸 보고는 `검토 → 나`와 **보고**로 보인다.
- **크기 조절:** 팀장 칸 오른쪽(좁은 창에서는 아래) 손잡이로 팀장 칸 비율을 25~80% 사이에서 바꾼다. 구성원 칸 사이 손잡이로 이웃한 두 칸을 각 15% 이상 남기고 나눈다. 화살표 키는 5%씩 바꾸고, Home이나 두 번 클릭은 처음 크기(팀장 63%, 구성원 반반)로 돌린다. 크기는 팀마다 앱의 `localStorage`에 남고, 구성원 수가 달라진 팀은 구성원 칸을 같은 크기로 다시 시작한다.

## 실제 앱 확인 (2026-10-15, 아스트라)

저장소 규칙에 따라 아스트라(`gpt-6-astra`)가 실제 Electron 창을 컴퓨터 유즈로 조작했다.

- **대상과 환경:** PR #96의 `9d6f583`(병합 결과와 같은 트리)을 %TEMP%에 복사해 빌드했다. `MONGLE_DATA_DIR`과 `MONGLE_CLAUDE_CONFIG_DIR`을 같은 %TEMP% 폴더 아래로 지정했다. 데이터만 격리하면 실행부가 Claude·Codex 연동을 꺼서 파이프와 중계가 붙지 않는다. 격리된 Claude 설정 폴더를 따로 주면 실행부는 그 폴더에만 훅을 설치하고 파이프를 연다. 구성원 Claude는 사용자의 `~/.claude`를 그대로 읽는다. 이미 신뢰된 시험 저장소(`.test-data\agent-team-probe\work`)를 썼고, Claude Code는 2.1.300이었다.
- **결과:** 다섯 시나리오가 모두 통과했다.

  | 시나리오 | 결과 |
  |---|---|
  | 팀 시작 창 | 기본 3인 템플릿을 세 명 모두 Claude `haiku`로 구성했다. 모델 선택 상자의 목록(도구 기본값·fable·opus·sonnet·haiku·직접 입력…), 직접 입력 전환과 목록 복귀가 동작했다. |

  | 정리 | 세 CLI를 `/exit`로 끝내고 앱의 정상 종료로 격리 실행부를 껐다. 설치된 몽글 프로세스(10개, 후손 포함 44개)의 PID, 사용자 `.claude/settings.json`·`.codex/hooks.json`, Tailscale Serve 출력의 해시, 시험 저장소의 상태와 파일 해시가 전후 같았다. |

- **모델 요청:** 사람이 보낸 요청은 4회(아래 준비 요청 3회, 과제 1회)였다. 중계로 시작된 차례 3회를 더해 응답 차례는 모두 7회였고, Codex 요청은 없었다.
- **시작 대기(시험 환경 사정):** 팀을 시작하자 세 CLI가 화면에는 떴지만 "준비되기를 기다리는 중"이 풀리지 않았다. 원인은 사용자 `~/.claude`의 몽글 훅이었다. 이 PC에 설치된 몽글이 0.3.20이라서 훅 파일(2026-10-10)에 0.3.24의 "시작 신호를 파이프로도 보내기"가 없었다. 사용자 설정은 Claude 전체 화면 모드다. [Claude 전체 화면 모드의 시작 신호](claude-fullscreen-start.md)와 같은 조건이다. 사용자 설정을 바꾸지 않고, 세 터미널에 "'준비'라고만 답하라"는 첫 요청을 한 번씩 보내 준비 상태로 만들었다. 0.3.24 이상을 설치해 실행부가 훅을 새로 쓴 PC에서는 생기지 않아야 한다. 이번에는 이 경우를 확인하지 않았다.
- **찾아서 고친 것 두 가지:**
  - 모델이 받은 메시지를 흉내 내 `send_message` 본문 앞에 `[몽글 팀 메시지] 설계 → 개발`을 직접 써서, 받는 쪽에 머리글이 두 번 보였다. 실행부가 본문 맨 앞에 붙은 머리글(라벨과, 그 뒤에 이어지는 구성원·사용자 이름 두 개의 경로)을 지우게 했다. 역할 지시문에는 "머리글은 몽글이 붙이니 쓰지 마세요"를 넣었다. 본문 중간의 같은 글자와, 이름으로 시작하기만 하는 낱말(`나중에`)은 그대로 둔다.
  - 손잡이를 두 번 눌러 크기를 초기화하면 옆 글자가 선택됐다. 두 번째 누름의 기본 동작(낱말 선택)을 막았다. Aside 미리보기에서 수정 전에는 두 번 클릭 뒤 선택이 생겼고, 수정 뒤에는 두 손잡이 모두 선택이 비어 있으며 크기는 63%·50%로 돌아갔다.
- 증거(스크린샷과 접근성 기록, 전후 비교)는 커밋하지 않는 `test-results/agent-team-relay-live/`에 있다.

## 확인하지 못한 범위

- 실제 앱 확인은 Claude 구성원 세 명, Claude auto 모드, 한 번의 과제로 했다. Codex 구성원의 대화형 실행에서 중계를 부르는 것은 `codex exec`로만 확인했다. 팀별 크기 저장 분리, 앱을 다시 켠 뒤 크기 복원, 정확한 1180px 경계, 실제 앱에서의 브랜치 맞추기는 확인하지 않았다. 두 가지 수정은 단위·호스트 시험과 Aside 미리보기로 확인했고 실제 앱에서 다시 확인하지 않았다.
- 모델이 역할 지시문대로 일을 나누고 빠짐없이 보고하는지는 모델에 달려 있다. 보고하지 않을 때 알려 주는 보고 누락 알림은 아직 없다.
- **발견한 기존 문제:** Windows PowerShell 5.1은 큰따옴표가 든 인자를 네이티브 명령에 넘길 때 바깥 따옴표를 잃는다. 시험용 인자 `developer_instructions="첫 줄 \"인용\" 둘째"`가 5.1에서는 따옴표가 빠진 채 전달됐다. PowerShell 7은 정확했다. 0.3.24부터 Codex 구성원의 역할 지시문 옵션이 이런 값을 쓰므로, PowerShell 7이 없어 5.1로 구성원을 여는 PC에서는 Codex 역할 지시문이 깨질 수 있다. 몽글은 PowerShell 7을 먼저 고르고 이 PC에는 7.6.6이 있어 드러나지 않았다. 이번 중계 설정은 큰따옴표를 쓰지 않아 영향이 없다. 고치는 일은 따로 한다.
