# 몽글터미널 — 요구사항과 사용 흐름

작성일: 2026-09-29 · 상태: 구현 전 설계안 v0.1

## 1. 제품의 목적

각자의 컴퓨터에서 PowerShell 같은 셸을 여러 개 실행하고, 그룹과 분할 화면으로 정리하며, 다른 PC와 휴대폰에서 실행 중인 같은 터미널에 다시 연결한다. 사용자는 터미널 안에서 필요한 프로그램을 직접 실행한다.

앱 창은 작업을 보여주는 화면이다. 셸과 실행 중인 프로그램의 생명주기는 별도의 호스트 프로세스가 관리한다. '세션 유지'와 '재부팅 후 환경 복원'을 제품 문구와 실제 동작 모두에서 구분한다.

## 3. 첫 버전 범위

### 포함

- 로컬 셸 프로필 탐지: 설치된 PowerShell 7을 우선 제안하고 Windows PowerShell·CMD를 제공. WSL 배포판·Git Bash는 실제 설치된 경우만 표시.
- 그룹 생성·이름 변경·순서 변경·삭제. 그룹별 기본 작업 폴더와 셸 프로필.
- 터미널 생성·이름 변경·종료·이력 확인, 재귀적 좌우/상하 분할, 크기 변경, 자리 교환, 최대화.
- 그룹과 배치의 자동 저장, 저장된 출력의 제한된 복원, 실행 중인 세션 재연결.
- 호스트 등록·전환·연결 상태 표시, Tailscale을 통한 승인된 기기의 원격 접속.
- 모바일의 한 패널 보기, 터미널 전환, 한글 입력, 보조 키, 복사/붙여넣기, 재접속.
- 기본 검색·글꼴 크기·테마·단축키 설정, 연결 진단, 기기 승인/해제.

### 후속 범위

AI 에이전트 상태 추정, 채팅 UI, 자체 LLM/API, Git/코드 편집기, 파일 탐색기·파일 전송·포트 포워딩, 브라우저 패널, 다중 사용자 공동 편집, 자체 릴레이, 앱스토어 모바일 앱, 커스텀 플러그인, 무중단 호스트 업데이트, 운영체제 재부팅을 넘는 프로세스 체크포인트는 첫 버전의 필수 기능이 아니다.

## 4. 화면 구조

```text
┌ 몽글터미널 ─────────────────────────────────────────┐
│ [이 PC ▾]         │ 그룹명                 [+ 터미널] │
│ ● 연결됨          ├─────────────────┬───────────────┤
│ + 그룹            │ PowerShell      │ WSL           │
│ ● 프로젝트 A      │                 ├───────────────┤
│   터미널 3        │                 │ CMD           │
│   프로젝트 B      │                 │               │
│   서버 로그       ├─────────────────┴───────────────┤
│ 설정              │ 호스트 · 작업 폴더 · 제어 상태    │
└───────────────────┴─────────────────────────────────┘
```

GPT 데스크톱 앱에서 참고하는 것은 간결한 사이드바, 분명한 선택 상태, 넓은 작업 영역이다. 상표·아이콘·고유 화면을 복제하지 않는다. 첫 버전은 **호스트 → 그룹 → 패널**의 3단계이며 그룹 안의 별도 탭 계층은 추가하지 않는다.

컴퓨터 선택기는 왼쪽 사이드바 상단에 둔다. '이 PC·집 PC·회사 PC'처럼 등록한 호스트를 선택하면 아래 그룹 목록과 오른쪽 터미널이 해당 컴퓨터의 작업으로 전환된다. 접속 대상은 몽글 호스트가 생성·관리하는 세션이며, 이미 실행 중이면 같은 프로세스에 다시 연결한다. 별도로 열어 둔 일반 PowerShell/CMD 창을 자동으로 가져오지는 않는다. 원격 대상 PC와 몽글 호스트·Tailscale이 실행 중이고 기기 승인이 유효해야 한다. 이 배치와 접속 범위는 2026-09-29 사용자 확정 사항이다.

시각 수치는 제안값이다: 사이드바 기본 240px(180–360px 조절), 패널 제목줄 32px, 터치 대상 최소 44px, 본문 UI 13–14px, 터미널 글꼴 기본 14px. 색·간격·모서리·글꼴은 토큰으로 관리하며 어두운/밝은 테마 모두 선택·초점·연결 끊김을 구별한다. 상태는 색 외에 텍스트와 아이콘으로도 표현한다. 최종 시각 디자인은 구현 전 화면 시안으로 확인한다.

## 5. 분할 및 그룹 동작

| 동작 | 규칙 |
|---|---|
| 분할 | 선택 패널을 좌우 또는 상하 두 자식으로 나눈다. 기본 비율 50:50 |
| 새 셸 | 같은 호스트·같은 셸 프로필, 신뢰할 수 있는 현재 작업 폴더를 상속 |
| 폴더를 모를 때 | 마지막 확인 폴더, 없으면 시작 폴더 사용. 실행 중인 프로세스의 폴더를 추측하지 않음 |
| 크기 | 경계 드래그, 더블클릭으로 해당 두 영역 균등 분할 |
| 이동 | 제목줄 드래그로 두 패널의 위치 교환. 그룹 간 이동은 메뉴로 제공 |
| 최대화 | 선택 패널만 크게 표시. 원본 분할 트리는 보존하고 복귀 가능 |
| 닫기 | '터미널 종료'로 명명. 살아 있는 세션은 종료 확인 후 처리, 이웃이 빈 공간을 채움 |
| 그룹 전환 | 화면만 변경. 숨겨진 터미널도 계속 실행하고 호스트가 출력 수집 |
| 그룹 삭제 | 실행 중인 세션 수를 표시하고 그룹의 세션까지 종료하는지 명확히 확인 |
| 마지막 패널 | 빈 그룹 안내와 새 터미널 버튼을 표시. 자동으로 새 프로세스를 만들지 않음 |

레이아웃은 분할 트리로 저장한다. 고정 열/행 격자만으로 저장하면 비대칭 분할을 표현하기 어렵다. 최소 영역 미만으로 줄어들면 억지로 추가 분할하지 않고 최대화·패널 전환을 안내한다. 빠른 배치(2분할, 4분할, 큰 창+작은 창 둘)는 현재 세션을 재배치하고 부족한 셸만 만든다. 자주 바꾸는 비율·선택·그룹 순서는 자동 저장한다.

기본 제한 제안은 그룹당 16개 패널, 호스트당 32개 실행 세션이다. 출시 전 메모리·반응성 실측에 따라 조정한다. 이는 구현 안전장치이지 확인된 성능 수치가 아니다.

## 6. 세션 유지의 정확한 계약

| 사건 | 프로세스 | 화면/저장 상태 | 다음 사용자 경험 |
|---|---|---|---|
| 그룹 전환/패널 최대화 | 유지 | 유지 | 즉시 전환 |
| 창 닫기/GUI 프로세스 종료 | 별도 호스트가 살아 있으면 유지 | 호스트에서 계속 갱신 | 실행 중인 세션에 붙음 |
| Wi-Fi↔모바일 전환/브라우저 백그라운드 | 대상 호스트에서 유지 | 클라이언트는 오래된 상태 표시 | 인증·세션 확인 후 재동기화 |
| PC 잠금 | 사용자 세션/호스트가 살아 있으면 유지 | 유지 | 잠금과 로그아웃을 구분 |
| 절전 | 실행과 네트워크 일시 중단 가능 | 마지막 상태 | 깨어난 뒤 재접속, 계속 실행했다고 표시하지 않음 |
| Windows 로그아웃/호스트 크래시 | 유지 보장 불가 | 마지막 저장본까지 | '실행 종료/중단됨' 표시 |
| 재부팅/전원 종료 | 기존 프로세스 유지 불가 | 그룹·배치·시작 폴더·저장된 출력 | 기록 확인 후 사용자가 새 셸 열기 |
| 터미널 종료/호스트 전체 종료 | 명시적으로 종료 | 정책에 따라 기록 보관 | 자동으로 재실행하지 않음 |

'앱 종료'라는 모호한 메뉴 대신 '창 닫기(작업 유지)'와 '모든 작업 종료'를 구분한다. 로그인 시 호스트 시작은 선택 설정이다. 무인 부팅 직후·사용자 로그인 전 실행은 v1 보장 범위가 아니다. 셸에서 별도로 분리해 실행한 OS 프로세스까지 모두 종료된다고 보장하지 않는다.

## 7. 모바일 사용 흐름

1. 휴대폰에 Tailscale을 설치·연결한 뒤 승인된 호스트의 HTTPS 주소를 연다.
2. PC에서 생성한 일회용 기기 연결 코드를 입력하고 기기 승인을 완료한다.
3. 그룹을 선택하고 터미널 한 개를 크게 본다. 패널 목록에서 전환한다.
4. 기본 관찰 상태에서 '여기서 제어'를 누르면 해당 터미널의 입력·크기 제어권을 얻는다.
5. 화면을 껐다 돌아오면 연결 상태를 확인하고 출력부터 동기화한다. 끊긴 동안 입력한 키를 자동 재전송하지 않는다.

모바일은 PC 분할 트리를 변경하지 않는다. 관찰 중에는 호스트의 현재 셀 크기를 유지하고 가로 스크롤/확대 또는 '화면에 맞추기'를 제공한다. 모바일이 제어권을 가져가면 활성 패널만 새 행·열 크기로 바뀔 수 있고 PC 관찰 화면에는 제어 기기를 표시한다. 제어권을 돌려받은 PC가 자신의 크기로 다시 조절한다. 숨겨진 패널이나 단순 창 크기 변화가 PTY를 반복 resize하지 않도록 한다.

보조 키는 Esc, Tab, Ctrl, Alt, 방향키, Ctrl+C를 제공한다. Ctrl/Alt 고정 여부를 명시하고 패널 전환 시 해제한다. 모바일 가상키보드가 열려도 입력 위치와 하단 버튼이 가려지지 않게 visual viewport를 사용한다. 한글 조합 중 Enter는 조합 확정과 명령 제출을 구분한다. 자동 교정·스마트 따옴표·자동 대문자화를 터미널 입력에 적용하지 않는다.

## 8. 입력·클립보드·접근성

- Ctrl+C는 선택 유무와 관계없이 기본적으로 터미널의 중단 입력이다. 데스크톱 복사는 Ctrl+Shift+C, 붙여넣기는 Ctrl+Shift+V를 기본 제안으로 한다.
- 앱 명령 단축키는 재설정 가능하게 하고 브라우저·한글 IME·셸 단축키와의 충돌을 실기 검증한다. 모바일/웹의 필수 기능은 키보드 없이 버튼으로 수행 가능해야 한다.
- 붙여넣기는 bracketed paste 모드를 존중한다. 여러 줄 입력은 줄바꿈/제어문자를 확인할 수 있는 UI를 제공하며 숨겨진 키 자동 삽입을 하지 않는다.
- 출력에 포함된 링크는 사용자가 누를 때만 허용된 http/https URL을 연다. 터미널 출력으로 앱 명령·외부 프로그램을 자동 실행하지 않는다.
- 출력 기반 클립보드 쓰기(OSC 52)는 기본 비활성화하고, 필요 시 명시적인 동작으로 허용한다.
- 패널 제목·그룹명은 일반 텍스트로 처리한다. 키보드만으로 그룹/패널 전환·분할·크기 조절 메뉴에 접근하고 초점이 보이게 한다.

## 9. 중요한 실패 화면

| 상황 | 표시/행동 |
|---|---|
| 호스트 꺼짐/절전 | 마지막 연결 시각과 재시도. 로컬 PC에 새 셸을 대신 만들지 않음 |
| Tailscale 미연결 | 네트워크 연결 안내. 인터넷 연결 오류와 구분 |
| 세션 프로세스 종료 | 종료 코드와 기록 표시, '새 셸 열기' |
| 원격 권한 해제 | 즉시 입력 중지·연결 종료, 재승인 안내 |
| 입력 전달 결과 불명 | '마지막 입력의 전달 여부를 확인할 수 없음'. 실행 결과 확인 전 재전송 안 함 |
| 앱/호스트 버전 불일치 | 업데이트 필요 안내. 실행 중 호스트를 강제 재시작하지 않음 |
| 폴더·셸 삭제됨 | 해당 프로필 오류 표시, 다른 폴더/셸을 사용자가 선택 |
| 저장 공간 부족 | 라이브 세션은 유지 시도, 기록 저장 중단 상태와 정리 동작 제공 |
