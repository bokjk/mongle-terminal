# AI 팀 흐름과 Codex 첫 메시지, 남은 팀 해제

2026-10-16, Windows x64. **0.3.26 배포 준비.** 배포 검사는 [0.3.26 배포 검증](public-release-0.3.26.md)에 기록한다. 사용자가 0.3.25를 다른 PC와 이 PC에서 시험하며 알려 온 세 문제를 고쳤다. [구성원끼리 메시지](agent-team-relay.md)와 [에이전트에게 메시지 보내기](agent-messages.md)의 후속이다.

## 사용자가 알려 온 문제

1. **Codex 검토가 일을 받지 못함(이 PC):** 팀장·개발은 Claude, 검토는 Codex인 팀에서 개발이 검토에게 보낸 메시지가 팀 대화에 "에이전트가 다시 실행되기를 기다리는 중"으로 남고 검토 터미널에 들어가지 않았다.
2. **검토를 건너뜀(다른 PC):** 같은 구성에서 일 흐름은 `개발 → 검토`였는데 개발이 설계(팀장)에게 보고했고, 검토는 일을 받지 못했다.
3. **팀을 지울 수 없음(다른 PC):** 팀에 연결된 프로젝트(그룹)를 지우자 팀 화면이 열리지 않아, 팀 화면 안에만 있던 **팀 해제…**를 쓸 수 없었다.

## 원인

### Codex는 첫 요청 전에는 시작 훅을 실행하지 않는다

몽글은 Claude·Codex 연동 훅이 "이 셸에서 실행 중"이라고 알려야 메시지를 넣는다. Codex는 `SessionStart` 훅이 그 신호다. 이 PC에서 확인한 사실은 다음과 같다(모두 읽기만 했다).

- 이 PC의 설치본은 0.3.25, Codex CLI는 0.163.0이다. `~/.codex/hooks.json`의 몽글 훅 8개는 `config.toml`의 `[hooks.state]`에 신뢰됨으로 기록되어 있다. 훅 신뢰 확인 미완료는 원인이 아니다.
- 팀 폴더의 검토 실행 설정(`*.mcp.toml`, 역할 지시문)은 `codex -c ... -c ... mcp list`에서 오류 없이 읽혔다.
- PowerShell 입력 기록에는 몽글이 넣은 검토 실행줄(`codex -m 'gpt-6-astra' -c (팀 도구) -c (역할 지시문) -s read-only -a never`) 다음에 `codex`가 한 번 더 있었다. 실행 중인 검토 Codex의 명령줄은 `codex.exe --no-daemon`뿐이었다. 처음 실행된 Codex를 끝내고 다시 띄운 것으로 보인다.

시험용 이름 있는 파이프를 띄우고 몽글 터미널과 같은 환경 변수(셸 토큰, 실행 표식)로 Codex 0.163.0을 실행해, 몽글 훅이 언제 신호를 보내는지 기록했다(`test-results/team-orphan/codex-start-probe.cjs`, 작업 폴더 `.test-data/agent-team-probe/work`).

| 실행 | 결과 |
|---|---|
| `codex --no-daemon`, 요청 없음, 30초 | 입력창(`› Ask Codex to do anything`, `? for shortcuts`)을 그렸고 꺼지지 않음. 훅 신호 0개 |
| 팀 실행 옵션(역할 지시문, 읽기 전용, `-a never`), 요청 없음 | 같음. 꺼지지 않고 신호 0개 |
| 이 PC 팀의 실제 검토 역할 지시문, `gpt-6-astra`, 팀 도구 자리에 시험용 MCP 서버, 요청 없음 | 같음. 꺼지지 않고 신호 0개 |
| `gpt-6-luna`, 입력창이 보이고 1.5초 뒤 "ready" 한 단어 요청(모델 요청 1회) | `SessionStart`(source `startup`) 4.9초, `UserPromptSubmit` 5.6초, `Stop` 12.9초. 아직 불러오는 중에 넣은 요청은 "Queued follow-up inputs"로 대기했다가 처리됨 |

Codex는 첫 요청이 들어와야 대화를 시작하고 그때 `SessionStart`를 실행한다. 그래서 몽글은 첫 요청을 받지 않은 Codex 구성원을 끝까지 "실행 중"으로 보지 않았고, 개발이 보낸 메시지는 보류함에서 기다렸다. 몽글 팀 도구나 실행 옵션 오류는 아니다. 0.3.25 실기 확인은 Claude 구성원 세 명으로만 했기 때문에 이 경우를 보지 못했다.

### 팀장의 "나에게 보고"가 일 흐름을 이김

역할 지시문은 구성원에게 "끝나면 보고 대상에게 보고"라고 알렸지만, 팀장이 일을 맡기며 "끝나면 나에게 보고해"라고 쓰면 그 말을 막는 문구가 없었다. 팀장 지시문에는 일 흐름의 단계를 다 거쳤는지 확인하라는 말도 없었다. 사용자가 다른 PC에서 본 일 흐름은 `개발 → 검토`였으므로 보고 대상 설정은 맞았다.

### 그룹 삭제가 팀을 남김

`groups.delete`는 그룹과 터미널만 지우고 그 그룹의 팀 기록을 남겼다. 팀 화면은 팀의 그룹이 있어야 열리고, **팀 해제…**는 팀 화면 맨 아래 줄 메뉴에만 있었다.

## 동작

- **Codex 첫 메시지:** PowerShell `codex` 감싸기가 대화형 실행(`--no-daemon`을 붙이는 경우)마다 셸 토큰이 붙은 표식 `OSC 777 mongle-codex;<토큰>`을 낸다. 엔진은 표식이 온 순간 화면에 있던 `? for shortcuts` 개수를 기억하고, 그보다 많아졌을 때 훅 신뢰 창과 승인 창이 없으면 한 번만 "입력창 준비"를 알린다. 앞서 실행한 Codex의 글자가 화면에 남아 있어도 준비로 보지 않는다. 실행부는 셸 프롬프트로 돌아오지 않은 PowerShell에서만 이를 받아 보류함을 화면 확인 상태로 연다. 보류함은 이 상태에서 메시지를 **하나만** 보내고, 그 뒤에는 훅(`SessionStart` 등)이 오기 전까지 다시 "준비되기를 기다리는 중"으로 둔다. 시작 직후 1.5초 대기, 입력 중·작업 중·확인 요청·방해 금지 보류, 붙여넣기와 Enter를 나눠 쓰는 방식은 그대로다. 셸 프롬프트 표식이 오면 모두 초기화된다. 감싸기를 거치지 않은 Codex(전체 경로 실행, `codex exec` 등)는 표식이 없어 이전처럼 훅을 기다린다.
- **일 흐름:** 팀장 지시문에 "결과를 누구에게 보내라고는 적지 마세요"와 "사용자에게 끝났다고 알리기 전에 일 흐름의 단계를 모두 거쳤는지 확인하고, 건너뛴 결과는 다음 구성원에게 넘기세요"를 넣었다. 구성원 지시문에는 "맡긴 구성원이 자기에게 보고하라고 해도 결과는 일 흐름대로 보냅니다. 사용자가 직접 다르게 지시했을 때만 그 지시를 따릅니다"를 넣었다. 구성원이 다른 구성원에게 받은 일(팀장 앞으로 온 것 제외) 끝에는 `[몽글 안내] 이 일을 마치면 결과를 send_message로 <다음 차례>에게 보내세요. 일 흐름에 정해진 다음 차례입니다.`가 붙는다. 모델이 이 줄을 베껴 보내면 다음 받는 사람에게는 빠진다. 팀장이 아닌 구성원이 다음 차례가 아닌 사람에게 보내면 도구 답 끝에 다음 차례를 알린다.
- **보내지 못한 메시지:** 구성원이 보낸 메시지가 받는 사람의 터미널이 닫혔거나 CLI가 꺼졌거나 보류함이 가득 차 거절되면 팀 대화에 `전달하지 못함 · 이유`로 남고, 보낸 구성원에게는 사용자에게 알리라고 답한다.
- **팀 해제:** 그룹을 삭제하면 그 그룹의 팀도 `teams.remove`와 같은 정리(기록, 중계 키, 팀 폴더)로 지운다. 사이드바 팀 행마다 `···` 메뉴가 있고, 그룹이 없는 팀은 **프로젝트 삭제됨**으로 표시되며 열 수 없지만 메뉴는 늘 보인다. 실행부를 시작할 때 그룹이 없는 팀을 저절로 지우지는 않는다. 팀을 해제할 때 구성원 보류함에 남은 팀 메시지는 취소된다.

- **내 템플릿 지우기:** 실행부에는 `teams.templates.delete`가 있었지만 화면에서 부르는 곳이 없어, 저장한 템플릿을 지울 수 없었다(사용자 질문으로 확인). 팀 시작 창의 내 템플릿 카드에 휴지통 아이콘을 두고, 누르면 카드 안에서 이름과 영향을 적은 확인(취소·지우기)을 보여 준다. 팀 시작 창이 이미 대화 상자라 창을 겹쳐 띄우지 않았다. Mobbin의 [DoorDash Merchant](https://mobbin.com/screens/0f5d4c54-b24c-4b16-bc08-0a72a86d4b3a)(행마다 휴지통, 이름을 적은 확인), [Gumloop](https://mobbin.com/screens/a2a43ab6-f3b4-4d6c-bd45-28c707ec0e3f)·[Square](https://mobbin.com/screens/d40d1fc9-a486-4a9a-9703-4af0638e3a2a)(취소와 빨간 삭제)를 참고했다. 지운 템플릿이 별표 기본값이면 기본값도 풀고, 이미 고친 구성원 표는 그대로 둔다.

## Electron 최종 확인과 Codex 제출 수정

**아스트라의 실제 Electron 확인(2026-10-16 11:07~11:32, 커밋 `b0e0856`, Codex 연동 켬):** 보고서와 증거는 로컬 증거 폴더 `test-results/agent-team-final-live/`에 있다.

- 시작 전 사용자 Codex 파일 5개의 해시를 확인했다. 실행 파일 2개는 파일 이름의 해시와 같았다. 실행 직후에도 5개 모두 같았다.
- **통과:**
  - 템플릿 지우기: 저장, 휴지통, 카드 안 확인 문구, 취소 시 유지, 지우기, 창을 다시 열어도 없음, 기본 제공 템플릿에는 휴지통 없음.
  - 팀 시작: 세 `pwsh` 모두 `__MongleCodex`와 `mongle-codex` 표식이 있었고, `codex.exe`에는 `--no-daemon`이 붙었다.
  - Codex 첫 요청 전 준비: 사람이 입력하지 않아도 `? for shortcuts`가 보인 뒤 '준비되기를 기다리는 중' 안내가 없었다.
  - 팀장이 "끝나면 너(설계)에게 보고하라"고 맡겼지만, 개발은 검토에게 보냈다.
- **결함:** 개발 → 검토는 '전달됨'으로 표시됐지만 검토 Codex가 제출하지 않았다. 메시지는 입력칸에 남고 커서는 새 줄에 있었다. 사람이 Enter를 한 번 누르자 18초 뒤 검토 → 설계, 23초 뒤 설계 → 나(보고)까지 이어졌다.
- 확인 중 이 PC가 `0x12B`(메모리 페이지 손상) 오류 검사로 재부팅됐다. 아스트라의 종료 뒤 확인에서 런타임 파일 하나가 다른 해시로 읽혔지만, 재부팅 뒤 원래 해시로 읽혔다. 작업 저장소의 `git fsck`는 이상이 없었다.

**원인 조사:** 시험용 파이프로 Codex 0.163.0을 띄우고 같은 348자·7줄 메시지를 몽글처럼 붙여넣었다(`test-results/team-orphan/codex-paste-probe.cjs`, 결과 `paste-*.json`).

| 붙여넣기 시점 | 줄바꿈 | Enter까지 | 결과 |
|---|---|---|---|
| 시작 후 14초(대기 상태) | CR | 150ms | 제출 안 됨(2회 중 2회) |
| 시작 후 14초 | LF | 150ms | 제출 안 됨 |
| 시작 후 14초 | CR | 400ms·800ms | 제출됨 |
| 시작 후 14초 | LF | 800ms | 제출됨 |
| 시작 후 2.5초(MCP 서버 시작 중) | CR | 1.2초 | 제출됐지만 `UserPromptSubmit`이 3번·6번(2회 시험). 줄마다 따로 제출됨 |
| 시작 후 2.5초 | LF | 1.2초 | 제출 1번 |
| 시작 후 8초 | CR | 1.2초 | 제출 1번 |

Windows의 Codex는 붙여넣기를 빠른 키 입력으로 받아 처리한다. 그래서 붙여넣기 직후 150ms 만에 온 Enter를 줄바꿈으로 받는다. 또 아직 시작 중인 Codex는 붙여넣기 안의 CR을 Enter로 받아 메시지를 줄마다 따로 제출한다.

**수정:**

- 보류함은 붙여넣기 뒤 최소 150ms를 기다린다. 그 뒤 터미널 화면이 300ms 동안 바뀌지 않을 때 Enter를 보내고, 화면이 계속 바뀌어도 3초 뒤에는 보낸다. 실행부는 터미널 출력이 올 때마다 시각만 보류함에 알린다.
- 화면으로만 준비를 확인한 Codex에는 화면이 1초 동안 멈춘 뒤 첫 메시지를 넣는다.
- 받는 CLI가 Codex이면 메시지의 줄바꿈을 LF로 바꿔 붙여넣는다. Claude 등 다른 CLI는 이전처럼 CR이다.
- 보류함 시험 3개를 추가했다. 수정 뒤 관련 시험 71개를 통과했다.

**수정 뒤 실행부와 실제 Codex로 확인:** 수정된 실행부 코드, 실제 `pwsh`, Codex 0.163.0으로 위 7줄 메시지 두 개를 연달아 보냈다(`test-results/codex-first-live/run.ts`, 격리 데이터 폴더, `gpt-6-luna` 요청 2회).

## 실제 앱 확인

**아스트라의 실제 Electron 확인(2026-10-16 10:14~10:45, 커밋 `3ff08f1`):** 보고서와 화면 증거는 저장소에 넣지 않은 로컬 증거 폴더 `test-results/agent-team-flow-live/`에 있다.

- 통과: 팀 시작(설계·개발 Claude haiku, 검토 Codex gpt-6-luna 읽기 전용, 일 흐름 표시), 그룹 삭제 확인 창의 팀 이름과 삭제 뒤 팀 사라짐, 팀 화면 밖 사이드바 `···` → **팀 해제…**.
- 일 흐름: 팀장이 "끝나면 나에게 보고해 달라"는 과제를 받았지만 개발은 검토를 건너뛰지 않고 검토에게 보냈다. 개발이 받은 메시지 끝에 `[몽글 안내] 이 일을 마치면 결과를 send_message로 검토에게 보내세요.`가 있는 것을 터미널에서 확인했다. 팀장이 실제로 "나에게"라고 적지 않아 충돌 조건을 완전히 재현했다고 보지는 않는다.
- 개발 → 검토는 첫 실행에서 보류됐다. 시험 앱을 `MONGLE_DATA_DIR`만 지정해 띄워 Codex 연동이 꺼졌기 때문이다(`apps/desktop/runtime.ts`). 그래서 `codex` 감싸기가 없었고 Codex는 `--no-daemon` 없이 실행됐다. 이번 수정을 시험할 조건이 아니었다.
- `MONGLE_CODEX_HOME`을 지정한 두 번째 실행은 사용자 `~/.codex/mongle-terminal-runtime`의 node 실행 파일 두 개의 해시가 달라 보여 팀을 만들기 전에 멈췄다. 이후 확인한 결과는 아래와 같다.
- 결함 후보: 보류 중인 팀 메시지가 있을 때 팀을 해제하면 그 터미널에 **보낼 메시지 1개**가 남았다. 팀 해제·그룹 삭제 때 기다리던 팀 메시지를 취소하도록 고치고 실행부 시험에 넣었다.
- 관련 없는 관찰: 1인 팀 Claude를 `/exit`한 직후 PowerShell `Internal CLR error (0x80131506)`, 연동이 꺼진 시험 앱의 시작 전 점검이 Codex 0.162.0을 표시(실제 실행은 0.163.0).

**내 템플릿 지우기 화면 확인(Aside):** 실제 팀 시작 창 컴포넌트와 스타일에 기록한 실행부 응답을 묶은 미리보기(`test-results/team-scope-preview`, 내 템플릿 1개 추가)를 Aside로 조작했다. 휴지통은 내 템플릿에만 1개 있었다. 누르면 카드가 "‘프론트·백 같이’ 템플릿을 지울까요?"와 설명, 취소·지우기로 바뀌었다. 취소하면 원래대로 4개가 남았고, 지우기를 누르면 기본 제공 3개만 남았으며 구성원 표 3행은 그대로였다. 실제 Electron 앱에서는 확인하지 않았다.

**런타임 해시 차이의 정체:** 바뀐 것으로 보인 두 파일은 크기와 수정 시각이 그대로였다. 다른 내용으로 읽힌 부분은 3바이트와 2바이트였고, 모두 한 비트씩만 달랐다(`0x41→0x51`, `0x3f→0x1f`, `0x0f→0x0d`, `0x54→0xd4`, `0xf9→0x79`). 버퍼를 거치지 않는 복사(`robocopy /J`)로 다시 읽자 두 파일 모두 파일 이름의 원래 해시와 같았다. 이후 일반 읽기도 원래 해시로 돌아왔다. 몽글이나 시험 앱이 파일을 다시 쓴 흔적은 없다. 이 PC의 메모리나 파일 캐시에서 비트가 바뀌어 읽힌 것으로 보이며, 원인은 확인하지 못했다. 이때 연동은 런타임 해시가 맞지 않으면 준비되지 않은 것으로 처리한다.

**실행부와 실제 Codex로 확인(2026-10-16):** Electron 대신 수정된 실행부 코드를 바로 띄우고, 실제 `pwsh`와 Codex 0.163.0으로 확인했다(`test-results/codex-first-live/run.ts`). 데이터 폴더는 `%TEMP%`에 따로 두었고, 연동은 설치된 것으로 두었다. 사용자 `~/.codex`에는 아무것도 쓰지 않았고, 전후 해시가 같았다. 실행부가 구성원 실행줄을 입력하듯 `codex -m gpt-6-luna ... -s read-only -a never`를 넣고 `agent.message.send`로 두 메시지를 보냈다(모델 요청 2회).

시험 스크립트가 Codex를 `Ctrl+C`로 끄는 단계는 셸 프롬프트로 돌아오지 않아 시간 초과로 끝났다. 실행부를 닫자 시험 셸도 정리됐다. Codex 구성원이 끼어 있는 팀이 실제 Electron 창에서 `나 → 설계 → 개발 → 검토 → 설계 → 나`로 이어지는 것은 아직 확인하지 않았다.

## 남은 제약

- Codex 입력창 판단은 Codex 화면의 `? for shortcuts` 글자에 기댄다. Codex가 이 문구를 바꾸거나 칸이 너무 좁아 그리지 않으면 이전처럼 첫 요청을 기다린다. 그때 팀 대화 입력창 아래 안내가 그 터미널에서 Codex에게 요청을 한 번 보내 달라고 알린다.
- 팀장·구성원이 일 흐름 안내를 따르는지는 모델에 달려 있다.
- 다른 PC에서 그룹을 지워 남은 팀은 이 버전을 설치한 뒤 사이드바 메뉴로 지워야 한다. 자동으로 지우지 않는다.
