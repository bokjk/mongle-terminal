# 터미널 탭과 상단 공간 검증

검증일: 2026-10-01 · 소스 버전: 0.3.3 · 작업 브랜치: `codex/terminal-tabs` · **미배포 소스 변경**

## 변경 범위

기존 중첩 드래그 분할을 유지하고 **각 분할 영역 안에 독립된 터미널 탭**을 표시한다. 영역의 +는 그 영역에 새 탭을 추가한다. 탭 전환은 옆 영역의 선택·분할 비율·배치를 바꾸지 않는다. 좌우·상하 분할 버튼과 왼쪽 아래 새 분할은 새 영역을 만든다. 드래그는 해당 영역의 모든 탭을 함께 이동하거나 교환한다. 그룹 전체의 탭/분할 보기 전환은 제공하지 않는다.

PC에서 터미널이 열려 있으면 별도 상단 도구줄을 제거하고 새 분할·파일 탐색기·설정을 왼쪽 아래에 표시한다. 탭과 기존 패널 조작은 32px 제목줄에 모았다. PC 좌우 바깥 여백은 6px다. 모바일의 60px 상단과 기존 패널 전환·화면 넓게·44px 터치 대상은 유지한다.

PC에서 탭 전환·재배치·최대화는 같은 `SplitTree`의 터미널 인스턴스를 유지한다. 숨긴 탭은 표시 크기를 호스트에 전송하지 않으며, 처음부터 숨겨진 탭은 자동으로 제어권을 얻지 않는다. 탭 전환은 선택만 바꾸고 다른 기기의 제어권을 가져오지 않는다. 탭 X·Delete는 기존 종료 확인 절차를 사용한다. 첫 탭을 닫으면 같은 영역의 다른 탭을 대표로 올리고, 마지막 탭을 닫을 때만 영역과 분할을 합친다.

## 저장과 API

`LayoutNode`의 기존 leaf는 유지하며 `tabs?: string[]`에 추가 세션 ID를 표시 순서대로 저장한다. `terminalId`와 `tabs`를 합쳐 그룹 내 모든 터미널이 정확히 한 번 포함되는지 검증한다. 기존 단일 탭 leaf는 변환 없이 읽는다. `terminals.create`에 `tabTarget`을 추가했으며 다른 그룹·삭제된 대상·splitTarget/axis 동시 지정은 거부한다. 기존 그룹당 16개·호스트 전체 한도와 배치 CAS를 유지한다.

호스트가 `layout.tabs` 기능을 알릴 때만 새 탭을 추가한다. 탭 지원 이전 버전은 여러 탭을 담은 배치를 모두 표시할 수 없다. 탭 구성·분할은 호스트 DB에 저장하고, 선택한 탭은 `mongle.tabs.<hostId>.<groupId>`에 각 구성원 ID 기준으로 기억하여 대표 탭이 닫혀도 나머지 영역의 선택을 찾는다. 다른 기기의 선택은 변경하지 않는다.

새 탭 회귀에서 직접 확인한 동작:

1. 1380px PC에서 두 영역을 나란히 표시하고 각 영역에 두 탭을 둔다. 별도 상단 없이 작업 영역이 6px 이내에서 시작하며 제목줄 높이는 32px다. 탭 클릭·방향키·Home·End·Ctrl+Tab·Ctrl+Shift+Tab은 영역 안에서 동작하며 셸에 입력을 보내지 않는다. Ctrl+Shift+T로 영역 내 탭을 만들 때도 셸 입력을 보내지 않는다.
2. 전환·영역 전체 드래그·최대화 전후 같은 xterm DOM·셸 PID·generation·상태·탭 구성. 시험 셸 변수 `TAB_PROOF` 유지와 명령 입력 단일 전달. 전환·재배치 중 attach·detach·제어권 재획득 없음.
3. 그룹·호스트 전환과 새로고침 후 양쪽 영역의 선택을 독립적으로 기억. 다른 기기가 제어하는 터미널의 탭 선택으로 제어권을 가져오지 않는다. 숨긴 이웃의 크기를 변경하지 않는다.
4. +로 해당 영역에 셸 하나만 추가, 추가/분할/닫기 취소 시 유지·닫기 확인 시 해당 작업만 종료. 대표 탭 삭제 후 영역 유지, 마지막 탭 삭제 후 분할 병합, 여러 탭이 있는 영역에서 새 분할 생성.
5. 701px PC의 긴 이름·최대화한 영역의 탭 가로 스크롤·문서 가로 넘침 없음, 왼쪽 아래 탐색기·설정 접근, 밝은/어두운 테마, 390px 모바일 단일 패널·전환 메뉴와 + 버튼 44px 이상.

이번 로컬 증거는 `test-results/ui/terminal-tabs/`의 `result.json`, `desktop-split-tabs-dark.png`, `desktop-split-tabs-light.png`, `per-pane-final-regression.log`, `per-pane-lifecycle-retest.log`, `per-pane-shortcut-retest.log`에 생성한다. 캡처는 시험용 그룹·셸과 `C:\Windows` 경로만 사용한다. 시험 호스트는 `%TEMP%\mongle-tabs-*`에 격리하고 검사 종료 시 닫고 삭제한다. 전체 회귀 실행의 앱 데이터 경로는 `.test-data/per-pane-tabs-full`로 명시한다. 기존 검사가 자동 갱신한 추적 중인 `artifacts/ui` 이미지는 원래 버전으로 복구하고 이 변경에 포함하지 않는다.

설정 이동 후 버튼 이름에 버전까지 포함되어 정확한 접근성 이름으로 찾지 못한 문제는 `aria-label="설정"`으로 수정했다. 호스트 전환 후 화면 동기화가 끝나기 전에 원격 제어권 검사가 시작되던 경합은 보이는 두 영역의 제어 준비를 확인한 뒤 원격 기기가 획득하도록 시험 순서를 수정했다. 기존 PC 제목 누르기 검증은 새 탭의 선택만으로 다른 기기의 제어권을 가져오지 않는지 확인하도록 갱신했다. 실제 PowerShell·모바일 왕복에서는 탭 선택 후 휴대폰 제어권을 유지하고 명시적인 가져오기로 전환해 ACK·명령 입력·동일 PID와 generation을 검증한다. 모바일 제목과 내용 누르기 검증도 유지했다. 인증 검사나 제품 제어권 정책은 완화하지 않았다.

## 적용·미검증 범위

이 기록은 빌드한 공통 웹 UI를 Chrome에서 실제 셸과 연결한 결과다. 기존 PowerShell/ConPTY 입력·드래그·불확실 입력 검사도 함께 통과했으며 실제 사용자의 호스트·세션·인증 데이터와 Tailscale Serve는 변경하지 않았다.

기존 설치 앱에 파일을 적용하지 않았고 버전·설치본·공개 Release를 변경하지 않았다. 이 변경의 패키지 Electron E2E, NSIS 설치·제거, 사용자 화면 확인, 실물 휴대폰과 실제 Tailscale 연결은 아직 검증하지 않았다. 기본 회귀의 선택 실행 E2E 생략을 해당 영역의 통과로 표현하지 않는다.
