# 몽글터미널 — 설계 검토와 현재 검증 상태

작성일: 2026-09-29

## 1. 현재 결과

**초기 설계 검토 PASS. 이 문서는 구현 전 검토 기록이다.** 이후 앱 구현과 실제 시험 결과는 [구현·검증 상태](IMPLEMENTATION-STATUS.md)를 기준으로 확인한다.

요구사항, 오픈소스 공식 문서·대표 소스·LICENSE 조사, 시스템/데이터/API/모바일/원격 설계, 구현 단계와 검증 시나리오를 작성했다. 독립 검토에서 나온 실제 계약 충돌 5개를 수정한 뒤 재검토했다. P0 기술 검증을 수행할 수 있는 구체적인 시작점과 실패 시 재검토 경로가 있다.

핵심 기능·구조 설계는 정리됐으며, 남은 설계 작업은 데스크톱·모바일 화면 시안과 P0 실험 결과에 따른 기술 결정 확정이다. 구현 기술은 실기 검증 전의 조건부 선택이다. 사용자에게 '모든 설계와 검증이 끝났다'고 설명하지 않는다.

2026-09-29 추가 확정: 왼쪽 사이드바 상단에서 접속할 컴퓨터를 선택하고, 아래에는 해당 컴퓨터의 그룹, 오른쪽에는 터미널을 표시한다. 몽글 호스트가 관리하는 실행 중인 세션에 다시 접속하며 외부에서 따로 연 일반 터미널 창은 자동으로 가져오지 않는다. 요구사항 D04와 화면 구조에 반영했다. 이 변경은 설계 결정 기록이며 실행 검증 결과가 아니다.

## 2. 독립 검토에서 수정한 사항

| 발견 사항 | 반영한 수정 | 확인할 시나리오 |
|---|---|---|
| 코드 입력만으로 session을 발급하는 API와 PC 승인 UX가 충돌 | pending→로컬 approve/reject→원래 requester claim. 승인 전 cookie 없음. bootstrap 요청 검증 분리 | S04 |
| 인증 폐기에 layout debounce가 적용될 가능성 | 인증 발급/폐기는 성공 응답 전 즉시 영속 commit. 소켓/lease 해제. crash/restart 후 폐기 유지 | S03 |
| 로컬 가짜 endpoint에 owner secret을 보낼 가능성 | SID 제한 named pipe, 서버 신원·nonce 상호 인증. HTTP owner 인증 금지 | P0-A, S11 |
| major 업데이트 후 구 세션을 조작할 GUI가 사라질 가능성 | GUI/host 교체 함께 보류, 구 GUI 보존. writer 종료·lock·일관 backup 후 migration과 롤백 | S09 |
| 제어권 이전 직후 오래된 화면 좌표로 입력할 가능성 | lease 이전→resize fence→화면 ACK→입력 활성화 | T12–T14 |

재검토 결과 추가 차단 이슈는 발견되지 않았다. 이는 앞으로 구현될 코드가 안전하거나 정확하다는 증명이 아니며, 문서의 일관성과 검증 가능성에 대한 판정이다.

## 3. 이번에 확인한 것

- 사용자 요구와 설계 기본값을 분리했다. 모바일 포함, 기본 셸 중심, Tailscale 수용, 별도 AI 기능 제외가 문서에 반영됐다.
- 6개 참조 앱과 xterm/node-pty/portable-pty 기반을 비교하고, 조사 소스는 가능한 경우 commit으로 고정했다.
- Windows의 GUI 종료·host 종료·로그아웃·재부팅 차이를 구분했다.
- 기능 수용 시나리오 24개와 보안/복구/배포 시나리오 12개를 정의했다.
- 설계의 각 위험에 P0 실험 또는 수용 테스트를 연결했다.
- 프로젝트 내부 상대 문서 링크, 참조 파일 존재, 테스트 ID·요구 ID의 중복/누락, 최종 저장본 일치 여부를 문서 검증 대상으로 삼았다.

문서 자동 검사 결과: Markdown 10개, 상대 링크 16개와 제목 anchor 2개 모두 정상; 요구 ID 9개와 기능 T01–T24·보안/복구 S01–S12의 중복/누락 없음; 코드 블록 닫힘과 UTF-8 대체 문자 검사 정상. 외부 출처 URL은 중복 제거 104개이고 그중 SHA 고정 소스 URL은 55개다. 외부 URL 전체의 현재 HTTP 응답을 일괄 검사한 것은 아니다. 이 검사 수치는 제품의 실행 검증 수치가 아니다.

## 4. 아직 검증하지 않은 것

| 항목 | 상태/다음 검증 |
|---|---|
| GUI 종료 뒤 동일 PTY가 실제로 유지되는지 | 미실행, P0-A |
| xterm snapshot/parser/mode와 자동 응답 제어 | 소스상 위험 확인, 구현 해결 미검증, P0-B |
| Windows Serve→iOS/Android 장기 WS | 공식 문서·소스 근거만, 실기 미검증, P0-C |
| 한글 IME·Ctrl/Alt·붙여넣기·한글 경로 | 미실행, P0-D |
| 성능·메모리·8시간 동작·업데이트/복구 | 수치 목표만 설정, 실측 없음 |
| 설치/로그인/Tailscale·Serve 설정 | 이번 작업에서 변경하지 않음 |
| 최종 UI 시각 품질 | 정보 구조와 동작 설계만. 시안/구현 화면 검증 없음 |

실기기나 해당 OS가 없으면 테스트를 통과 처리하지 않고 SKIP 사유와 지원 제한을 기록한다. emulator 공개 API만으로 필수 계약이 성립하지 않으면 기술 결정을 다시 열어야 한다.

## 5. 후속 기록 규칙

P0와 각 구현 단계의 결과는 `docs/validation/`에 날짜·환경·commit·절차·증거·판정을 기록한다. 실제 테스트를 하지 않은 문서는 제목이나 상태에 미실행임을 유지한다. 이번 조사 메모에 있는 사용자 신고는 직접 재현한 결함과 구분한다. 최종 사용자 설명에서도 설계 완료와 제품 완료를 섞지 않는다.
