# 완전 종료와 작업 공간 복원

2026-09-29. 사용자는 프로그램을 완전히 종료하거나 PC를 재부팅해도 이전 작업 공간이 돌아오는 동작을 요청했다. 기존 SQLite 저장소를 활용하며 별도 DB 서비스는 추가하지 않는다.

## 동작

- 트레이와 앱 메뉴의 `완전 종료…`는 현재 PC의 실행 중인 터미널 수와 보관 정책을 확인하고, 취소를 기본값으로 제시한다. 선택된 화면이 원격 PC여도 그 원격 호스트에 종료 요청하지 않는다.
- 새 실행부의 `host.shutdown`은 작업 큐에서 메타데이터와 허용된 출력 스냅샷을 SQLite 단일 트랜잭션으로 저장한다. 저장에 실패하면 셸을 종료하지 않는다. 승인 뒤 추가 출력이 생기고 이후 디스크 장애가 발생하는 경우, 승인 시점 이후의 바이트까지 보장하지는 않는다.
- 데스크톱은 종료 요청 응답만으로 닫지 않고 로컬 연결 종료, 원래 호스트 PID 종료, 준비 파일 제거를 확인한다. 진행 중 자동 재연결과 새 호스트 시작을 막는다. 인증 실패·시간 초과를 강제 종료나 인증 정보 재생성으로 처리하지 않는다.
- 다음 실행에서는 이전에 실행 중이던 패널만 같은 셸 프로필과 저장된 시작 폴더로 다시 연다. 패널·그룹 ID와 배치는 유지하고 PID·세대는 새로 만든다. 명시적으로 종료된 패널과 과거 명령은 자동 실행하지 않는다.
- 이전 출력은 별도 파서에서 읽어 평문 스크롤백으로 복원한다. 활성 대체 화면의 텍스트도 포함하되 이전 응답·입력 모드·색상·프로세스 메모리는 복원하지 않는다. 새 셸의 초기 화면 지우기로 기록이 사라지지 않게 분리한다.
- 저장된 셸이나 폴더가 사라졌으면 이전 세대와 기록을 남기고 패널에 실패 이유를 표시한다. 기록 보관을 꺼 둔 경우 출력을 저장하거나 복원하지 않는다.

## 이전 버전 실행부와 함께 적용

현재 사용자의 호스트와 셸을 종료하지 않고 앱을 갱신할 수 있다. 이전 버전 실행부는 종료 시 `resumeOnBoot`를 남기지 않으므로, 새 데스크톱은 완전 종료를 확인한 뒤 인증된 로컬 상태의 실행 중 패널 ID·세대만 `workspace-resume.json`에 기록한다. 새 실행부는 호스트와 세대가 일치하는 이전 형식 기록에 한해서 이를 사용하며 새 형식의 명시적 종료 의도는 덮어쓰지 않는다. 명령·출력·인증 정보는 이 파일에 쓰지 않는다.

사용자 세션을 종료하는 대신 독립 임시 저장소와 테스트용 PowerShell 프로세스를 사용했다.

E2E에서 실제 Electron 메뉴 콜백과 실행부·SQLite·PowerShell을 사용했다. 네이티브 확인창의 응답은 테스트가 지정했으며 물리적인 트레이 클릭·Windows 재부팅·전원 차단을 시험했다고 주장하지 않는다. 새 호스트 프로세스로 재실행하는 경로를 검증했다.

## 현재 앱 적용

설치 EXE·ZIP·blockmap과 현재 `release/win-unpacked`의 EXE·ASAR·호스트 JS·웹을 갱신했다. 패키지의 실행 코드 4개 SHA-256이 E2E에서 검증한 파일과 같고, 현재 배포 경로의 체크섬 7개도 모두 일치한다. native helper는 변경하지 않았다. 증거: `test-results/full-exit-rollout/package-verification.json`, `deployment.json`, `final-verification.json`, `release/SHA256SUMS.txt`.

실제 GUI만 44628에서 33148로 다시 실행했다. 처음 숨김 상태로 열린 창은 단일 인스턴스 열기로 표시했다. 최종 UI Automation 읽기 결과는 `연결됨` 1개, 인증 오류·연결 끊김 0개, 터미널 패널 3개였다(`actual-ui.json`). 호스트 PID 6400, boot ID, 셸 PID 14060·45092·34256, 세대와 배치는 모두 동일하다. 실제 사용자 작업의 완전 종료는 실행하지 않았다.

사용 중인 호스트는 작업 보존을 위해 기존 메모리 코드로 계속 동작한다. 새 종료 전 저장 검사·자동 복원 로직은 다음 호스트 실행부터 활성화된다. 현재의 첫 완전 종료는 새 앱의 일회성 복원 문서가 연결하며 위의 실제 이전 버전 E2E로 검증했다. OS 종료로 이 문서를 쓰지 못한 경우에도 기존 저장소가 `running`으로 남긴 패널은 다음 부팅에 복원한다.

참고: [Orca 세션 복원](https://www.onorca.dev/docs/model/session-restore)은 앱 종료 시 살아 있는 데몬에 재접속하고, PC 재부팅 후에는 배치와 기록을 복원하되 이전 에이전트 프로세스는 다시 실행해야 함을 구분한다. [ChatGPT 기록 보관](https://help.openai.com/en/articles/8983778)은 계정에 저장된 대화 기록을 다시 여는 동작이다.
