**AI 팀 구성원끼리 메시지와 팀 화면 크기 조절(2026-10-15, 0.3.25 배포 준비):** 설계 3단계의 몽글 MCP를 구현했다. 구성원 CLI마다 실행 옵션(Claude Code `--mcp-config`·`--allowedTools`, Codex `-c mcp_servers.mongle_team=...`)으로 중계 MCP 서버를 붙이고, 중계는 `list_agents`·`send_message`를 구성원 키와 함께 실행부의 로컬 파이프(응답을 돌려주는 메시지 v3)로 넘긴다. 실행부는 키로 보낸 구성원을 정하고 받는 사람의 보류함에 사용자 메시지와 같은 조건으로 넣으며, 사용자에게 보낸 보고는 팀 대화에만 남긴다. 역할 지시문은 맡기기·보고에 도구를 쓰라고 안내하고, 이전 팀은 재개할 때 새 지시문을 받는다. 팀 화면에는 팀장·구성원 칸 사이와 구성원 칸 사이에 크기 조절 손잡이를 넣고 팀별로 저장한다. 단위·호스트·화면 시험과 중계 스크립트를 실제 node로 띄운 전 구간 시험을 통과했다. 이 PC의 Codex 0.162.1(`codex exec`, 읽기 전용, `gpt-6-luna`)과 Claude Code 2.1.300(`-p`, `--tools 'Read,Grep,Glob'`, `haiku`)이 실제로 두 도구를 승인 없이 불렀다(모델 요청 각 1회). 아스트라가 실제 Electron 창에서 Claude `haiku` 세 명의 팀으로 `나 → 설계 → 개발 → 검토 → 설계 → 나(보고)`가 사람 개입 없이 이어지는 것과 크기 조절(끌기·화살표·초기화·좁은 창)을 확인했다. 설치본과 사용자 설정은 전후 같았다. 이 확인에서 찾은 머리글 중복(모델이 받은 머리글을 본문에 다시 씀)과 손잡이 두 번 클릭 뒤 글자 선택을 고쳤다. 이 PC의 설치본이 0.3.20이라 사용자 훅에 0.3.24의 전체 화면 시작 신호가 없어, 시험에서는 구성원마다 첫 요청을 한 번 보내 준비시켰다. Windows PowerShell 5.1이 기존 Codex 역할 지시문 옵션의 큰따옴표를 잃는 기존 문제를 발견해 기록했다. [구현과 검증](validation/agent-team-relay.md).

**AI 팀 구성원 모델 고르기(2026-10-15, 0.3.25 배포 준비):** 구성원 모델 칸을 각 CLI가 알려 주는 목록에서 고르는 선택 상자로 바꿨다. 실행부의 새 요청 `teams.models`가 Codex는 `codex debug models` 카탈로그에서 목록에 보이는 모델을 Codex 순서대로, Claude Code는 목록 명령이 없어 `claude --help`의 `--model` 설명에 나온 별칭과 opus·sonnet·haiku를 돌려준다. 모델 요청은 보내지 않고 결과는 10분 동안 재사용한다. 맨 위는 도구 기본값, 맨 아래는 직접 입력이며, 목록이 없으면 이전 입력칸을 쓴다. Mobbin 사례(FLORA·Cloudflare AI Playground·Relevance AI의 모델 선택)를 참고했다. 단위·호스트·화면 시험과 이 PC의 Claude Code 2.1.300·Codex 0.162.1에서 실제 목록(Claude 별칭 4개, Codex 7개, 0.13초)을 확인했다. 실제 Electron 앱 확인은 아직이다. [구현과 검증](validation/agent-team-models.md).

**AI 팀의 작업 범위와 브랜치 맞추기(2026-10-15, 0.3.25 배포 준비):** 팀 시작 창에서 팀이 함께 볼 폴더 여러 개와 시작 폴더를 고르고, 체크한 Git 저장소를 시작할 때 같은 브랜치로 맞춘다. 실행부는 `teams.scope`로 그룹 폴더·연결된 저장소·그룹 터미널 폴더를 저장소 맨 위 폴더로 모아 제안하고, 점검에서 저장소마다 바뀔 내용과 Git이 거절할 이유(병합 진행 중, 겹치는 변경, 다른 워크트리에서 쓰는 브랜치, 커밋 없음, 잘못된 이름)를 미리 알린다. 시작할 때 모든 브랜치를 먼저 맞추고 하나라도 실패하면 팀을 시작하지 않는다. 시작 폴더 밖의 폴더는 Claude Code·Codex의 `--add-dir`로 넘기고(읽기 전용 Codex 제외) 재개할 때도 붙이며, 역할 지시문에 작업 범위와 브랜치를 적는다. 사용자 의견에 따라 기본 템플릿 구성원은 모두 기본 폴더로 시작하고 새 워크트리는 골라서 쓴다. Mobbin 사례(Devin·Graphite 저장소 선택, ChatGPT Codex·Cursor의 저장소·브랜치 칩, GitLab 새 브랜치)를 참고했다. 타입 검사·빌드, 팀 단위·호스트·화면 시험(실제 임시 Git 저장소 2개와 일반 폴더로 겹치는 변경·병합 중·잘못된 이름 거절, 새로 만들기·있는 브랜치로 바꾸기, CLI 실행 줄의 폴더 인자, 역할 지시문)을 통과했다. 실제 화면 컴포넌트와 스타일을 시험용 응답으로 묶은 미리보기를 Aside로 조작해 확인했고, 그 과정에서 창보다 내용이 길면 구성원 표가 높이 0으로 줄어 보이지 않던 문제를 고쳤다. 실제 Electron 앱과 실제 CLI가 `--add-dir`로 받은 폴더를 쓰는지는 아직 확인하지 않았다. [구현과 검증](validation/agent-team-scope.md).

**AI 팀의 워크트리 저장소 찾기(2026-10-15, 0.3.25 배포 준비):** 시작 전 점검이 그룹에 연결된 저장소 수만 세어, Git 프로젝트가 있는 그룹이나 `git init`한 새 프로젝트에서도 "프로젝트(Git 저장소) 하나를 먼저 열어 주세요"로 팀 시작을 막던 문제를 고쳤다. 이제 작업 폴더로 저장소를 찾고, 그룹에 연결되지 않은 저장소는 팀을 시작할 때 연결한다. 저장소가 아니거나 커밋이 없으면 주의로 알리고 워크트리 구성원도 기본 폴더에서 일한다. 타입 검사와 팀 호스트·단위 시험 7/7(일반 폴더, 커밋 없는 새 저장소, 연결 안 된 저장소의 자동 연결과 워크트리 생성)을 통과했다. 실제 앱 확인은 아직이다. [원인과 검증](validation/agent-teams-host.md#작업-폴더로-저장소-찾기).

**Claude 전체 화면 모드의 시작 신호(2026-10-15, 0.3.24에 공개):** Claude Code 전체 화면 모드(`tui: fullscreen`)는 화면을 그리기 전과 닫은 뒤에 나온 터미널 신호를 버린다. 그래서 첫 요청 전까지 메시지·팀 대화를 보낼 수 없었다. 이전 기록이 원인으로 적은 "다른 시작 훅"은 원인이 아니었음을 조건별 실행으로 확인했다. 관리 Claude 훅이 시작 신호를 실행부 로컬 파이프로도 보내고, 실행부는 셸 프롬프트가 다시 나오기 전에 온 신호로만 준비됨을 켠다. 신규·추가 시험과, 실제 PowerShell·실행부 코드·사용자 설정 그대로인 Claude Code 2.1.300으로 수정 전 20초 동안 미준비, 수정 후 0.7초에 준비됨을 확인했다(모델 요청 없음). 실제 Electron 앱 확인은 사용자 Claude 설정을 바꾸게 되어 하지 않았다. [원인과 검증](validation/claude-fullscreen-start.md).

**AI 팀 화면(2026-10-15, 0.3.24에 공개):** 새 작업 흐름(작업 그룹·템플릿·구성원 표·역할 지시문 펼침·내 템플릿 저장·기본 템플릿 별표 → 시작 전 점검 → 팀 시작), 팀 화면(팀장 크게·구성원 세로·머리줄 표시), 팀 대화(받는 사람 선택, 실행부가 기록하는 전달 상태 최근 100개, 보류 메시지 취소), 맨 아래 팀 정보 줄, 사이드바 AI 팀 목록을 만들었다. 실행부에는 `teams.message`와 보류함의 메시지별 결과 보고를 더했고, 보류 사유가 그대로일 때 보류 목록이 갱신되지 않던 1단계 문제를 고쳤다. 신규·추가 시험(화면 4, 보류함 9, 팀 실행부 2)과 전체 회귀 721개 중 700 통과·1 실패(기존 PowerShell 실행 정책 환경 문제)·20 생략을 확인했다. 아스트라가 실제 Electron에서 시작 창·점검·팀 시작·팀 대화 전달과 보류·취소·재시작 뒤 기록·팀 해제를 확인했고(Claude 요청 9회, Codex 0회), 찾은 결함 5개와 개선점 1개를 고친 뒤 다시 확인했다. 휴대폰 너비에서는 팀 화면을 보여 주지 않는다. Codex 구성원에게 보내기, 응답 중 앱 종료, 실물 휴대폰은 확인하지 않았다. 구성원끼리 직접 보내기는 3단계다. [구현과 검증](validation/agent-teams-ui.md).

**AI 팀 실행 호스트(2026-10-15, 0.3.24에 공개):** 팀 템플릿(기본 3개와 내 템플릿), 시작 전 점검, 구성원별 PowerShell 탭과 워크트리 만들기, 역할 지시문 파일을 붙인 Claude Code·Codex 실행, 읽기 전용 옵션, 이어 켤 때 역할 다시 붙이기를 실행부에 구현했다. 팀 기록은 별도 `agents.sqlite`에 둔다. 신규 시험 7/7과 관련 회귀 241/244(3 생략)를 통과했다. 화면과 실제 앱 확인은 다음 PR에서 한다. [구현과 검증](validation/agent-teams-host.md).

**에이전트에게 메시지 보내기(2026-10-14, 0.3.24에 공개):** PowerShell에서 실행 중인 Claude Code·Codex에게 제어권 없이 메시지를 보낸다. 실행부는 에이전트가 훅으로 실행을 증명했고, 작업 중·확인 요청 중이 아니며, 아무도 입력하지 않고 쓰다 만 글도 없을 때만 붙여넣기 하나와 별도 Enter로 전달한다. 그 밖에는 보류하고 이유를 보여 준다. 터미널별 방해 금지도 있다. 보류함·호스트·화면 시험 10/10을 통과했다. 전체 회귀는 707개 중 686 통과, 1 실패(기존 PowerShell 실행 정책 환경 문제), 20 생략이다. 아스트라가 실제 Electron 창과 Claude Code 2.1.299로 전달·작업 중 보류·입력 중 보류·방해 금지·셸 복귀 시 미전달을 확인했다. 셸 복귀 때 남던 표시 두 가지를 고쳤고, 이 수정은 실제 앱에서 다시 확인하지 않았다. Claude가 첫 요청 뒤부터 보낼 수 있던 문제는 [전체 화면 모드의 시작 신호](validation/claude-fullscreen-start.md)에서 원인을 바로잡고 고쳤다. 실제 Codex, 승인 창 보류, 지금 보내기 실행, 휴대폰 화면은 확인하지 않았다. [구현과 검증](validation/agent-messages.md).

**AI 팀 설계와 0단계 확인(2026-10-14, 구현 전):** Claude Code·Codex 여러 개를 팀으로 묶는 선택 기능의 [설계안](08-agent-team-design.md)을 정했다. 이 설계 항목은 문서만 추가했고, 1단계 구현은 위의 메시지 보내기 항목에 있다. 실제 CLI(Claude Code 2.1.299, Codex 0.162.1)로 격리 폴더에서 확인한 결과는 다음과 같다. `codex queue`는 몽글의 `--no-daemon` Codex에 메시지를 전달했고, 사람 승인 창이 떠 있는 동안은 기다렸다. Claude Channels는 이 PC의 Team 계정에서 조직 정책으로 막혀 있었다. 역할 지시문은 두 CLI 모두 이어 하기 뒤에도 남았다. 읽기 전용은 Claude `--tools`와 Codex `-s read-only -a never`로 막혔다. 모델 목록은 로그인한 계정만으로 받았다. Claude는 지시문 없이 이어 켠 뒤 압축하면 지시문이 사라졌다. Codex는 `-s read-only`만 주면 자동 검토가 쓰기를 승인했다. 두 결과를 설계에 반영했다. [확인 기록](validation/agent-team-probe.md).

**Codex 동시 실행·자동 검토 표시(2026-10-12, 0.3.22에 공개):** 같은 차례에서 함께 실행된 도구가 끝나면 아직 승인을 기다리는 Codex 요청의 확인 요청 표시가 내려가고 휴대폰 알림이 빠지던 문제(PR #69 검토 P2)를 고쳤다. 훅이 도구 이름과 명령(또는 입력)의 SHA-256만 보내고, 끝난 도구는 같은 지문의 요청만 지운다. 고치는 중에 Codex가 자동 검토(auto-review)를 쓸 때도 승인 요청 훅을 먼저 실행한다는 점을 Codex 공개 소스에서 확인했다. 그래서 사람이 답할 필요 없는 요청에도 확인 요청·앱 알림·휴대폰 알림이 나갔다. 이제 승인 요청은 그 터미널 화면에 Codex 승인 창이 보이면 확인 요청으로 표시하고, 자동 검토 표시가 보이면 버리며, 2.5초 안에 둘 다 알아보지 못하면 이전처럼 표시한다. 훅 등록 내용은 그대로라 다시 신뢰할 필요가 없다. 타입 검사·빌드, Codex 상태 시험 11/11(신규 6, 훅 확인 창 감지 포함), Codex 연동 시험 9/9(훅 지문 확인 추가), Claude 상태 시험 16/16, 격리한 `MONGLE_DATA_DIR`의 전체 회귀 653개 중 635 통과·1 실패·17 생략을 확인했다. 실패 1개는 기존 PowerShell 실행 정책 환경 문제다. 2026-10-12 아스트라가 격리 앱과 실제 Codex 0.162.1로 확인했다. 사람 승인 모드에서 승인 창과 물음표가 함께 나타나고 Enter 승인 뒤 작업 중으로 바뀌었으며, 승인 설정을 덮어쓰지 않은 실행에서는 관찰한 화면에 물음표·알림이 없었다. 자동 검토 구간 전체와 다른 도구가 정상으로 끝나는 동시 실행은 확인하지 못했다(동시 실행 시험의 읽기 명령이 Codex 실행 환경 오류로 실패). [구현과 검증](validation/codex-status.md#동시-실행과-자동-검토).

**휴대폰 알림(2026-10-12, 0.3.21에 공개):** 휴대폰 브라우저에서 켜면 PC 앞에 없을 때(잠금 또는 5분 무입력, 어느 기기에서도 이 PC의 몽글 화면을 5분 안에 보지 않음) Claude·Codex의 확인 요청과 새 기기 연결 요청을 Web Push로 보낸다. 요청마다 기기당 한 번, 이름만 담고 출력·연결 코드는 담지 않는다. RFC 8291·8292를 `node:crypto`로 구현해 RFC 예제와 바이트 단위로 맞췄고, PC 상태는 `OwnerPipe.exe presence`로 잠금과 마지막 입력 시간만 읽는다. 타입 검사·빌드, 웹 푸시 5/5, 알림 판정 9/9, PC 상태 3/3, 보안 32/32(신규 5), 설정 화면 1/1(Chrome, 모의 Push API), 격리한 `MONGLE_DATA_DIR`의 전체 회귀 647개 중 629 통과·1 실패·17 생략(기존 PowerShell 실행 정책 환경 문제)을 확인했다. 2026-10-12 아스트라가 격리 앱과 Aside로 알림 설정의 설명·예시를 확인했다. **0.3.10 응답성·안정성 개선:** 작은 출력 배치·자동 캡처 중복 방지, 출력 중 마우스 선택 유지, 워크트리 조회 병렬화·브랜치/태그 충돌 수정, heartbeat 지연·재연결 경쟁·최신 상태 후퇴·닫은 입력창의 늦은 완료·탐색기 불필요한 대기 읽기를 보완했다. 관리자 환경 첫 실행 수정 전 로컬 전체 회귀는 **372개 중 357 통과·실패 0·선택 실행 15 생략**이었다. 타입·빌드·배포 문서 검사·별도 패키지 네이티브 로드와 아이콘 검사도 통과했다. 앞선 개발 Electron과 패키지의 실제 OwnerPipe·cmd·지속 출력 중 탐색 조작은 각각 **1/1 통과**했다. 최종 PR·태그 CI 수치는 위 결과와 구분한다. ## 제공 범위와 남은 확인

왼쪽 컴퓨터·그룹 선택, 셸 프로필, 중첩 상하·좌우 분할, 크기 조절, 이동·최대화, 검색·복사·붙여넣기, 다크·라이트, 앱 재실행 후 세션 재연결, 모바일 단일 패널·보조 키, Tailscale 연결 설정과 기기 승인, 설정 가져오기·내보내기를 구현했다. 0.3.4에는 각 분할 영역 안의 터미널 탭과 개별 탭 드래그를 추가하고 PC 별도 상단 도구줄을 제거했다.

사용자 휴대폰의 Tailscale 접속·승인과 키보드·스크롤 수정 후 Android 삼성 인터넷의 정상 동작은 사용자 응답으로 확인했다. Android/iPhone 전체 호환성, 실제 OS 한글 IME 조합별 동작, 네트워크 전환, 60분 원격 연결 및 8시간 지속 시험, OS 재부팅·로그오프, NSIS 설치·제거 마법사는 아직 검증하지 않았다. 설치된 WSL 배포판이 없어 WSL 실제 실행도 미검증이다. 이 항목을 로컬 자동 검사 성공으로 대체하지 않는다.

이전 실행본 적용 기록의 경로는 `release/win-unpacked/MongleTerminal.exe`의 0.2.0이며 원격 연결 복구를 포함한 `release-remote-recovery/win-unpacked`의 검증 파일을 적용했다. 기존 0.1.0 파일은 별도 백업했고 사용자 데이터는 초기화하지 않았다. 0.2.0부터 Windows NSIS 설치본의 자동 확인·다운로드·사용자 확인 후 설치 기능을 구현했다. 이후 공개 버전의 게시·실제 다운로드 검증을 이어 왔으며 최신 공개 버전 0.3.10의 결과는 [배포 기록](validation/public-release-0.3.10.md)을 따른다. 실제 버전 간 NSIS 설치·재실행은 별도다. ZIP 실행본과 개발 모드는 수동 교체한다. **코드 서명은 없는 미리보기**이며 로그인 자동 시작은 제공하지 않는다. 설치·제거 전 작업을 저장하고 **완전 종료…**를 사용하며 사용자 데이터는 자동 삭제하지 않는다. [배포 안내](RELEASING.md)

후속 QR 웹 파일도 현재 실행 폴더에 적용했다. 초기에는 도구의 MSIX 설정 폴더와 실제 앱의 사용자 설정이 달라 원격 주소가 502였으나, 이후 실제 프로필에 정상 인증해 관리 기록을 복원하고 원격 접속을 켰다. GUI·호스트·셸을 유지한 상태에서 실제 HTTPS와 QR 자산까지 검증했다. 실물 카메라 스캔은 아직 미확인이다. [최종 복구](validation/msix-profile-recovery.md)

이후 화면 누르기로 입력 시작 기능의 호스트 JS·웹을 백업 후 적용했다. 적용 시점에 기존 호스트가 이미 종료돼 있었으며, 저장된 복원 정보와 데이터 불변을 확인하고 앱을 열었다. 현재 실제 호스트의 지원 목록과 복원된 패널, 원격 HTTPS의 최신 파일을 확인했다. 모바일은 새로고침해야 새 화면을 읽는다. 빈 격리 프로필로 시작한 별도 패키지 검사는 연결 대기로 미완료이며 실제 프로필 검증과 구분한다. [터치 입력 적용](validation/tap-control.md)

PC·모바일 왕복 입력의 후속 수정은 웹 파일만 적용했다. **앱 종료 · 터미널 유지** 메뉴로 데스크톱 화면을 갱신한 뒤에도 기존 호스트와 PowerShell의 PID·generation이 그대로 유지됨을 확인했다. 실제 HTTPS도 최신 파일을 제공한다. 모바일은 새로고침이 필요하다. 2026-09-29 사용자가 수정 후 정상 동작을 확인했으며, 기기·브라우저별 전체 시험이나 삼성 인터넷의 세부 동작 검사와는 구분한다. [입력 전환 후속 검증](validation/input-handoff.md)

최종 폴더 이동 검증에서 native 의존성 누락을 발견해 수정했다. 개발 폴더의 상위 `node_modules`에 의존한 실행을 배포 성공으로 판단하지 않는다. 패키징 단계에서 필수 파일 존재, 배포 내부 모듈 해석, 동봉한 Node의 native 모듈 로드와 ZIP 포함 여부를 검사하며, 최종 E 폴더의 실제 실행까지 검증했다.

## 설계 대비 구현 판단

호스트가 터미널 파서를 소유하고 완전한 표시 프레임을 전달한다. 연결마다 PTY를 독립 파싱할 때 생기는 응답 중복과 불완전한 재연결 상태를 피한다. 화면 갱신이 지연되면 대기 중인 최신 화면 하나만 유지한다. 기록은 프레임 크기 예산에 맞춰 오래된 부분부터 생략하며 현재 화면은 보존한다.

`packages/terminal/pinned-xterm.ts`는 xterm 6.0.0 내부 API 의존성을 모은다. `node-pty` 1.1.0의 Windows 종료 동작도 버전 고정 어댑터로 다룬다. 관련 패키지를 바꿀 때 화면·입력·프로세스 수명주기 회귀 검사가 필요하다. 모든 터미널 프로그램과 환경의 호환성을 보장하지는 않는다.

PC 재부팅·로그아웃·호스트 종료 후에는 저장한 그룹·배치·기록을 복원하고, 이전에 실행 중이던 패널의 셸을 저장된 시작 폴더에서 새로 연다. 이전 프로세스의 메모리나 명령을 재실행하지 않으며 명시적으로 종료한 패널은 다시 실행하지 않는다. 복원한 출력은 평문이고 기존 기록 보관 정책과 용량 한도를 따른다. 기존 외부 PowerShell 창은 수집하지 않는다. 원격에는 대상 PC와 실행부가 켜져 있고 Tailscale 연결이 유지되어야 한다.

몽글터미널 자체는 `private`/`UNLICENSED`다. 공개 라이선스는 별도 결정 전까지 부여하지 않는다. 의존성 원문과 출처는 [제3자 고지](THIRD-PARTY-NOTICES.md)에 보존한다.
