# 파일 편집기 배포 전 추가 검증

**후속 공개 완료:** 아래는 개발 시점의 기록이다. 최종 0.3.11의 회귀·실제 NSIS 설치·백신·공개 다운로드 결과는 [0.3.11 배포 기록](public-release-0.3.11.md)에 있다.


검증일: 2026-10-05. 기준 소스 `ecb554a`, 버전 0.3.8의 **미배포 개발 변경**이다. 이 기록은 공개 배포나 기존 설치본 교체를 의미하지 않는다.

## 추가 종료 보호와 최신 dev 통합

`800e461` 전체 CI에서 탐색기 통합 검사 6개와 Git UI 검사가 실패했다. 전자는 이전 단일 미리보기 기대와 독립 파일 탭 동작이 달랐고, 후자는 시험 자체가 화면의 두 읽기 외에 세 번째 호스트 읽기를 보내 제한에 걸렸다. 실패 후 브라우저가 호스트보다 늦게 종료되어 다음 검사도 대기했다. 독립 탭 보존·늦은 응답·탐색 취소를 검사하도록 갱신하고 기대값을 화면 시작 전에 조회하며 실패 시 브라우저를 먼저 정리한다. 코드에서도 중복 큐가 취소 신호를 잃는 문제와 삭제 스테이징 후 재생성한 파일의 열기를 수정했다. 타입과 큐 회귀 3/3은 통과했으며 수정 후 전체 CI는 재실행한다.

알약 정밀검사에서 `release-editor-final` 폴더를 선택해 검사했다. 기본 검사와 선택 폴더를 포함한 16,572개 검사, 11분 7초 후 **탐지 0개**로 완료했다. 이 결과는 위 후속 큐 수정 전 패키지에 대한 것이며 백신 제외·보호 해제·자동 치료를 적용하지 않았다.

최신 `dev`의 0.3.10 변경과 충돌을 해결해 `c523005`로 통합했다. 새 데이터 폴더 소유권 준비와 탐색기 읽기 취소를 유지하고, 탐지된 IconBuilder 실행을 되살리지 않았다. 통합 후 타입·전체 빌드·배포 문서 검사가 통과했다. 공개 배포 버전 0.3.10은 유지하며 같은 번호의 다른 설치본을 공개하지 않는다.

앞서 생성한 0.3.8 개발 패키지에서 실제 파일 편집기로 미저장 문서를 만든 뒤 생산 코드의 앱 종료·완전 종료 메뉴를 호출했다. 각각 Windows의 `저장하지 않은 파일` 알림을 확인했고 문서와 터미널이 유지됐다. 업데이트는 다운로드 완료 상태와 최종 설치 호출만 시험용으로 바꾸고 실제 보호 경로를 실행했다. 동일한 알림이 뜨며 설치 호출 0회, 상태가 ready로 복귀한 것을 확인했다. 실제 다운로드나 NSIS 교체를 검증한 결과는 아니다.

실제 NSIS 교체는 별도의 [Installed upgrade validation](https://github.com/bokjk/mongle-terminal/actions/runs/37226973518)에서 **통과**했다(`800e461`, Windows Server 2022). 공개 0.3.8 설치본을 해시 검증 후 실제 설치하고, 인증된 호스트에 cmd 두 개를 만든 뒤 생산 코드의 완전 종료 메뉴로 종료했다. 새 NSIS 설치 후 실제 실행 버전·설치 표식·설치된 app.asar와 후보 패키지의 해시 일치, 그룹·터미널 식별자·이름·폴더 보존, 새 호스트와 새 셸의 자동 시작, 문서 보존과 모든 시험 프로세스 종료를 확인했다. 확인창의 답변만 자동화했으며 설치·호스트·저장소·프로세스는 실제다. 결과는 실행의 `installed-upgrade-result` artifact에 보관한다.

최신 소스의 로컬 `release-editor-final` 패키지도 실제 창에서 마크다운 미리보기·편집·한글 저장과 미저장 일반 종료·완전 종료·업데이트 보호를 반복 확인했다. 업데이트 다운로드 완료 상태와 설치 호출을 대역 처리한 검사는 설치 호출 0회·ready 복귀를 확인했다. 저장 후 완전 종료로 호스트·셸을 정리하고 SQLite의 그룹·터미널 식별자를 대조했다. 같은 실행 환경에서 다시 열어 동일 작업·폴더·저장 문서가 유지되며 새 bootId와 셸 PID로 복원되는 것을 확인했다. 첫 재실행 시도는 원래 시험 폴더의 문서가 실행 환경에서 보이지 않아 복원 근거에서 제외하고, 새 시험 자료의 저장 전후를 직접 대조한 결과만 채택했다.

위 로컬 후보 설치 파일 SHA-256은 `d5615185178350621a6429ec8e5d634fa9eb7bb5dc1c4efc26eeaaa57adcccf1`이다(148,534,665바이트). GitHub에서 설치한 후보와 로컬에서 직접 조작한 패키지의 데스크톱 app.asar SHA-256은 모두 `efbdbc10f45d6b6ba0c3818bb1056ac2171bf7a725b3abcf3273298ba8de37a4`다. 웹과 호스트는 별도 hostbundle에 포함되므로 app.asar 일치만으로 전체 앱 동일성을 판단하지 않는다. 후속 설치 검사는 hostbundle의 전체 상대 경로와 파일별 해시를 정렬해 후보와 설치본의 일치를 추가 검증한다. 버전 0.3.10 표기는 검증용이며 기존 공개 0.3.10을 덮어쓰지 않는다.

## 범위와 격리

- 브라우저 자동화가 없는 회귀 파일 31개를 순차 실행했다. Chrome/Playwright 기반 UI·E2E는 사용자의 Aside 기본 브라우저 지침에 따라 이 실행에서 제외했다. 따라서 전체 CI 완료가 아니다.
- Windows 패키지는 `%TEMP%` 아래 고유한 `mongle-native-editor-audit-*` 프로필과 시험 문서, cmd 하나로 실행했다. 실사용 앱·호스트·인증 데이터·Tailscale 설정을 변경하지 않았다.
- 네이티브 창의 파일 편집기는 Computer Use로 조작했다. 터미널에 명령을 입력하지 않았다. 패키지 호스트의 HTTP 연결 화면은 Aside로 열었지만 연결 승인을 진행하지 않았다.

## 실제 Windows 패키지 창

`release-editor-reliability-test/win-unpacked/MongleTerminal.exe`를 실제 실행해 확인했다.

- Electron의 `file:///.../dist/web/index.html`에서 마크다운 제목·한글·강조·체크 목록·표가 표시됐다. 기존 브라우저 HTTP 시험과 달리 패키지의 file URL에서 Worker를 사용하는 경로를 확인한 것이다.
- 나란히 보기에서 시험 문구를 입력하고 저장 버튼으로 저장했다. 화면이 `수정 없음`으로 바뀌고, 별도 파일 읽기로 디스크에 같은 한글 문구가 기록됐음을 확인했다. 이 입력은 도구의 텍스트 입력이며 실제 한글 IME 조합 검사는 아니다.
- 저장 후 실행 취소로 미저장 상태를 만들었다. 창 닫기(X)는 기존 동작대로 트레이로 숨겨졌고, 같은 격리 프로필로 다시 실행해 창을 복원하자 초안과 수정 표시가 유지됐다. 다시 실행(Ctrl+Y)으로 저장한 내용과 `수정 없음` 상태를 복원했다.
- 창을 숨기고 복원한 전후 호스트 bootId, 터미널 ID·PID·generation이 동일했다. 프로세스를 재시작한 뒤 초안을 복구한 시험은 아니다.
- 검증 후 파일이 저장된 상태에서 설정 → 컴퓨터 → 백그라운드 실행 종료 → 모든 작업 중단 후 종료를 조작했다. 오프라인 안내와 시험 호스트·셸 PID 종료를 확인한 뒤 시험 GUI와 대기 스크립트만 정리했다. 이는 메뉴의 완전 종료·다음 실행 복원 시험과 구분한다.
- 이 최초 검사에서는 일반 종료·완전 종료·업데이트 설치를 미저장 상태에서 차단하는 네이티브 확인창을 검증하지 않았다. 이후 실제 확인 결과는 위 후속 기록에 적었다. 창 닫기(X)로 숨기는 동작은 앱 종료와 구분한다.

## NSIS·ZIP 생성

`runtime/node.exe --import tsx scripts/package.ts --output release-editor-audit`가 통과했다.

- NSIS 설치 파일, ZIP, blockmap, latest.yml, SHA256SUMS.txt 생성.
- 패키지 자체의 node-pty·ConPTY 네이티브 모듈 로드, 외부 개발 폴더에 의존하지 않는 모듈 경로, 공개 포함 파일 제한 검사 통과.
- EXE의 아이콘 7개 프레임, ZIP 내부 필수 네이티브 파일 7개, 설치 파일의 SHA-512·크기와 latest.yml 일치 검사 통과.
- 직접 조작한 기존 디렉터리 패키지와 새 산출물의 `resources/app.asar` SHA-256이 동일했다.
- 버전을 올리지 않은 **로컬 시험 산출물**이다. 공개된 0.3.8을 덮어쓰거나 이 산출물을 새 공개 버전으로 게시하면 안 된다. 설치 프로그램은 실행하지 않았다.

## 최초 검사 시 남았던 범위

최초 0.3.8 개발 패키지 검사 당시에는 GitHub 전체 CI, 미저장 네이티브 종료·업데이트 보호, 실제 NSIS 교체·재실행·복원과 최종 백신 검사가 남아 있었다. 이후 수행한 결과는 위 후속 기록으로 갱신한다. 실물 휴대폰·외부 원격·물리 한글 IME와 Windows 11 설치 마법사 전체 수동 조작은 이번 결과에 포함하지 않는다.

로컬 로그는 `.test-data/release-audit-{regression,retry,lifecycle,pwsh-diagnostic}.log`, `.test-data/release-editor-audit-package.log`, `.test-data/native-editor-audit*.log`에 보관한다. 시험 프로필 경로와 식별자를 포함한 원시 자료는 커밋하지 않는다.

## 0.3.11 배포 준비와 설치 파일 누락 조사 (2026-10-05)

- `660e025` 전체 Windows CI: 423개 중 408 통과·실패 0·선택 실행 15 생략. 별도 네이티브 클립보드·업데이트 브리지 2/2 통과. 실행: https://github.com/bokjk/mongle-terminal/actions/runs/37228601360
- 같은 커밋의 강화된 실제 설치 검사에서 app.asar는 일치했지만 hostbundle 496개 중 490개만 설치되어 실패했다. 이전 app.asar 단독 검사 통과는 전체 패키지 일치를 증명하지 않는다.
- 로컬 수정 후보의 원본 7z를 최신 7-Zip으로 풀면 495개 모두 일치했다. NSIS와 동일한 nsis7z 플러그인을 쓰는 격리된 압축 해제 전용 프로그램으로는 489개만 풀렸다. 누락은 node-pty의 win32-arm64 아래 conpty.dll·OpenConsole.exe·winpty-agent.exe·winpty.dll과 third_party/conpty/1.23.251008001/win10-arm64의 conpty.dll·OpenConsole.exe 6개였다. x64 파일과 나머지 파일은 모두 일치했다. 실제 사용자 설치·레지스트리를 건드리지 않고 재현했다.
- 패키징에 BCJ 필터를 명시해 NSIS가 지원하지 않는 최신 ARM64 필터의 자동 선택을 막는다. 예외 없이 전체 설치 파일을 비교하며 수정 후 결과는 별도로 기록한다. 최종 태그 배포에도 실제 NSIS 교체·복원 검사를 추가했다.
- `release-editor-fixed` 알약 2.5 정밀검사: 최신 2026-10-05 엔진, 15,915개·1분 5초·탐지 0. 지정 폴더 및 하위 win-unpacked/resources 검사 완료 로그를 확인했다. 제외 설정이나 보안 기능을 변경하지 않았다. 해당 로컬 패키지의 결과이며 최종 태그 artifact 검사를 대신하지 않는다.
- 알약 검사 로그에 기본 임시 파일 삭제 단계가 포함되어 있었다. 같은 시점 활성 TEMP 시험 프로필의 메타데이터가 사라졌으므로 이후 백신 검사는 TEMP 시험 앱을 정상 종료한 뒤 진행한다. 이 현상의 원인을 MSIX 리디렉션으로 단정하지 않는다. 시험 앱은 연결된 설정 화면에서 시험 호스트를 정상 종료하고 앱 메뉴로 닫았으며 소유한 프로세스 종료를 확인했다.
- 0.3.11 버전·README·사용자 안내·변경 이력과 배포 안내를 준비했다. 실제 공개는 아직 하지 않았다.
