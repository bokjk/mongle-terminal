# 몽글터미널 사용자 안내

이 문서는 **0.3.16 구현**을 기준으로 작성했습니다. 설치 파일과 실제 게시된 버전은 [공개 배포 페이지](https://github.com/bokjk/mongle-terminal-releases/releases/latest)에서 확인합니다.

## 처음 실행하기

지원 대상으로 개발 중인 환경은 Windows 11 x64입니다. 배포본을 설치하거나 압축을 푼 뒤 몽글터미널을 실행합니다. 처음에는 **현재 컴퓨터**와 **기본 그룹**을 표시합니다. 새 터미널을 만들고 사용할 셸과 작업 폴더를 선택하세요.

앱 아이콘은 살구색 몽글 캐릭터가 `>_` 터미널을 들고 있는 모습입니다. 설치하면 바탕화면과 시작 메뉴의 **몽글터미널** 바로가기로 열 수 있습니다. PC와 휴대폰에서 같은 세션을 보려면 각각 몽글터미널 화면으로 접속하세요. 실행되는 PowerShell은 별도 Windows 콘솔 창 없이 백그라운드에서 유지됩니다.

0.3.16 산출물 이름은 `MongleTerminal-Setup-0.3.16-x64.exe`(현재 사용자 설치)와 `MongleTerminal-0.3.16-x64.zip`(압축 배포본)입니다. 압축 배포본은 전체 폴더를 유지하고 `MongleTerminal.exe`를 실행하세요. 압축 배포본도 사용자 데이터는 아래 안내한 AppData 폴더에 저장합니다. 코드 서명이 없는 Windows 미리보기입니다.

[공개 배포 페이지](https://github.com/bokjk/mongle-terminal-releases/releases/latest)에서 설치 파일을 받았다면 실행 후 안내에 따라 설치합니다. 관리자 권한은 필요하지 않습니다. 코드 서명이 없어 **Windows의 PC 보호** 창이 뜰 수 있으며, 받은 경로를 확인했다면 **추가 정보 → 실행**을 선택합니다. **0.3.0 이하 버전은 0.3.1 이상 설치 파일을 한 번 직접 설치해야 새 업데이트 주소로 전환됩니다.** 수동 업데이트할 때는 앱 메뉴의 **완전 종료…**로 작업을 저장·종료한 뒤 새 설치 파일을 실행하세요.

PowerShell 7, Windows PowerShell, 명령 프롬프트, Git Bash, WSL 중 실제 설치된 셸을 표시합니다. 몽글터미널은 해당 셸이나 WSL 배포판을 대신 설치하지 않습니다. 이미 별도 창에서 실행 중인 PowerShell을 가져오는 기능도 없습니다. 몽글터미널 안에서 만든 세션에 다시 접속합니다.

프로그램은 로그인한 Windows 사용자 권한으로 실행합니다. 관리자 권한으로 실행하는 것을 기본 사용법으로 삼지 않습니다. 새 셸의 시작 폴더는 그룹 설정 또는 선택한 폴더를 사용합니다.

0.3.10은 첫 실행에 필요한 새 데이터 폴더를 현재 Windows 사용자 소유의 전용 폴더로 준비합니다. 관리자 권한 환경에서도 같은 보호 기준을 적용합니다. 다른 계정이 소유한 기존 데이터 폴더는 자동으로 가져오거나 소유권을 바꾸지 않습니다.

**현재 폴더 표시:** 세션 하단의 제어 상태 옆 경로는 셸이 보고한 현재 폴더입니다. 새 PowerShell·Windows PowerShell·명령 프롬프트·Git Bash 세션에서는 명령을 마치고 프롬프트로 돌아오면 갱신됩니다. 이 표시는 시작·분할·복원 폴더 설정을 바꾸지 않습니다. 셸 설정이 프롬프트 보고를 덮어쓰거나 WSL 등에서 경로 보고가 없으면 시작 폴더를 표시하고, 마우스를 올리면 구분할 수 있습니다. 기존 실행 중인 셸에는 새 보고 기능을 소급 설치하지 않습니다.

한글 입력은 조합 중에도 앞서 확정한 글자와 셸 출력을 갱신합니다. 밝은 테마에서는 흰색·밝은 ANSI 색상과 256색·RGB 글자의 대비를 보정합니다.

**0.3.10의 응답성 개선:** 작은 출력이 연속으로 들어오는 터미널과 워크트리 목록 조회의 대기 시간을 줄였습니다. 브라우저의 **다시 연결**은 이전 연결 시도를 취소하고 새 연결을 시작합니다. 이전 연결의 늦은 응답이 새 화면을 덮지 않으며, 전송 여부가 불확실한 입력은 자동으로 다시 보내지 않습니다.

- 파일 탐색기에서 폴더를 접거나 다른 터미널·폴더·미리보기로 이동하면, 아직 시작하지 않은 이전 읽기를 취소합니다. 이미 전송한 읽기가 끝날 때까지는 잠시 기다릴 수 있습니다.
- 저장 중인 그룹·터미널·컴퓨터 편집창을 닫아도 서버에 이미 보낸 작업은 완료될 수 있습니다. 늦은 완료 때문에 새로 연 입력창을 닫거나 다른 작업으로 자동 이동하지 않습니다.
- 브랜치와 태그 이름이 같으면 워크트리의 기존 브랜치 선택과 기준 브랜치 선택은 해당 로컬 브랜치를 사용합니다. 태그를 기준으로 만들려면 `refs/tags/태그이름`처럼 명확한 참조를 입력합니다.

**시작 폴더 선택:** 이 PC에 연결한 데스크톱 앱에서는 새 터미널·분할·그룹 설정의 **시작 폴더 → 찾아보기**로 Windows 폴더 선택창을 엽니다. 취소하면 기존 경로를 유지합니다. 선택한 폴더는 저장되어 다음 셸 시작과 복원에도 사용됩니다. 그룹의 기본 폴더를 바꿔도 이미 실행 중인 셸은 이동하지 않습니다. 원격 연결과 모바일 브라우저에서는 접속 대상 컴퓨터의 전체 폴더 경로를 직접 입력합니다.

## 작업 알림 — 0.3.16

작업 목록·탭·그룹과 모바일 전환 목록에서 미확인 알림을 종으로 표시합니다. 해당 터미널의 최신 화면을 보면 사라집니다. 숨긴 탭·설정창 뒤·백그라운드·연결 끊김 상태에서는 읽음 처리하지 않습니다. 시간만 지나서는 사라지지 않습니다.

읽음은 기기별로 저장됩니다. 워크트리 이름을 누르면 미확인 터미널을 먼저 열며, 여러 알림이 있으면 각각 확인해야 합니다. 소리나 OS 알림은 띄우지 않습니다.

Claude는 아래 자동 연동을 사용합니다. Codex 등 다른 CLI는 프로그램이 보낸 BEL/OSC 알림을 표시하며, 작업 중이나 성공 여부를 추측하지 않습니다. Codex는 설치한 버전의 터미널 알림 설정을 따릅니다. [기존 CLI 알림 검증](https://github.com/bokjk/mongle-terminal/blob/dev/docs/validation/cli-notifications.md).

## Claude 자동 연동과 작업 상태 — 0.3.16

지원되는 Windows 네이티브 Claude Code **2.1.292 이상**에서 몽글 실행부가 연동을 자동 준비합니다. 새 터미널에서 평소처럼 `claude`를 실행하면 되며 `preferredNotifChannel`을 수동으로 켤 필요가 없습니다. 업데이트 전에 이미 열어 둔 셸·Claude는 그대로 유지하므로 자동 연동을 사용하려면 작업을 마친 뒤 새 터미널에서 실행하세요.

| 표시 | 의미 |
| --- | --- |
| 천천히 맥동하는 표시 | Claude가 질문을 처리하거나 도구를 사용하는 중 |
| 종 · 응답 완료 | Claude가 이번 응답을 종료함. 작업이나 테스트 성공을 보장하지 않음 |
| 확인 요청 | 승인 또는 사용자 답변이 필요한 이벤트를 받음 |
| 오류 | Claude가 오류로 이번 응답을 종료함 |

작업 목록과 탭·그룹에서 상태를 구분합니다. 작업 중 표시는 천천히 맥동하며 기기의 모션 줄이기 설정에서는 움직이지 않습니다. 완료 종은 해당 터미널의 최신 화면을 확인하면 사라집니다. 작업 중 Esc·Ctrl+C를 전달하면 오래된 상태 표시를 초기화하며 완료 알림을 만들지 않습니다. Codex 등 일반 터미널의 BEL/OSC 알림은 알림으로 표시하며, 그 신호만으로 작업 중·성공 여부를 추측하지 않습니다.

연동은 Claude 사용자 설정의 다른 항목과 훅을 유지하면서 몽글용 훅만 병합합니다. 변경 전 설정은 같은 폴더의 `settings.json.mongle-backup-*`에 보존합니다. 훅은 몽글 셸의 실행별 토큰이 없으면 상태를 보내지 않으며, 훅 입력의 대화 내용·작업 경로 원문을 상태에 포함하거나 transcript·인증 파일을 읽지 않습니다. 이벤트 분류와 세션·도구 요청 구분용 해시만 전달합니다.

Claude 설정 폴더에 `mongle-terminal-hook.cjs`와 `mongle-terminal-runtime`을 보관합니다. 런타임은 앱에 포함된 파일의 검증된 복사본이며 별도 다운로드나 시스템 PATH 변경은 없습니다. 앱 삭제·ZIP 이동 뒤에도 훅 실행 경로가 깨지지 않도록 남겨 둡니다. 몽글 밖에서는 상태를 보내지 않습니다.

설정 파일이 잘못되었거나 훅 사용을 명시적으로 껐거나 쓰기 권한이 없으면 임의로 복구하거나 켜지 않습니다. **설정 → 도움말 → Claude 작업 상태와 알림**에서 연결 준비 상태와 안내를 확인합니다. 프로젝트·관리자 정책으로 훅을 막은 경우도 자동으로 해제하지 않습니다. 기존 실행부에 연결만 다시 한 경우에는 새 설치 절차가 실행되지 않습니다.

WSL·SSH 내부의 Claude, `claude -p` 같은 비대화형 실행, 다른 CLI 버전과 실물 모바일 검증은 이번 자동 연동 범위에 포함하지 않습니다. 원격 브라우저는 지원되는 Windows 호스트에서 받은 상태를 표시합니다. [구현 및 검증 기록](https://github.com/bokjk/mongle-terminal/blob/dev/docs/validation/claude-task-status.md)

## 컴퓨터 선택 메뉴

데스크톱 앱 왼쪽 위의 컴퓨터 이름을 누르면 앱 테마에 맞는 목록을 펼칩니다. 컴퓨터 이름 아래에 **이 PC** 또는 **원격 컴퓨터**를 표시하고, 현재 선택에는 체크 표시가 붙습니다. 방향키·Home·End로 항목을 이동한 뒤 Enter 또는 클릭으로 전환합니다. Escape는 선택하지 않고 닫으며 Tab은 다음 조작으로 이동합니다. 목록 바깥을 눌러도 닫힙니다. 현재 컴퓨터를 다시 선택해도 재연결하지 않습니다. 이 메뉴는 0.3.3부터 사용할 수 있습니다.

## 파일 탐색기

**0.3.16 수정:** Git Bash의 `/c/...`·`/tmp/...` 표기 대신 셸이 변환한 Windows 경로로 현재 폴더를 읽습니다. 기존 Git Bash 셸은 이전 프롬프트 설정을 유지하므로, 수정 버전의 실행부에서 새 터미널을 열면 적용됩니다. 개인 셸 설정 파일을 수정하지 않습니다.

**파일 탐색기**로 공용 패널을 열고 닫습니다. PC에서는 왼쪽 아래 버튼, 모바일에서는 상단 폴더 버튼을 사용합니다. 분할 화면 전체 오른쪽에 하나만 표시합니다. 0.3.2부터 사용할 수 있습니다.

- 터미널을 클릭하거나 키보드 포커스를 옮기면 해당 터미널의 현재 폴더를 표시합니다. `cd`로 이동하면 새 폴더로 갱신합니다. 경로를 보고하지 않는 셸에서는 시작 폴더를 표시하며 안내 문구로 구분합니다.
- 폴더를 눌러 하위 항목을 펼치고 파일을 눌러 오른쪽 편집 영역에서 엽니다. 이 조작은 터미널의 작업 폴더나 제어권을 바꾸지 않습니다. 파일이 생성·변경되면 **새로고침**을 누릅니다. 다른 터미널이나 현재 폴더로 전환하면 트리를 갱신하며 이미 연 파일 탭은 유지합니다.
- 위쪽 복사 버튼은 현재 폴더 경로, 미리보기의 복사 버튼은 해당 파일의 전체 경로를 복사합니다. 원격 연결이면 내 PC가 아닌 선택한 원격 PC의 경로입니다.
- 패널 왼쪽 경계를 끌거나 키보드 좌우 방향키로 폭을 조절합니다. 두 번 클릭 또는 Home으로 기본 폭으로 돌아갑니다. 열림 상태·폭·파일/Git 보기는 이 화면에 저장하며 다른 기기의 배치를 변경하지 않습니다. 모바일에서는 터미널 위에 패널을 띄우고 닫기 버튼이나 바깥 영역을 눌러 돌아갑니다.

파일 생성·삭제는 제공하지 않으며 기존 텍스트 편집은 아래 조건에서 지원합니다. 목록은 폴더당 최대 500개, 텍스트는 처음 64 KiB를 표시하고 제한 여부를 안내합니다. UTF-8 또는 BOM이 있는 UTF-16 텍스트만 미리 볼 수 있으며 HTML도 실행 없이 텍스트로 표시합니다. 링크·특수 파일, UNC 네트워크·WSL 경로, 앱의 인증·세션 데이터 폴더는 열 수 없습니다. 현재 폴더 밖을 보려면 해당 터미널에서 먼저 폴더를 이동하세요. 원격 호스트가 기능을 지원하지 않으면 해당 PC의 앱을 업데이트해야 합니다.

### 파일 편집과 마크다운 — 0.3.11

아래 기능은 0.3.11에 추가되었습니다. 이전 버전은 읽기 전용 텍스트 미리보기를 제공합니다.

1. 파일 목록이나 Git 변경 목록에서 파일을 누르면 오른쪽 편집 탭으로 엽니다. 텍스트 파일은 편집기로, `.md`·`.markdown`·`.mdown`은 마크다운 미리보기로 엽니다.
   Git에서 삭제를 스테이징한 뒤 같은 경로에 파일을 다시 만들었다면 작업 폴더의 새 내용을 엽니다. 폴더 조회는 탐색 위치를 바꾸면 대기 요청을 취소하지만 이미 연 파일 탭은 읽기를 계속합니다.
2. 마크다운의 **편집 / 미리보기 / 나란히 보기**로 표시를 바꿉니다. 나란히 보기는 충분히 넓으면 좌우로, 좁은 영역·휴대폰에서는 위아래로 표시합니다. 제목·목록·표·체크리스트·인용·코드 블록을 지원합니다. HTML은 실행하지 않으며 이미지 자동 로드는 하지 않습니다. HTTP(S)·메일 링크는 누르면 주소를 복사하고 상대 경로 링크는 이동하지 않습니다.
3. **저장** 또는 `Ctrl+S`로 저장합니다. 줄 번호와 기본 구문 강조를 제공하며 `Ctrl+F`로 찾기/바꾸기, `Ctrl+Z`로 실행 취소, 편집기 안의 `Ctrl+Tab`으로 파일 탭을 전환합니다. UTF-8·BOM UTF-16LE/BE와 BOM을 유지하고 편집기의 줄바꿈 형식은 처음 연 파일의 CRLF 또는 LF를 따릅니다.
4. 파일 목록을 접고, 영역 왼쪽 경계를 끌거나 방향키로 너비를 조절하고, 최대화할 수 있습니다. 편집기를 숨겨도 파일·수정 내용·실행 취소/다시 실행 기록과 커서 위치는 유지됩니다. 아래 **열린 파일**로 다시 엽니다. Windows에서 다시 실행은 `Ctrl+Y`입니다. 목록은 선택한 터미널의 현재 폴더를 따라가고 이미 열린 편집 파일은 그대로 유지합니다.
5. 수정한 탭에는 점과 **저장하지 않은 변경**을 표시합니다. 탭 닫기나 **디스크 파일 다시 열기**에서 변경을 버리려면 확인해야 합니다. 데스크톱 종료·완전 종료·업데이트 설치 전에 미저장 탭을 저장하거나 닫아야 합니다. 창을 트레이로 숨기는 동작은 편집 내용을 유지합니다. 브라우저 새로고침·닫기에는 미저장 경고를 요청합니다.

마크다운 미리보기는 입력과 별도로 처리하므로 복잡한 문서는 잠시 늦게 표시될 수 있습니다. UTF-8 기준 64 KiB 초과 내용은 미리보기를 제한합니다. 미리보기 처리에 실패해도 편집 내용은 유지되며, **편집** 모드로 전환했다 미리보기를 다시 열어 재시도할 수 있습니다.

열린 파일은 최대 24개이며 내용과 편집 이력은 현재 화면의 메모리에만 보관합니다. 새로고침을 강제로 진행하거나 앱·브라우저·PC를 종료하면 미저장 내용이 복원되지 않습니다. 작업 중 파일 내용은 localStorage·호스트의 세션 기록에 따로 저장하지 않습니다.

활성 텍스트 파일은 화면이 보일 때 5초 간격과 창 복귀 시 디스크를 확인합니다. 수정하지 않았다면 외부 변경을 반영하고, 수정 중이면 내 내용을 유지하며 경고합니다. 저장 직전에도 버전을 확인해 오래된 내용으로 덮어쓰지 않습니다. 충돌하면 **내 내용 복사**로 보관한 다음 디스크 파일을 다시 열어 수정 내용을 합치세요.

파일 크기와 UTF-8로 표현한 저장 내용은 각각 64 KiB 이하여야 합니다. 큰 파일은 처음 64 KiB만 읽기 전용으로 표시합니다. 바이너리·앱 데이터·네트워크 경로는 편집할 수 없고, 링크·하드 링크·읽기 전용 파일에도 쓰지 않습니다. 파일 생성·삭제·이름 변경은 제공하지 않습니다.

파일은 열 당시 컴퓨터의 파일입니다. 다른 컴퓨터로 전환해도 탭과 수정 내용은 유지하지만 원래 컴퓨터에 연결되어야 저장할 수 있습니다. 연결이 끊겼다가 다시 연결되면 기존 편집 권한은 만료됩니다. 내 내용을 복사한 뒤 처음 파일을 연 폴더의 터미널에서 **디스크 파일 다시 열기**로 갱신하세요. 이전 호스트에서는 편집을 지원하지 않는다는 안내와 읽기 전용 보기만 표시합니다.

### PDF 보기 — 0.3.12

0.3.12에 추가된 기능입니다. 파일 목록의 `.pdf`를 누르면 오른쪽 파일 탭에서 읽기 전용으로 엽니다. 접속한 호스트도 PDF 기능을 지원해야 합니다.

- 이전·다음 페이지 버튼을 누르거나 페이지 번호를 입력하고 Enter를 누릅니다. 확대/축소 또는 **너비 맞춤**으로 크기를 조절합니다. 문서에 텍스트 정보가 있으면 드래그로 선택할 수 있으며 스캔 이미지의 글자를 인식하는 OCR은 제공하지 않습니다.
- 암호로 보호된 문서는 뷰어에서 암호를 입력합니다. 암호를 설정이나 세션 기록에 저장하지 않으며, 탭을 바꾸거나 뷰어를 숨겼다가 다시 열면 입력이 필요할 수 있습니다.
- 파일당 최대 8 MiB, 동시에 열린 PDF 탭은 최대 4개입니다. 전체 파일 탭 24개 제한에도 포함됩니다. 초과·손상·지원하지 않는 문서는 한국어로 안내합니다.
- 숨김·탭 전환 후에도 현재 화면 안에서는 페이지와 배율을 기억합니다. 이미 읽은 PDF는 연결이 끊겨도 볼 수 있습니다. 내용은 화면 메모리에만 남으며 앱 종료·새로고침 뒤에는 다시 열어야 합니다.
- PDF의 디스크 변경은 자동으로 반영하지 않습니다. 원래 컴퓨터에 연결한 상태에서 **디스크 파일 다시 열기**를 누릅니다. 처음 연 폴더를 사용하는 터미널이 필요합니다.

PDF 수정·저장·주석·양식 입력·인쇄는 제공하지 않습니다. 문서를 외부 변환 서비스로 업로드하지 않으며 뷰어와 글꼴 자산은 앱에 포함합니다.

### Git 변경 보기

**0.3.6부터 사용할 수 있습니다.** 선택한 PC의 호스트가 Git 조회를 지원하면 파일 패널 위에 **파일 / Git**이 표시됩니다. PC·모바일에서 같은 방식으로 사용하며, 탭에서 좌우 방향키나 Home·End로 전환할 수 있습니다.

Git 보기는 현재 터미널 폴더 안의 변경을 **충돌 / 스테이징됨 / 작업 폴더 변경 / 새 파일**로 나눕니다. 브랜치와 변경 파일 개수도 표시합니다. 저장소의 하위 폴더에서 실행했다면 그 폴더 안의 변경만 보며, 전체 저장소를 보려면 터미널에서 저장소 최상위 폴더로 이동합니다. 원격 접속에서는 원격 PC의 Git을 사용합니다. Git 저장소가 아닌 폴더나 Git을 찾지 못한 경우 안내하며 파일 탐색은 계속 사용할 수 있습니다.

| 표시 | 의미 | 색 |
|---|---|---|
| `M` | 수정됨 | 황갈색 |
| `A` / `?` | Git에 추가됨 / 아직 추가하지 않은 새 파일 | 초록색 |
| `D` | 삭제됨 | 빨간색 |
| `R` | 이름 변경 | 보라색 |
| `U` | 해결해야 할 충돌 | 빨간색 |
| `C` / `T` | 복사됨 / 파일 유형 변경 | 초록색 / 황갈색 |

파일 이름에도 같은 색과 문자를 표시합니다. 폴더 옆의 작은 점은 하위에 변경된 파일이 있음을 뜻하며, 마우스를 올리거나 접근성 설명으로 상태를 확인할 수 있습니다. 스테이징 후 다시 수정하거나 삭제를 스테이징한 뒤 다시 만든 파일은 두 목록에 나타나지만 위쪽 변경 파일 개수에는 한 번만 셉니다. 이름 변경 항목에 마우스를 올리면 이전·현재 경로를 확인합니다.

파일을 누르면 **작업 폴더의 현재 내용**을 읽기 전용으로 미리 봅니다. 스테이징된 버전의 diff 화면은 제공하지 않으며, 삭제 후 다시 만들지 않은 파일은 현재 내용이 없다는 안내를 표시합니다. 커밋·스테이징·복원은 터미널에서 진행합니다.

패널이 열려 있고 화면이 보이면 Git 상태를 5초 간격으로 갱신하고 화면으로 돌아올 때 다시 확인합니다. **새로고침**으로 직접 갱신할 수도 있습니다. 자동 갱신은 펼친 폴더를 유지하며 터미널·현재 폴더가 바뀌면 이전 결과를 버립니다. Git 변경 목록은 최대 1,000개이며 제한 여부를 안내합니다. 서브모듈 내부의 미커밋 파일 변경은 상위 저장소 목록에서 조회하지 않습니다.

## 복사와 붙여넣기

**0.3.14 수정:** Claude 등 프로그램이 마우스를 직접 받는 경우에도 화면 갱신이 드래그 이동·해제 전달을 끊지 않도록 보완했습니다. 이 모드에서 `Shift+드래그`의 자동 복사 누락도 수정했습니다. 일반 드래그의 선택·복사는 프로그램 자체 기능일 수 있으며, `Shift+드래그`는 현재 터미널 화면의 텍스트를 선택합니다. 화면 밖 대화 전체가 항상 터미널 기록에 있는 것은 아닙니다.

몽글터미널은 Claude의 렌더링 설정을 강제하지 않습니다. `CLAUDE_CODE_NO_FLICKER`가 없으면 추가하지 않고, 이미 지정된 값은 유지합니다. 시스템 환경 변수·Claude 설정 파일·실행 중인 작업도 변경하지 않습니다.

**Claude의 긴 대화 복사:** `Ctrl+O`로 대화 기록 보기를 연 다음 `[`를 누르면 전체 대화를 일반 터미널 기록으로 볼 수 있습니다. 이 상태에서 드래그하고 화면 위·아래 경계 밖으로 움직여 범위를 늘립니다. 검사에서는 한글 포함 300줄의 모든 글자가 일치했습니다. `Esc` 또는 `q`로 원래 화면으로 돌아갑니다. [Claude 공식 안내](https://code.claude.com/docs/en/fullscreen#search-and-review-the-conversation)에 따른 방법이며, 현재 화면에 보이지 않는 기록도 터미널로 넘겨 선택할 수 있습니다.

Claude 2.1.291 전체화면에서는 아래쪽 `Jump to bottom` 안내가 본문을 덮은 상태로 위로 길게 드래그하면 가려진 글자가 복사에서 빠지는 현상을 확인했습니다. 같은 대화를 아래로 드래그한 검사는 300줄이 일치했지만, 안내와 겹쳐 선택을 끝내면 잘릴 수 있습니다. 실제 앱 계측에서도 Claude가 내보낸 복사 문자열부터 글자가 빠졌습니다. 몽글의 드래그 입력 수정과 별개로 남아 있는 프로그램 자체 제약입니다.

**모바일 전체화면 스크롤(0.3.14):** Claude·Codex처럼 마우스 휠을 받는 프로그램에서는 대화 위를 한 손가락으로 위아래 밀면 스크롤합니다. 프로그램 내부 스크롤은 입력이므로 다른 기기가 제어 중이면 이 기기로 제어권을 가져옵니다. 키보드 포커스는 옮기지 않습니다. 연결·제어권·화면 크기 동기화가 끝나기 전 움직임은 보내지 않으며, 동기화 중 첫 동작이 끝났다면 다시 밀어 주세요. 일반 터미널 기록은 제어권을 바꾸지 않고 읽습니다. 두 손가락 확대와 가로 이동은 스크롤 입력으로 바꾸지 않으며, 마우스 스크롤을 지원하지 않는 전체화면 프로그램에 임의의 방향키를 보내지 않습니다. 모바일 Chrome을 검증 기준으로 삼으며, Chrome의 Android 화면·터치 에뮬레이션에서 실제 Claude·Codex 연결의 양방향 스크롤도 확인했습니다. 실물 휴대폰 확인은 별도입니다.

- **복사:** 터미널 내용을 드래그로 선택하고 마우스를 놓으면 자동 복사합니다. 더블클릭으로 단어를 선택해도 복사합니다. `Ctrl+C` 또는 `Ctrl+Shift+C`도 사용할 수 있습니다.
- **긴 내용 선택:** 마우스를 누른 채 터미널 위·아래 경계 밖으로 움직이면 자동으로 스크롤하며 선택을 늘립니다. 0.3.12에서는 출력 갱신 중 스크롤이 멈추던 문제를 수정했습니다. 프로그램이 마우스 입력을 직접 받는 모드에서는 `Shift`를 누른 채 드래그해 터미널 텍스트를 선택할 수 있습니다.
- **붙여넣기:** 터미널 안에서 마우스 오른쪽 버튼을 누르거나 `Ctrl+V` / `Ctrl+Shift+V`를 누릅니다. 여러 줄은 내용을 확인한 뒤 붙여넣습니다. 다른 기기가 제어 중이어도 승인한 붙여넣기는 이 기기로 제어권을 전환하고 화면 동기화를 마친 뒤 한 번 전달합니다.
- **0.3.16 수정:** 여러 줄 붙여넣기 확인창은 처음에 **붙여넣기** 버튼을 선택합니다. 내용을 검토한 뒤 Enter로 승인하거나 Esc·취소·닫기로 취소합니다. Tab/Shift+Tab으로 버튼 사이를 이동할 수 있으며 취소하면 터미널 입력을 보내지 않습니다.
- 선택한 내용이 없을 때 `Ctrl+C`는 실행 중인 작업에 중단 신호를 보냅니다. `Shift+우클릭` 또는 제목줄 `···`에서 복사·붙여넣기 메뉴를 열 수 있습니다. 마우스를 직접 사용하는 터미널 프로그램에서는 일반 우클릭을 해당 프로그램에 전달하므로 `Shift+우클릭` 메뉴로 붙여넣습니다.
- 모바일은 제목줄 `···`의 붙여넣기 또는 키보드의 붙여넣기를 사용합니다. 브라우저에서 클립보드 접근을 거부하면 기본 `Ctrl+C` / `Ctrl+V` 또는 브라우저의 복사·붙여넣기 기능을 사용하세요.

0.3.10에서는 데스크톱 클립보드에 저장된 내용을 확인한 뒤 복사 완료로 표시합니다. 접근 거부나 다른 내용으로 변경되어 확인하지 못한 경우 오류를 안내하며, 이전 복사의 성공 표시를 남기지 않습니다. 설정의 **접속 주소 복사·연결 코드 복사**도 같은 데스크톱 경로를 사용합니다. 설정에서 복사에 실패하면 주소나 코드를 직접 선택해 복사하도록 안내합니다. 브라우저에서는 기존 브라우저 클립보드 권한을 따릅니다.

**빠른 연속 입력:** 입력 요청이 한꺼번에 쌓이지 않도록 앞선 입력의 처리를 확인한 뒤 다음 입력을 순서대로 전달합니다. 창 크기가 바뀌면 새 화면의 동기화를 기다립니다. 연결이나 제어권이 바뀌거나 셸이 다시 시작되면 아직 보내지 않은 입력은 취소하며, 전송에 실패한 입력을 자동으로 다시 보내지 않습니다.

**0.3.7 키 입력 개선:** Windows Codex CLI에서 `Shift+Enter`는 입력창 줄바꿈으로 전달됩니다. 일반 `Enter`와 구분되며, 실제 줄바꿈·실행 기능은 사용 중인 터미널 프로그램의 단축키 설정을 따릅니다. 한글 조합 중 `Shift+Enter`를 누르면 마지막 글자가 확정된 뒤 줄바꿈을 한 번 전달합니다. 확정 전에 탭을 바꾸거나 초점·제어권을 잃으면 대기 중인 줄바꿈은 취소합니다. Windows에서 검증했으며 WSL·SSH의 모든 프로그램 조합을 확인한 것은 아닙니다.

## 프로젝트와 워크트리

**0.3.7부터 사용할 수 있습니다.** 워크트리는 같은 Git 저장소에서 서로 다른 브랜치의 파일을 별도 폴더에 두는 기능입니다. 몽글터미널의 그룹은 터미널을 자유롭게 모으는 공간입니다. 한 그룹에 서로 다른 Git 저장소와 일반 폴더의 터미널을 함께 둘 수 있습니다. Windows의 짧은 경로와 폴더 별칭은 실제 위치로 비교해 같은 작업에 연결하며, 선택한 시작 폴더 표기는 유지합니다.

1. 작업할 폴더에서 터미널을 엽니다. **워크트리를 만들 기준은 해당 터미널의 현재 폴더**입니다. 현재 경로를 알 수 없으면 시작 폴더를 사용합니다. 폴더부터 시작하려면 사이드바의 **프로젝트 열기**를 누릅니다. 이 PC의 데스크톱 앱에서는 기존 프로젝트 폴더를 고르는 창이 열립니다. 원격·모바일에서는 화면에 표시된 컴퓨터의 전체 경로를 입력합니다. 등록한 프로젝트라면 기존 그룹을 재사용하고 선택한 폴더의 터미널을 찾거나 엽니다. Git 폴더가 아니면 **일반 그룹으로 열기**로 입력한 경로를 이어받아 그룹을 만들 수 있습니다.
2. 터미널 상단 오른쪽의 **+ 워크트리**를 누릅니다. 좁은 분할·모바일에서는 해당 터미널의 **··· → 워크트리**를 사용합니다. Git 저장소가 아니거나 지원하지 않는 경로에서는 비활성화하고 이유를 표시합니다. 그룹 옆 **+**는 새 그룹, 탭 옆 **+**는 새 터미널입니다.
3. 생성 화면에 표시된 **저장소 이름과 전체 경로**를 확인하고 이름과 **기준 브랜치**를 입력합니다. 기본 브랜치는 이 터미널이 위치한 작업 폴더에서 가져옵니다. 새 브랜치와 폴더 경로가 미리 표시됩니다. **생성 후 터미널 열기**는 기본으로 켜져 있습니다. 끄면 워크트리만 만들고 현재 터미널·배치를 유지합니다. 고급 설정에서 브랜치·생성 위치를 바꾸거나 기존 브랜치를 연결할 수 있습니다. 다른 워크트리에서 사용 중인 브랜치는 선택할 수 없습니다.
4. 사이드바에는 연결한 저장소의 기본 작업·워크트리와 그 밖의 터미널이 모두 표시됩니다. 기본 작업은 실제 프로젝트 폴더 이름 앞의 작은 `기본` 배지, 추가 작업은 가지 아이콘과 작업 이름으로 구분합니다. 기본 작업의 터미널 탭에도 Git 아이콘 대신 이름 앞에 `기본` 배지가 표시됩니다. 이름을 바꿔도 종류 표시는 유지됩니다. 목록은 이름과 보조 정보의 두 줄로 표시합니다. 여러 저장소가 있으면 둘째 줄에 `저장소 · 브랜치`를 표시하되 제목과 같은 저장소 이름은 반복하지 않습니다. PC 작업 행은 40px이며 모바일에서는 최소 44px의 선택 영역을 유지합니다. 긴 이름·브랜치·전체 경로는 마우스를 올려 확인할 수 있습니다. 그룹 화살표로 목록을 접고 펼칠 수 있습니다. 워크트리 이름을 누르면 이 화면에서 마지막으로 선택한 해당 터미널로 이동합니다. 터미널이 없으면 하나를 만들며, 여러 번 눌러도 중복 생성하지 않습니다. 행의 숫자는 이 그룹에 연결된 터미널 수이며 눌러 직접 선택할 수 있습니다. 종료된 출력 탭도 숫자에 포함하며, 해당 탭은 먼저 출력만 표시하고 **다시 실행**으로 셸을 시작합니다. 작업에 묶이지 않은 일반 터미널은 터미널 아이콘·이름·현재 폴더(알 수 없으면 시작 폴더)를 표시하고, 누르면 셸을 새로 만들지 않고 기존 탭으로 이동합니다. 일반 터미널의 **··· → 이름 변경**에서 사이드바·탭에 표시할 제목을 함께 바꿀 수 있습니다. 탭을 더블클릭하거나 터미널 메뉴의 **이름 변경**을 사용해도 같습니다. 새 터미널의 기본 제목은 `PowerShell`·`명령 프롬프트`처럼 선택한 셸 프로필 이름이며, `일반 폴더`는 예제에서 지정한 제목입니다. 제목을 바꿔도 실제 폴더 이름·경로·실행 중인 셸은 유지됩니다. Git 연결이 없는 그룹에서도 그룹 화살표를 펼쳐 선택할 수 있습니다. 그룹의 터미널 수는 워크트리별 연결 터미널과 개별 표시된 터미널의 합계이며, 작업 행 수와는 다를 수 있습니다.
5. 탭 제목은 `로그인 수정 · 개발 서버`처럼 워크트리 이름과 터미널 제목을 함께 표시합니다. **탭 +**는 바로 왼쪽 마지막 탭의 현재 폴더를, 분할과 `Ctrl+Shift+T`는 선택한 탭의 현재 폴더를 기본값으로 사용합니다. 현재 경로 보고가 없으면 시작 폴더를 사용하며, 열기 전에 다른 폴더로 바꿀 수 있습니다. 새 워크트리는 기준 터미널의 **+ 워크트리**로 만듭니다. 작업 행의 `···`를 누르면 버튼 바로 아래(공간이 부족하면 위)에 이름 변경·목록 새로고침 메뉴가 열립니다. 바깥을 누르거나 `Esc`로 닫으며, 방향키로 항목을 선택할 수 있습니다. 이름 변경은 화면의 이름만 바꾸고 실제 폴더·브랜치는 유지합니다.

**실제 생성 위치:** 프로젝트 안에 표시되지만 기본 파일 경로는 원래 프로젝트의 옆 폴더입니다. 예를 들어 `C:\Projects\web`은 `C:\Projects\web.worktrees\로그인-수정-고유값` 아래에 새 작업을 만듭니다. 이 경로는 생성 화면에서 확인할 수 있습니다. 기준 브랜치의 커밋부터 시작하므로 커밋하지 않은 파일, `.env`, 설치된 의존성은 자동 복사하지 않습니다. 필요한 개발 환경 준비는 각 작업 폴더의 터미널에서 진행합니다.

**선택과 제어권:** 사이드바에서 워크트리를 선택해도 다른 기기의 제어권을 가져오지 않습니다. 기존처럼 터미널 내용 클릭·명시적인 입력으로 제어권을 전환합니다. 파일/Git 패널은 선택한 터미널의 현재 폴더를 따라갑니다. 셸에서 워크트리 밖으로 `cd`하면 하단에 **다른 폴더에서 작업 중**을 표시하며 연결 이름은 유지합니다.

**닫기·복원·삭제:** 터미널 탭을 닫아도 워크트리와 브랜치는 남습니다. 다음에 이름을 누르면 새 셸을 엽니다. 창을 닫았다 다시 열면 기존 호스트의 셸에 재연결하며, 터미널 없이 만든 워크트리는 호스트를 재시작해도 자동으로 셸을 만들지 않습니다. 프로젝트 그룹을 삭제해도 작업 폴더를 지우지 않습니다. 워크트리 폴더 삭제는 해당 행의 `··· → 워크트리 삭제…`에서 별도로 확인합니다. 기본 작업·외부에서 만든 워크트리는 앱에서 삭제할 수 없습니다. 다른 그룹으로 옮긴 터미널과 종료된 탭을 포함해 연결된 터미널이 있거나, 수정·새 파일·ignored 파일·잠금·하위 모듈이 있으면 삭제하지 않습니다. 정상 삭제 후에도 Git 브랜치와 커밋은 남습니다.

**작업이 중단되었을 때:** 생성창을 닫아도 호스트의 Git 작업은 계속됩니다. 응답을 놓치면 **결과 확인**으로 같은 요청의 결과를 조회합니다. 호스트 재시작이나 저장 실패 뒤에는 **목록 새로고침**으로 실제 폴더와 작업 기록을 다시 맞춥니다. 이미 만들어진 작업을 복구하면서 임의로 터미널을 열지 않습니다. Git 오류로 일부 폴더만 남으면 보존하므로 화면의 오류와 경로를 확인해야 합니다.

선택한 Windows 호스트에 Git과 첫 커밋이 필요합니다. 첫 구현은 로컬 폴더 및 PowerShell·명령 프롬프트·Git Bash를 지원하며 WSL·UNC/네트워크 경로·bare 저장소·하위 모듈 관리는 지원하지 않습니다. 오래된 호스트는 프로젝트 기능을 표시하지 않으며 기존 터미널 기능으로 사용할 수 있습니다. 저장 형식을 갱신하므로 새 호스트로 한 번 연 세션 DB를 구버전 앱으로 다시 여는 것은 지원하지 않습니다.

## 그룹과 분할

왼쪽 그룹을 선택하면 오른쪽에 해당 그룹의 터미널을 보여 줍니다. 터미널의 분할 버튼은 선택한 영역을 좌우 또는 상하로 나눕니다. 경계를 움직여 비율을 바꾸고 최대화 기능으로 한 터미널만 크게 볼 수 있습니다. 그룹을 바꾸거나 최대화해 숨겨진 터미널도 호스트에서 계속 실행됩니다.

**0.3.4부터 영역별 탭과 간결한 제목줄을 제공합니다.** PC의 각 분할 영역에 독립된 탭 줄을 표시합니다. 새 터미널·파일 탐색기·설정은 왼쪽 아래에서 엽니다. 0.3.8부터는 아래 안내처럼 컴퓨터·작업 그룹 전환을 창의 상단 줄에 모았습니다.

- **영역 안에서 전환:** 탭 클릭 또는 `Ctrl+Tab` / `Ctrl+Shift+Tab`으로 현재 영역의 다음·이전 터미널을 고릅니다. 탭에 초점이 있으면 방향키·Home·End도 사용할 수 있습니다. 옆 영역의 선택과 분할 비율은 그대로 유지합니다. 긴 이름은 생략 표시하며 탭이 많으면 가로로 스크롤합니다. 탭 선택만으로 제어권을 가져오지 않으며 터미널 내용을 눌러 입력합니다.
- **탭 추가와 새 분할:** 영역의 **마지막 탭 바로 뒤에 있는 +** 또는 `Ctrl+Shift+T`는 그 영역에 새 탭을 엽니다. 탭이 넘치면 목록을 가로로 스크롤하며 +는 목록 옆에서 계속 사용할 수 있습니다. 영역의 좌우·상하 분할 버튼과 왼쪽 아래 **새 터미널**은 새 영역에 터미널을 엽니다. 셸과 시작 폴더 선택 화면을 취소하면 기존 배치를 유지합니다. 탭 추가는 이를 지원하는 새 호스트에 연결했을 때 가능합니다.
- **저장과 복원:** 탭 구성과 분할 배치는 호스트에 저장하여 연결된 화면에 공유합니다. 각 영역에서 선택한 탭은 컴퓨터·그룹별로 현재 앱·브라우저에 저장합니다. 다른 기기의 탭 선택은 바꾸지 않습니다. 최대화 상태에서도 해당 영역의 탭을 전환할 수 있습니다.
- **탭 닫기:** 탭의 **X** 또는 탭에 초점을 둔 **Delete**는 확인창을 엽니다. 확인하면 해당 터미널의 작업·기록을 삭제하며 같은 영역의 나머지 탭은 유지합니다. 영역의 마지막 탭을 닫을 때만 빈 영역을 없애고 분할을 합칩니다. 작업을 유지하려면 다른 탭을 선택하거나 앱 창을 닫으세요.

PC에서는 드래그로 놓을 자리를 선택할 수 있습니다.

- **탭 하나 옮기기:** **탭 제목**을 현재 영역의 왼쪽·오른쪽·위·아래 가장자리로 끌면 미리보기가 나타납니다. 놓으면 그 탭만 떼어 새 분할을 만듭니다. 나머지 탭은 원래 영역에 남으며 비활성 탭도 바로 끌 수 있습니다. 다른 영역의 가장자리에 놓아도 탭 하나만 분할하고, 다른 영역 가운데에 놓으면 해당 영역의 탭으로 합칩니다. 탭 합치기는 탭을 지원하는 호스트에서만 가능합니다. 자기 영역 가운데나 혼자 있는 탭의 자기 가장자리에 놓으면 배치를 유지합니다.
- **탭 앞뒤로 합치기·순서 변경:** 탭 제목을 같은 영역 또는 다른 영역의 탭 제목줄로 끕니다. 세로 삽입선이 나타난 위치에 놓으면 그 앞뒤로 이동합니다. + 위에 놓으면 마지막 탭 뒤에 붙습니다. 분리해 둔 탭도 같은 방법으로 다시 합칩니다. 한 영역에는 최대 16개 탭을 둘 수 있습니다.
- **기존 영역 옮기기:** 터미널 제목줄의 잡는 부분을 다른 영역의 왼쪽·오른쪽·위·아래로 끌면 반투명 배치 미리보기가 나타납니다. 놓으면 그 위치로 옮겨 분할합니다. 가운데에 놓으면 두 영역의 위치를 바꿉니다. **왼쪽 점 손잡이**로 해당 영역의 모든 탭을 함께 옮깁니다.
- **새 터미널로 분할:** 왼쪽 아래 **새 터미널** 버튼을 원하는 영역의 가장자리로 끌어 놓습니다. 대상 터미널에 기록된 셸과 시작 폴더 설정으로 새 셸 하나를 엽니다. 실행 중인 셸에서 이후 `cd`로 바꾼 폴더를 자동 추적한다는 뜻은 아닙니다. 버튼을 클릭하면 셸·시작 폴더 선택 화면을 엽니다.
- **취소와 크기 조절:** 드래그 중 Esc를 누르거나 패널 밖에 놓으면 취소됩니다. 배치 후 경계를 끌어 크기를 바꾸며, 경계 더블클릭 또는 Home으로 반반 크기로 돌아갑니다.

드래그 배치는 연결된 PC의 분할 화면에서 사용합니다. 모바일의 단일 패널 화면이나 최대화 상태에서는 분할 버튼·패널 전환을 사용합니다. 기존 탭이나 영역을 옮겨도 셸을 종료하거나 다시 실행하지 않습니다. 마지막 탭이 다른 영역으로 옮겨지면 빈 원래 영역만 정리합니다.

그룹 이름, 터미널 이름과 화면 배치는 저장합니다. 터미널을 종료하면 그 안의 셸과 연결된 작업이 끝날 수 있으므로 확인 내용을 읽고 종료하세요. 명시적으로 분리해 실행한 다른 Windows 프로세스까지 모두 끝났다고 보장하지는 않습니다.

## 간결한 PC 화면

0.3.8부터 PC 화면은 Windows 제목 표시줄과 컴퓨터 선택·작업 그룹 전환을 한 줄에 표시합니다. 최상단의 그룹 이름을 누르면 작업 공간이 바뀌고, 각 분할 영역 안의 탭은 해당 영역의 터미널을 바꿉니다. 상단의 **+**는 새 작업 그룹, 영역 탭 옆의 **+**는 새 터미널 탭입니다.

1. 왼쪽 사이드바 맨 위의 **사이드바 접기**를 누르면 목록이 44px 아이콘 줄로 바뀝니다. 같은 자리의 **사이드바 펼치기**로 돌아옵니다. 접기·펼치기 아이콘은 두 상태에서 같은 위치에 있고, 펼친 상태에서는 버튼 이름도 함께 보입니다.
2. 접힌 상태에서도 위쪽 **터미널 전환**, 아래쪽 **새 터미널·파일 탐색기·설정**을 사용할 수 있습니다. 아이콘에 마우스를 올리면 이름이 표시됩니다. 그룹 전환은 상단에서 바로 할 수 있습니다.
3. 펼친 사이드바의 경계를 끌어 너비를 바꿉니다. 경계에 키보드 초점을 둔 뒤 좌우 방향키로 조절할 수도 있습니다. 경계를 더블클릭하면 새 기본 너비인 212px로 돌아옵니다. 접힘 상태와 펼친 너비는 이 앱·브라우저에 저장됩니다.
4. **설정 → 화면 → 터미널 글자 크기**에서 10~24px를 선택합니다. 저장값이 없는 PC의 기본값은 13px, 모바일은 11px입니다(0.3.15부터 모바일 11px, 이전 0.3.14는 14px). 이전에 저장한 유효한 크기는 유지하며 여기서 직접 바꿀 수 있습니다.

사이드바를 접거나 펼쳐도 셸을 다시 실행하지 않고 기존 터미널의 크기만 맞춥니다. 모바일은 기존 서랍 메뉴·보조 키·터치 영역을 사용합니다.

## 창 닫기와 작업 종료

창의 **X**, **Alt+F4**, 앱 메뉴의 **트레이로 숨기기**는 창을 숨깁니다. 작업표시줄 오른쪽 알림 영역의 몽글 캐릭터 아이콘을 클릭하거나, 오른쪽 클릭 후 **몽글터미널 열기**를 선택하면 같은 창으로 돌아옵니다. 아이콘이 바로 보이지 않으면 숨겨진 아이콘 **^** 안을 확인하세요. 바탕화면 바로가기를 다시 실행해도 기존 창이 열립니다.

| 행동 | 결과 |
|---|---|
| 창 닫기 | 트레이에 남아 같은 셸과 작업 유지 |
| 트레이 클릭·바로가기 다시 실행 | 숨기거나 최소화한 기존 창 열기 |
| 앱 종료 · 터미널 유지 | 창과 트레이 종료, 백그라운드 세션과 원격 접속 유지 |
| 완전 종료… | 현재 PC의 배치·설정·허용된 출력 기록을 저장하고 터미널·실행부·앱·트레이 종료 |
| 터미널 종료 | 해당 셸과 연결된 작업 종료 |
| 모든 작업 종료 | 해당 컴퓨터의 몽글 실행부와 관리하는 작업 종료 |
| PC 재부팅·로그아웃·전원 종료 | 다음 앱 실행에서 마지막 저장 배치·기록과 새 셸 복원. 이전 프로그램의 실행 상태는 복원하지 않음 |
| 절전·네트워크 끊김 | 원격 화면 일시 중단; 깨어나거나 연결이 돌아오면 다시 연결 |

PC가 꺼졌거나 절전 중이면 원격에서 작업할 수 없습니다. 화면 잠금은 로그아웃과 다릅니다. 창 닫기만으로 실행부를 끝내지 않도록 설계했지만 백그라운드 실행부 자체가 비정상 종료된 경우에는 기존 프로세스 유지가 보장되지 않습니다.

로그인 시 자동 시작은 아직 제공하지 않습니다. Windows에 다시 로그인한 뒤 앱을 열면 작업 공간을 복원합니다. 트레이나 앱 메뉴의 **앱 종료 · 터미널 유지**로 종료한 뒤에는 계속 실행되던 세션에 연결합니다. 앱과 백그라운드까지 모두 끝내려면 트레이 우클릭 또는 상단 **몽글터미널 → 완전 종료…**에서 확인합니다. 다른 PC 화면을 보고 있더라도 완전 종료의 대상은 앱이 실행되는 현재 PC입니다.

완전 종료·재부팅 전 실행 중이었던 패널은 저장한 셸과 **시작 폴더**로 새 셸을 엽니다. 그룹·분할·이름·마지막으로 선택한 패널은 유지하고, 출력 기록 보관이 켜져 있으면 이전 출력을 평문 스크롤백으로 복원합니다. `이전 기록 · 새 셸 시작` 구분선은 이전 프로세스와 새 셸을 구분합니다. 셸에서 나중에 `cd`로 이동한 폴더는 현재 자동 추적하지 않습니다.

직접 `exit`하거나 **작업 종료 · 기록 유지**로 끝낸 패널은 자동 실행하지 않습니다. 저장한 셸이나 시작 폴더가 없어 다시 열지 못하면 패널에 이유를 표시하고 남아 있는 기록을 보존합니다. 이전 명령, 셸 변수, 실행 중이던 Codex·Claude·개발 서버를 자동 재실행하지 않습니다. 해당 프로그램은 새 셸에서 다시 실행하거나 그 프로그램의 세션 재개 기능을 사용하세요.

새 실행부는 종료 전 저장이 실패하면 작업을 중단하지 않고 오류를 표시합니다. 완전 종료는 실행부가 실제 끝났는지 확인한 뒤 앱을 닫습니다. 갑작스러운 전원 차단에서는 마지막 저장 이후 출력이 남지 않을 수 있습니다.

## 집·회사 PC와 휴대폰에서 접속하기

1. 작업을 실행할 PC와 접속할 기기에 Tailscale을 설치하고, 서로 접속할 수 있는 같은 네트워크에 연결합니다. 최초 Tailscale 로그인과 네트워크 정책 설정은 Tailscale에서 진행합니다.
2. 작업 PC의 몽글터미널에서 원격 설정을 열어 상태를 확인하고 원격 접속을 켭니다. 생성된 `https://컴퓨터이름.…ts.net` 주소를 사용합니다. 웹이 아닌 TCP 서비스가 443을 사용 중이면 포트가 붙은 주소가 나올 수 있으므로 표시된 주소 전체를 사용하세요. 같은 호스트 이름에 다른 웹 서비스가 있으면 포트를 나누더라도 인증 쿠키를 공유하므로 자동 설정을 중단합니다.
3. 휴대폰에서 Tailscale을 켠 뒤 작업 PC의 **설정 → 원격 연결**에 나온 QR코드를 카메라로 찍어 주소를 엽니다. 처음 접속하는 기기는 작업 PC에서 새 연결 코드를 만들고, 휴대폰에 기기 이름과 그 코드를 입력해 승인을 요청합니다. 다른 Windows PC의 몽글터미널에서는 컴퓨터 추가로 주소를 등록할 수도 있습니다.
4. 작업 PC에서 요청한 기기 이름을 확인하고 승인합니다. 코드의 유효 시간은 3분이며 한 번 사용한 코드는 다시 사용할 수 없습니다. 만료되면 새 코드를 만드세요.
5. 접속한 기기에서 그룹·터미널을 고르고 내용을 눌러 입력합니다. 다른 기기가 제어 중이어도 누른 기기로 전환되며, **가져오기** 버튼으로도 전환할 수 있습니다. 사용하지 않는 기기는 작업 PC의 연결 기기 목록에서 해제합니다.

Tailscale 연결만으로는 몽글터미널 접근 승인이 완료되지 않습니다. 몽글 승인을 받은 기기는 터미널을 통해 해당 Windows 사용자 권한으로 명령을 실행할 수 있습니다. 자신이 관리하는 기기만 승인하세요. 원격 주소는 Tailscale 내부용이며 몽글터미널은 공개 Funnel을 켜지 않습니다.

QR코드는 현재 켜져 있는 원격 접속 주소만 담으며, 기기 인증 정보나 연결 코드를 포함하지 않습니다. 앱 안에서 생성하므로 QR 생성 사이트에 주소를 전송하지 않습니다. 원격 접속을 끄면 QR이 사라지고 접속 주소를 저장해 변경하면 새 주소로 바뀝니다. 이미 승인된 휴대폰은 브라우저에 남아 있는 인증으로 이어서 접속할 수 있습니다.

이전 몽글 연결만 남아 있으면 **원격 접속 켜기**가 현재 실행부로 향하는 전용 경로를 확인해 재사용하고 관리 기록을 복원합니다. 저장된 관리 기록으로 자기 경로임을 확인한 경우에는 바뀐 내부 포트만 갱신합니다. 연결 대상이 불명확하거나 다른 웹 서비스·추가 경로·Funnel이 있으면 기존 설정을 보존하고 중단합니다. 오류를 없애기 위해 Tailscale Serve 전체를 초기화하거나 인증 파일을 지울 필요는 없습니다.

기기 인증은 최대 30일이며 로그아웃·기기 해제·원격 주소 변경·브라우저 쿠키 삭제 후에는 다시 승인이 필요할 수 있습니다. 다른 PC 목록에서 항목만 지우는 동작과 작업 PC에서 승인 기기를 해제하는 동작은 구별합니다. 연결을 허용하지 않으려면 작업 PC에서 기기 승인을 해제하세요.

## 모바일과 제어권

휴대폰에는 Tailscale 앱이 필요합니다. 몽글터미널 전용 앱 설치 없이 모바일 브라우저에서 원격 HTTPS 주소를 엽니다. 사용자가 Android 삼성 인터넷에서 접속과 키보드 수정 후 정상 동작을 확인했습니다. Safari·Chrome 등 다른 환경의 실제 검증 범위는 상태 문서를 확인하세요. 브라우저의 홈 화면 추가/설치 기능을 이용할 수 있습니다.

**0.3.15 기능 — 모바일 스크롤:** 천천히 밀면 손가락 이동을 따라가고, 빠르게 넘기면 짧게 감속합니다. 다시 터치하면 멈추며, 손가락을 잠시 멈춘 뒤 놓으면 추가로 이동하지 않습니다. 기기의 모션 줄이기가 켜져 있으면 관성을 사용하지 않습니다. 일반 기록은 기본 설정에서 손가락 이동 거리만큼 움직이되 터미널의 행 단위로 표시됩니다. Claude·Codex에는 글자 크기와 무관한 거리로 휠 입력을 보내므로 작은 글자에서 신호가 과도하게 늘어나지 않습니다. 실제 이동 줄 수는 CLI가 결정하며 일반 휴대폰 문서와 완전히 같은 픽셀 스크롤은 아닙니다.

조금 밀어도 너무 많이 이동하면 **설정 → 화면 → 모바일 스크롤 속도**에서 0.25·0.5(기본)·1·1.5·2배 중 값을 낮춥니다. 설정은 현재 브라우저/웹앱에 저장되고 다음 스와이프부터 적용되므로 터미널을 재시작할 필요가 없습니다. 다른 기기와 마우스 휠 속도는 바뀌지 않습니다. 입력 전달을 기다리는 동안의 관성 이동은 버리고, 대기가 길어지거나 제어권·화면 크기가 바뀌면 관성을 멈춰 나중에 한꺼번에 이동하지 않게 합니다. 브라우저 저장소를 지우면 기본값으로 돌아가며, 저장소 사용이 차단되면 현재 화면에서만 적용될 수 있습니다. 네트워크 지연은 감도 설정과 별개입니다. 0.3.15에 추가되었습니다.

모바일에서는 터미널 하나를 크게 표시하고 목록으로 전환합니다. 모바일의 패널 전환은 PC의 분할 배치를 지우지 않습니다. 보조 키로 Esc·Tab·Ctrl·방향키 등을 입력합니다. 모바일 화면에 맞춘 셸 크기는 제어권을 가져왔을 때 바뀔 수 있습니다.

터미널 위의 **A− / 숫자 / A+**로 글자 크기를 10~24px 사이에서 바꿀 수 있습니다. 숫자를 누르면 기본 11px로 돌아갑니다(0.3.15부터, 이전 0.3.14에서는 14px). 선택한 크기는 해당 브라우저에 저장되며, 설정의 글자 크기에도 반영됩니다. 일반 기록은 같은 손가락 이동 거리에서 작은 글자일수록 더 많은 줄이 보이고 이동합니다. Claude·Codex에 보내는 휠 입력 간격은 글자 크기에 영향을 받지 않습니다. 너무 빠르면 모바일 스크롤 속도를 낮추세요. **화면 넓게**는 컴퓨터·그룹 제목 영역을 접어 터미널 높이를 확보합니다. 같은 자리의 **기본 화면**을 눌러 복원합니다. 터미널 메뉴와 제어 상태, 패널 전환은 유지합니다. 보기 전용 기기는 글자 표시 크기만 바꾸며, 셸의 행·열 크기는 제어권을 가진 기기에서 맞춥니다.

PowerShell 같은 일반 터미널의 이전 출력은 **내용 위에서 손가락을 아래로 밀어** 볼 수 있습니다. 위로 밀면 최근 출력 쪽으로 돌아갑니다. 보기 전용에서도 기록 스크롤은 가능합니다. 화면보다 긴 기록이 있어야 이동하며, 전체 화면 프로그램 내부의 스크롤은 해당 프로그램의 조작 방식에 따릅니다.

한 터미널에는 한 기기만 입력·크기를 제어합니다. PC와 모바일 모두 **터미널 내용을 한 번 누르면** 그 기기로 제어권을 옮기고 화면 동기화 후 입력할 수 있습니다. 모바일 제목·키보드 열기, 보조 키와 승인한 붙여넣기도 같은 방식으로 동작합니다. PC의 탭은 선택만 바꿉니다. 0.3.3 이하 PC 제목은 입력을 시작합니다. 아래의 **여기서 제어 중**은 현재 상태를 나타냅니다.

기존 기기는 보기 전용으로 바뀌며 계속 같은 출력을 볼 수 있습니다. 다시 그 기기에서 터미널을 누르면 입력을 이어갈 수 있습니다. **가져오기** 버튼도 남아 있지만 평소에는 따로 누르지 않아도 됩니다. 두 기기의 입력을 동시에 합치지 않으며, 전환 도중 다른 기기가 다시 제어권을 얻으면 이미 넘긴 제어권으로 입력을 보내지 않습니다.

일반 터미널 기록 스크롤·드래그 선택·길게 누르기·여러 손가락 동작과 창 활성화·재연결만으로는 다른 기기의 제어권을 가져오지 않습니다. 위의 0.3.14 전체화면 CLI 터치 스크롤은 프로그램에 휠 입력을 보내는 조작이므로 필요하면 제어권을 가져옵니다. 더블클릭으로 단어를 선택할 때는 첫 번째 클릭이 입력 시작으로 처리될 수 있습니다. 내용이나 제목 누르기 등 직접 조작으로 전환하는 동작은 이전 실행부에서도 사용할 수 있습니다.

연결이 끊기면 입력을 중단합니다. 전송 여부가 불확실한 키 입력을 자동으로 반복 전송하지 않으며, 이 상태는 화면 터치나 붙여넣기로 해제하지 않습니다. 마지막 명령이 실행되었는지 출력을 확인한 뒤 **입력 확인 후 다시 제어**를 누르세요. 제어권 획득에 실패한 경우도 **제어 다시 시도**로 복구합니다. 브라우저가 백그라운드에서 멈춰도 작업 PC가 정상 실행 중이면 그곳의 프로그램은 계속 동작합니다.

## 기록과 개인 데이터

기본 실행부 데이터는 `%LOCALAPPDATA%\MongleTerminal`에 보관합니다. 개발 실행에서 `--data-dir` 또는 `MONGLE_DATA_DIR`을 지정하면 다른 폴더를 사용합니다. 주요 파일은 다음과 같습니다.

| 파일 | 내용 |
|---|---|
| `sessions.sqlite` | 호스트 식별자, 그룹·배치·설정, 제한된 터미널 화면 기록 |
| `auth.sqlite` | 승인 기기와 인증 관련 데이터 |
| `gateway-port.json`, `host-info.json` | 로컬 연결 포트와 실행 상태 |
| `remote-serve.json` | 몽글이 설정한 Tailscale Serve 주소 |
| `desktop-hosts.json` | 데스크톱에 등록한 컴퓨터 목록과 선택 상태 |
| `workspace-resume.json` | 이전 버전 실행부의 첫 완전 종료를 위한 일회성 패널 복원 정보. 명령·출력·인증 정보는 포함하지 않음 |
| `desktop-profile/` | 데스크톱 화면 설정과 원격 접속에 사용하는 Electron 사이트 데이터 |

SQLite의 `-wal`, `-shm` 파일도 함께 만들어질 수 있습니다. 실행 중인 데이터베이스 파일 일부만 복사해 백업하면 일관된 기록이 아닐 수 있습니다. 모든 작업을 저장하고 실행부를 정상 종료한 뒤 데이터 폴더 전체를 백업하세요. 인증 데이터가 들어 있는 백업은 다른 사람과 공유하지 마세요.

화면에 출력된 토큰·주소·문서 내용도 기록에 포함될 수 있습니다. 출력 기록 보관 설정과 기록 지우기 기능을 사용하세요. 기록 보관을 끄는 것과 현재 실행 중인 터미널의 화면이 없어지는 것은 다릅니다. 터미널 기록은 운영체제나 디스크 수준으로 별도 암호화되었다고 가정하지 않습니다.

초기화가 필요하면 먼저 원격 연결을 끄고 모든 작업을 종료한 뒤 데이터 폴더를 별도 위치에 백업하고 원래 폴더를 제거하세요. 다음 실행에서 새로운 설치로 시작하며 기존 승인 기기는 다시 등록해야 합니다. 프로그램 제거만으로 실행 중인 작업과 사용자 데이터가 모두 지워진다고 가정하지 마세요. 브라우저/PWA에 저장된 인증은 해당 사이트 데이터에서 따로 삭제할 수 있습니다.

수동 업데이트·제거는 실행 중인 작업을 저장하고 **완전 종료…**를 한 다음 진행합니다. 설치 프로그램은 `host-info.json`이 남아 있으면 작업을 보호하기 위해 진행을 멈춥니다. 이전 앱을 다시 열어 정상 종료하면 됩니다. 설치·제거는 사용자 데이터를 자동 삭제하지 않습니다. 압축 배포본도 실행부가 동작 중인 폴더의 파일을 덮어쓰거나 옮기지 마세요.

## 앱 업데이트

Windows 설치본은 앱 시작 30초 후와 6시간마다 공개 GitHub Release의 새 안정 버전을 확인하고 다운로드합니다. 새 버전을 받기 시작하면 **사이드바 아래에 업데이트 카드**가 나타나 다운로드 진행률을 보여 주고, 준비되면 **설치 후 다시 시작** 버튼을 표시합니다. 사이드바를 접어 두었다면 아래쪽 아이콘 배지를 누르면 사이드바가 펼쳐지며 카드가 보입니다. 컴퓨터 연결이 끊긴 상태에서도 카드는 표시됩니다. **설정 → 앱 업데이트**에서도 버전·진행률을 보거나 직접 **업데이트 확인**을 누를 수 있고, 앱 메뉴와 트레이에도 확인·설치 항목이 있습니다. 이는 지금 실행하는 데스크톱 앱의 업데이트이며, 선택한 다른 PC를 대신 업데이트하지 않습니다.

준비 완료 알림 후 **설치 후 다시 시작**을 누르면 현재 PC의 실행 중인 터미널 수와 종료 안내를 표시합니다. 작업을 저장한 뒤 확인하면 그룹·분할·설정된 출력 기록을 저장하고 로컬 호스트 종료를 확인한 후 설치합니다. 이 동안 카드와 설정 화면에 **설치 확인 → 작업 저장·종료 → 설치 프로그램 실행** 중 현재 단계가 표시됩니다. 설치 비율은 추정해 표시하지 않습니다. 이 PC로 들어오는 원격 연결도 잠시 끊깁니다. 다른 PC의 터미널은 종료하지 않습니다. 저장이나 정상 종료에 실패하면 설치하지 않고 앱에 오류를 표시합니다.

앱이 닫히면 몽글터미널 설치 창이 열리고 파일 설치 진행 막대가 표시됩니다. 앱 업데이트에서는 설치 위치를 다시 묻지 않으며, 설치가 끝나면 완료 페이지 없이 몽글터미널이 다시 열립니다. 자동으로 다시 열지 못하면 설치 창이 안내를 표시하므로 시작 메뉴나 바탕화면 바로가기로 실행하세요. 직접 받은 설치 파일을 실행하는 일반 설치는 기존처럼 완료 페이지에서 끝나며 앱을 자동 실행하지 않습니다.

설치 후 새 앱에서 작업 공간과 새 셸을 복원합니다. 실행 중이던 Claude·Codex·개발 서버와 저장하지 않은 프로그램 상태는 그대로 실행되지 않습니다. 다운로드만으로 작업을 종료하지 않으며, 평소 창 닫기나 **앱 종료 · 터미널 유지**에도 업데이트를 설치하지 않습니다.

ZIP 실행본·개발 실행은 수동 교체 방식입니다. 모바일 브라우저와 홈 화면에 설치한 웹앱(PWA)은 작업 PC가 제공하는 화면을 사용합니다. PC의 업데이트 설치·재시작을 마친 뒤 화면을 새로 불러와야 하며 웹앱을 다시 설치할 필요는 없습니다. 연결만 복구하는 **다시 연결**은 화면 새로고침과 다릅니다.

**0.3.15 기능 — 화면 새로고침:** 모바일 상단이나 사이드바에서 **설정 → 앱 업데이트 → 화면 새로고침**을 누릅니다. 일반 PC 브라우저에도 같은 버튼을 제공합니다. 미저장·저장 중인 파일이 있으면 버튼이 비활성화됩니다. 설정을 닫고 파일을 저장하거나 변경을 취소하고, 저장 중이면 완료를 기다린 뒤 다시 누릅니다. 열린 파일 탭·PDF 보기 상태는 닫히고 PC의 터미널 작업은 계속됩니다. 접속할 PC와 네트워크가 정상이어야 화면을 다시 불러올 수 있습니다. 새 버전 자동 감지·자동 새로고침은 제공하지 않습니다. 0.3.15에 추가되었습니다.

0.3.1부터 [배포 전용 저장소](https://github.com/bokjk/mongle-terminal-releases/releases/latest)를 사용합니다. 소스 저장소가 비공개여도 업데이트를 받을 수 있습니다. 0.3.0 이하는 한 번 수동 설치가 필요합니다. 실제 구버전 설치본의 자동 교체·재실행·기록 복원 검증 범위는 [배포 기록](https://github.com/bokjk/mongle-terminal/blob/dev/docs/validation/public-release-0.3.14.md)을 확인하세요.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| 로컬 창이 연결되지 않음 | 같은 Windows 사용자로 실행했는지 확인하고 앱을 다시 여세요. 실행부 오류가 지속되면 데이터 폴더를 보존한 상태에서 진단하세요. |
| 원격 주소가 열리지 않음 | 대상 PC 전원·절전, 양쪽 Tailscale 연결, 주소의 포트, 몽글 원격 상태를 확인하세요. |
| Tailscale 상태가 정상인데 연결 거부 | tailnet 접근 정책과 HTTPS/Serve 사용 가능 여부를 확인하세요. 기존 Serve 설정을 임의로 초기화하지 마세요. |
| 연결 코드가 실패함 | 새 코드를 만들고 3분 안에 연결한 후 작업 PC에서 승인하세요. |
