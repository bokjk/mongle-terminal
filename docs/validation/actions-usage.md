# Actions 사용량 조사와 검사 분리

## 공개 전환 후 실제 실행

2026-10-07 사용자 승인으로 소스를 공개한 뒤 PR #48의 Linux 범위·PR 본문·대상 정책 검사가 통과하고 Windows 전체 검사가 시작됐다. [설치 검사 37550221754](https://github.com/bokjk/mongle-terminal/actions/runs/37550221754)는 실제 NSIS 교체·파일 일치·작업 복원 및 정상 정리를 통과했다. [전체 검사 37550221764](https://github.com/bokjk/mongle-terminal/actions/runs/37550221764)는 별도로 완료 여부를 확인한다.

검사 중 PR 본문을 수정해도 Windows job `112563688689`와 설치 job `112563680535`는 유지됐다. 메타데이터 이벤트의 skipped 상태는 필수 `Windows checks`나 실제 설치 상태를 덮어쓰지 않았다. GitHub는 실행 전 생략한 동적 job 이름을 표현식 문자열로 표시했으며 실제 실행된 필수 상태와 구분된다. 아래 예산 차단·미적용 문구는 공개 전 기록이다.

2026-10-07에 계정의 2026년 10월 사용량과 소스 저장소 실행 기록을 읽기 전용으로 확인했다. 결제·예산·요금제는 변경하지 않았다.

## 확인된 사용량

GitHub Free 계정 화면은 Actions 2,000/2,000분, artifact 저장 할당량 0.5/0.5GB 사용을 표시했다. Actions 예산은 $0, Stop usage는 Yes였다. 사용액 환산 $12.19는 포함 사용량 할인 $12.19로 상쇄되어 Actions 청구 대상은 $0이었다. 저장소별 환산액 중 mongle-terminal은 $11.96이었다. 화면의 한도 초기화 표시는 26일 후였다. 현재 저장 파일 크기와 이번 주기의 누적 저장 사용량은 구분한다.

월간 API 실행 253건의 작업 시작·종료를 집계했다. 조회 오류·100건 초과로 잘린 작업 목록은 없었다. 아래 시간은 시작한 작업의 경과시간 합계이며 청구 분 단위 반올림·운영체제별 한도 환산과는 다르다. 횟수는 시작 전 예산 차단·취소를 포함한 workflow 요청 수이며 재시도 작업 수와도 다르다.

| 작업 | 요청 수 | 작업 경과시간 합계 |
|---|---:|---:|
| Contribution checks | 116 | 729.4분 |
| Installed upgrade validation | 35 | 189.2분 |
| Windows release draft | 10 | 131.1분 |

실패 작업은 156.3분, 취소 작업은 106.7분을 소비했다. 전체 검사가 반복 시작된 같은 head SHA는 23개(작업 51개)였다. 반복이 모두 불필요한 것은 아니지만 PR 설명 수정·draft 해제에도 전체 검사를 다시 실행했고, PR 검사 뒤 dev/main push가 다시 전체 검사를 실행하는 중복이 있었다.

## 변경한 검사 경계

- PR description: 제목·본문·커밋 변경과 draft 해제에서 Linux/Node 24만 사용한다. 의존성 설치 없이 기존 PR 계약을 검사한다. 별도 필수 상태로 ruleset 정의에 추가한다.
- CI scope: `dev` 대상 PR의 루트 README/CHANGELOG/CONTRIBUTING/SECURITY/AGENTS 및 docs 아래 Markdown 추가·수정만 경량화한다. 문서도 패키징 입력일 수 있으므로 모든 삭제·파일 유형 변경은 전체 검사로 보내고, 이름 변경 양쪽을 비교한다. 미확인 경로·빈 목록도 전체 검사로 보낸다. 비교 실패나 문서 검사 실패는 필수 상태를 실패시킨다.
- 문서 PR: Linux 문서 검사 결과를 Windows checks라는 기존 필수 상태에 전달하되, 요약에 Windows 런타임 미실행을 표시한다. 성공한 문서 검사를 실제 Windows 검증으로 표현하지 않는다.
- 코드 PR·배포 PR·수동 실행: Windows 타입·빌드·네이티브·전체 회귀 검사를 유지한다.
- PR 설명 수정은 코드 검사와 다른 concurrency 그룹과 상태 이름을 사용한다. 진행 중인 코드 검사를 취소하거나 실패한 Windows checks를 skipped 성공으로 덮어쓰지 않는다. base 변경은 재검사한다.
- 병합 뒤 dev/main push의 전체 검사는 제거한다. 병합 전 최신 base를 반영하도록 ruleset 정의와 유지보수 절차를 함께 갱신한다. 서버 측 ruleset 적용은 별도이며 현재 무료 비공개 계정에서는 미적용이다.
- 공개 협업 기준으로 모든 코드 PR의 전체 회귀를 유지한다. 변경 파일에 해당하는 일부 테스트만 고르는 방식은 도입하지 않는다.
- 별도 설치 리허설만 웹 UI와 알려진 개발 문서의 추가·수정에서 생략한다. Windows 아이콘 원본, 동봉 사용자 안내·제3자 고지·라이선스, 데스크톱·호스트·패키징·의존성·설정·시험·미확인 경로 및 모든 삭제·파일 유형 변경은 수행한다. 배포 PR·수동 실행은 항상 수행하며 판정 실패 시 실패한다. PR 설명 수정은 별도 상태·동시성 그룹으로 분리하고 생략 시 실제 설치 미실행을 표시한다.
- 최종 태그 배포 workflow의 패키지·NSIS 검증은 변경하지 않는다. 저장소 공개 범위·라이선스·결제 설정은 그대로다.

## 검증과 남은 범위

- `npm.cmd run typecheck`: 통과.
- CI 범위·PR 계약·브랜치 정책·배포 문서 관련 검사: **35 통과, 실패·생략 0**. 실제 임시 Git 저장소의 코드→문서 이동·코드 삭제·문서 삭제를 확인하고, node_modules 없는 폴더에서 Node 24로 판정 CLI를 실행했다. 잘못된 이벤트에서 출력 없이 실패하는 것도 확인했다. UI 변경의 전체 회귀 유지·추가 설치 검사 생략 및 설치 입력 예외도 확인했다.
- actionlint **1.7.12**: 변경한 세 workflow 검사 통과(shellcheck·pyflakes는 사용하지 않음). 공식 Windows 배포 ZIP의 SHA-256 `6e7241b51e6817ea6a047693d8e6fed13b31819c9a0dd6c5a726e1592d22f6e9`를 확인한 뒤 실행했다.
- `node scripts/release-check.ts`, `git diff --check`: 통과.
- 독립 코드 검토에서 문서 삭제와 최신 base 확인의 필요성을 지적받아 삭제 시 전체 검사 및 최신 base 반영 절차를 보완했다. 서버 규칙이 미적용이므로 유지보수자는 검사 당시 base SHA와 병합 직전 base SHA를 대조해야 한다. 다르면 브랜치를 갱신하고 재검사한다.
- 설치 범위의 독립 검토에서 웹 아이콘 원본이 Windows 설치·제거 아이콘에도 쓰이는 점을 지적받아 해당 파일을 설치 검사 필수 예외에 추가했다.

실제 Actions 이벤트별 실행, 상태 이름·동시성, Linux 환경에서의 실행은 예산 제한으로 아직 확인하지 않았다. 로컬 검사로 GitHub 실행·서버 측 ruleset 적용·공개 배포를 대신하지 않는다. CI 구성은 병합 전 후보이며, 0.3.14 배포 후보 PR #47과 분리되어 있다.
