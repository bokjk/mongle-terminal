# 원격 접속 QR

2026-09-29, Windows x64. 원격 접속 주소를 휴대폰에서 직접 입력하지 않고 카메라로 열 수 있도록 설정 → 원격 연결에 QR을 추가했다.

## 동작

- 현재 컴퓨터의 원격 접속이 켜져 있고 저장된 HTTPS 주소가 있을 때 QR을 표시한다. 입력 중인 미저장 주소는 반영하지 않는다.
- QR은 `qrcode.react`로 기기 안에서 만든다. 외부 이미지 서비스 요청, 연결 코드, 인증 토큰은 포함하지 않는다. 기존 최초 연결 코드·PC 승인 절차를 유지한다.
- 검정/흰색, 4모듈 여백, 232px 크기로 표시하고 좁은 화면에서는 안내문을 아래에 배치한다. Tailscale을 켠 휴대폰의 카메라로 스캔한다.
- 원격 끄기·원격 사용자 화면에는 QR을 표시하지 않는다. HTTPS origin 이외의 경로·쿼리·프래그먼트·사용자 정보가 들어간 주소도 표시하지 않는다.

## 검증

- `tests/ui/remote-qr.test.ts`와 기존 설정 UI 검사 2/2 통과. Chrome에서 실제 SVG를 표시 크기로 래스터화하고 jsQR로 정확한 주소를 복원했다. 별도 HTTPS 포트가 포함된 주소도 확인했다.
- 저장 전/후 주소, 연결 코드 생성 후에도 URL만 포함하는지, 원격 끄기/켜기, 비소유자 화면, 잘못된 주소 차단, 외부 QR 서비스 호출 없음 확인.
- 데스크톱과 320px 화면의 다크/라이트 스크린샷을 확인했고 가로 넘침이 없다.
- `npm run typecheck`, `npx vite build` 통과. 기존 대형 웹 번들 안내 외 빌드 오류 없음. 제3자 고지 검사 30개 production 패키지·33개 고지·오류 0.
- 현재 저장된 접속 주소의 QR 이미지도 별도로 생성하여 해독 검사했다. 실제 휴대폰 카메라 스캔은 사용자 확인 대상이다.

검사 스크린샷과 개인 접속용 이미지는 커밋하지 않는 `test-results/remote-qr/`에 보관한다. 현재 실행본 적용 결과는 아래에 별도로 기록한다.

## 현재 실행본 적용

**후속 복구 완료:** 아래 초기 적용의 차단 사유는 MSIX 설정 폴더 분리로 확인되어 복구했다. 실제 사용자 호스트에서 원격 접속 켜기 반복·HTTPS 응답·최신 QR 자산 제공·기존 터미널 유지까지 검증했다. [실제 프로필 복구](msix-profile-recovery.md)를 최신 상태로 삼는다. 아래 내용은 복구 전 경과다.

- `release/win-unpacked/resources/hostbundle/dist/web`에 웹 파일과 제3자 고지를 적용했다. 교체한 모든 웹 파일의 SHA-256이 빌드 결과와 일치하며, 실행 중인 로컬 게이트웨이도 새 QR 번들을 제공한다. 이전 웹 파일은 `.test-data/remote-qr/previous-web`에 보존했다.
- 실행 중인 GUI·호스트를 종료하지 않았다. 호스트 PID·bootId와 호스트 실행 코드 해시가 그대로임을 확인했다. 외부 소유자 IPC 인증 실패 때문에 터미널별 상태 조회는 수행하지 못했다.
- 사용자 Explorer에서 실행된 현재 앱에는 기존 소유자 연결 프로세스가 남아 있으나, 작업 도구의 별도 클라이언트는 `Owner IPC server authentication failed.`로 실패한다. 현재 호스트가 응답하는 포트와 도구가 읽는 저장된 원격 포트도 다르다. 같은 경로의 파일 상태가 실행 맥락에 따라 다를 가능성을 조사했으나 원인은 확정하지 않았다. 인증 파일이나 사용자 데이터를 초기화하지 않았다.
- 저장된 HTTPS 주소는 이 확인 시점에 502였고, 현재 게이트웨이는 그 Host 헤더를 허용하지 않았다. 원격 연결을 임의 우회하지 않았으며, 현재 앱의 기존 연결에서 **원격 접속 켜기**를 실행하도록 요청했다.
- 현재 떠 있는 GUI의 새 QR 화면 확인, 후속 HTTPS 접속, 실제 휴대폰 스캔은 아직 미확인이다. 새 GUI는 다음 정상 앱 재실행 시 적용된 웹 파일을 읽는다. 원격 접속 QR 이미지 자체는 별도로 열어두었다.

적용 증거: `test-results/remote-qr/deployment.json`. 이전 원격 복구 검증은 당시 실행본의 결과이며, 이번 새 실행 맥락의 접속 성공을 대신하지 않는다. 기존 `release-autoupdate/`의 NSIS·ZIP에는 QR 변경이 포함되지 않아 공개 배포 전 전체 패키징이 필요하다.
