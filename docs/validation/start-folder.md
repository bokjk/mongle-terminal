# 시작 폴더 선택 검증

2026-09-29, Windows 배포 앱 기준.

- 이 PC 연결의 새 터미널·좌우/상하 분할·그룹 설정에 `시작 폴더 → 찾아보기`를 추가했다. Electron의 폴더 전용 선택창을 사용하며 경로 직접 입력도 유지한다.
- 선택 취소는 기존 경로를 보존한다. 요청 중 중복 선택과 저장을 막는다. 신뢰한 앱 화면에서만 호출 가능하며 원격 연결·연결 변경·완전 종료 중에는 로컬 경로를 반환하지 않는다.
- 버튼으로 분할할 때도 대상 터미널의 저장된 셸과 시작 폴더를 기본값으로 사용한다. 원격/모바일은 대상 컴퓨터의 경로를 직접 입력한다.
- `tests/e2e/start-folder.test.ts`: 실제 패키지의 화면·preload·IPC·호스트·ConPTY를 연결해 취소, 한글·공백 경로 선택, 그룹 저장, 개별 터미널 시작 위치(`Get-Location`), 분할 상속, 없는 경로 거부, 새로고침 후 PID/폴더 유지, 잘못된 IPC 인수 거부, 원격 화면에서 로컬 선택창 숨김을 검증했다. 테스트 프로세스 정리도 확인했다.
- OS 폴더 선택창의 반환값만 자동화용으로 대체했다. Windows 선택창 내부의 실제 마우스 조작은 자동화하지 않았다. 결과: `test-results/e2e/start-folder/result.json`, 화면: `folder-selected.png`.
- 테스트 데이터는 기존 배포 검증처럼 Windows 임시 폴더를 사용한다. 프로젝트 내부 테스트 데이터 위치에서는 앱이 초기 연결에 도달하지 못해 해당 위치의 시도는 실패했다. 실제 사용자 데이터와 실행 중인 세션은 테스트에서 사용하지 않았다.

## 현재 앱 적용

- 최종 설치/ZIP 빌드와 네이티브 의존성·아이콘·ZIP 검사가 통과했다. 최종 패키지 E2E는 4.96초에 통과했다.
- 현재 `release/win-unpacked`의 EXE·ASAR·웹과 설치/ZIP을 갱신했다. 7개 산출물 SHA256 일치를 확인하고 `release/SHA256SUMS.txt`에 기록했다.
- GUI만 29920 → 47032로 교체했다. 백그라운드 호스트 33652와 boot ID는 유지했다. 사용자 데이터와 인증 비밀값을 변경하지 않았다.
- **실사용 연결은 미해결:** 적용 전 로컬 진단 연결에서 `Owner IPC server authentication failed.`가 발생했고, 적용 후 실제 앱 화면에서도 같은 경고와 오프라인 상태를 확인했다. 기능 E2E 통과가 이 기존 인증 오류의 해결을 뜻하지 않는다. 현재 저장소의 터미널은 0개였고, 이 업데이트에서 터미널이나 그룹을 삭제하지 않았다.
- 적용 증거: `test-results/start-folder-rollout/deployment.json`, `actual-ui.json`. 실제 창에서 폴더 선택을 사용하려면 로컬 인증 오류 해결이 필요하다.
