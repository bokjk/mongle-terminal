# PDF 보기 검증

검사일: 2026-10-06. 개발 변경이며 공개 0.3.11 설치본에 적용하거나 배포하지 않았다. 기존 드래그 선택 변경의 검사는 [별도 기록](terminal-drag-scroll.md)을 따른다.

## 구현 범위

파일 목록의 PDF를 기존 오른쪽 탭으로 열고 현재 페이지 하나를 표시한다. 페이지 이동/번호 입력, 확대·축소/너비 맞춤, 텍스트 레이어, 암호 입력을 지원한다. 편집·주석·양식·인쇄·OCR은 제외한다. 8 MiB/파일, PDF 4탭(전체 24탭에 포함), 64 KiB 분할 읽기로 제한한다. 활성 뷰어만 Worker를 유지하며 숨김/탭 전환/닫기에서 종료한다. 원본 바이트와 페이지·배율은 화면 메모리에만 유지한다.

호스트 `files.pdf`는 기존 승인 연결·hostId/bootId·터미널 generation/현재 폴더·동시 읽기 제한을 공유한다. 보호된 앱 데이터·경로 탈출·네트워크/특수 경로를 거절하며, 읽는 동안 파일 식별자·크기·수정 정보를 검사한다. 청크 버전/오프셋/크기를 클라이언트에서도 검사하고 취소·연결 변경 뒤 결과를 버린다. 편집 권한을 발급하지 않는다.

`pdfjs-dist` 6.4.299(Apache-2.0)는 lazy import하며 Worker·CMap·기본 글꼴·JS 이미지 디코더를 로컬에 동봉한다. 기존 CSP를 완화하지 않았고 외부 PDF 업로드·문서 JS/주석 액션·XFA는 사용하지 않는다. 한 캔버스는 12 Mi 픽셀, 페이지 표시 크기는 최대 8192px로 제한한다. 읽기 제한이 모든 PDF의 처리 비용을 보장하지 않으므로 로드/렌더 시간 초과 안내도 둔다.

## UI 참고

Aside에서 Mobbin 공개 **Midday Web Invoice Preview** 사례를 직접 열고 문서 이미지를 확인했다: [참고 화면](https://mobbin.com/explore/screens/da25cdb4-9505-4404-b7ea-8ad9b2668f9f). 중립 배경 위 흰 문서와 분리된 도구 영역을 참고하고 기존 파일 탭·아이콘·테마에 맞췄다. PDF 전용 사례 전체나 로그인 뒤 자료를 확인했다고 주장하지 않는다.

## 자동 검사

격리 프로필에서 Node 24로 수행했다. 아래 합계는 **31 통과, 실패 0, 생략 0**이며 게이트웨이 재실행은 중복 집계하지 않는다.

| `tests/security/gateway.test.ts` | 15 | 승인 전 PDF RPC 거부, 승인 후 경로, 정적 PDF 자산 MIME 및 기존 게이트웨이 회귀 |

타입 검사·전체 빌드·제3자 고지 strict 검사도 수행했다. 고지는 161개 production 패키지/164개 고지이며 PDF.js에 동봉된 글꼴·CMap·디코더 원문을 포함한다. 선택적 canvas 플랫폼 패키지의 누락된 라이선스 파일은 저장소·버전이 같은 부모 npm 패키지 원문으로 출처를 표시한다. 빌드의 기존 500 kB 초과 청크 경고는 남는다. 새 PDF 미리보기 청크 약 436 kB, Worker 약 1.19 MB는 PDF를 열 때 불러온다.

의존성 audit에는 기존 Electron 패키징 도구 계열 10건(중간 8/높음 2)이 남았고 새 pdfjs/canvas 항목은 없었다. audit 결과가 전체 앱 보안이나 모든 PDF의 안전성을 보증하지는 않는다.

## Aside 실제 UI 검사

시험 문서는 ReportLab/pypdf로 생성한 한글·영문 3페이지(세로 2/가로 1), 암호 PDF, 손상 파일, 8 MiB 초과 파일이다. 임시 폴더의 실제 HostCore 및 자체 cmd 세션에 연결했다. 파일 UI·문서 훅·뷰어·CSP는 제품 코드를 사용했으나 요청 전송은 loopback HTTP 시험 어댑터이며 실제 OwnerPipe/WebSocket 원격 E2E와 구분한다.

- 한글 문서 화면을 직접 확인하고 텍스트 레이어 원문을 대조했다. 페이지 버튼·번호 Enter·확대/축소·너비 맞춤을 조작했다.
- 틀린 암호 안내와 올바른 시험 암호로 열기, 손상 파일·8 MiB 초과 안내를 확인했다.
- 마크다운 탭 전환·숨김에서 PDF 캔버스가 사라지고 Worker가 종료됨을 계측했다. 재표시 때 청크 재조회 없이 페이지·배율이 복원됐다.
- 연결 끊김을 시험 어댑터에서 모의하여 읽어 온 PDF가 유지되고 다시 읽기가 비활성화됨을 확인했다.
- 연속 확대/너비 맞춤 검사에서 `RenderingCancelledException`을 발견했다. 처음에는 렌더 취소·페이지 정리의 경합으로 판단하여 작업 직렬화, 완료된 렌더의 중복 취소 방지, 현재 페이지 자원 유지로 보완했으나 오류가 재발했다. 추가 측정에서 브라우저가 약 1프레임/초로 제한됨을 확인했다. PDF.js의 프레임 기반 렌더가 30초 벽시계 제한에 걸리고, 취소 예외가 시간 초과 안내를 덮는 문제가 있었다. 렌더 제한을 화면 프레임이 진행한 시간으로 계산하고 취소 전에 작업 종료를 표시해 시간 초과 안내를 보존한다. 문서 파싱 Worker의 30초 로드 제한은 유지한다.

최종 수정 후 가로 3페이지에서 확대/너비 맞춤 6회, 밝은 테마·오프라인에서 3회를 반복했다. 후속 확인에서 로딩 종료(`aria-busy=false`), 오류/경고 0개, 페이지의 한글·영문 텍스트 일치와 실제 화면 표시를 확인했다. 밝은 테마에서 배율·페이지 수 글자 대비도 명시적으로 테마 색을 적용했다. 릴리스 문서 검사와 `git diff --check`를 통과했다.

## 후속 검증 — 2026-10-06

사용자의 추가 테스트 요청으로 이전에 미완료였던 Electron file URL 검사를 수행했다. 모든 시험 프로필·셸·생성 문서는 임시 폴더에 격리했다.

| 영역 | 실제 확인 결과 |
|---|---|
| Electron file URL | sandbox/contextIsolation/nodeIntegration 설정을 제품과 맞춘 전용 파일 뷰어 창에서 한글 3페이지 표시, 다음 페이지, 암호 입력 후 렌더, 비내장 한글 CID 글꼴/CMap·Helvetica, 6,304,123바이트 이미지 PDF 표시를 native UI로 확인했다. 전송 어댑터는 시험용이며 실제 제품 전체 창 조작과 구분한다. |
| 패키지 실행 | `release-pdf-validation/win-unpacked/MongleTerminal.exe`를 새 임시 프로필로 실제 실행했다. 제품의 OwnerPipe 연결·`files.pdf` 지원과 6,304,123바이트 PDF의 원문 일치를 확인했다. 시험 스크립트의 초기 GUI 종료 호출이 실패하여 수정했고 최종 실행은 GUI와 호스트의 정상 종료·readiness 기록 제거까지 통과했다. 실사용 앱은 변경하지 않았다. |

관련 자동 검사 범위는 기존 31개에 새 PDF 게이트웨이 1개와 HTTPS 전송 1개를 더한 **33개**다. 후속 작업에서는 추가 2개와 타입 검사·패키지 빌드·파일 해시·diff 검사를 수행했으며 이미 통과한 31개를 전체 재실행한 것으로 집계하지 않는다. 제품 소스 추가 수정 없이 검사와 기록을 보강했다.

## 남은 범위

실제 NSIS 설치/버전 교체, 실제 Tailscale 네트워크·실물 모바일 기기, 모든 PDF 압축·글꼴·양식 유형, PDF 선택에서 OS 클립보드까지의 복사 E2E는 미수행이다. 모바일 폭 검사는 실물 휴대폰 검사를 대체하지 않는다. 기존 0.3.11 버전 이름으로 만든 격리 시험 산출물이며 설치본 적용·새 버전 공개 배포는 하지 않았다.
