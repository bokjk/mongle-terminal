# 실제 Windows 앱의 Claude 드래그 검사

2026-10-06, `fix/claude-selection-live`. 구현과 격리 시험 단계이며 새 버전 공개·설치 완료가 아니다.

## 이전 검증의 한계

0.3.12의 [드래그 검사](terminal-drag-scroll.md)는 일반 xterm 선택과 동일한 전체 프레임의 반복, 시험용 전송·클립보드 경계였다. 실제 Claude 대화와 프로그램 자체 마우스 선택 경로를 검증하지 않았다. 그 결과를 실제 Claude 문제 전체 해결로 해석하면 안 된다.

## 실제 재현 환경

- 공개 ZIP에서 추출한 몽글터미널 0.3.12 Windows 실행 파일을 별도 TEMP 프로필로 실행했다. 기존 설치본·사용자 호스트·터미널은 종료하거나 교체하지 않았다.
- Claude Code 2.1.289의 실제 로그인된 대화에서 도구가 필요 없는 번호·영문·한글 시험 문장을 생성했다. `--safe-mode --tools "" --no-chrome`을 사용했으므로 사용자 플러그인·훅 설정까지 같은 환경은 아니다. 개인 작업 출력이나 인증 데이터는 저장소에 넣지 않았다.
- 실제 창은 Windows 마우스로 조작하고 확인했다. 재현 가능한 느린 드래그는 같은 실행 파일의 Electron `webContents.sendInputEvent`로 150ms 간격 이동을 전달했다. 웹페이지·모의 Claude 응답으로 대체하지 않았다.
- 격리 앱의 정상 IPC 요청과 실제 Windows 클립보드를 비교했다. 수정 후 검사는 이 시험 실행본의 웹 자산을 현재 빌드로 교체하고 화면을 다시 연 결과다. 새 NSIS/ZIP 전체 검증이나 사용자 설치본 업데이트는 아니다.

## 원인과 수정

1. 실제 Claude 응답은 `mouseTrackingMode=any`, SGR 마우스, 대체 화면을 사용했다. 빠른 6줄 선택은 성공했지만 누름 뒤 200ms, 각 이동 사이 150ms를 둔 드래그에서는 `terminal.input`에 누름 한 건만 남고 이동·해제가 사라졌다.
2. 전체 프레임 표시의 `terminal.reset()`이 잠깐 마우스 모드를 NONE으로 바꾼다. xterm은 그때 document의 이동·해제 리스너를 제거한다. 이후 ANY 복원은 다음 누름을 준비할 뿐 진행 중인 제스처의 document 리스너를 다시 붙이지 않는다.
3. 실제 프레임의 마우스 모드는 먼저 반영하고, 화면 복원 중 발생하는 일시적인 프로토콜 알림만 억제한다. 완료·실패 시 알림을 복구하며, 실제 모드 변경은 그대로 반영한다. 마우스 입력 권한·입력 큐·호스트 인증은 바꾸지 않는다.
4. `Shift+드래그`에서는 xterm이 시작 이벤트의 버블링을 중단한다. TerminalPane이 시작을 놓쳐 자동 복사를 실행하지 않았으므로 시작 감지를 캡처 단계로 옮겼다.

## 실제 확인 결과

- 수정 전 빠른 일반 드래그: 응답 완료 후 6줄, 다음 응답 생성 중 기존 6줄 모두 복사됨. 빠른 동작만 검사하면 실패를 놓쳤다.
- 수정 전 느린 일반 드래그: 누름 1건, 이동·해제 0건. 실제 앱에서 선택 범위를 늘리지 못함.
- 수정 후 같은 Claude 세션의 느린 드래그: 누름·이동 12회·해제 전부 전달. LIVE-263~268의 6줄, 359자가 실제 클립보드에 들어옴.
- 수정 후 Shift 선택: 한글 포함 6줄의 모든 글자가 일치(터미널 화면의 앞뒤 패딩 제외), 앱의 클립보드 쓰기 1회, 그 쓰기 문자열과 실제 클립보드는 완전히 일치. CLI 마우스 보고는 전송하지 않음.
- 수정 후 영문 긴 선택: 화면 위 경계에서 2초 유지하며 자동 스크롤. ASCII-001~060의 60줄이 번호·본문·끝 표시까지 전부 원문과 일치. 앱의 클립보드 쓰기는 0회로 프로그램 자체 복사 경로임을 확인.
- **미해결:** 한글을 포함한 긴 응답 123줄 선택에서는 줄 번호는 연속이지만 스크롤로 지나간 일부 줄의 `END-번호` 끝이 빠졌다. 전체 원문 비교는 실패다. 짧은 선택과 영문 긴 선택의 성공으로 이 현상을 덮어 완료 처리하지 않는다. 별도 프로그램·버전 대조 없이는 Claude 자체 결함으로 확정하지 않는다.

## 자동 검사와 남은 범위

- 타입 검사와 웹·호스트·데스크톱 빌드 통과. 기존 청크 크기 경고는 남아 있다.
- 마우스 알림 회귀 3개와 엔진·기록 복원·입력 큐 관련 검사: 44 통과, 실패·생략 0.
- 기존 브라우저 회귀 파일에 CLI 마우스 DRAG/ANY의 프레임 사이 이동·해제 2개 및 Shift 자동 복사 1개를 추가했다. 이 작업의 로컬 화면 검사는 네이티브 앱으로 진행했으며 해당 Chrome 회귀는 아직 실행하지 않았다.
- 실제 응답 생성 중 기존 내용 선택, 출력 완료 후 선택, 느린 드래그, 화면 경계 자동 스크롤, Windows 클립보드를 확인했다. 모든 스트리밍 타이밍·CLI 사용자 설정·버전·Codex·원격 웹·모바일을 검증한 것은 아니다.
- 전체 CI·새 패키지 검증·공개 배포·실사용자 확인은 미수행이다. 긴 한글 복사 누락도 남아 있으므로 전체 드래그 문제 해결 또는 배포 준비 완료로 표시하지 않는다.
