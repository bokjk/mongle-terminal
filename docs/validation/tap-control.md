# 화면 클릭·터치로 입력 시작

> **이전 동작의 검증 기록입니다.** 이 문서의 ‘다른 기기가 제어 중이면 가져오기 버튼 필요’ 및 ‘이전 실행부는 수동 버튼만 지원’ 정책은 후속 수정으로 바뀌었습니다. 현재는 PC·모바일 모두 내용·제목 클릭과 직접 입력 조작으로 제어권을 전환합니다. 현재 동작과 검증 범위는 [PC·모바일 입력 전환](input-handoff.md)을 따릅니다. 아래 결과는 당시 검사·적용 이력으로 보존합니다.

2026-09-29, Windows x64. 원격·모바일에서 매번 별도 제어 버튼을 눌러야 했던 조작을 줄인다.

## 동작과 보호 조건

- 제어자가 없는 터미널은 내용 클릭·터치 또는 모바일 키보드 버튼으로 입력을 시작한다. 모바일 키보드 포커스는 사용자 입력 이벤트 안에서 동기적으로 처리하고, 화면 동기화가 끝나기 전에는 입력을 호스트로 보내지 않는다.
- 다른 기기가 제어 중이면 자동으로 가져오지 않는다. 명시적인 가져오기는 기존 전환 방식으로 처리한다.
- 호스트는 `control.acquire-if-free` 지원을 알리고, 자동 요청의 `takeover:false`를 처리할 때 다른 기기의 유효한 제어권이 있으면 변경 전에 거부한다. 구형 클라이언트의 기존 명시적 전환은 유지한다.
- 스크롤, 드래그 선택, 길게 누르기, 여러 손가락 동작은 자동 취득에서 제외한다. 전송 여부가 불확실한 입력은 재전송하지 않고 명시적인 상태 확인·복구를 유지한다.
- 지원 기능이 없는 구형 실행부에는 자동 취득을 시도하지 않고 기존 수동 버튼을 유지한다. 새 호스트를 적용하려면 실행부를 정상 종료한 뒤 다시 실행해야 한다.

호스트 지원 여부는 저장된 설정이나 앱 버전 문자열로 추정하지 않고 현재 연결된 실행부의 지원 목록으로 확인한다. 따라서 새 파일만 교체한 동안에는 기존 실행부가 수동 모드로 동작하며, 정상적인 완전 종료·재실행 후 자동 취득이 활성화된다.

모바일 검사는 실제 Chrome의 모바일 화면·터치 에뮬레이션이다. 이번 변경 후 실제 Android 삼성 인터넷에서 소프트 키보드와 손가락 조작은 아직 사용자 확인 전이다. 이전 키보드·스크롤 수정의 실물 확인을 이번 변경의 실물 확인으로 간주하지 않는다.

## 실제 적용과 검증 한계

현재 실행본의 `resources/hostbundle/dist/host`와 `dist/web`에 최종 파일을 적용했다. EXE·데스크톱 ASAR·인증 키·설정 DB·Tailscale 설정은 교체하거나 초기화하지 않았다. 파일 적용 전 사용자 호스트는 이미 종료됐고 저장된 패널의 `resumeOnBoot`가 참인 상태였다. 다음 실행에서 그 패널이 새 셸로 복원됐음을 확인했으며, 이 적용을 이전 PID나 프로세스 메모리를 유지한 업데이트로 표현하지 않는다. 기존 파일은 프로젝트의 별도 `release-backup-tap-control-*` 폴더에 백업했다.

`tests/e2e/tap-control.test.ts`에는 패키지 Electron과 실제 owner IPC를 사용하는 시나리오를 추가했지만 **빈 격리 프로필의 시작 단계가 통과하지 못했다**. 첫 sandbox 실행은 GPU 프로세스 오류로 시작이 중단됐고, 권한 확장 및 일반 Windows 사용자 환경에서는 ‘연결 중’ 상태에서 25초 안에 호스트 준비 파일이 생기지 않아 기능 시나리오를 수행하지 못했다. 초기 실패에서 남은 후보 앱 프로세스는 실행 경로·부모 PID를 확인해 정리했다. 후보와 기존 실행본의 데스크톱 `main.cjs`가 동일함은 확인했지만 빈 프로필 시작 실패의 원인은 확정하지 못했다. 이 검사를 통과한 것으로 집계하지 않는다.

후속으로 후보 호스트를 격리 폴더에서 직접 실행했을 때는 `Host startup failed: 권한이 없는 작업을 수행하려고 했습니다.` 오류로 종료됐다. 시험 프로필 초기화의 권한 제한을 확인했지만 실패한 세부 작업의 위치는 확정하지 못했다. 진단에 사용한 후보 앱·호스트·보조 프로세스의 잔류가 없음을 마지막에 확인했다.

현재 실제 사용자 프로필의 앱은 동일한 데스크톱 코드로 정상 시작했고, 새 호스트 기능과 원격 HTTPS까지 확인했다. 이는 빈 프로필 첫 시작 검사의 미완료를 대체하지 않는다. 실제 PowerShell 브라우저 검사에서 sandbox의 기본 PSReadLine 기록 파일 접근 경고가 있었으나 입력·출력·변수·PID 검증은 통과했으며 사용자 기록 파일을 수정하지 않았다.

증거는 저장소에서 제외한 `test-results/tap-control/`에 있다. `stage-offline-result.json`은 적용 파일 해시·백업·저장소 불변 확인, `live-result.json`은 실제 호스트 지원과 복원·HTTPS 검증, `packaged/`는 빈 프로필 시작 실패와 진단을 기록한다. 실제 사용자 주소·식별자·터미널 내용은 커밋 문서에 넣지 않는다.
