# Git 변경 검토(diff) 검증

기준일: 2026-10-12. 브랜치 `feat/git-diff-view`의 구현과 자동 검사 결과를 기록한다. **0.3.22 배포 준비** 상태이며 실제 Electron 앱·패키지·설치본 검증은 아직 하지 않았다. 배포 검사는 [0.3.22 배포 검증](public-release-0.3.22.md)에 기록한다.

## 설계와 참고

처음에는 IntelliJ 비교 창처럼 파일 하나를 좌우로 비교하는 탭을 만들었다. 사용자와 논의한 뒤 Orca 방식을 기본으로 바꿨다. 몽글에서 diff를 여는 때는 대개 에이전트가 한 작업을 통째로 확인할 때라서, 파일을 하나씩 여는 것보다 전체를 이어서 훑는 편이 맞다는 판단이다. 파일별 나란히 비교는 검토 탭에서 여는 세부 화면으로 남겼다.

- Orca는 [Diff viewer 문서](https://www.onorca.dev/docs/review/diff-viewer)와 [AI diff 검토 문서](https://www.onorca.dev/docs/recipes/review-ai-diff)의 글로 동작을 확인했다(워크트리 시작 ref 기준 비교, 파일 이동 j/k·변경 이동 n/p, 한 화면에 모은 변경). 화면 캡처를 직접 열어 대조하지는 않았다.
- Mobbin 사례는 **확인하지 못했다.** Aside 브라우저의 Mobbin이 로그아웃 상태였고, 계정 로그인은 자동 승인 검토에서 계정·인증 세션 접근 승인 근거가 없다는 이유로 거부됐다. 사용자에게 로그인 허용 여부를 물었으며 답을 받으면 이 절을 갱신한다.

## 화면 구성

- Git 목록에서 파일을 누르면 Orca·VS Code처럼 그 파일 하나의 비교 탭이 검토 탭과 같은 기준으로 열린다. 처음에는 검토 탭이 그 파일 위치로 열리게 했지만, 파일 하나가 궁금할 때 여러 파일이 섞인 페이지로 가는 것이 불편하다는 사용자 논의 뒤 바꿨다. 목록 위 **변경 검토 열기**는 전체 검토 탭을 연다. 검토 탭은 터미널 폴더마다 하나다.
- 도구 줄: 파일 목록 버튼, **브랜치 전체 / 커밋 안 한 변경**, 실제 기준(`origin/main 이후 · 커밋 7자리`), 파일 수와 추가·삭제 줄 합계, 변경 위치(`3 / 12`)와 이전·다음, 모두 접기/펼치기.
- 왼쪽 파일 목록(넓은 화면) 또는 겹쳐 여는 목록(편집 영역 폭 640px 미만·휴대폰). 오른쪽은 파일별 접을 수 있는 구역이 이어지고 머리글은 스크롤해도 위에 붙는다.
- 각 파일은 지운 줄을 바뀐 줄 위에 함께 보여 주는 diff이며 바뀌지 않은 구간을 접는다. 머리글에서 파일 하나 비교 탭과 파일 편집 탭을 연다. 파일 하나 비교 탭은 사용자가 보낸 Orca 화면 캡처에 맞춰 처음에는 한 화면으로 파일 전체를 펼치고, 줄 번호 옆 +/−와 VS Code 기본 diff 색, 오른쪽 변경 위치 표시를 쓴다. 나란히 보기로 바꿀 수 있다.
- 색은 기존 Git 상태 색(추가 초록·삭제 빨강)과 테마 변수를 쓴다.

## 구현 범위

호스트에 `git.review`·`git.diff` RPC와 capability를 추가했다. 기존 `git.status`와 같은 읽기 경로를 써서 연결·hostId·bootId·generation·현재 폴더를 I/O 전후에 확인하고 연결당 2개·전체 8개 읽기 한도를 공유한다. 화면도 기존 탐색기 요청 대기열(동시 2개)을 그대로 쓴다.

- **기준 계산(`git.review`):** 브랜치 모드는 터미널의 워크트리 프로젝트 또는 같은 경로로 연 프로젝트가 기억하는 기준 브랜치, 없으면 `origin/HEAD`를 `rev-parse --verify --end-of-options`로 확인하고 HEAD와의 `merge-base`를 기준으로 한다. 찾지 못하거나 커밋이 없으면 HEAD 기준으로 바꾸고 이유를 함께 보낸다.
- **변경 목록:** 기준→HEAD는 트리끼리 비교(`git diff --relative --name-status -z -M --no-ext-diff --no-textconv`)만 하므로 작업 폴더 파일을 읽거나 필터를 실행하지 않는다. 여기에 기존 `git status` 결과를 합쳐 기준→작업 폴더 상태(추가·수정·삭제·이름 변경·충돌)를 계산한다. 현재 폴더 밖·앱 데이터 경로는 제외하고 최대 1,000개로 제한한다.
- **파일 내용(`git.diff`):** 기준은 HEAD·인덱스·전체 커밋 ID만 받는다. 저장된 내용은 `git cat-file`로 읽어 textconv·smudge 필터와 외부 프로그램을 실행하지 않고, 작업 폴더 파일은 직접 읽으며 폴더 밖 링크와 앱 데이터는 거부한다. 한쪽 256 KiB까지 UTF-8(BOM 포함)·BOM이 있는 UTF-16만 보내 원격 송신 대기 한도(2 MiB)보다 충분히 작다.
- **화면:** CodeMirror 공식 확장 `@codemirror/merge` 6.12.2(MIT). 편집기 패널과 함께 지연 로드되어 앱 첫 화면 번들에 포함되지 않는다. 파일 내용은 화면에 보이는 파일부터 하나씩 읽고, 처음 150개는 줄 수를 위해 미리 읽는다. 편집기는 한 번이라도 화면 근처에 온 파일만 만든다.
- **갱신:** 탭이 보이는 동안 5초마다 목록을, 화면에 보이는 파일의 내용을 다시 읽고 달라진 경우에만 다시 그린다.
- `git.review`가 없는 이전 버전 호스트에서는 Git 목록의 파일을 누르면 지금처럼 현재 내용을 연다. 제3자 고지는 배포용 `runtime/node.exe` 기준으로 다시 생성했다.

## PR #74 검토 반영

자동 코드 검토가 브랜치에서 커밋한 파일을 작업 폴더에서 기준 내용으로 되돌리면 실제 차이가 없는데도 검토 목록에 수정으로 남고, 커밋한 이름 변경을 되돌린 경우 가짜 항목이 생긴다고 지적했다. 경로마다 기준과 작업 폴더에 있는지로 상태를 다시 계산하고, 이름 변경은 기준에 실제로 있던 경로만 출처로 인정하도록 고쳤다. 커밋 뒤 다시 바뀐(또는 스테이징 뒤 되돌린) 파일은 기준 커밋의 blob 해시(`git ls-tree`)와 작업 폴더 파일 해시(`git hash-object --no-filters`)가 같으면 목록에서 뺀다. 두 명령 모두 필터·외부 프로그램을 실행하지 않고 인덱스를 쓰지 않는다. 지적한 두 상황을 재현하는 호스트 시험을 추가해 Git 시험 11/11, 화면 시험 2/2를 통과했다. 줄 끝 변환(`core.autocrlf`)을 쓰는 저장소에서 줄 끝만 다른 파일은 해시가 달라 목록에 남고 화면에서 줄 끝만 바뀌었다고 안내한다.

재검토(`f6c79e6`)에서 두 가지를 더 고쳤다. 작업 폴더의 심볼릭 링크는 링크를 따라가 대상 파일 내용을 읽었는데, Git은 링크를 대상 경로 텍스트로 저장하므로 링크 값 자체(`readlink`)를 비교하도록 바꿨다. 이 시험은 이 PC에서 링크를 만들 권한(개발자 모드)이 없어 건너뛰었고 GitHub Windows CI에서 실행된다. 파일 하나 비교 탭에서 이동 명령이 움직이지 못할 때 이전 방향도 첫 변경으로 돌아가던 것을 마지막 변경으로 가도록 고치고 화면 시험에 순환 이동을 추가했다.

세 번째 검토(`0d38260`)의 지적도 반영했다. 검토 목록의 기준 비교에서 심볼릭 링크는 링크 값으로 Git blob 해시를 직접 계산한다(`hash-object`는 링크가 가리키는 파일을 읽기 때문). 새 파일·삭제 파일의 줄 수는 마지막 줄바꿈 뒤 빈 줄을 세지 않는다(검토 목록과 파일 하나 비교 모두). `git rm`으로 스테이징한 삭제가 빠진다는 지적은 코드상 HEAD에 있던 경로로 처리되고 있었고, 커밋 안 한 변경 모드에서 삭제로 나오는 것을 호스트 시험으로 확인해 답했다. 링크 관련 시험은 이 PC에서 권한이 없어 건너뛰었고 CI에서 실행된다.

## 알려진 제약과 확인하지 않은 범위

- 파일 하나를 읽을 때 Git 프로세스를 여러 번 실행하므로 변경 파일이 수백 개면 전체 줄 수가 채워지기까지 시간이 걸린다(화면에 보이는 파일이 우선).
- 워크트리마다 기준 브랜치를 따로 저장하지 않고 프로젝트가 마지막으로 쓴 기준 브랜치를 쓴다.
- Mobbin 사례 확인, 실제 Electron 개발 앱·패키지 앱 조작, 아스트라 모델의 컴퓨터 유즈 검증, 실물 휴대폰 원격 화면, 전체 회귀·CI·설치 검사.
- 줄·변경 단위 스테이징, 줄 코멘트를 에이전트에게 보내기, 3칸 충돌 해결은 제공하지 않는다.
