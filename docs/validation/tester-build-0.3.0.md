# 0.3.0 비공개 테스트 배포본

2026-09-29, Windows 11 x64. 저장소가 비공개인 동안 테스터에게 설치 파일을 직접 전달하기 위해 0.3.0을 만들고 검증한 기록이다. GitHub Release 게시, 코드 서명, 이 PC에서의 실제 NSIS 설치·제거는 수행하지 않았다.

## 빌드

```powershell
node --import tsx scripts/package.ts --output release-candidate
```

실사용 앱이 실행 중인 `release/`와 분리된 `release-candidate/`에 만들었다. 패키징 중 실사용 GUI·호스트·PowerShell 프로세스는 그대로 유지됐다.

첫 빌드(dbede20)는 아래 패키지 실행 검사에서 복원 결함을 찾아 배포하지 않고 같은 폴더의 최종 빌드로 교체했다. 테스터에게 전달된 적이 없으므로 같은 버전 번호를 유지했다.

## 패키지 실행 검사

`tests/e2e/full-exit.test.ts`로 패키지 실행본을 격리 데이터 폴더에서 실행해 시작·그룹·분할·실제 PowerShell 명령·완전 종료 취소·완전 종료·SQLite 무결성·재실행 복원과 복원된 셸의 명령 실행까지 확인한다.

1. **첫 빌드, E: 작업 폴더 아래 데이터 폴더:** 실행부가 `Host startup failed: 권한이 없는 작업을 수행하려고 했습니다.`로 시작하지 못했다. OwnerPipe는 데이터 폴더의 소유자와 보호 ACL을 현재 사용자 전용으로 다시 설정한다. 이 작업 폴더에서는 현재 사용자가 상속된 **수정(Modify)** 권한만 있어 소유자 변경이 거부된다(`Get-Acl`로 확인). 설치본이 쓰는 `%LOCALAPPDATA%\MongleTerminal`에는 해당하지 않는다. OwnerPipe를 쓰는 패키지 E2E는 기존 [E2E 절차](e2e.md)처럼 `%TEMP%` 아래 격리 폴더를 사용한다.
2. **첫 빌드, `%TEMP%` 격리 폴더:** 시작부터 완전 종료 후 SQLite 확인까지 통과했다. 재실행 후 복원된 두 번째 터미널이 빈 화면과 “현재 컴퓨터에서 제어 · 가져오기”로 남아 실패했다. 개발 빌드에서도 같은 위치에서 재현되어 패키징이 아닌 코드 결함으로 판단했다. 원인과 수정은 [복원 제어권 검증](restore-control.md)에 기록했다.
3. **최종 빌드, `%TEMP%` 격리 폴더:** **1/1 통과**(39.7초). 복원된 두 터미널이 모두 이 창의 제어권으로 연결되고, 새로 시작한 두 PowerShell이 저장된 작업 폴더에서 실제 명령을 실행했다. 이전 명령은 다시 실행되지 않았다. 시험 앱·실행부·셸은 검사 후 정리됐다.

## 첫 GitHub Actions 실행

main 푸시(2fff49e)의 **Windows checks**가 252개 중 240 통과·1 실패·11 생략으로 끝났다. 실패한 `tests/host/shell-profiles.test.ts`는 GitHub 러너의 TEMP가 8.3 짧은 경로(`RUNNER~1`)로 노출되고 PowerShell은 긴 경로를 보고해 문자열 비교가 달라진 경우였다. 검사를 실제 위치 비교로 바꿨고(00ab988), 로컬에서 짧은 TEMP 경로를 지정해 수정 전 비교가 다르고 수정 후 6/6 통과함을 확인했다. 이후 dev 푸시(2efd1d3)의 **Windows checks**가 통과했다. 제품 코드 결함은 아니다.

## 테스터에게 전달하는 파일

`release-candidate/MongleTerminal-Setup-0.3.0-x64.exe` 하나만 전달한다. 파일 확인이 필요하면 위 SHA256 값을 함께 알려 준다. 설치·SmartScreen·업데이트 안내는 [비공개 테스트 배포](../RELEASING.md#비공개-테스트-배포)를 따른다.

## 확인하지 않은 범위

이 PC는 실사용 호스트가 실행 중이라 NSIS 설치·제거를 직접 실행하지 않았다. 다른 PC 설치, SmartScreen 실제 표시, 테스터 PC의 원격 접속은 테스터 확인이 필요하다. 비공개 저장소라 테스터 PC의 자동 업데이트는 동작하지 않는다.

## 개발 PC 실행본 교체 (같은 날 후속)

완전 종료로 기존 0.2.0 실행본(원격 연결 복구 수정 포함)을 정상 종료한 뒤, `release` 폴더를 이 최종 0.3.0 빌드로 교체했다. 관리자 계정이 아닌 별도 작업 계정에서는 실제 앱의 창 핸들 접근이 Windows 권한 격리로 막혀 있어 직접 조작할 수 없었으므로, 완전 종료·재실행은 사용자가 실제 화면에서 수행했다. 재실행 후 프로세스 목록으로 실행 파일 해시가 새 빌드와 일치하고 실제 데이터 폴더(`%LOCALAPPDATA%\MongleTerminal`)에 연결되었으며 종료 전과 같은 개수의 PowerShell 콘솔이 함께 시작됨을 확인했다. 사용자가 실제 화면에서 그룹·터미널 목록이 그대로 복원되었음을 확인했다. 임시 백업(`release-old-0.2.0`)은 확인 후 삭제했다.
