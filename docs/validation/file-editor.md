# 파일 편집과 마크다운 검증

검증일: 2026-10-04. 소스 버전 0.3.8의 **미배포 개발 변경**이다. 기존 설치본 교체, 공개 배포, 사용자 수락 확인은 수행하지 않았다.

## 참고한 화면과 적용 판단

- Aside에서 [Mobbin의 Databricks SQL 편집 화면](https://mobbin.com/explore/screens/dfea709f-3245-4e15-983f-f76b96001f2c)을 열고 스크린샷을 직접 확인했다. 탐색 목록과 문서 작업 영역을 분리하는 구조를 참고했다.
- 사용자가 설명한 Orca의 오른쪽 편집 흐름과 공개 홈페이지의 Editor 소개를 참고했지만 Orca 설치 앱을 조작한 것은 아니다.
- 몽글의 기존 터미널·사이드바·색상 체계를 유지하고, 오른쪽 파일 작업 영역에 파일 탭과 저장·다시 열기·크기 조절을 배치했다. 파일 목록을 접으면 문서 폭을 확보한다. 마크다운은 미리보기로 시작하고 편집/미리보기/나란히 보기를 선택한다. 편집 영역이 좁으면 나란히 보기를 상하로 배치한다.

## 구현과 경계

- CodeMirror 6: 줄 번호, 구문 강조, 실행 취소, 찾기/바꾸기, Ctrl+S. `react-markdown` + `remark-gfm`: 제목·표·체크리스트·인용·코드 블록. HTML 실행과 이미지 자동 요청을 하지 않으며 HTTP(S)/메일 링크는 주소 복사로 제공한다.
- 텍스트 파일 크기와 UTF-8 저장 요청을 각각 64 KiB 이하로 제한했다. UTF-8/BOM과 UTF-16LE/BE BOM을 보존한다. 큰 파일은 읽기 전용이며 바이너리·보호 데이터·네트워크 경로·링크·하드 링크에는 쓰지 않는다. 기존 128 KiB 전송 제한을 늘리지 않았다.
- 열린 파일별 권한은 인증된 연결·호스트·부팅 세대에 묶는다. 터미널의 현재 폴더가 바뀌어도 열린 파일의 원래 경로에 저장한다. 재연결 후에는 내용을 복사·비교하고 원래 폴더의 터미널을 통해 다시 열어 권한을 갱신한다.
- 파일 내용과 파일 식별자로 버전을 계산한다. 파일별 저장을 직렬화하고 임시 파일에 기록·flush한 뒤 기존 버전과 연결 권한을 다시 검사하고 교체한다. 외부 변경 충돌에서 사용자 초안을 자동으로 버리거나 강제 덮어쓰지 않는다. 마지막 검사와 파일 교체 사이에 다른 프로그램이 쓰는 극히 짧은 경쟁 구간을 OS 간 배타 잠금으로 제거한 것은 아니다.
- 최대 24개 파일 탭의 수정 내용을 화면 메모리에 유지한다. 앱 재실행 시 초안 복원·자동 저장·파일 생성/삭제/이름 변경은 제공하지 않는다. 저장 중 추가 입력은 저장한 시점 이후 변경으로 남긴다.
- 미저장 탭 닫기·다시 열기 확인, 브라우저 이탈 경고, 데스크톱 종료·완전 종료·업데이트 설치 차단을 구현했다. 데스크톱 차단은 빌드 확인까지이며 실제 네이티브 확인창과 업데이트 설치까지 검증하지 않았다.

새 파일 편집 검사에서는 한국어/이모지/CRLF/인코딩 보존, 외부 충돌, 동시 저장 중 한 건만 성공, 교체 전 권한 폐기, 악성 경로·잘못된 인코딩·크기 제한, 연결 간 권한 격리·재연결 만료를 확인했다. 실제 파일 I/O와 cmd 셸을 사용했다. cwd 변경 알림만 테스트에서 주입했고 실제 셸 PID가 유지되는지 검사했다.

확장 회귀 실패는 기존 `publish-release.test.ts`의 PowerShell 실행 정책 거부, `remote-transport.test.ts`의 Electron GPU 프로세스 초기화 종료(-1073741515)다. 시스템 실행 정책이나 제품 보안 설정을 완화하지 않았다. 전체 회귀/CI 완료로 간주하지 않는다. `npm audit`의 개발 의존성 `http-cache-semantics@4.2.0` 경고(GHSA-ch52-4w7c-c8xp)는 변경 전 잠금 파일에도 존재한다. 이번 편집기 변경에서 관련 없는 의존성을 일괄 갱신하지 않았다.

로그는 커밋하지 않는 `.test-data/file-editor-{focused,regression,lifecycle,package}.log`에 남겼다. 기존 `tests/ui/file-explorer.test.ts`와 `git-explorer.test.ts`는 새 편집 영역에 맞추고 저장/충돌/미저장 확인 회귀를 추가했다. 사용자 브라우저 규칙에 따라 로컬에서는 Chrome 기반 UI 테스트를 실행하지 않고 아래 Aside 검증을 수행했다.

## Aside 실제 UI 조작

격리된 임시 폴더에 HostCore와 loopback 게이트웨이를 실행하고 일회성 브라우저 페어링을 거쳤다. 실제 cmd 터미널 2개와 실제 파일을 사용했으며 UI의 호스트 응답을 가짜 값으로 대체하지 않았다. 실사용 호스트·인증·셸·Tailscale Serve는 변경하지 않았다.

- 파일 클릭 → 오른쪽 탭, Markdown 기본 미리보기 및 편집/나란히 보기 전환.
- 한글 편집 → Ctrl+S → 디스크 파일 내용 확인, 저장 후 수정 없음 표시.
- 터미널 탭 변경 후 문서 유지. 여러 파일 탭을 전환한 뒤 실행 취소하여 수정 전 상태 복구.
- 외부 프로그램 역할로 시험 파일을 변경한 후 저장: 충돌 표시, UI 초안 보존, 디스크 외부 변경 보존. 명시적 다시 열기/변경 버리기로 새 내용 로드.
- 미저장 탭 닫기 확인창: 계속 편집, Escape 취소, 두 버튼 사이 Tab 포커스 순환.
- 편집기 숨김 → 하단 열린 파일 버튼 → 기존 내용과 파일 탭 복원.
- 64 KiB 초과 파일 읽기 전용 안내 및 저장 버튼 비활성화.
- `<script>`, javascript 링크, 외부 이미지가 포함된 Markdown: 렌더링 DOM에 script/img/실행 링크 0개 확인.
- 1440×900 화면의 밝은 테마를 실제 스크린샷으로 확인. 어두운 테마는 초기 실화면 확인. 편집 영역을 439px로 줄이면 상하 배치이며 가로 넘침이 없고, 719px로 복원하면 좌우 배치다. 최대화 시 작업 영역의 1228px 폭을 사용한다.

Aside의 `setViewportSize`는 지원되지 않았다. 별도 390px iframe 검증은 앱의 기존 frame-ancestors/X-Frame-Options 차단으로 사용할 수 없어 해당 임시 페이지를 제거했다. 390px 전체 화면·실물 휴대폰 검증을 완료한 것으로 표현하지 않는다. 최종 화면 캡처 중 Aside 클립 캡처가 여러 번 시간 초과했지만 전체 화면 캡처는 성공했다. 테스트 이미지와 개인 경로가 포함된 화면은 저장소에 추가하지 않았다.

## 남은 검증

네이티브 종료/업데이트 확인창 실제 조작, 패키지 GUI E2E, 재연결/호스트 재시작 뒤 UI 복구, 실제 Tailscale 원격·휴대폰·네이티브 한글 IME 조합 입력, 전체 GitHub CI 실행, 설치본 교체와 공개 배포는 별도다. 브라우저 `insertText`로 검증한 한글 입력을 실제 IME 조합 입력 검증으로 표현하지 않는다.
