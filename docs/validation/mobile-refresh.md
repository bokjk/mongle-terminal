# 모바일 설치형 웹앱 화면 새로고침

2026-10-07, 미배포 변경. 현재 공개 버전 0.3.14에는 포함되지 않는다.

## 동작과 범위

- 모바일/PWA와 일반 브라우저에서 **설정 → 앱 업데이트 → 화면 새로고침**을 제공한다. 브라우저 주소창이 없는 설치형 화면에서도 조작할 수 있다.
- `window.location.reload()`로 HTML과 화면 코드를 다시 불러온다. 통신만 복구하는 **다시 연결**과 구별한다. 호스트는 웹 자산에 `Cache-Control: no-store`를 사용한다.
- 접속한 PC에서 업데이트 설치·재시작이 끝나야 새 화면을 받을 수 있다. 자동 버전 감지나 자동 새로고침은 이번 변경에 포함하지 않는다.
- 현재 화면의 미저장 파일과 저장 중인 파일이 하나라도 있으면 버튼을 비활성화하고 이유를 표시한다. 모바일의 `beforeunload` 경고에만 의존하지 않는다. 설정을 닫고 저장/변경 취소 후 다시 시도한다.
- 새로고침으로 열린 파일·PDF 탭은 닫힌다. PC 터미널 종료·생성·재시작 RPC는 요청하지 않는다. 네트워크와 호스트가 정상이어야 다시 접속한다.
- Electron 데스크톱 앱에는 기존 설치 업데이트 UI를 유지한다.

## 디자인 참고

Aside에서 [Mobbin 모바일 About 사례](https://mobbin.com/explore/mobile/screens/about)의 공개 이미지를 직접 확인했다. Klarna는 제목 아래 버전·설명, Bolt는 앱 정보와 아이콘을 포함한 동작 목록, Teams는 앱 정보 아래 별도 동작 행을 배치한다. 정보를 읽고 관련 동작을 실행하는 흐름을 참고해 기존 **앱 업데이트** 탭 안에 제목·짧은 설명·텍스트 버튼을 배치했다. 터미널 위에 상시 버튼을 추가하지 않으며 기존 모바일 44px 터치 크기와 테마를 사용한다. 이 앱들이 PWA 새로고침을 구현했다는 근거로 사용하지 않는다.

## 검증

- `npm.cmd run typecheck`, `npm.cmd run build`, `node --import tsx scripts/release-check.ts`, `git diff --check` 통과. 빌드는 기존 500kB 초과 청크 경고를 남겼다.
- 기존 업데이트 UI 자동 검사에 브라우저 전용 버튼, 차단 상태, 실제 문서 다시 로드를 추가했으며 통과했다. 데스크톱의 업데이트 확인·설치·실패·이전 이벤트 처리 검사도 유지했다.
- 전체 회귀 `node --import tsx --test --test-concurrency=1 tests/**/*.test.ts`: 475개 중 458 통과, 1 실패, 16 선택 생략. 실패 1개는 `publish-release.test.ts`의 자식 Windows PowerShell 실행 정책 차단이었다. 시스템 정책은 변경하지 않고 재검사 프로세스에만 `PSExecutionPolicyPreference=Bypass`를 지정해 해당 검사 1/1 통과를 확인했다. 합산 459개 통과이며 전체 단일 실행이 실패 없이 끝났다고 표현하지 않는다. 전체 실행 로그는 `.test-data/mobile-refresh-regression.log`에 남겼다.
- 독립 코드 검토에서 중요한 결함은 발견되지 않았다. 실제 App→Settings 전달과 저장 중 단독 차단의 검증을 추가 확인 항목으로 받았다.
- Astra가 Aside에서 실제 빌드 웹앱과 격리 HostCore/gateway, 실제 cmd 셸로 검사했다. 표준 기기 연결 요청·승인·claim을 사용했다. 새로고침 전후 hostId·bootId·터미널 ID·generation·셸 PID가 같고 셸이 계속 실행 중임을 확인했다. 문서의 navigation type이 `reload`이고 timeOrigin이 바뀌었으며 자동 재연결됐다.
- 파일 수정 시 버튼 차단, 실제 저장 응답을 시험 helper에서만 8초 지연한 동안 원문으로 되돌려 미저장 표시가 사라진 상태에서도 차단 유지, 응답 후 변경이 남으면 차단 유지, 다시 저장 완료 후 버튼 활성화를 확인했다. 제품 코드나 React 상태를 시험용으로 바꾸지 않았다.
- 실제 조작 뷰포트는 1440×900이다. Aside에 `setViewportSize`와 `context` API가 없어 모바일 너비를 검증하지 못했다. 공식 스크린샷 호출 두 번도 시간초과로 이미지를 확보하지 못했으며 실제 snapshot 8개를 남겼다. 모바일 크기 실기 또는 스크린샷 검증 통과로 표현하지 않는다.
- 증거는 `test-results/mobile-refresh/validation.md`, `dom-evidence.json`, 호스트 전후 JSON과 `cleanup.json`에 남겼다. 시험 탭·격리 호스트·셸을 정상 종료하고 종료 코드 0 및 해당 프로세스 종료를 확인했다. 열린 파일 탭을 가진 상태에서의 추가 새로고침은 실기 검사하지 않았다.

실물 갤럭시에서 설치한 PWA와 삼성 인터넷, 외부 Tailscale 네트워크 검증은 별도다. 이번 변경의 새 설치본 패키징·NSIS 설치·공개 배포도 수행하지 않았다. 실사용 앱은 이번 작업에서 업데이트하거나 재시작하지 않는다.
