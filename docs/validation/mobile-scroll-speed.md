# 모바일 터치 스크롤 감도와 감속

2026-10-07, 미배포. 기존 공개 0.3.14와 앞선 미배포 새로고침 변경을 보존한다.

## 현재 동작: 손가락 추종과 짧은 관성

사용자가 휴대폰 문서처럼 자연스러운 스크롤을 요청해 아래 초기 감도 조절을 추가로 다듬었다. **아래 초기 검증 기록은 이전 구현의 결과이며 최신 검증과 구분한다.**

- 일반 기록: 기본 0.5 설정에서 손가락 CSS 이동 거리와 화면 이동 거리를 맞춘다. 행 높이 미만의 거리는 누적하며 xterm의 실제 기록을 이동한다. 행 단위 렌더링은 유지한다.
- CLI: 24 CSS px를 선택한 배율로 나눈 거리마다 표준 휠 입력 한 번을 보낸다. 기본 0.5에서는 48px당 한 번이므로 글자 크기를 줄여도 신호 횟수가 늘지 않는다. CLI가 한 신호를 여러 줄로 해석하는 차이까지 없애지는 않는다.
- 최근 80ms 이동에서 속도를 구하고, 빠르게 움직이다 놓았을 때만 지수 감속한다. 정지 후 재이동과 방향 반전은 표본을 새로 시작한다. 감속은 최대 600ms, 배율 적용 후 최대 200px 또는 화면 높이의 60% 상당 중 작은 값으로 제한한다. CLI에서는 이 거리를 휠 횟수로 환산한다. 미만 잔량에 따른 행/휠 양자화가 있다.
- 새 터치·키·컨텍스트 메뉴·마우스 휠·창 비활성화·화면 숨김·모션 줄이기·글자 크기/화면 크기 변경·프로토콜/제어권 변경은 관성을 중단한다. RAF가 80ms 넘게 늦어지면 관성을 재생하지 않는다. 입력 큐 ACK 대기 중에는 해당 frame의 거리·잔량을 버리면서 실제 시간에 맞춰 감속한다. 대기가 80ms 이상 지속되면 종료하며, 만료 이후 ACK가 풀려도 관성을 재개하지 않는다. 짧은 정상 ACK 뒤에는 새로 발생한 이동만 보낼 수 있다. 직접 손으로 움직이는 입력의 기존 순서 보장 경로는 유지한다.
- 전체 화면 프레임을 파싱하는 동안의 로컬 기록 이동은 한 화면 이내로 보관하고 복원된 viewport에 **첫 화면 그리기 전** 적용한다. 실패·취소·버퍼 전환·80ms 이상 지연된 프레임은 보관량을 폐기한다. CLI 입력을 이 로컬 보관 경로에 넣지 않는다.
- 공개 xterm 6.0.0 소스의 `src/browser/Viewport.ts`에서 행 렌더링과 정수 scroll API를 확인했다. 렌더러 변형이나 복사 화면을 추가하지 않고 기존 터미널 버퍼와 휠 인코딩을 사용한다. 새로운 의존성은 없다.

Mobbin 추가 확인: Astra가 Aside로 [Origin AI 대화](https://mobbin.com/explore/flows/1b6fe3de-239c-4b43-97ba-f7a20d35aa87), [Swiggy 고객지원 대화](https://mobbin.com/explore/flows/26a11940-a254-4bea-87f2-282357efe932)의 공개 화면을 확인했다. 긴 대화를 읽으며 기존 입력 화면을 유지하는 흐름을 참고했다. 정적 화면이므로 관성이나 감속 수치의 근거로 사용하지 않았다. 기존 속도 선택 UI는 유지하고 이전 방식과 같지 않은 `1배(기존)` 표기를 제거했다.

### 실제 앱·CLI와 남은 범위

Astra가 Aside에서 실제 제품 웹 UI, 새 격리 HostCore/gateway, 실제 Claude·Codex 프로세스를 정상 페어링해 검사했다. 새 모델 요청을 보내지 않고 기존 합성 대화만 재개했다. viewport는 1440×900, 입력은 DOM `TouchEvent`(`isTrusted:false`)이며 실물 손가락/모바일 viewport와 구분한다.

- 느린 144px 양방향 스와이프: Claude 11·14·20px와 Codex 11px 모두 DOM/호스트 휠 3개씩 일치. Claude 11px 표시 첫 행 LIVE-254→247→254, Codex 11px CX-L-256→247→256을 확인했다. 최초 제어권 응답을 1200ms 지연한 구간에 터미널 입력은 0개, 뒤늦은 휠 재생도 0개였다.
- 최종 번들 `index-KoC4dKac.js`에서도 Claude·Codex의 빠른 144px 이동은 각각 휠 3회로 전달됐다. **touchend 이후 추가 wheel은 0회**였으므로 실제 CLI의 관성/진행 중 관성 재터치 중단을 통과로 판정하지 않는다.
- 최종 시험의 입력 RTT는 Claude 2~12.9ms, Codex 1.6~1.9ms였다. hidden 표본은 false이고 reduced-motion도 false. 별도로 요청한 RAF 계측 콜백은 0회였다. 제품의 RAF 요청 횟수는 계측하지 않아 예약 여부/실행 여부를 완전히 분리할 수 없다. 이 결과는 ACK 지연이 실제 CLI의 관성 미발생 원인이었다는 증거가 아니다. 앞선 짧은 ACK 보완은 독립 자동 재현에 근거한다.
- 첫 시험의 Claude 20→11px 변경·제어권 재취득 직후에는 표시 행 재배치와 첫 flick의 예상 방향 불일치도 관측됐다. 해당 사례는 방향 이동 성공으로 세지 않는다. 크기 변경/CLI 위치 복원과의 인과관계는 확인하지 않았으며, 이 작업이 모든 CLI의 재배치 문제를 해결했다고 주장하지 않는다.
- 원본/집계/한계: `test-results/mobile-natural/actual-app/validation.md`, `summary.json`, `dom-evidence.json`, 호스트·CLI 프레임. 최종 시험은 그 아래 `follow-up/`에 별도로 기록했다. 시험 탭과 기록한 소유 프로세스는 첫 실행 26개, 후속 24개 모두 종료를 확인했다. 실사용 프로필·셸·인증·Tailscale Serve는 변경하지 않았다.

실물 갤럭시·삼성 인터넷·설치형 PWA의 손가락 체감과 외부 Tailscale 지연은 미검증이다. 현재 작업은 미배포이며 실사용 호스트를 재시작하거나 설치본을 교체하지 않았다.

## 초기 감도 조절: 문제와 변경

사용자가 휴대폰에서 조금만 밀어도 너무 많이 이동한다고 보고했다. 기존 구현은 터미널 한 행 높이의 손가락 이동마다 로컬 기록 한 행 또는 CLI 휠 입력 한 번을 발생시켰다. CLI가 휠 입력 한 번을 여러 줄로 해석하면 체감 이동량은 더 커질 수 있다. 기기에서 발생한 실제 줄 수는 측정하지 않았으므로 특정 CLI 내부 가속을 원인으로 확정하지 않는다.

**설정 → 화면 → 모바일 스크롤 속도**에 0.25·0.5(기본)·1(기존)·1.5·2배를 추가했다. 새 기본값은 기존 이동량의 절반이다. 일반 기록과 CLI 모두 행으로 환산하기 전 누적 픽셀에 배율을 적용한다. xterm은 마우스 모드에서 휠 이벤트 하나당 보고 하나를 보내므로, `deltaY` 값만 줄이는 방식 대신 보고 횟수를 줄인다. 실제 이동 줄 수는 프로그램이 결정하며 행 경계에서 반올림 없이 소수 이동을 누적한다.

- 설정은 `mongle.touchScrollSpeed`로 현재 브라우저/웹앱에 보관한다. 없는 값·지원하지 않는 값·잘못된 JSON은 0.5배로 복원한다. 저장소 실패는 앱 실행을 막지 않으며 현재 화면에는 적용된다.
- 각 스와이프 시작 시 최신 속도를 읽는다. 진행 중인 스와이프의 잔량을 갑자기 확대하지 않으며 다음 스와이프부터 반영한다. 터미널·입력 어댑터를 재생성하지 않는다.
- 마우스 휠, 키보드, 제어권·ACK 대기 중 입력 폐기, 핀치 줌, 한 번의 이동 처리 상한은 유지한다.
- 방향을 바꾸면 기존 소수행 잔량과 상쇄한다. 제어권 획득 때의 크기 변경이나 네트워크 지연은 이 설정으로 해결되는 문제가 아니다.

## 초기 감도 조절 검증 (위 자연스러운 스크롤 변경 전)

- 타입 검사와 프로덕션 웹·호스트·데스크톱 빌드 통과.
- 단위 검사: 배율별 양방향 이동, 동일 거리의 이벤트 분할 동등성, 잔량을 남긴 방향 반전, 진행 중 속도 변경과 다음 스와이프 반영, 잘못된 값 복원. 기존 입력 차단·핀치·취소·프로토콜 변경 보호를 유지한다.
- Chrome Android 에뮬레이션: trusted touch로 실제 xterm의 SGR 휠 보고 수가 배율별로 줄고 늘며 양방향 인코딩이 올바른지 확인했다. 실제 Claude/Codex 앱의 줄 이동량 측정은 아니다.
- 320px·390px 전체 React App와 실제 CSS 검사: 다섯 배율 선택, 즉시 저장, reload 후 복원, 잘못된 저장 값의 0.5 복원, 터미널 DOM 유지, 가로 넘침 없음, 터미널 생성·종료·재시작·입력 RPC 없음. 호스트는 테스트 더블이다. 첫 실행의 설정 버튼 선택자가 두 버튼에 일치하여 실패했고, main 영역으로 한정한 뒤 5/5 통과했다.
- 전체 회귀 `node --import tsx --test --test-concurrency=1 tests/**/*.test.ts`: **481개 중 465 통과·0 실패·16 선택 생략**, 종료 코드 0. 격리 `MONGLE_DATA_DIR`를 사용하고 자식 PowerShell 스크립트 검사를 위해 이 프로세스에만 `PSExecutionPolicyPreference=Bypass`를 설정했다. 시스템 정책은 변경하지 않았다. 로그: `.test-data/mobile-scroll-speed-regression.log`.
- `npm.cmd run typecheck`, `npm.cmd run build`, `node --import tsx scripts/release-check.ts`, `git diff --check` 통과. 독립 코드 검토에서 중요한 결함이나 차단할 검증 공백이 발견되지 않았다.
- Astra가 Aside에서 실제 빌드 웹앱(`index-nZj-Ps7d.js`), 별도 프로필의 HostCore/gateway와 cmd 셸로 다섯 속도 선택·저장값 일치·새로고침 후 0.25배 보존을 확인했다. 설정 전·후·새로고침 후 hostId·bootId·terminalId·generation·셸 PID가 동일했고, 설정 변경은 터미널 생성·종료·재시작 RPC를 보내지 않았다. 화면 새로고침에서는 정상 재연결 조회가 발생했다.
- 실제 조작은 1440×900이다. Aside 모바일 viewport API 제약과 스크린샷 CDP 시간초과 때문에 실기 모바일 너비/이미지 검증으로 표현하지 않는다. `test-results/mobile-speed/validation.md`, `dom-evidence.json`, 호스트 전후 결과와 `cleanup.json`에 근거를 남겼다. 시험 탭·호스트·셸은 정상 종료하고 해당 프로세스 종료를 확인했다.

실물 갤럭시·삼성 인터넷·설치형 PWA의 체감 속도, 외부 Tailscale 네트워크는 미검증이다. 이번 작업으로 실사용 호스트를 재시작하거나 설치본을 교체하지 않는다. 새 버전 배포·패키징은 수행하지 않았다.

## 모바일 기본 글자 크기 11px

이후 사용자가 평소 사용하는 11px를 모바일 기본값으로 요청했다. 모바일 최초 실행/잘못된 저장값의 복원과 상단 숫자 버튼의 복원값·접근성 이름을 모두 11px로 바꿨다. 유효한 기존 저장 크기는 유지하며 PC 기본은 13px다. 기존 Mobbin Telegram 참고에서 확인한 크기 조절·선택 표시 패턴을 유지하며 숫자는 사용자 지정값을 따른다.

타입 검사·프로덕션 빌드 통과. `tests/ui/mobile-display.test.ts` **5/5 통과**: 320·390px, 새 기본값 11, 기존 14 저장값 유지, 11 복원, 10~24 범위, reload 저장값 보존, 잘못된 값 복원, PC 기본 13, 크기 변경 중 입력/ACK 보호와 속도 설정 회귀를 확인했다. 로그: `.test-data/mobile-font-11-test.log`. 이 검사는 실제 React App과 CSS에 테스트 호스트를 연결한 Chrome 에뮬레이션이며 실물 PWA 또는 설치된 앱 검사가 아니다. 위 전체 회귀·Aside 실제 호스트 결과는 11px 기본값 변경 전의 결과다. 이번 기본값 변경 후 전체 회귀·패키징·배포는 반복하지 않았다.

이 단계까지의 스크롤 계산은 실제 행 높이를 사용해 작은 글자에서는 같은 손가락 이동에 더 많은 행/휠 보고가 발생할 수 있었다. 상단의 후속 구현에서 CLI 계산을 글자 크기와 분리했다.
