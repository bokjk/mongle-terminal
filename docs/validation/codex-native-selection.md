# 실제 Windows 앱의 Codex 드래그 검사

2026-10-06, `fix/claude-selection-live`, 제품 코드 `5692a53` 기준. 기존 Claude 검사에는 실제 Codex 검사가 포함되지 않았으며, 이번에 별도로 수행했다. 수정본 시험 결과이며 새 공개 배포 완료가 아니다.

## 환경과 방법

- 공개 0.3.12 ZIP에서 추출한 실제 `MongleTerminal.exe`를 별도 TEMP 데이터·작업 폴더로 실행했다. 시험 실행본의 웹 자산은 PR #44 빌드로 교체했다. 설치된 사용자 앱·호스트·셸과 인증 데이터는 변경하지 않았다.
- 설치된 Codex CLI **0.160.0**을 `--no-daemon --sandbox read-only --ask-for-approval on-request`로 실행했다. 기본 전체 화면을 사용했고 `--no-alt-screen`은 지정하지 않았다. 시험 요청은 도구·파일 접근 없이 번호와 한글·영문을 출력하도록 했다.
- 실제 CLI 화면에서 마우스 모드 ANY, SGR, Windows 입력 모드를 확인했다. 느린 드래그는 실제 앱의 Electron `webContents.sendInputEvent`로 누름 후 200ms, 이동 12회에 각각 150ms 간격을 두었다. 브라우저 fixture나 가짜 CLI 출력으로 대체하지 않았다.
- 시험 앱의 입력·클립보드 IPC를 일시 관찰하고 각 검사 후 관찰 함수를 복구했다. Windows 클립보드의 시험 문자열을 번호·본문·끝 표시까지 비교했다. 원시 세션·출력·시험 도우미는 커밋하지 않았다.

## 결과

| 검사 | 실제 결과 |
|---|---|
| Windows 마우스 빠른 드래그 | 실제 창의 CX-L-266~271 6줄을 Windows 입력으로 선택해 클립보드 원문 일치 확인. |
| 완료된 응답의 느린 일반 드래그 | CX-026~031, 한글·영문 6줄 전체 일치. 누름·이동 12회·해제 14건 전달. |
| 화면 경계 자동 스크롤 | 경계에서 5초 유지, CX-001~060 전체 60줄 일치. |
| 실제 응답 생성 중 느린 드래그 | 300줄 응답 생성 중 CX-L-046~051의 6줄 전체 일치. 누름·이동·해제 전달, 선택 유지와 이후 출력 진행 확인. |
| Shift+드래그 | CX-L-038~043의 6줄 일치(터미널 앞뒤 패딩 제외). CLI 마우스 입력 0건, 앱 복사 1회, 앱이 쓴 문자열과 실제 클립보드 완전 일치. |
| 긴 한글 응답 전체 | 완료 후 화면 위 경계에서 12초 유지, CX-L-001~300 전체 300줄의 번호·한글·영문·END 번호 일치. |

일반 드래그 검사의 앱 클립보드 쓰기는 0회였다. Codex 자체 선택·복사 경로로 실제 클립보드에 들어온 문자열을 비교한 결과다. 긴 선택에는 앞선 배너·요청도 포함됐으며, 그 안의 응답 60줄·300줄을 추출해 연속 번호와 전체 문장을 확인했다.

초기 시험은 도우미가 명령을 보내고 제어권을 놓은 뒤 터미널을 다시 클릭하지 않아 마우스 입력이 전달되지 않았다. 입력 영역을 클릭해 정상 제어권을 얻은 뒤 위 검사를 수행했다. 다른 기기의 제어권을 드래그만으로 가져오지 않는 기존 정책을 실패로 분류하지 않는다. 두 번째 요청도 실제 제출·생성을 확인한 뒤 스트리밍 검사를 진행했으며, 요청 입력 중 선택 결과를 스트리밍 성공으로 계산하지 않았다.

## 범위와 남은 제약

- 이번 검사에서 추가 제품 수정은 필요하지 않았다. 위 결과는 PR #44 수정본에 대한 것으로, 공개 0.3.12 원본의 Codex 문제가 모두 해결됐다는 의미가 아니다.
- 모든 출력 타이밍, CLI 버전·설정, `--no-alt-screen`, WSL·SSH·원격 웹·모바일, 실제 사용자 설치본 업데이트는 검사하지 않았다.
- [Claude의 긴 한글 fullscreen 복사 누락](claude-native-selection.md)은 별도로 남아 있다. Codex 통과로 해당 결함을 해결 처리하지 않는다.
- 제품 코드 `5692a53`의 [Windows CI](https://github.com/bokjk/mongle-terminal/actions/runs/37444133266)는 423 통과·실패 0·선택 15 생략, 별도 네이티브 클립보드·업데이트 2/2 통과다. [실제 NSIS 교체·복원](https://github.com/bokjk/mongle-terminal/actions/runs/37444133124)도 통과했다. 이 수치와 이번 수동 네이티브 Codex 검사는 구분한다.
- 검사 후 격리 앱·호스트를 정상 종료하고 시험 실행본의 원래 웹 진입 파일을 복원했다. 이번 문서 변경은 `git diff --check`와 배포 문서 검사를 통과했다.
