# AI 팀 구성원 모델 고르기

2026-10-15, Windows x64. **0.3.25 배포 준비.** 배포 검사는 [0.3.25 배포 검증](public-release-0.3.25.md)에 기록한다. [AI 팀 화면](agent-teams-ui.md)의 구성원 표를 바꿨다.

## 왜 만들었나

0.3.24의 모델 칸은 이름을 직접 쓰는 입력칸이었고, 추천도 템플릿에 들어 있는 이름뿐이었다. 사용자는 `opus` 같은 이름을 미리 알아야 했고, 업체가 새 모델을 내도 몽글을 고치기 전에는 추천에 나오지 않았다. [설계안](../08-agent-team-design.md)은 "목록은 업체 도구에서 그때그때 받는다"고 정했다. 이번 변경은 이 PC에 설치된 CLI가 알려 주는 목록을 그대로 보여 준다. 몽글은 모델 이름을 따로 들고 있지 않으므로, CLI를 업데이트하면 목록도 따라 바뀐다.

## 동작

- **목록 받기(`teams.models`):** 실행부가 두 CLI에 목록만 묻는다. 모델 요청은 보내지 않는다.
  - Codex: `codex debug models`가 출력하는 모델 카탈로그에서 목록에 보이는 항목(`visibility: list`)만 Codex의 순서(`priority`)대로 쓴다. 보이는 이름은 `display_name`, 설명은 `description`이다. 카탈로그에 모델별 지시문이 들어 있어 출력이 크므로 20초·32MB까지 기다린다. app-server의 `model/list`는 세션을 열고 요청을 주고받아야 해서 쓰지 않았다.
  - Claude Code: 목록 명령이 없다. `claude --help`의 `--model` 설명에 예로 나온 별칭(지금은 `fable`·`opus`·`sonnet`)에 `opus`·`sonnet`·`haiku`를 더해 중복 없이 쓴다. 별칭은 항상 그 계열의 최신 모델을 가리킨다. 0단계 확인에서 쓴 Claude Agent SDK의 `supportedModels()`는 SDK를 앱에 새로 넣고 Claude Code를 띄워야 해서 쓰지 않았다.
  - 실행 줄에 그대로 넣을 수 없는 이름(`TEAM_MODEL` 형식 밖)은 빼고, 최대 40개까지만 둔다. CLI가 없거나 실패하면 그 도구의 목록은 비어 있다. 결과는 10분 동안 재사용한 뒤 다시 묻는다. 실행부를 다시 켜지 않아도 업데이트한 CLI의 목록이 나온다.
- **선택 상자:** 맨 위 **도구 기본값**(빈 값), CLI 목록, 목록에 없는 지금 값(템플릿에 저장된 이름 등), 맨 아래 **직접 입력…** 순서다. **직접 입력…**을 고르면 입력칸으로 바뀌고, 지금 값이 선택된 채 커서가 간다. 옆의 목록 단추를 누르면 선택 상자로 돌아간다. 도구를 바꾸면 모델은 도구 기본값으로 돌아간다(이전과 같음).
- **목록이 없을 때:** 이전 실행부이거나 그 도구의 목록이 비어 있으면 이전처럼 추천이 붙은 입력칸을 쓴다.
- 고른 이름은 이전처럼 Claude Code에 `--model`, Codex에 `-m`으로 넘긴다. 시작 전 점검과 실행 줄은 바뀌지 않았다.

## 검증

- `tests/host/teams.test.ts` 7/7. `codexModels`가 숨은 모델과 실행 줄에 넣을 수 없는 이름(`bad name`)을 빼고 Codex 순서로 정렬하는지, 설명이 없는 모델은 설명 없이 돌려주는지, `claudeModels`가 도움말의 별칭과 기본 계열을 중복 없이 돌려주고 예시가 없는 도움말에서도 세 계열을 주는지 확인했다.
- `tests/host/teams-host.test.ts` 3/3(샌드박스 밖, 격리된 `MONGLE_DATA_DIR`). `teams.models`가 두 도구의 목록을 돌려주고, 두 번째 요청에서는 CLI에 다시 묻지 않는지 확인했다.
- `tests/ui/teams.test.ts` 6/6. 선택 상자의 순서(도구 기본값, 목록, 직접 입력…)와 지금 모델 선택, 설명 표시, 목록에 없는 지금 값의 유지, 목록이 없을 때의 입력칸을 확인했다.
- 실제 CLI: 이 PC의 Claude Code 2.1.300과 Codex 0.162.1에서 실행부 코드(`defaultTeamEnvironment.models`)로 목록을 받았다. 모델 요청은 없었고 두 목록을 함께 받는 데 0.13초 걸렸다. Claude는 `fable`·`opus`·`sonnet`·`haiku`, Codex는 `gpt-6-astra`·`gpt-6.1-sol`·`gpt-6-luna`와 이 PC의 opencodex 설정이 더한 `anthropic/claude-fable-5-1`·`anthropic/claude-haiku-5-5`·`anthropic/claude-opus-5-5`·`anthropic/claude-sonnet-5-5`였다.
- 화면 확인(Aside): 실제 `TeamSetup` 컴포넌트와 `styles.css`를 시험용 응답으로 묶은 미리보기에서 선택 상자 표시, **직접 입력…** 전환과 입력, 목록 단추로 돌아가기를 조작해 확인했다. **직접 입력…**을 고르면 지금 값(`gpt-6-astra`)이 전체 선택된 채 커서가 가고, `gpt-7-preview`를 입력한 뒤 목록 단추를 누르면 그 이름이 선택된 채 선택 상자로 돌아왔다. 처음에는 입력칸 안의 브라우저 추천 화살표와 옆의 목록 단추가 칸을 좁혀 `gpt-7-preview`의 앞부분이 잘렸다. 목록이 있을 때는 추천을 빼고 단추를 입력칸 안쪽 오른쪽에 겹쳐, 입력칸이 선택 상자와 같은 폭에서 이름 전체를 보이게 고쳤다. 미리보기의 목록은 위 실제 CLI 결과를 옮긴 것이고 실제 실행부가 아니다.
- 타입 검사·빌드·배포 검사와 전체 회귀 결과는 PR의 검증 결과에 적는다.

## 확인하지 못한 범위

- 실제 Electron 앱에서 모델을 골라 팀을 띄우는 확인(아스트라 실기 확인)은 하지 않았다.
- `codex debug models`는 이름에 debug가 붙은 명령이라 Codex가 바꾸거나 없앨 수 있다. 그러면 Codex 구성원의 모델 칸이 입력칸으로 돌아간다.
- Claude Code가 도움말 형식을 바꾸면 예시 별칭을 찾지 못하고 `opus`·`sonnet`·`haiku`만 나온다.
- 고른 모델을 그 계정에서 실제로 쓸 수 있는지는 시작 전 점검이 확인하지 않는다. 모델 요청을 보내야 알 수 있기 때문이다.
