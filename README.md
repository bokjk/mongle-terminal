# 몽글터미널

**그룹과 분할 화면으로 작업을 정리하고, 다른 기기에서 같은 터미널에 이어서 접속하는 Windows 앱입니다.** PowerShell·명령 프롬프트와 설치된 Git Bash·WSL을 사용합니다. Claude·Codex 등은 원하는 터미널에서 직접 실행하면 됩니다.

현재 개발 버전은 **0.2.0 Windows 미리보기**입니다. 저장소는 비공개이며, 공개 배포와 프로젝트 자체의 오픈소스 라이선스는 아직 준비 중입니다. 실제 구현과 확인 범위는 [구현·검증 상태](docs/IMPLEMENTATION-STATUS.md), 변경 이력은 [CHANGELOG](CHANGELOG.md)에 기록합니다.

## 주요 기능

- **컴퓨터와 그룹:** 왼쪽에서 작업할 컴퓨터·그룹을 고르고, 그룹별로 터미널 이름과 배치를 저장합니다.
- **드래그 분할:** 터미널 제목줄을 가장자리로 옮겨 좌우·상하로 나누거나 가운데에 놓아 위치를 교환합니다. 경계를 끌어 크기를 바꾸고 한 패널을 최대화할 수 있습니다.
- **익숙한 터미널 조작:** 시작 폴더의 **찾아보기**, 블록 선택 후 자동 복사, 우클릭 붙여넣기, 검색과 글자 크기 조절을 제공합니다. 선택 없는 `Ctrl+C`는 실행 중인 작업을 중단합니다.
- **작업 공간 유지:** 창을 닫으면 트레이에 남고 셸은 계속 실행됩니다. 완전 종료 후 다시 열면 저장된 그룹·분할·시작 폴더와 보관을 허용한 출력 기록을 복원합니다.
- **PC·모바일 원격 접속:** Tailscale과 기기 승인을 통해 접속합니다. 원격 설정의 **QR코드**를 휴대폰 카메라로 찍으면 주소 입력 없이 열 수 있습니다. 휴대폰은 별도 몽글 앱 없이 브라우저에서 터미널을 전환하고, 보조 키·글자 크기·기록 스크롤을 사용할 수 있습니다.

연속 답변에서 보이던 중간 빈 화면을 없애도록 화면 갱신을 수정했습니다. 실제 사용자의 정상 동작 확인과 자동 검증 범위는 [출력 깜박임 검증](docs/validation/streaming-flicker.md)에 구분해 기록했습니다.

## 사용하기

지원 대상으로 개발 중인 환경은 **Windows 11 x64**입니다. 배포본에는 Node.js를 포함하므로 사용자가 따로 설치할 필요가 없습니다. 사용할 PowerShell·Git Bash·WSL 등은 해당 PC에 설치되어 있어야 합니다.

1. 설치본 또는 압축 배포본으로 몽글터미널을 엽니다. 압축본은 폴더 전체를 유지하고 `MongleTerminal.exe`를 실행합니다.
2. **현재 컴퓨터 → + 터미널**에서 셸과 시작 폴더를 선택합니다. 로컬 데스크톱은 **찾아보기**를, 원격·모바일은 대상 PC의 전체 경로 입력을 사용합니다.
3. 터미널 내용을 드래그하고 놓으면 복사됩니다. 우클릭 또는 `Ctrl+V`로 붙여넣으며 여러 줄은 먼저 확인합니다. 마우스를 직접 사용하는 프로그램에서는 `Shift+우클릭`으로 메뉴를 엽니다.
4. 다른 기기에서 접속하려면 양쪽 Tailscale 연결 후 작업 PC의 **설정 → 원격 연결**에 표시된 QR코드를 휴대폰 카메라로 찍습니다. 처음 접속한 기기는 새 연결 코드를 입력하고 작업 PC에서 승인합니다. 주소 복사도 사용할 수 있습니다.

이전에 만든 Tailscale HTTPS 연결이 남아 있어도 현재 몽글터미널의 전용 경로임을 확인하면 재사용합니다. 실제 다른 웹 서비스와 같은 호스트 이름을 공유하는 경우는 인증 쿠키를 보호하기 위해 차단하며 기존 서비스를 덮어쓰지 않습니다.

창의 **X**는 트레이로 숨깁니다. 트레이 아이콘이나 바로가기로 다시 열 수 있습니다. **앱 종료 · 터미널 유지**는 화면만 종료하고, **완전 종료…**는 현재 PC의 작업을 저장한 뒤 셸과 백그라운드 실행부까지 종료합니다.

완전 종료·PC 재시작 후에는 **새 셸**을 저장된 시작 폴더에서 엽니다. 이전 명령·셸 변수·Claude/Codex 대화·개발 서버의 실행 상태를 자동 재개하지 않습니다. 원격 접속 중에는 작업 PC와 실행부가 켜져 있어야 합니다. 자세한 종료 동작, 기록 보관과 문제 해결은 [사용자 안내](docs/USER-GUIDE.md)에 있습니다.

## 업데이트와 배포 상태

0.2.0에는 NSIS 설치본의 새 버전 자동 확인·다운로드와 사용자 확인 후 설치를 구현했습니다. 시작 후와 6시간마다 확인하며, 설정의 **앱 업데이트**와 앱·트레이 메뉴에서 상태를 볼 수 있습니다. 다운로드만으로 작업을 끝내지 않고, 사용자가 설치를 확인하면 현재 PC의 작업을 저장·종료한 뒤 진행합니다. ZIP·개발 실행은 수동 업데이트 대상입니다.

현재 저장소는 비공개이고 공개 GitHub Release가 없으므로 일반 설치본에서 새 버전을 받아 설치하는 공개 배포 흐름은 아직 사용할 수 없습니다. 공개 Release 다운로드와 실제 구버전 NSIS → 새 버전 설치는 미검증입니다. 개발 PC에는 원격 연결 복구 수정을 포함한 0.2.0 압축 실행본을 수동 적용하고 실제 HTTPS 연결을 확인했습니다. 압축 실행본은 자동 설치 대상이 아닙니다. 구현 및 검증 상태와 배포 준비는 [배포 안내](docs/RELEASING.md)를 따릅니다.

수동 업데이트 전에는 실행 중인 작업을 저장하고 **완전 종료…**를 선택하세요. 실행부가 동작 중인 설치 폴더의 파일을 덮어쓰지 마세요. 사용자 데이터는 기본적으로 `%LOCALAPPDATA%\MongleTerminal`에 저장하며, 업데이트·제거 시 자동 삭제하지 않습니다.

현재 산출물은 코드 서명 없는 미리보기입니다. Windows의 실제 앱·PowerShell/ConPTY와 Android 삼성 인터넷의 키보드·기록 스크롤을 확인했습니다. OS 재부팅 자체, 모든 모바일 브라우저, WSL 실제 실행, 장시간 연결 및 설치·제거 마법사의 검증은 아직 남아 있습니다. 인증 오류 발생 이력과 미확정 원인도 [구현·검증 상태](docs/IMPLEMENTATION-STATUS.md)에 남겨 두었습니다.

## 개발 환경에서 실행하기

Windows 11 x64와 Node.js **24 LTS**를 사용합니다.

```powershell
npm.cmd ci
node node_modules/node-pty/scripts/prebuild.js
node node_modules/node-pty/scripts/post-install.js
node node_modules/esbuild/install.js
node node_modules/electron/install.js
npm.cmd run typecheck
npm.cmd run build
npm.cmd test
npm.cmd start
```

준비 단계는 고정된 의존성의 공식 설치 스크립트를 실행합니다. npm이 의존성 설치 스크립트를 차단하거나 Electron 바이너리를 자동으로 내려받지 않은 경우에도 네이티브 런타임을 준비합니다. 최초 다운로드에는 인터넷 연결이 필요합니다.

브라우저 검사에는 Chrome이 필요합니다. 설치되어 있지 않으면 `npx.cmd playwright install chrome`으로 준비합니다. UI 검사가 생략되지 않도록 빌드한 뒤 테스트합니다.

`npm.cmd run dev`는 빌드 후 데스크톱 앱을 실행합니다. `npm.cmd run package`는 `release/`에 `MongleTerminal-Setup-0.2.0-x64.exe`와 `MongleTerminal-0.2.0-x64.zip`을 생성하도록 구성되어 있습니다. 압축 전 실행 파일은 `release/win-unpacked/MongleTerminal.exe`입니다. 실제 산출물 검증과 배포 절차는 [배포 안내](docs/RELEASING.md)를 확인하세요. `npm.cmd run host`는 개발용이며 배포본의 독립 실행부 검증을 대신하지 않습니다.

개발·수동 검사는 실행 전에 `$env:MONGLE_DATA_DIR = Join-Path (Get-Location) '.test-data\dev-profile'`처럼 별도 데이터 폴더를 지정하세요. MSIX로 설치된 개발 도구에서 실행하면 AppData가 도구 전용 폴더로 분리될 수 있습니다. 시험 프로필로 실사용 Tailscale 연결을 바꾸지 말고, 실제 앱의 원격 설정에서 연결을 관리하세요. [설정 폴더 분리와 복구 기록](docs/validation/msix-profile-recovery.md)

## 구조와 라이선스

| 경로 | 역할 |
|---|---|
| `apps/desktop` | Electron 창·트레이·로컬 연결 |
| `apps/web` | PC·모바일 공통 화면 |
| `packages/host` | 셸·배치·원격 연결을 유지하는 독립 실행부 |
| `packages/terminal` | 터미널 화면과 입력 동기화 |
| `docs` | 사용자 안내·설계·오픈소스 분석·검증 근거 |

xterm 내부 API에 의존하는 어댑터가 있어 관련 패키지의 정확한 버전을 함께 유지하고, 화면·입력 회귀 검증 후 변경합니다. 초기 설계와 비교 분석은 [문서 목록](docs/README.md)에서 확인할 수 있습니다.

몽글터미널 자체 코드의 공개 라이선스는 아직 정하지 않았습니다. `private`/`UNLICENSED` 상태이며 의존 패키지의 MIT·ISC 라이선스가 앱 자체의 사용 허가를 뜻하지 않습니다. 사용한 구성요소와 고지 원문은 [제3자 고지](docs/THIRD-PARTY-NOTICES.md)를 확인하세요.
