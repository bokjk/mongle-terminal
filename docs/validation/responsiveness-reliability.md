# 응답성·안정성 점검

기준일: 2026-10-03. 소스 버전 **0.3.8의 미배포 변경**. 공개 설치본 업데이트나 실제 사용자 세션에 적용했다는 의미가 아니다.

## 재현한 문제와 변경

| 영역 | 재현 조건 | 변경 |
|---|---|---|
| 작은 출력의 누적 지연 | 같은 시점에 작은 PTY 출력이 여러 번 도착 | 연속 출력만 xterm 파서 큐로 함께 전달한다. 문자열/바이트 경계, UTF-8 증분 해석, 출력 revision, snapshot·resize·기록 삭제·종료 순서는 보존한다. |
| 출력 중 선택 드래그 중단 | 마우스 버튼을 누른 동안 새 화면이 reset/복원됨 | 같은 버퍼·크기·선택 텍스트일 때 드래그 상태를 복원한다. 갱신 중 마우스를 놓은 경우 화면 완성 후 한 번만 복사하고 새 선택·입력·컴포넌트 종료는 이전 복사를 취소한다. |
| 워크트리 목록 대기 | 저장소를 조회할 때 독립적인 Git 명령을 하나씩 실행 | 경계 확인 후 읽기 명령 5개를 병렬화한다. 실패해도 모든 프로세스가 끝날 때까지 조회 슬롯을 유지한다. 캐시로 오래된 결과를 쓰지 않는다. |
| 태그와 브랜치의 이름 충돌 | 같은 이름의 태그와 로컬 브랜치가 다른 커밋을 가리킴 | 목록에는 정확한 로컬 브랜치 이름을 표시하고 생성·연결 시 `refs/heads/`를 사용한다. |
| 연결 유지 응답 지연 | 느린 snapshot이 전역 작업 큐를 잡고 있음 | 연결 검사와 기존 제어권만 갱신하는 heartbeat는 큐 밖에서 처리한다. |

| 데스크톱 종료된 원격 연결 | `/health` 또는 인증 응답 전에 연결 종료 | HTTP와 인증 대기를 취소하고 다음 단계·identity 저장·소켓 생성을 막는다. |
| 최신 작업 공간의 후퇴 | 최신 state 이벤트 또는 후속 조회가 먼저 도착 | 이벤트 세대·요청 순번·호스트 선택을 검사하고 오래된 응답을 폐기한다. 드래그 이후 조회도 같은 경로를 쓴다. |

| 탐색기 오래된 읽기 누적 | 두 읽기를 기다리며 폴더를 접거나 미리보기·터미널·cwd 변경 | 아직 시작하지 않은 읽기를 취소한다. 이미 전송한 읽기는 완료까지 슬롯을 점유하여 호스트 동시 읽기 2개 제한을 유지한다. |

## 측정

Windows, Node.js 24.18.0에서 격리된 데이터로 측정했다. 아래 수치는 특정 부하의 처리 시간이며 앱 전체가 같은 비율로 빨라졌다는 뜻은 아니다.

| 측정 대상 | 변경 전 | 변경 후 | 조건 |
|---|---:|---:|---|
| 작은 출력 1,000조각 | 15,269.7ms | 7.88 / 2.90 / 3.14ms | 새 TerminalEngine, 80×24, 한 글자씩 같은 tick에 1,000회 write 후 Promise.all 대기. revision 1,000 유지. 전 1회, 후 3회 측정. |
| `inspectProject` | 674 / 572 / 601 / 721 / 783ms | 327 / 282 / 278 / 260 / 226ms | 작은 임시 Git 저장소, 각각 5회. 중앙값 674→278ms, 약 59% 감소. |

출력 측정은 `node --import tsx tests/terminal/benchmark.ts`로 반복할 수 있다. 일반적인 간격으로 들어오는 실제 CLI 출력, 대형 Git 저장소, 원격 지연의 측정과 구분한다.

통합 중 재측정에서도 작은 출력 1,000조각은 5.36 / 2.00 / 2.01ms, revision 1,000이었다. 100×30 화면의 snapshot 직렬화는 100/1,000/5,000줄에서 각각 중앙값 0.80/5.96/30.68ms였다. 원시 결과는 커밋하지 않는 `test-results/quality-benchmark.log`에 남겼다.

## 디자인 참고와 적용 판단

Mobbin의 [Tree UI](https://mobbin.com/glossary/tree)를 브라우저에서 직접 읽고 공개 예시를 확인했다. 부모/자식 항목의 펼침·접힘, Deel의 아이콘과 텍스트가 있는 문서 트리, 메뉴 계층 예시를 비교했다. 기존 파일 트리의 계층·아이콘·선택 구조를 유지하고, 접은 폴더의 대기 요청을 취소해 현재 탐색이 불필요한 과거 읽기 뒤에 밀리지 않게 했다.

Mobbin 앱 갤러리는 로그인 안내로 연결되어 개별 유료 앱 흐름을 확인하지 못했다. Aside도 연결되지 않아, 실제 확인 범위는 Codex 브라우저의 공개 Tree 페이지다. 이 자료가 비동기 취소 구현이나 성능 수치를 검증한 것으로 해석하지 않는다.

## 검증 범위

- 출력 배치·문자열/바이트 경계·snapshot/resize/clear/종료, 브라우저 연결 취소·오래된 소켓 이벤트, 실제 Git 이름 충돌, 느린 작업 중 heartbeat에 회귀 검사를 추가했다.
- 별도 검토에서 대량 출력 배치가 xterm의 대기 데이터 상한을 넘을 수 있음을 확인해 여러 조각을 합치는 총 길이를 1,048,576단위(문자열 code unit 또는 바이트) 이하로 제한했다. 단일 입력 조각을 재분할하지는 않는다. 50 MiB burst에서 오류 없이 revision 50까지 처리하는 회귀를 포함한다. 화면 선택 복원은 고정 버전 xterm 6 내부 API를 사용하므로 의존성을 갱신할 때 관련 Chrome 회귀가 필요하다.
- 소스를 메모리에서 번들한 실제 Chrome UI로 상태 응답 역전, 취소한 창의 늦은 완료, 드래그 후 상태 보존, 탐색기의 폴더 접기·미리보기 닫기·마지막 선택·터미널/cwd 변경을 검증한다. RPC 지연은 테스트 브리지로 주입하며 실제 원격 네트워크 검증과 구분한다.
- 격리 Electron과 localhost TLS 서버로 원격 연결 종료, 기존 쿠키·CSRF·호스트 identity·버전 경계를 확인한다.
- 초기 전체 검사에서 Windows 부모 Job 수명주기 항목이 샌드박스 권한 제한으로 실패했다. 같은 격리 검사를 제한 밖에서 다시 실행하여 `tests/platform/lifecycle.test.ts` **3/3 통과**를 확인했다. 제품 버그로 분류하지 않았다.

## 실제 앱과 패키지

`node --import tsx scripts/package.ts --output release-quality-pass --dir`로 별도 실행 폴더를 만들었다. 빌드·동봉 Node 24.18.0의 네이티브 모듈 로드·외부 node_modules에 의존하지 않는 패키지 모듈 해석·7종 아이콘 검사를 통과했다. 설치 파일·ZIP 생성이나 공개 배포는 실행하지 않았다. 기존 500 kB 초과 웹 청크 경고와 author 메타데이터 안내는 비차단 경고로 남는다.

`MONGLE_E2E_RESPONSIVENESS=1`과 TEMP 아래 `MONGLE_E2E_DATA_ROOT`를 지정하여 `tests/e2e/responsiveness.test.ts`를 개발 Electron **1/1**, 생성한 패키지 **1/1** 통과했다. Electron 44.4.5 / Chromium 152.0.7977.130의 실제 OwnerPipe·cmd·ConPTY를 사용했다.

- 실제 셸이 계속 출력하는 동안 폴더 6개 펼침·접힘, 연속 미리보기 변경, Git 변경 파일 열기와 다른 터미널 전환을 완료했다. 출력 시험은 UI 검증 후 stop 파일로 정상 종료했다.
- 원래 탭으로 돌아와 최종 출력을 확인하고 셸 변수 유지·입력 응답·`cd` 후 탐색기 갱신을 검증했다. 두 셸의 PID/generation과 xterm DOM 노드는 유지됐다.
- 화면 오류 0개, 정상 `host.shutdown`과 시험 앱 종료를 확인했다. 원시 결과와 화면은 `test-results/e2e/responsiveness/`, `test-results/e2e/responsiveness-packaged/`에 보관하며 Git에는 포함하지 않는다.

개발 Electron의 첫 제한 환경 실행은 launch timeout/GPU DLL 종료로 완료하지 못했다. 같은 격리 시험을 제한 밖에서 실행한 위 성공 결과와 구분한다. 이 검사는 동시 조작 회귀이며 입력 지연의 수치형 벤치마크가 아니다.

## 네이티브 클립보드: 최초 실패·후속 조사

아래는 최초 점검에서 남긴 실패 기록이다. 후속 조사에서 Windows `OpenClipboard`의 접근 거부(오류 5)를 확인했고, Electron의 조용한 쓰기 실패를 복사 성공으로 표시하던 제품 결함과 설정 화면의 데스크톱 복사 경로 누락을 수정했다. [후속 원인·변경·검증 경계](clipboard-followup.md)를 현재 상태로 함께 읽는다.

`MONGLE_E2E_CLIPBOARD=1`과 새 패키지로 실행한 `tests/e2e/clipboard.test.ts`는 첫 선택 자동복사 후 Windows 클립보드에서 시험 문자열을 읽는 검사에 **실패**했다. 다른 Electron 시험과 분리하고 제한 밖에서 단독 실행해도 동일했다. 제한 환경의 별도 실행 시작 실패와도 구분한다.

임시 격리 진단으로 다음을 확인했다. 실제 개인 클립보드 내용은 출력하거나 저장하지 않았다.

- 자동복사 핸들러가 정확한 시험 문자열을 `clipboard.writeText`에 한 번 전달했고 화면의 복사 성공 상태도 표시됐다.
- 선택·UI·IPC 경로를 건너뛰고 Electron에서 `await clipboard.writeText('MONGLE_CLIP_DIRECT')` 후 `clipboard.readText()`를 호출해도 길이 0이었다.
- 같은 시험 앱에서 실행한 PowerShell의 읽기 전용 `Get-Clipboard`도 길이 0, 시험 문자열 일치 false였다. `ClipboardItem` 쓰기 경로에서도 읽은 내용은 비어 있었다.
- 시험 앱·호스트 정상 종료(`cleanedUp: true`)와 화면 예외 0개를 확인했다. 제품의 클립보드 구현, OS 설정, 인증·권한을 우회하는 변경은 하지 않았다.

이 도구 실행 환경에서 **Electron→Windows 네이티브 클립보드 왕복 자체가 성공하지 않았다.** 최초에는 OS와 런타임 중 원인을 미확정으로 남겼으나, 후속 읽기 전용 진단에서 네이티브 접근 거부를 확인했다. 실제 사용자 데스크톱에서의 최신 패키지 선택 자동복사·붙여넣기 성공은 여전히 완료로 간주하지 않는다. 원시 최초 실패·분리 진단 로그는 `test-results/quality-clipboard.log`, `test-results/quality-clipboard-sequential.log`, `test-results/quality-clipboard-probe.log`에 있다.

## 남은 범위

실물 Android·Tailscale 왕복, 실제 NSIS 설치·자동 업데이트·재부팅은 이번 검사에 포함하지 않는다. 사용자 호스트·셸을 종료하거나 인증·세션 데이터를 복사하지 않았고, 실제 Tailscale Serve 설정도 바꾸지 않았다. 새 의존성, 버전 변경, 저장소 공개 범위·라이선스 변경은 없다.
