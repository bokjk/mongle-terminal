# 모바일 보조 키 편집

휴대폰 키보드 위 보조 키 줄의 키와 순서를 **설정 → 화면 → 모바일 보조 키**에서 바꾸는 기능의 구현과 검증 범위다. 미배포 상태다.

## 동작

- 키 목록·기본값·저장값 정리는 `apps/web/src/key-bar.ts`, 키 줄은 `KeyBar.tsx`, 편집 화면은 `KeyBarSettings.tsx`에 있다. 구성은 기기 브라우저의 `localStorage`(`mongle.keyBar`)에 키 ID 목록으로 저장한다. 호스트·다른 기기·CLI 설정은 바꾸지 않는다.
- 저장값은 알려진 키만 순서대로 한 번씩, 최대 16개만 쓴다. 저장값이 없거나 목록이 아니면 기존 기본 구성(Esc, Tab, Ctrl, Alt, ^C, 방향키 4개)을 쓴다. 빈 목록은 그대로 빈 목록이다.
- 키를 누르면 기존 보조 키와 같은 경로(`PaneActions.key` → 제어권 확인 → 입력 대기열)로 보낸다. 방향키·Home·End는 `sendKey`로 커서 키 모드(`ESC [` / `ESC O`)를 따른다. Ctrl·Alt는 기존처럼 고정 토글이다.
- 기본 9개 키는 이전처럼 키 줄 폭을 나눠 쓰며, 390·320px 화면에서 스크롤 없이 들어가는 것을 검사했다. 키가 많으면 키 목록만 가로로 스크롤하고 키보드 열기 버튼은 36px로 고정해 맨 오른쪽에 남긴다.
- 기본 키의 접근성 이름(Esc, Tab, Ctrl, Alt, ^C, 왼쪽·아래·위·오른쪽, 키보드 열기)은 그대로다. 기호만 있는 새 키에는 읽을 수 있는 이름(Shift+Tab, Enter, 세로 막대 등)을 붙였다.

## 디자인 참고

2026-10-12 Aside로 Mobbin 공개 상세 화면을 열어 확인한 iOS 사례다. 터미널 앱(Termius, Blink, Working Copy, Textastic)의 보조 키 편집 화면은 Mobbin에서 찾지 못해 보지 못했다.

- Obsidian **Toolbar**: 현재 툴바 명령 세로 목록, 행 왼쪽 빨간 −, 오른쪽 드래그 핸들, 위쪽 명령 검색으로 추가.
- Spark Mail **Personalize toolbar**: 툴바 항목과 More 항목을 나누고 + / −로 옮김, 최대 개수 안내.
- Yahoo News **Edit Navigation**: 현재 탭 목록과 카테고리별 추가 후보 목록을 나눔, 후보에는 정렬 핸들 없음.
- X **Custom navigation**: 하단에 실제 모양의 내비게이션 바를 미리보기로 보여 줌.
- Lensa AI **Setup**: 목록 위 Reset 버튼.

적용한 판단: 사용 중 목록과 분류별 추가 목록을 나누고(Yahoo News·Spark Mail), 행마다 −·+ 버튼을 두며, 실제 크기 미리보기(X)와 기본값 되돌리기(Lensa AI), 개수 안내(Spark Mail)를 넣었다. 순서 변경은 사례들의 드래그 핸들 대신 ↑·↓ 버튼을 썼다. 몽글 설정은 휴대폰에서 스크롤되는 대화상자 안에 열려 드래그가 스크롤과 겹치고, 버튼은 터치·키보드·화면 낭독기에서 같은 방식으로 동작하기 때문이다. 키를 빼거나 옮긴 뒤에는 같은 행(또는 그 자리로 온 행)의 버튼으로 포커스를 돌려준다. 다른 화면 설정처럼 바로 적용하며 별도 저장 버튼은 두지 않았다.

## 검증(2026-10-12)

- 단위 검사 `tests/ui/key-bar.test.ts` 2/2 통과: 저장값 정리(모르는 키·중복·개수 제한·빈 목록), 이동·추가·삭제, 기본값 판정.
- 실제 Chrome 휴대폰 화면 검사 `tests/ui/mobile-key-bar.test.ts` 4/4 통과(아래 검토 후 추가한 Ctrl 해제 검사 포함): 기본 키 줄의 이름·순서가 이전과 같고 390·320px에서 넘치지 않음, 저장한 구성대로 표시하고(모르는 키 제외) Home·세로 막대·End·PgUp·Enter가 `ESC[H | ESC[F ESC[5~ CR`로 전달됨, 16개면 가로 스크롤되고 키보드 버튼은 화면 안에 그대로 있음, 편집 화면의 빼기·추가·순서 변경·되돌리기·최대 개수와 포커스 이동.
- 같은 검사 중에 스크린샷으로 키 줄과 편집 화면을 확인했다. 빼기 아이콘이 0.5px 위치 때문에 줄마다 다른 색으로 보여 아이콘을 16px로 바꿨다.
- 타입 검사 통과.

## 아스트라 검토와 수정(2026-10-12)

아스트라(`gpt-6-astra`)가 커밋 `a8f8a92`를 검토해, 켜 둔 Ctrl·Alt를 설정에서 빼도 켜짐 상태가 남아 보이지 않는 보조 키가 계속 입력을 바꾸는 문제를 코드 경로로 지적했다(예: Ctrl이 남아 `c`가 Ctrl+C가 됨). 새 `^D`·`^Z` 등에 읽을 수 있는 이름이 없다는 점과, 새 파일 끝 빈 줄로 `git diff --check`가 실패하는 점도 지적했다.

수정: 목록이 바뀔 때 빠진 Ctrl·Alt를 끈다. `^C`·`^D`·`^Z`·`^L`·`^R`에 `Ctrl+C` 같은 접근성 이름을 붙였다. 실제 Chrome 휴대폰 화면에서 Ctrl 켜기 → 설정에서 Ctrl 빼기 → `c` 입력을 재현하는 검사를 추가했고, 수정 전 연결로는 `\x03`이 전달되어 실패하고 수정 후 `c`가 전달됨을 확인했다(휴대폰 화면 검사 4/4, 단위 2/2).

아스트라가 실제 격리 앱(Electron 창을 좁혀 휴대폰 화면 표시)에서 키 줄 표시, 키 빼기·다시 넣기·순서 변경 반영을 확인했다. 실물 휴대폰과 가상 키보드의 상호작용은 확인하지 않았다.

## 확인하지 않은 범위

- 실물 휴대폰(Android·iPhone)과 가상 키보드에서의 확인은 하지 않았다. 실제 몽글터미널 앱은 위 아스트라 기록처럼 좁힌 Electron 창에서만 확인했고, 검토 수정(Ctrl·Alt 해제) 뒤의 실제 앱 확인은 하지 않았다.
- 설정 내보내기·가져오기에는 이 구성이 포함되지 않는다(기기별 설정).
