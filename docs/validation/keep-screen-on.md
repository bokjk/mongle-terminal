# 화면 켜 두기

휴대폰으로 작업을 지켜볼 때 화면이 저절로 꺼지지 않게 하는 **설정 → 화면 → 화면 켜 두기**의 구현과 검증 범위다. 미배포 상태다.

## 동작

- `apps/web/src/use-screen-wake-lock.ts`가 브라우저의 Screen Wake Lock API(`navigator.wakeLock.request('screen')`)를 쓴다. 설정이 켜져 있고, 컴퓨터에 연결되어 있고, 터미널이 선택되어 있고, 페이지가 보일 때만 요청한다. 호스트·CLI·다른 기기는 바꾸지 않는다.
- 페이지가 가려지면 브라우저가 잠금을 풀고, 다시 보이면 새로 요청한다. 절전 모드 등으로 시스템이 푼 경우에는 즉시 다시 요청하지 않고 다음에 페이지가 보일 때 요청한다. 거절은 조용히 넘긴다.
- 요청이 끝나기 전에 조건이 사라졌다면(설정 끔, 페이지 가려짐) 늦게 받은 잠금을 바로 푼다.
- 설정은 기기 브라우저의 `localStorage`(`mongle.keepScreenOn`)에 저장하고 기본값은 꺼짐이다. 보안 페이지(HTTPS·localhost)가 아니거나 API가 없으면 체크박스를 비활성으로 두고 이유를 보여 준다.

## 디자인 참고

2026-10-12 Aside로 Mobbin 공개 상세 화면을 열어 확인한 iOS 사례다. Paprika·Mela의 해당 화면은 찾지 못했고, Crouton에서는 화면 유지 설정을 확인하지 못했다.

- Any Distance(설정 → Auto-Lock 그룹): `Prevent screen auto-lock` 토글, "활동 기록 중 직접 잠그기 전까지 화면을 켜 둔다"는 설명.
- Strava(설정 → Screen Lock): `Prevent Auto-Lock` 토글, "기록하는 동안 화면이 꺼지지 않게 한다"는 설명.

적용한 판단: 두 사례처럼 켜고 끄는 컨트롤 하나에 적용 조건을 설명으로 붙였다. 몽글 설정의 기존 형식(설명이 붙은 라벨 + 체크박스, 예: 터미널 기록 보관)을 따랐다. 사례에는 없었지만 배터리 사용이 늘어난다는 안내와, 지원하지 않는 브라우저에서의 이유를 함께 적었다.

## 검증(2026-10-12)

- `tests/ui/keep-screen-on.test.ts` 3/3 통과:
  - 늦게 받은 잠금을 바로 푸는지, 거절을 조용히 넘기는지(단위).
  - 실제 Chrome 휴대폰 화면(브라우저 API를 기록용 대체물로 바꿔 요청·해제를 셈): 기본값에서는 요청하지 않음, 켜면 한 번 요청, 페이지가 가려지면 해제, 다시 보이면 다시 요청.
  - 설정 체크박스: API가 있으면 켤 수 있고 값이 반영됨, API가 없으면 비활성과 안내 문구.
- 설정·모바일 관련 UI 회귀 27/27 통과, 타입 검사 통과.

## 아스트라 검토(2026-10-12)

아스트라(`gpt-6-astra`)가 커밋 `fabea7a`를 검토했다. 늦게 도착한 잠금의 해제와 설정·연결·페이지 표시 조건 처리에서 막아야 할 결함은 찾지 못했다. 새 파일 끝 빈 줄로 `git diff --check`가 실패한 점만 고쳤다. 실제 격리 앱에서 기본 꺼짐 → 켜기 → 설정을 다시 열어도 유지 → 끄기를 확인했다. 실제 화면 잠금 방지, 다시 돌아왔을 때의 재요청, 실물 휴대폰 동작은 확인하지 못했다.

후속 제안(이번에 반영하지 않음): 브라우저가 요청을 거절하거나 시스템이 잠금을 풀었을 때 실제 유지 상태를 설정에 보여 주면, 켜 두었는데 동작하지 않는 상황을 이해하기 쉽다.

## 확인하지 않은 범위

- 실제 휴대폰에서 화면이 실제로 꺼지지 않는지는 확인하지 않았다. 헤드리스 Chrome의 실제 잠금 요청은 쓰지 않고 대체물로 요청·해제 시점만 확인했다. 실기 확인은 실제 휴대폰과 HTTPS 원격 주소가 필요하다.
- 실제 몽글터미널 앱에서의 확인(아스트라)은 하지 않았다.
