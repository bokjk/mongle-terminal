# Astra 실제 앱 선택 손실 경계 계측

검사일: 2026-10-06. 실행 시 저장소 HEAD: `e951cfa`. 제품 웹은 준비된 `dist/web`을 그대로 사용했고, 호스트만 `.test-data/selection-probe-host.cjs`로 교체한 격리 시험 실행이다. 계측 호스트는 기존 OSC 52 차단 동작을 유지하면서 차단 직전의 합성 LIVE 복사 문자열을 기록했다. 제품 기능 수정이나 수정 후 검증을 의미하지 않는다.

## 확인한 손실 경계

**안내가 겹친 39줄에서는 CLI가 보낸 OSC 52 복사 문자열 자체가 이미 6자 부족했다.** 몽글의 OSC 처리·클립보드 쓰기보다 앞에서 `END-299`가 `E`로 잘렸다는 직접 증거를 확보했다. 같은 실행의 안내가 겹치지 않은 6줄 OSC 원문은 정확했다.

이 결과만으로 몽글이 앞서 보낸 화면 크기/입력 상태가 CLI 선택에 영향을 주었을 가능성까지 배제하지 않는다. Claude 내부의 어느 함수에서 잘리는지와 근본 수정은 별도 분석 대상이다.

## 실제 조작과 결과

gpt-6-astra가 `node_repl` + `@oai/sky`로 실제 몽글터미널 Windows 창을 활성화하고 조작했다. 브라우저/Aside, Electron 가상 입력, 별도 복사 화면, 클래식 모드, 창 너비 변경은 사용하지 않았다. 기존 합성 대화를 전체화면 Claude로 재개했고 하단 고정 입력창을 유지했다.

각 사례 직전에 `capture-start`, 직후에 `capture-end`로 UI→호스트 `terminal.input`과 몽글 `clipboard-write` 호출을 수집했다. 계측은 기존 핸들러를 호출하며 종료 시 복원한다.

| 사례 | 실제 조작 | OSC 52 원문 | 몽글 clipboard-write | Windows 클립보드 관찰 |
| --- | --- | --- | --- | --- |
| 정상 대조 | LIVE-295~300, 6줄. 창 좌표 (237,630)→(728,715) | 359자, 원문 전체 일치 | 0회 | 도우미의 합성 LIVE 조건에 일치하는 텍스트 없음 (`text: null`) |
| 겹침 실패 | LIVE-261~299, 39줄. (237,103)→(1100,749) | 예상 2339자 중 2333자. 끝의 `ND-299` 6자 누락 | 0회 | 동일하게 `text: null` |

두 번째 사례는 PageUp, PageDown, 위쪽 휠 스크롤을 실제 앱에 입력해 준비했다. 직전 화면에서 LIVE-261은 y103, LIVE-299는 y749였고 `Jump to bottom` 안내가 마지막 행 끝을 덮었다. 드래그 끝점 x1100은 안내와 원래 텍스트 끝보다 충분히 오른쪽이다. 따라서 이전처럼 안내 안쪽에서 드래그를 끝낸 조건에만 의존하지 않는다.

실패한 CLI 복사 원문 마지막 행:

```text
예상: LIVE-299 selection test 가나다라마 ABCDEFGHIJ 0123456789 END-299
실제: LIVE-299 selection test 가나다라마 ABCDEFGHIJ 0123456789 E
```

원문과의 첫 불일치는 0부터 세는 문자열 위치 2333이며, 그 앞의 2333자는 일치한다. 화면에도 `copied 2333 chars to clipboard` 안내가 표시됐다. 이 안내 자체를 Windows 클립보드 성공의 증거로 취급하지 않는다.

## 입력·출력의 시간 순서

39줄 사례의 UI→호스트 입력 계측에는 다음 SGR 마우스 이벤트가 순서대로 있었다. 시간은 기록 파일의 Unix epoch 밀리초다.

| 시각 | 이벤트 |
| --- | --- |
| 1791297636823 | down: `ESC[<0;2;2M` |
| 1791297636831 | 왼쪽 버튼 이동: `ESC[<32;116;40M` |
| 1791297636854 | up: `ESC[<0;116;40m` |
| 1791297636862 | OSC 52 차단 직전 복사 원문: 39줄, 2333자 |

39줄 사례는 hover를 포함해 입력 5개, 몽글 복사 쓰기 0개였다. UI→호스트 요청은 관측했지만, 이번 기록을 별도 PTY 입력 함수까지 직접 계측한 것으로 표현하지 않는다. 6줄 사례에는 입력 7개가 있었고, 1791297535769에 정확한 359자 OSC 원문이 기록됐다.

## 준비 과정과 한계

- 시작 직후 두 번의 드래그는 선택 표시와 `terminal.input` 모두 발생하지 않았다. 유효한 선택 검사로 집계하지 않았다. 실제 터미널 면을 클릭한 뒤 선택 표시와 down/move/up이 확인된 6줄 사례를 수집했다. 초기 무입력의 내부 원인을 이번 검사로 확정하지 않는다.
- 새 node_repl 세션에서 처음 `sky` 변수가 없었고 공식 초기화 후 정상 진행했다. `foreground window did not report a process id` 오류는 재발하지 않았다.
- Windows 클립보드 반환값은 합성 LIVE 필터에 일치하지 않아 `null`로 기록됐다. 사적인 클립보드 원문은 출력·저장하지 않았다. 이번 실행에서 OS 클립보드 일치 성공을 주장하지 않으며, 앞선 비계측 실행의 클립보드 실패 증거와 구분한다.
- 이번 증거는 OSC 52 원문에서 이미 누락됐다는 경계를 확정한다. 정확한 CLI 내부 함수 원인, 모든 입력 전달의 적합성, 300줄 자동 스크롤 드래그, 스트리밍 중 선택, 수정 후 정상화는 아직 검증하지 않았다.

## 증거 파일 및 정리

다음 파일은 합성 시험 증거이며 무시된 `.test-data` 안에 보존했다.

- `astra-boundary-osc52.jsonl`: 이번 OSC 수집 기록 사본
- `astra-boundary-six.json`: 유효한 6줄 UI 입력·몽글 쓰기·클립보드 관찰
- `astra-boundary-overlap39.json`: 유효한 겹침 39줄 관찰
- `astra-boundary-summary.json`: OSC 원문 전체 비교 결과
- `astra-boundary-focus-only.json`: 초기 무입력 사례

시험 도우미의 정상 종료 결과 `closed: true`를 확인했고, 해당 시험 실행 파일 및 이번 TEMP 프로필에 해당하는 앱/호스트 프로세스가 남지 않았음을 확인했다. 시험용 web index와 host main은 기존 백업으로 복원했으며 각각 SHA-256이 일치했다. 기존 백업을 덮어쓰지 않았다. 해시 이름 web assets는 무시된 시험 디렉터리에만 남는다.

설치 사용자 앱·실사용 호스트·인증 데이터를 변경하거나 종료하지 않았다. 제품 코드, 기존 테스트 파일, 부모 담당 문서를 수정하지 않았다. 커밋·push·배포하지 않았다.
