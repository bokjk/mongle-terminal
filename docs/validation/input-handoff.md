# PC·모바일 입력 전환

2026-09-29, Windows x64. 모바일에서 입력한 뒤 데스크톱으로 돌아왔을 때 별도 **가져오기**가 필요했던 흐름을 수정한다. [앞선 화면 누르기 구현](tap-control.md)은 제어자가 없는 터미널에만 적용되어, 다른 기기로 작업을 넘기는 동작을 완성하지 못했다.

## 현재 동작

- PC·모바일의 터미널 내용 클릭·터치, 제목 클릭, 키보드 열기는 사용자가 해당 터미널에 입력하려는 조작으로 처리한다. 다른 기기가 제어 중이어도 이 기기로 전환한다. 기존 **가져오기** 버튼도 사용할 수 있다.
- 기본 붙여넣기 이벤트, 우클릭·메뉴·`Ctrl+Shift+V` 붙여넣기, 등록된 붙여넣기 동작과 모바일 보조 키도 같은 전환 경로를 사용한다. 여러 줄 확인에서 승인한 내용만 처리하며 취소한 붙여넣기는 제어권을 옮기거나 전송하지 않는다.
- 스크롤, 드래그 선택, 길게 누르기, 여러 손가락 동작, 창 활성화·재연결은 다른 기기의 제어권을 가져오지 않는다. 더블클릭은 첫 번째 클릭이 입력 시작으로 처리될 수 있으므로 모든 텍스트 선택이 제어권을 유지한다고 설명하지 않는다.
- 한 터미널에는 하나의 유효한 제어권만 유지한다. 화면 동기화 ACK 뒤에도 현재 연결·epoch가 유효한지 확인한 후 입력을 허용한다. 전송 여부가 불확실한 입력을 재전송하지 않으며, 불확실 상태나 제어 획득 실패는 직접 복구 버튼을 눌러야 한다.
- 직접 조작에 따른 전환은 기존 `control.acquire`로 처리하므로 이전 실행부에도 적용된다. 사용자 조작 없이 데스크톱이 처음 붙을 때의 취득은 제어자가 없고 `control.acquire-if-free`를 지원할 때만 시도한다. 이 수정에는 호스트·인증·Tailscale 설정 변경이 필요하지 않다.

## 검증 상태

최종 코드의 입력 전환 UI 13개와 관련 회귀 8개가 통과했다. 실제 사용자 실행본의 웹 파일을 적용하고 데스크톱 화면도 정상 종료·재실행으로 갱신했다. 실제 휴대폰 확인과 새 설치 패키지 검사는 아래와 같이 구분한다.

| 검사 | 현재 결과와 범위 |
|---|---|
| 입력 전환 UI | **13/13 통과**. 다른 기기에서 돌아오기, 제목·붙여넣기·보조 키, ACK 대기 중 공유 요청과 한 번만 전송, 취소·제어권 상실 후 미전송, 재연결·스크롤·드래그 선택의 수동 제어권 유지, 이전 호스트 호환 검사 |
| 실제 PowerShell·두 기기 화면 | **1/1 통과**, 아래 관련 회귀 8개에 포함. 격리된 실제 Windows PowerShell을 데스크톱·모바일 크기 브라우저에서 왕복 제어하고 같은 PID·generation·셸 변수 유지, ACK 전 입력 차단, 이전 제어자의 입력 차단 확인 |
| 관련 회귀 | **8/8 통과**. 위 왕복 검사 1개, 작업 공간·드래그 2개, 모바일 키보드 1개, 모바일 표시 4개. `test-results/input-handoff-regression.log` |
| 타입·최종 빌드·독립 검토 | **통과**. `npm run typecheck`, `npm run build`, 입력 전환·동시 취득·연결과 epoch 유효성에 대한 읽기 전용 검토. 기존 웹 번들 크기 안내 외 빌드 오류 없음 |
| 현재 사용자 앱·원격 HTTPS | **적용·확인 통과**. 실행 중인 호스트의 웹 파일만 백업 후 갱신. 정상 메뉴 **앱 종료 · 터미널 유지**로 데스크톱 화면을 다시 열고 연결된 조작 요소 확인. 동일 호스트 PID·bootId와 기존 PowerShell PID·generation 유지, 실제 HTTPS 자산과 빌드 파일 일치, 미승인 상태 API 접근 401 확인 |
| 실제 모바일 브라우저 | 이번 입력 전환 수정 후 Android 삼성 인터넷 실기 확인 전 |
| 사용자 사용 확인 | 2026-09-29 사용자가 수정 적용 후 **잘된다**고 확인. 기기·브라우저별 전체 시험이나 삼성 인터넷의 세부 동작 검사로 확대 해석하지 않음 |
| 새 설치 패키지·패키지 E2E | 이번 후속 수정에서는 수행하지 않음. 패키지 E2E의 입력 전환 기대 동작은 갱신했으며, 앞선 빈 격리 프로필 기동 검사의 미완료 결과는 [이전 기록](tap-control.md)에 보존 |

자동 검증은 격리 프로필에서 수행했다. 실제 적용은 MSIX 도구 프로필과 구분한 정상 사용자 실행 맥락에서 소유자 인증으로 확인했다. 호스트 JS의 빌드·실행본 해시가 같음을 확인했으며, 기존 사용자 호스트·셸을 종료하거나 인증 데이터·DB·Tailscale 설정을 변경하지 않았다. 실제 사용자 주소·식별자·터미널 출력은 이 문서와 저장소에 넣지 않는다.

적용 증거는 Git에서 제외한 `test-results/input-handoff/`의 `apply-web.json`, `desktop-refresh.json`, `desktop-ready.json`, `live-result.json`에 있다. 브라우저 왕복 검사 화면은 `test-results/tap-control/real-desktop-roundtrip-controller.png`와 `real-mobile-roundtrip-viewer.png`에 저장했다. 모바일의 이미 열린 페이지는 새로고침해야 새 파일을 읽는다.
