# Astra 실제 몽글터미널 드래그 검증

검증일: 2026-10-06. 제품 코드 기준: `91ccd1d`. 실행 시 HEAD는 아스트라 전용 Computer Use 규칙 문서만 추가한 `6877f67`이며, 두 커밋 사이 `apps/`, `packages/` 차이는 없다.

## 결론

**직접 드래그 복사는 아직 완전히 해결되지 않았다.** 짧은 범위와 안내가 겹치지 않은 범위는 정확히 복사됐지만, Claude의 `Jump to bottom` 안내가 마지막 행과 겹치면 행 끝이 누락되는 현상을 최종 빌드에서도 재현했다.

## 실행 방식

- gpt-6-astra의 `node_repl` + `@oai/sky`로 실제 몽글터미널 Windows 창을 조회·활성화하고 드래그, PageUp/PageDown, 휠 스크롤했다. 브라우저 또는 Aside 검사는 수행하지 않았다.
- 기존 개발 빌드의 host/web 산출물을 격리 시험용 unpacked 앱에 적용했다. 기존 백업은 덮어쓰지 않았다.
- 새 TEMP `MONGLE_DATA_DIR`와 OwnerPipe 시험 호스트를 사용했다. 미리 준비된 합성 LIVE-001~300 대화를 Claude 전체화면 안전 모드로 재개했고, 하단 고정 입력창을 유지했다. 명령 실행 준비는 실행 도우미로 수행했으며 UI로 셸 명령을 입력하지 않았다.
- `sky.drag`로 일반 드래그한 뒤 Electron 메인 프로세스의 Windows 클립보드 읽기 API로 결과를 확인했다. 38줄·39줄은 합성 원문 문자열과 전체 일치 여부를 비교했다. UI 입력을 Electron `sendInputEvent`로 대신하지 않았다.

## 직접 확인한 결과

| 조건 | 직접 선택 범위 | Windows 클립보드 결과 |
| --- | --- | --- |
| 안내 겹침 없음, 하단 고정 입력창 유지 | LIVE-295~300, 6줄 | 한글과 각 END 표식을 포함해 원문 일치 |
| 안내 겹침 없음, 같은 창 너비 | LIVE-263~300, 38줄 | 전체 문자열 일치, 마지막 `END-300` 보존 |
| PageUp/PageDown 및 위쪽 휠 스크롤 후 안내 겹침 | LIVE-261~299, 39줄 | **불일치**. 39줄은 복사됐지만 마지막 `END-299`가 `E`로 잘림 |

실패한 마지막 행:

```text
예상: LIVE-299 selection test 가나다라마 ABCDEFGHIJ 0123456789 END-299
실제: LIVE-299 selection test 가나다라마 ABCDEFGHIJ 0123456789 E
```

실패 시 실제 창에서 `Jump to bottom (ctrl+End)` 안내가 마지막 행의 끝부분을 덮고 있었다. 이번 결과는 겹침 조건에서 누락이 남았다는 직접 증거이며, 이 검사만으로 원인을 특정 구현 한 곳에 확정하지 않는다. 이전 검사에서 기록한 LIVE-262~300 범위와 달리, 이번 직접 재현 범위는 LIVE-261~299다.

## 도구 상태와 검증 한계

- 새 아스트라 세션에서 창 목록, 캡처, 창 활성화, 드래그 입력이 정상 동작했다. 이전 `foreground window did not report a process id` 오류는 이번 검사에서 재발하지 않았다.
- 초기 샌드박스 실행은 격리 호스트 준비에 실패했다. 승인된 외부 실행으로 새 시험 인스턴스를 준비한 뒤 검증했다. 이 준비 실패를 드래그 실패로 집계하지 않았다.
- 활성화 전 캡처는 준비한 Claude 세션을 보여주지 않았다. 대상 시험 창을 활성화한 뒤 Claude 합성 화면을 확인하고서만 선택 검증을 수행했다.
- 실패 재현 뒤 진단 목적으로 시험 앱 사이드바를 한 번 접었으나, 추가 비교 중단 지시에 따라 넓어진 상태의 드래그는 검사하지 않았다. 너비 변경을 해결책으로 제시하지 않는다.
- `sky.drag`에는 마우스 홀드 시간 옵션이 없다. 이번 검사로 300줄 전체 자동 스크롤 드래그, 스트리밍 중 선택, Codex CLI 또는 모든 선택 방향을 검증했다고 주장하지 않는다.

## 정리

- 시험 도우미의 정상 종료 경로로 이번 시험 앱과 호스트를 종료했고 `closed: true`를 확인했다. 이후 시험 실행 파일 및 이번 TEMP 프로필에 해당하는 앱/호스트 프로세스가 남지 않았음을 확인했다.
- 시험용 `dist/web/index.html`과 `dist/host/main.cjs`를 기존 백업으로 복원했다. 각각 SHA-256 비교 결과가 일치했다. 복사했던 해시 이름 web assets는 무시된 시험 디렉터리에만 남는다.
- 설치된 사용자 앱, 기존 사용자 호스트 및 인증 데이터를 수정하거나 종료하지 않았다. 제품 코드 변경, 커밋, push, 배포는 수행하지 않았다.
